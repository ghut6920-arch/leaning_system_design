# AI 个人学习系统：工作包 8／多 Agent 协作与共享状态设计方案 v0

日期：2026-09-30  
成熟度：概念设计 v0，供评审与有限试用；尚未验证教学收益、协作净收益或技术实现。  
本轮与工作包 7 同期形成方案，共用学习需求、需求处理结果、计划承诺、恢复记录、变更与纠错影响五类交接含义。本文中的运行记录和情境均为假设，不是个人学习事实或真实接收回执。

**本包推荐围绕决定组织协作：专业责任方维护自己的有效依据，计划责任方维护唯一有效安排，执行者在清楚的范围内直接教学。**换 Agent 需要转移的是尚未完成的责任、可信依据和执行边界，不是重做一次完整诊断，也不是复制一份完整画像。8 将授权、版本和接管规则放入已有工作，不增加一个逐项批准的管理层。

## 一、设计从哪些问题开始

前包已经允许高能力模型负责关键设计与评价，执行者负责实时教学，但仅有分工方向还不能确保连续运行：一个建议可能被写成承诺，一份旧摘要可能覆盖新纠错，发送方可能以为已经交出、接收方却只理解为收到消息。本包优先修复这些会改变学习结果的断点。

## 二、责任跟随决定，不跟随 Agent 名称

### 1. 一项决定有一位当前责任方

“责任方”是需要对结果、依据与未决项负责的职能，可以由同一 Agent 兼任，也可交给具有相应能力的执行者。每个具体目标的目标责任、评估责任、教学责任和计划责任在启动时要可辨认；只写“高层会处理”不足以构成归属。换人可以改变承担者，不能悄悄改变专业权限。

下表中的直接决定包含既有授权，不要求每次先获得批准。重要程度由决定的后果和所需依据确定，例如影响整段跳过、扩大支持范围、改变目标要求，比同判据下的一次普通评分需要更强复核。

| 要改变什么 | 可以提出；谁可直接决定 | 最终责任及必须返回的边界 |
|---|---|---|
| 用途、正式范围、投入、个人记录控制 | 用户决定；系统提供具体选项与影响，并沿已有授权执行 | 用户；普通排课和局部教学不重复询问 |
| 目标、判据、必要依赖和允许资源 | 各方可指出问题；2 的高能力责任方按有效依据修订 | 2；涉及用户用途、最终范围或新增投入时取得相应用户决定，7 接收安排影响 |
| 重要能力结论、重大诊断、重要跳过、评分争议 | 执行者提交原答及建议；3／评估责任方复核 | 3；先看原答、帮助和判据，再看教学总结；内容或目标争议先取得 4 或 2 的结果 |
| 内容可靠性、材料用途、关键参考 | 4 负责核验；授权内的摘录、制作和常规核对可直接完成 | 4；关键条件、答案或用途变化重新核验，不能靠主题相同声明等价 |
| 关键教学设计及复杂证明、方法构造 | 5 的高能力教学责任方给出具体任务、参考锚点和分支 | 5；参考可靠性由 4 支撑，目标匹配由 2 约束，不能因执行便利改低要求 |
| 措辞、呈现、局部帮助、常规反馈和评分 | 执行者在核验过的内容、活动和授权范围内直接决定 | 5 保存事实，3 维护证据解释；实质帮助如实记录，不得追认为未帮助 |
| 当前换法、策略配置的复用规则 | 5 决定本活动怎样换；6 维护可复用配置和限制 | 6 不替 5 作每轮选择；只有影响承诺与资源时返回 7 |
| 需求去向、时间竞争、计划承诺与生效范围 | 7 在用户目标、投入及专业约束内直接决定 | 7 维护唯一当前展开单；不能覆盖 2／3／4 的专业判断；8 的规则随该决定执行 |
| 立即停用、事实勘误、纠错与删除落实 | 任何发现者可要求停用受影响用途；原记录维护者据依据处理 | 专业方复核派生结果；8 保证通知、接管和旧结果处置，不代替所有专业决定 |

同一执行者兼任教学和评价时，评价仍从原答、条件和先定判据重新开始。让另一模型重复同一错误答案，或让同一模型换角色表示同意，都不是独立内容核验。可靠性来自适当的来源、推导、反例、测试或专业审查；具体采取哪一种由内容与错误后果决定。

### 2. 升级应指明哪项权限或依据不足

执行者先说明“拟改变什么、现有授权到哪里、哪条依据不够、可继续哪部分”，再找相应责任方。仅写“题目很复杂”容易把普通工作全部上交；仅写“时间紧”也不能授权降低标准。

需要返回的典型信号是：关键定义或参考冲突；结果将支持重要跳过；原诊断受到持续反证；需提供超出边界的帮助；变式改变对象域或核心条件；承诺已无法在资源内完成。这些信号不设统一次数阈值。一次可核查反例可能足以暂停，多次没有新信息的转述则不值得新增委派。

高层不可用时，执行者立即限制争议或越权用途，保留原答与待处理决定；仍可继续不依赖争议、材料可靠、预算足够且已授权的工作。可以给予已允许的解释、整理中间产物、完成其他目标或收束；不能新增重大能力结论、擅自跳过、扩大投入或改低目标。如果没有这样的可行工作，就结束本次学习并保留下一处理入口，不以等待填满学习时间。

## 三、高层必须交出足够具体、又不过度铺开的设计

本轮决定把“交付是否够用”放在开始当前活动之前，由接收执行者核对；这可以是几句短反馈，不增加独立审签文件。高层提供关键内容，执行者负责发现缺项；交付不够不能由执行者凭空编造核心证明后继续称已核验。

| 接收者应能回答的问题 | 足够的交付 | 不足时具体返回什么 |
|---|---|---|
| 现在实际让用户做什么 | 可执行任务或明确制作要求，目标关键操作及产物 | “只有理解目标，缺可观察任务；请给出要比较的条件及产物” |
| 怎样判断合法与不合法 | 可靠参考锚点、关键连接、允许的多解或信息不足分支 | “目前参考只验证一个例子，无法审查一般结论；可先教学该例，暂停一般证明评分” |
| 哪一步必须留给用户 | 可见输入、备用帮助、不能提前给出的方法或关系 | “图中的箭头已经给出待评价关系；请确认转教学或另备检查” |
| 表现不同怎样调整 | 会改变下一步的重要分支、帮助作用、反证与停止条件 | “失败后只要求继续追问，未给可行支持或返回路径；请补关键分支” |
| 我能改变到哪里 | 本次范围、局部调整、资源边界、返回对象和受限用途 | “可缩到局部论证，但尚未说明能否保留必要反馈；先收束，不承诺通过” |

已覆盖当前工作即可开始，不预先准备整个学期所有分支。复杂任务则必须有足以审查整体的参考结构：分段准备可以，永远只核查片段而无法判断整体不可以。缺参考时减少可作结论或缩小本次范围，不能把原本的一般证明换成听懂示范后宣布达成。

例如，目标是独立证明一个算法在给定条件下终止并正确，高层可以交付待证性质、关键不变量、允许查阅的定义、合法证明路线的审查锚点，以及卡在不变量保持时的局部支持。执行者可改写符号和选用已经核验的例子，不能仅用几次运行通过作整体结论。若学习者提出未列出的合法路线，应保留完整产物，交能核查该路线的责任方；“不符合参考顺序”本身不构成错误。

这一安排用准备投入换取执行时少等待。若为普通活动预先写尽全部话术，准备成本超过用途，则只保留会改变关键工作、评分或停止条件的设计。

## 四、共享的是有归属的依据，不是统一状态总分

### 1. 每类信息只有一处事实或专业结论的维护责任

共享可由引用和短说明完成。当前摘要用来找到事实和决定，不成为独立证据来源；某 Agent 自己整理的长画像无权覆盖原记录。

| 共享信息 | 维护责任与用途 | 何时更新、怎样限制使用 |
|---|---|---|
| 目标、判据、前置和允许资源 | 2；确定要求、比较旧证据 | 用户用途或内容要求变化时修订；旧要求按原情境解释 |
| 学科参考、来源、任务材料及用途 | 4；支撑教学和评分 | 内容、条件或用途变化触发核验；准备好、已采用与实际展示分开 |
| 任务、原答、过程、实际帮助和相关时间 | 5／C0；保留实际发生的学习 | 每次有关事件追加；初答与修订分开，未知接触不记为没有接触 |
| 条件化判断、诊断及使用限制 | 3；决定哪些能力可用于后续判断 | 新证据、冲突、纠错、删除触发复核；支持状况与可用性分开 |
| 可复用方法、适配限制与成本依据 | 6；减少重复选法和准备 | 有实际使用反馈时更新；不把策略建议当已执行或因果效果 |
| 需求处理、计划承诺、当前展开单 | 7；决定做什么、何时及投入边界 | 会改变取舍的新信息触发；材料安排属于同一有效安排的供给视角 |
| 父任务、停止原因、中间产物和下一连接点 | 5 保存教学事实，7 决定本次恢复范围 | 真实停止、恢复或产物变化时更新；完整证明等整体要求持续可见 |
| 委派、未决交接、采用版本与变更影响 | 提出或作决定的原责任方维护，计划责任方承接跨会话入口 | 收到、承担、处理或限制发生时更新；8 提供共同规则，不另存全量个人资料 |

“支持／未达／未知／混合”回答表现如何；“可使用／待复核／已撤销”回答判断能否驱动后续决定。材料可用、活动完成、需求已安排与目标达成也各有归属。本文不把这些合为一个进度或状态。

### 2. 常规恢复和重要复核采用不同读取范围

常规恢复先看 7 的当前有效范围与暂停事项、所引用目标／判据和 3 的当前判断、当前材料用途，然后看上次停止点、关键原答位置、实际帮助与时间背景、父任务和未决交接。稳定部分直接复用；不重新询问完整学习经历。

准备重要跳过、扩大结论、处理评分异议、删除影响或相互冲突证据时，必须再回查相关任务原文、原答和修订、帮助时序、具体判据及内容核验。评估者先自行对照这些依据，再看其他 Agent 总结，减少流畅总结替代事实的风险。若原答已不存在，只能依据剩余材料作有限判断，不能从摘要还原一份“等价原答”。

时间同样按相关内容引用：初学、练习、帮助／反馈、已知再接触和本次事件分别保留能改变解释的关系，不逐句计时。昨天只修订一个条件，不重置全主题历史；刚看过完整方法，也不能因换执行者便称无暴露。文件能打开不代表已读完，没有展示日志不证明从未看过。

保存到足以作后续决定和恢复为止。正式使用前明确课程内保留范围、何时归档或清理以及用户修改入口；不默认永久保存全部聊天，也不借推断独立性做隐蔽监测。可见的成本、用户主动陈述和真实产物已足够支持本轮设计。

## 五、从委派到接管：责任必须真正落下

### 1. 委派的是一个可收束的决定

一份最小委派在现有活动或交接尾部写清：要解决的决定、所据目标与材料等版本、可读依据、授权与资源、期待产物、停止条件和返回对象。简单工作一段话即可。

例如：“请据目标 G 的当前判据和任务 T，核查原答 E 的第二个连接是否成立；先读 E 与实际提示记录，再看现有评分。可重推和比较已授权来源，不能改目标或追加学习任务。返回可接受路线、错误位置或无法裁定原因；若涉及参考错误，交 4 核验并限制该处评分，由 3 接收最终判断。”这比“请评估学习者理解程度”更容易检查是否完成。

再委派只有在需要不同核验能力、独立材料准备或确有并行价值时发生。新受托者的权限是原授权范围内可分出的部分，不能取得原委派者没有的权限；预算也不能复制为每人一份。原发起责任方仍负责拼接结果和收束，除非有权安排的责任方明确转移了责任。

准备材料和整理独立来源可以并行；面对同一用户的活动默认只有一位当前执行者，避免两个 Agent 同时提示、重复索答或不知彼此暴露。需要切换时先确认执行权和未完成位置。若同一问题被反复转回、没有新依据或资源，停止转交，由原责任方选择已有可行路径、限制结论或交 7 暂缓；不继续制造“正在处理”的假象。

### 2. 收到消息不等于承担责任，更不等于已安排

本轮保留三个必要区别，措辞可以自然表达，不要求建立复杂状态机：尚未取得有效接收；已有人明确承担、结果尚未形成；已经得到实质处理结果。接收者若只是表示看到了，应追问其是否承担哪个决定，而非把一句“收到”解释成已排程。

承担责任至少说明接了哪部分、还缺什么、何时或在什么事件后处理。下一触发可以是“材料核验完成后”“下次周计划复盘时”，不要求每个需求强加日期。有真实使用期限时则须说明能否及时处理及延期后果。

| 接收情况 | 当前责任与继续路径 | 不能如何表述 |
|---|---|---|
| 未回应或仅确认收到 | 发送方保持追踪，7 保留跨会话未决入口；继续不受影响活动，必要时由原责任方改派或暂缓 | 不写已交完，不让用户自行追各 Agent |
| 接受部分范围 | 接收方负责已接部分，发送方保留未接部分及去向 | 不把部分接收扩写成整项已落实 |
| 条件不足而退回 | 接收者指出会改变决定的具体缺项；发送方补齐、缩用途或请 7 取舍 | 不反复索要完整画像或无限补材料 |
| 明确拒收或暂不能接 | 说明能力、资源或权限原因；原责任方选可用承担者，或保留未承诺与影响 | 不以换收件人消除原问题，也不自动扩大预算 |
| 已接责但没有处理 | 接收方仍负责；在所约触发失效、期限将受影响或下次恢复时检查，必要时接管 | 不长期停留在已接收而没有下一触发 |
| 返回实质结果 | 原决定方确认依据和权限，按相应专业结果更新；7 才把所选范围纳入有效安排 | 不以“建议采用”代替实际采用 |

活动可先结束，未决交接继续保留；为让记录好看而留用户在线等待没有必要。角色合并时，承担和处理可以在同一短记录内完成，也无需制造一次发送回执。

### 3. 接管必须确认“可以继续什么”

接管者核对当前版本和限制，指出接手的未完成工作、预算与权限、下一步和停止／返回条件。原责任方可用时，由其交出未决项；突然离线时，由当前计划责任方把已有依据与权限交给可承担者。没有人有权扩大授权时，接管仅继承原范围，缺失责任的重大决定保持待处理。

同一活动的新执行者接任时，交接同时结束旧执行者对该范围的面向用户教学权限；若旧执行者仍承担后台核验，须单独说明其保留范围。旧执行者迟到的结果只作为提交内容进入当前责任方的采用检查，不能直接补发提示、继续索答或改写当前安排。不能确认唯一当前执行入口时，先暂停该活动的新提示与任务展示，保留产物，由有权责任方明确接任后再继续。确认执行入口可以并入同一条接任记录，无需另设审批层；其技术保障留到实现验证。

接任短记录可以是：“已接当前安排 P 的有效部分；原答 E 与提示 H 可查，父证明停在引理完成、一般连接未做。材料 M 的争议部分仍停用。本次按 7 新承诺完成连接草稿，常规反馈可直接做，整体通过待评估复核；预算不足时保存产物返回 7。”它同时回答依据、责任、有效范围和下一步，不需要附上全量对话。

## 六、版本和采用：保留新信息，不让旧决定覆盖现在

任何会影响要求、证据解释或安排的结果，应说明“基于什么版本，建议改变什么”。版本可以是稳定标识与修订日期，不要求预先设计数据库或消息协议。只改错字无需使所有判断失效；改变定义域、允许资源、可见帮助、判据或预算则需要检查相应影响。

先区分三件事：执行者提出建议；有权专业方作出决定；7 将可行范围合入当前安排。它们可由一人连续完成，但不能语义上合并。专业结果成立不保证本次有预算执行；计划写入也不能让不合格材料或无效判断重新成立。

迟到或并行结果按以下顺序处理：先检查是否涉及删除、撤回或停用；再看与当前目标、判据、材料、帮助、证据和资源是否相容；最后由相应责任方决定采用、部分采用、重新核验或不采用，并说明其对当前安排的影响。无实质变化的旧稿可直接引用已有核验；部分相容则只采用对应范围，不因日期旧一律丢弃。

相反建议先辨认是否真的针对同一问题。一个评价开卷推理，一个评价无提示方法选择，可以同时成立；对同一条件下同一原答结论相反，交 3 查判据与依据，涉及内容交 4，涉及目标交 2。相互矛盾的结论不平均、不投票，也不按最后提交者覆盖。不同时间发生的真实原答分别保存，不以保留唯一当前判断为理由删除反证。

关键依据变化即时限制相关执行，不等完整新版计划。执行者在下一次相关使用、提示展示或确定判断之前，须能取得当前有效范围与限制；暂不能确认时，不继续受该变化影响的用途。停用通知由发起方跟进当前执行与计划接收；这是一项运行要求，尚不等于已经具备可靠推送技术。7 后续整合新版本时保留其他有效部分。

## 七、与工作包 7 共用的五类交接

以下为两份同期 v0 的共同语义。它们可附在原活动、展开单与变更记录中，不要求五张表，也不要求每次填写所有信息。

| 交接对象 | 最少应表达什么 | 谁负责决定、谁负责接续 |
|---|---|---|
| 学习需求 | 目标及版本、尚缺工作和已有支持、必要理由与延期影响；必需条件与建议时窗；原答、帮助、接触、材料、父任务及恢复引用 | 5 形成一份需求，6 按需补配置、成本、可拆与合并条件；7 接收并取舍 |
| 需求处理结果 | 与原需求对应的实际接收／承担；安排、合并、延后、缩范围、退回补充或不再投入的理由、去向与重新考虑条件 | 7 作实质决定；8 的规则确保来源有权、回执真实、未接部分有人追踪 |
| 计划承诺／当前展开单 | 有效依据、入选范围、投入边界、顺序或时窗、局部调整权限、未入选部分及后果 | 7 维护唯一有效版本及生效范围；5 确认教学可执行，6 按需校核方法约束 |
| 恢复记录 | 当前有效依据、完成与未完成、停止原因、父任务、中间产物、帮助与时间、争议和下一连接点 | 5 保存事实；7 决定现在恢复什么及重新承诺多少；接管者按 8 确认权限和受限用途 |
| 变更与纠错影响 | 什么依据变了、哪些需求和承诺受影响、何处立即停用、哪些仍可用、需要谁重新判断与各方处理结果 | 原专业方决定本领域影响；7 调整安排；8 防漏接、旧版本覆盖和迟到复活 |

同一缺口由教学与策略端同时提出时，沿同一需求引用补充信息，不增加第二项承诺。合并安排需要 5 确认线索、资源、整体操作与时间条件相容，3 限定实际证据；7 将活动放在同一时段，不等于这些条件自动满足。

7 缩短预算后，5／6 可在既有授权内直接给出保留必要反馈与收束的做法；若做不到，由 7 真正缩小承诺或暂缓。8 不批准缩水后的活动“算等效”，也不把 7 的预算决定解释成修改目标的权限。

## 八、纠错必须修到依赖它的决定

本包继承两条回查链，新增的是让每个接收者返回自己的处理结果，且缺漏仍可见：

1. **来源／规则 → 材料、解释、任务和参考 → 实际使用与评分 → 能力判断 → 学习安排。**
2. **来源／规则 → 目标及判据 → 材料、任务与评价 → 能力判断与学习安排。**

发现者先定位具体疑误并限制相关用途。4 给出更正依据、适用范围与已知直接依赖；2 检查错误是否进入要求，必要时修订目标／判据；3 据原答和当时条件重评；5 修复已发生的误导；7 撤回错误补课、错误跳过并安排仍必要工作。8 的协作责任由发起方与当前计划责任方落实：确保每条相关分支有人接、指出尚未回报部分，不自行替各方作专业判断。

变更记录可以只有几行：“参考漏条件，相关评分先暂停；4 已更正当前参考；2 确认判据需修订；3 已用原答重评两项，第三项条件缺失待处理；5 尚未完成向用户说明；7 已撤回由误判产生的补课，原一般证明任务仍在。”这比一句“错误已修复”保留了真正未完成的工作。

恢复需分别确认：内容在当前用途下可用；已实际误导的部分是否得到必要纠正；旧评分与判断是否重审。三者可以不同时间完成，材料修好不自动恢复旧能力结论。原答充分则直接重评并撤销错误安排；仅在原答不足以支持必要结论时补相应证据。若错误教学确有影响，后续纠正活动说明是修复系统造成的误导，不把它包装成用户原本欠下的补课。

依赖关系不全时，由各方列出已知影响和尚不能排除的用途。对无法排除关键错误依赖的确定判断继续受限，已确认无关部分继续。查不到记录不等于没有影响；也不因此默认整章失效。新要求与旧错误分别处理，不能用后来新增标准倒推用户当时答错。

## 九、用户控制贯穿原记录、派生判断和迟到结果

用户应能查看本次依据、理解为何安排、质疑评分、纠正个人信息、导出或删除记录。普通请求沿既有权限直接执行；只有指向不明确、无法辨认删除范围时才澄清，不把日常查看和纠正做成反复确认流程。

**事实勘误**依据原始记录修正，例如提示实际在初答之后，却误标为之前；保留更正理由。**解释修订**改变评分或诊断，保留修订关系和受影响用途。**用户异议**可以在尚未裁定时保留，不强迫用户接受原评分；但用户希望某次算独立，并不能把确有的关键帮助改成未发生。

导出默认围绕用户指定课程、目标或记录范围，带出仍保留的任务／原答引用或内容、实际帮助和时间条件、当前判断及限制、当前承诺与未决项，使接收者能辨认支持范围。原始证据不随导出提供时明确“仅摘要，不足以独立复核”。非必要聊天和其他课程的个人信息不随手附带；删除内容不再从摘要或导出副本回填。

删除先使所指个人内容退出后续使用，再由维护者清理可控制范围内的原记录、引用性摘要、派生产物及活动副本，通知仍在处理它的执行者停止使用和回传。3 按剩余支持重审，7 据新判断调整相关承诺，5 更新恢复位置和摘要。非个人学科参考可以保留，不能在其中藏一份个人作答、经历或没有依据的暴露结论。

为防旧结果复活，接收者在采用前检查它所依赖的记录是否已删除或失效。已知依赖被删内容的回传，不再进入评价、摘要或安排；回传中的个人副本按同一删除范围清理。尚有独立保留依据的结果，可由 3 仅据那些依据重新形成判断，不将旧总结当作证据。

阻止旧引用再次采用所需的最少“该引用已不可用”信息，不得携带已删作答或重建其内容；若用户删除范围也包括这些个人关联，就不保留个人关联索引，改为要求接收结果能够指向当前仍存在、获准使用的依据，无法对应即不采用。这是删除语义与接收要求，不预定哈希、审计库或备份方案。实现阶段必须核实副本、备份和外部导出的实际控制边界，并准确报告完成范围；本版不声称已具备永久擦除一切副本的技术。

## 十、假设走查：规则是否会产生可检查的不同结果

以下案例中“已接收”“已采用”描述各自假设分支发生后的状态，不能记入真实学习档案。

### 情境 A：充分设计让普通互动直接完成

**依据与决定。**目标是给定公式时正确计算并解释单位；2 已给判据，4 已核验题面和参考，5 的设计说明单位错误时可澄清、计算错误时可局部提示，7 给出足够完成与反馈的范围。执行者不需逐轮询问高层，按授权调整措辞、给一次单位澄清，保存澄清前后作答。

**产物与接收。**5 交原答、实际提示、时间及按既有判据的评分；3 接收可用证据并明确“给定公式及单位澄清条件下”的支持，7 接收本次完成结果。如果目标本就允许单位说明且所需工作已覆盖，7 结束该项投入；若目标要求自主辨认单位，则仅该部分仍需合格证据。

**有效状态与下一步。**活动已完成与目标支持范围分别可查。前一种分支没有新增必修任务；后一种由同一需求进入 7 取舍，不能为了回执闭环立刻补考。此例检验授权能否减少等待，而非让所有动作绕行所有责任方。

### 情境 B：复杂证明缩时后换执行者

**依据与决定。**原目标要求完成构造并证明一般性质，参考足以审查整体。用户可用时间缩短，5 说明只够完成一个中间论证并收束，7 将本次承诺收缩到该位置；2 的完整目标不变。执行者保存构造、已证引理、未完成连接、曾展示的反例，以及父任务引用。

**产物与接收。**下次由 7 在当前预算下承诺继续一般连接；新执行者确认已接上述产物和授权，明确已证引理不重做、一般结论尚未通过。若他只看到“构造成功”的摘要，就必须取得完整中间产物及帮助记录，不能直接作整体通过判断。

**有效状态与下一步。**局部证据仍有效，父证明未完成，恢复无需重新冷启动。新执行者按参考支持下一连接，路线超出自己可核验能力时交高能力责任方；等待中可整理论证或收束，不能把运行成功换作一般证明。

### 情境 C：旧版本建议、相反评分和迟到回执

**依据与决定。**执行者甲据 G1 的开卷推理要求提交“可跳过重复推理练习”；执行者乙据用户已确认的新 G2 提交“尚缺无提示方法选择”。两者看似相反，3 先对照原答和要求，判定 G1 范围内的支持可保留，但不能支持 G2 新增操作；2 确认版本关系，7 只安排新增要求内的有限检查。

**产物与接收。**7 的新安排 P2 记录原推理不重学、选择证据待补。甲随后返回基于 P1 的“已准备好整段跳过”，接收方发现 P1 已被替代，保留其中相容的材料引用，退回跳过建议并说明原因；甲确认停止旧任务。

**有效状态与下一步。**P2 是唯一当前安排，旧回执不恢复 P1。若两名执行者实际针对相同条件下同一原答仍相反，3 须回查评分依据而非按此例条件化并存；裁定前只限制争议结论，原始表现各自保留。

### 情境 D：多模型赞同了漏条件的参考

**依据与决定。**假设题目求解时参考除以含未知数的因子，漏掉因子为零的解，多个模型均同意参考。用户原答保留该解且说明分情况，却被误判。执行者提出疑误并暂停相关评分；4 用代回和分情况推导确认遗漏，票数不参与正确性裁定。

**产物与接收。**4 更正题解并回查解释、题目和图示；2 检查判据是否也写成无条件约去该因子，若是则修订，这同时走完两条纠错链。3 用保存的原答重评，撤回误判；5 向用户说明系统错误以及因子非零时原变形仍合法；7 撤回由误判产生的补课。各方回报自己完成的部分。

**有效状态与下一步。**更正材料可以先恢复教学用途；未重评的历史判断仍待复核，不能借材料已更正全部恢复。该用户原答已够，不要求重考；若另一活动已让用户学会错误规则，5 另作必要纠正，3 只据实际后续表现判断修复，7 承担其真实成本。

### 情境 E：答案意外展示，高层暂不可用

**依据与决定。**原检查要求自主选择方法，执行者误展示完整方法。初答和展示时点可查，评估高层暂不能响应。执行者保存暴露事实，停止把展示后执行解释为自主选择；已授权的开卷比较活动仍可继续，或在预算不足时收束。

**产物与接收。**交接给新执行者时包含原答、已展示内容和待复核用途，后者明确承接限制。3 恢复后据原答解释展示前实际已有的支持，7 处理仍必要的选择检查；没有预备且合格的新任务时，只保留未支持，不能临时生成一道未核验题来填平结论。

**有效状态与下一步。**原始支持不因后续暴露全部消失，展示后的表现按实际帮助解释。换 Agent、隐藏方法或换数字都不能重置条件；下一次检查必须重新确认所需线索与资源相容。

### 情境 F：删除关键证据，旧执行者迟到回传

**共同依据与动作。**原判断 J 引用 A、B；用户删除 A 及其个人派生摘要。维护者停止 A 的使用并清理可控副本，3 取得仍保留的 B 与判据，7 暂停仅依赖 A 的重要跳过。旧执行者此时回传含 A 摘要的“通过”，接收方不采用并按删除范围清理，通知它停止该依赖。以下三分支分别审查 B 的内容与条件，不按剩余条数机械决定。

| 假设剩余依据 | 谁决定、交出什么 | 接收结果与当前有效状态 | 下一步及改变条件 |
|---|---|---|---|
| B 单独完整覆盖同一目标的范围和条件 | 3 重新确认 J 可保留，引用仅指向 B；5 更新摘要 | 7 接收保留结果，原安排中相应跳过可继续；A 不再有任何证据作用 | 不因删除自动补测；有新反证或要求变化时再复核 |
| B 仅支持给定方法后的执行，A 曾是自主选择的唯一支持 | 3 将结论收窄到执行支持，选择部分未知；交出限制及必要性判断 | 7 保留可用执行结论，取消以已会选择为前提的跳过；相应需求按使用时点取舍 | 若选择不影响当前活动，可带未知继续；目标内重要使用前再决定是否补证 |
| B 无效或与该要求无关，没有剩余有效支持 | 3 撤销失据判断，明确未知而非能力下降；5 移除摘要中的通过声明 | 7 接收撤销结果，停止依赖该结论的承诺；其他有效目标继续 | 只有重要决定需要该支持时安排有限证据，用户也可选择不再投入 |

三分支都不能从迟到总结、旧个人画像或材料库恢复 A。若回传声称另有新证据，却不能对应当前获准保留的原答与条件，就先保持未采用；“以前看过，所以我确认”不能代替已删除依据。

### 情境 G：突然中断，没有结束摘要，且帮助记录被质疑

**依据与决定。**系统只留下任务 T、初答 E1、提示发送事件 H 和未完成草稿 D，没有收束。用户表示“提示是在初答之后”，旧局部备注却写成提示前已展示。接管者读取当前有效安排，确认 E1 的时间早于 H，原记录维护者据此勘误；3 重审该条件对评分的影响。若只有互相矛盾的备注，无法核对，则保存异议并将该帮助条件标为有争议，不选对结论更方便的一方。

**产物与接收。**恢复记录写清已确认事件、无法确认的最后动作、草稿实际内容、未完成父任务和受限用途，不猜补用户最后一句或最终提交。5 说明可以从 D 的可核查连接继续；7 据本次投入形成新承诺，接管者确认接收。只有缺失信息会改变当前动作时，才向用户作最小澄清；否则带着限制继续。

**有效状态与下一步。**E1 能支持什么由实际时间与判据决定，D 不因存在就算完成，未知帮助不算无帮助。已经有可靠证据的其他部分保留；没有结束摘要只增加有限恢复工作，不触发整章冷启动。

### 情境 H：无人接手，委派反复绕回

**依据与决定。**5 提出一项目标内保持检查，6 已附可行条件，发给 7 后只收到“消息已读”。5 保留待接收，并将需求放在本次收束的未决入口。若计划责任方仍在、只是未作决定，则由其在下次资源取舍时处理；若无法承接，则由原责任方安排已有授权且可承担的接管者。无权或无能力接替时如实暂缓。

**产物与接收。**若接管者已在原授权内明确承担 7 的计划职能，发现原检查时窗内没有足够资源，就作出“暂缓到下一次相关使用前重新评估，期间不能声称已满足保持要求”的决定，并维护到唯一安排；无需再交给一个实际上无人承担的“7”。若接管者只有教学权限，只能记录原时窗不可执行、保持需求待处理，不能冒称已作计划决定。如果 6 再次收到同样无变化的预算请求，不重复返回同一配置，直接引用不可行原因，留给有权承担计划责任者作取舍。

**有效状态与下一步。**前一分支有明确责任、真实暂缓和再次触发条件；后一分支如实保留尚缺计划承担者及其影响，由原发送方维持跟进。两种情况下当前活动都可以结束，未承诺工作不伪装成已安排，也不无限循环转交。若该保持支持对当前其他工作不是必要前提，其他学习照常继续。

## 十一、协作成本如何约束方案，而不牺牲关键依据

首期推荐由尽可能少的承担者完成一条完整学习路径：一个当前教学执行者配合有能力承担关键设计与复核的责任方，计划、材料、证据等相容职能可兼任。需要专业核验、独立材料准备或有价值并行时再分开。这里不预定恰好两个 Agent，也不要求高能力模型永久在线。

成本包含高层准备、内容核验、实际学习、反馈、等待、交接、重复索答、上下文重建、费用和用户打断。可以按活动粗估并注明来源，不必精确到每轮；延期工作保持未完成，不能计为节约。评价协作时同时观察是否漏接、误用旧版本、错误恢复、重复教学以及关键判断失真。

| 失败信号 | 首选简化或修订 |
|---|---|
| 普通问答持续等待高层 | 补具体分支和授权，把常规决定还给执行者 |
| 多位 Agent 只复述同一参考 | 合并相容责任；必要核验改用能发现错误的依据或方法 |
| 换人后反复索取相同原答 | 改善原记录定位和恢复短说明，减少复制画像 |
| 同一需求跨包绕回、无新信息 | 停止再委派，原责任方给出可行取舍或受限收束 |
| 记录很完整，教学却被打断 | 删除不影响决定的字段和过程记录，保留关键产物及条件 |
| 错误参考或迟到结果反复进入安排 | 收紧对应采用检查，修复依赖和责任；不能只增加会签人数 |

有限试用比较分层协作与同一执行者兼任的简单安排，尽量保持目标、材料质量、判据、资源和反馈机会相近；使用难度和先验相近的不同单元，避免把同内容第二遍的练习收益归给协作。分别看内容与评价正确性、教学关键操作、目标条件下的学习表现、总成本与连续性，不用满意度或消息数替代学习结果。个人样本和顺序效应限制因果结论。

纸上先检查本节案例能否找出依据、责任、产物、真实接收、有效状态和下一步，再在一条狭窄课程路径上观察真实中断、范围变化和正常收束。测试删除、参考更正、旧回传和无摘要恢复可使用专门的虚构记录，避免制造真实个人误判。即使全部走查通过，也只说明规则暂未暴露断点；多 Agent 是否有净收益仍需真实使用支持。

## 十二、本版决定与仍需校准的事项

本轮已经选择：专业责任保持原归属；7 维护唯一有效安排；8 的协作规则嵌入原记录；关键设计需达到可执行程度；普通活动按授权直接继续；委派不会扩权；接收与处理分开；旧结果按当前依据检查；纠错走两链；删除后按剩余支持更新且禁止旧结果复活；缺高层或缺摘要时保留受限继续路径。后续不能因为模型或数据库尚未确定，把这些决定重新悬置。

真实试用前需要落实具体承担者、当前目标和投入、关键参考能由谁核验、复杂工作可中断位置、怎样让当前执行者得知停用、个人记录保留范围以及无法承接时的入口。实例化可用短记录和人工辅助完成，不必先建设通用共享记忆或知识图谱。

仍待验证的是：哪些关键决定确实需要分离复核，准备能否减少总等待，当前最小记录能否支持准确恢复，合并责任后是否降低成本而不增加错误。实现阶段再选择模型、通信、访问控制、备份删除、版本与通知机制，并验证其确实满足上述语义。工作包 9—10 负责把这些假设与跨学科、用户体验及首期验证贯通；本包交付的是可评审、可被试用结果修订的协作设计。
