# SK01 目标设计规则

资源版本：`pl-goals/0.1.0`；共用协议：`pl-contracts/0.1.0`。规则转译自 D02 第三至五、八至十节和 D03 第三、四、八至十节；设计源按[来源登记](../../../../resources/source-registry.json)回查。常规工作只加载当前要求、相关内容片段及这些精简规则，重要歧义或未覆盖配置再回查原文。

## 资料与用途

| 输入 | 可支持的目标工作 | 仍需保留的限制 |
|---|---|---|
| 课程表 | 主题地图、节点、候选顺序 | 不能确定深度、必要前置或验收标准 |
| 正式大纲／课程目标 | 课程范围、明确要求、考核方向 | 可观察判据与个人起点仍需辨认 |
| 正文／讲义／视频 | 定义、关系、条件、例题与解释依据 | 不自动成为课程必修要求，不证明用户掌握 |
| 作业／考试样题／评分说明 | 操作深度、任务形式、允许资源、评分线索 | 不推整门课、长期保持或陌生应用 |
| 个人产物 | 候选表现、接触线索 | 实际帮助未知时不能称独立能力 |
| AI 补充 | 有出处身份的候选桥接 | 未核验不作权威内容或正式课程要求 |

分别记录“为什么要求这项能力”和“内容在什么条件下成立”。系统建议不得转成课程要求。要求可能已明确但内容仍缺失；教材也可能充分但不在个人近期用途内。只有书目或章节名时，可交暂定粗地图与近期缺项，不补造可评分判据。

课程评分与内容正确性冲突时并列保存。查当前课程发布者与版本；数学、程序或事实正确性依定义、合法推导、复现结果及合适来源判断，不能凭来源身份压过核验结果。理论或价值立场分歧保留竞争解释和论证标准。

## 粗地图与近期规格

粗地图给主要能力、最终综合任务、课程与个人覆盖差异、延期／范围外内容、关键依赖及未知。远期部分注明暂定程度和细化触发，不填学习者会／不会。只有会改变本次关键决定的信息才需要补问；远期缺项不拦已有可靠近期范围。

近期目标应能表达：在指定对象域与情境、使用允许资源时，学习者完成关键操作，产生可检查产物，满足关键判据；结论不覆盖列明范围。仅在目标确实需要时加入时间或情境变化条件。判据逐要求版本化，关键错误不能被无关高分抵消；允许有依据的不同解法。

每个要求、判据和前置保留要求来源与内容依据的具体修订定位。B1 已登记的来源片段由共享组件读取；新片段尚未完成 AG2 内容工作时只标候选，不能靠 AG1 自报“核验通过”赋予资格。

拆分以是否改变观察、判断、帮助、材料或安排为理由，避免按段落机械拆分。保留局部与综合两层：子项分别成功不能自动支持端到端组织；综合产物只支持其中实际可辨认的操作。

开始课程／新单元时，把近期目标所需的知识及联系交给教学：哪些对象须认识、哪些关系和条件须使用、要达到什么解释／判断／推导／实现要求、将接到哪项整体工作。它们约束本次材料及主要问题的准备，按 [内容准备](../../learning-teaching/references/design-whole.md)实例化。不能只为一题另立很小的目标再将它当作本次课程设计；真正的一次性事实目标仍可按其范围结束。

**系统建议的目标须回对原用途。**从用户请求、课程要求和有限正文说明：为了完成本次希望做的工作，必须认识哪几条关系；近期目标怎样承接；本次只推进哪里，以及未展开部分为何可暂缓、何时影响后续。用户明确要求、内容所需依赖与系统建议分别保留。能观察、容易出题或已有材料，不足以证明一项目标选得充分；不得先缩成容易验收的目标，再只凭题目满足它认定用途已覆盖。

例如，解释给定系统怎样运行、论证结构为何适用、解释参数怎样从数据学习、依据预测作选择，是可分别需要的工作。按真实用途选取，不强制每个主题都含四项；正式使用目标只需接口时可保留内部黑箱，宽泛主题则交有理由的近期候选，不能自称已覆盖整主题。简单解释不暗加实现或测验。具体不足与合法简化见 [备课质量实例](../../learning-teaching/references/preparation-quality-examples.md)。

材料或审查指出用途承接不足时，AG1回原要求与内容处理，再同步受影响的材料、任务及计划；认知初稿不是不可回改的前提。原目标下已经合法的表现按原标准保留，新要求不倒判旧答。现有授权支持的内容设计直接落实，只有改变用户最终用途、承诺或新增投入才需要相应用户决定。

从正文落实判据时，先找定义域、前提、所求结论与使用目的，再辨认必须由学习者完成的计算、选择、解释、证明、构造或实现。将每项关键条件落实到产物中的可检查位置：例如证明的充分／必要方向与存在性，构造的可行性与所称最小性，代码的规格／接口／边界，实验的比较条件与解释范围。完整工作可以分段教，但整体目标仍须一次审查其连续连接；不能只统计子项数量。相应实例及不同深度的实际判据见 [目标实例](goal-worked-design.md)。

## 前置与证据要求

前置分必要、可伴随补充和有益背景。说明它针对的目标版本、缺少时哪个操作无法完成、依据、允许工具能否替代、补到何种程度及如何返回。课程顺序只作线索；单次失败不证明必要依赖，也不证明用户基础弱。互相依赖时先查粒度或显式支架接口，不展开无限前置链。

证据要求写明拟支持结论、必须调用的操作、观察产物、资源与帮助、正确性标准、典型／边界／综合覆盖和不能推出什么。若目标是选择方法，题干和帮助不能先代做选择；若目标是实现，完整代码由 AI 给出后照抄运行不能证明自主实现；若只需简单事实，不强制额外解释。

允许示范或跳过诊断；此选择改变随后表现条件，不新增达标结论。材料或参考缺关键正确性依据时限制相关活动／评分，交 AG2；任务能观察的结论不清时交 AG3。必要时间条件尚未满足则列具体待证范围，未要求的延迟／迁移用 `not_required`，不成为复习债务。

## 交付与停止

交付 `GoalSpec`、粗地图、未决项和 P-Goal 本地结果视图，含处理／未处理范围、双来源、证据要求、限制、接收责任与下一触发。已具有兼容有效目标时只交复用理由与引用；无理由不修订。缺预算或高能力资源时交可用子范围和会改变决定的缺项，不循环索要完整背景。

采用、教学、判断、承诺分别记录。只有相应责任及当前授权可以使候选成为正式依据；AG2 参考已恢复不代表 AG3 判断已恢复。SK01 不替材料核验、评分或规划完成未执行工作。

交教学时可从既有对象／人工记录合成一段短视图：本次目标与范围、已有支持及未知、现在给什么、学习者剩余工作、反馈依据、必要分支、预算与停止／返回。目标标准由目标维护，当前展开由活动／计划维护，表现由 Judgment 维护；短视图只是引用它们的可执行解释，不另建状态或同步一份掌握记录。普通反馈不要求重写整份视图；来源、目标、帮助或承诺实质变化时才更新相关连接。

进入 B4 专项设计时，AG1 在每个被引用 requirement 的 `teaching_scope` 中明确 `whole_required` 布尔值及 `whole_obligations` 列表；根据目标实际工作判断完整证明、组织或产物义务。不能为了通过执行检查取消原有整体要求。未声明的旧目标交回 AG1 澄清，不批量补默认值；修订后材料与证据用途按新引用重新检查。局部活动与整体核验的格式见[B4 教学接口](../../../../contracts/teaching-b4.md)。
