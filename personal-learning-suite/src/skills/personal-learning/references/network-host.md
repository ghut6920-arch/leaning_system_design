# B6 受控本地工作网络

仅在调用者显式建立 [NetworkHost](../../../runtime/network_b6.py) 时读取本文件。局部请求、状态和行为见 [network-b6.md](../../../../contracts/network-b6.md)，范围见 [B6 验收](../../../../specs/b6-acceptance.md)。原 B1 查看和 B5 `execute` 仍是独立开发接口。

宿主由可信本地调用方建立，加载四角色与相应 Skill 规则，并签发不可用 JSON 角色字段代替的能力对象。角色绑定仅作用于该宿主生命周期和受控调用通道，授权仍用现有共享记录；不宣称自然人认证或独立模型已启动。宿主保持单工作区独占与串行，异步后台及并行展示未启用。

需要专业处理时创建明确工作单，引用当前目标／判据、材料、事件、共享预算和受托方授权。收到不算接责，部分接责保留发送方对未接部分的跟进，缺授权保持候选未就绪。普通可靠活动和已获授权常规评分可走已有短路径，不为每题制造会签。

专业动作只处理已接范围，返回规范引用、限制与下一责任。返回和采用分开，采用只确认网络结果的相容范围，具体目标／判断／安排仍由原专业服务维护。过期依据先重核，不能以结果 adopted 覆盖当前专业原件或恢复旧计划。

接管前核对当前活动、父产物、实际帮助、预算、限制和可信断点；由宿主停止旧入口并原子推进执行代次。只通过当前 AG0 的 `present` 显示受控学习者载荷；不能把专业工具的完整回执当作可显示内容。旧代次不能继续展示，后台角色只能返回当前入口。

控制先于读取、重试、返回、采用及展示。删除结束受影响能力，清理已记录依赖的工作单和候选，不从返回摘要补造原答。后续建立新能力和仅含剩余合法依据的工作单。宿主不会清除调用者已拿到的对象、外部 stdout、聊天历史或模型上下文；原件已进入外部模型时由调用方实际结束该任务。无法确认单一入口时保留受限串行范围。
