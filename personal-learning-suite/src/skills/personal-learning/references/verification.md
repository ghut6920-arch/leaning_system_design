# 有限验证：实际教学输出、真实学习与投入分别判断

仅在维护修复、用户明确试用或已有实际问题需要核查时读取。本说明依据 D11 第二至九节、D10 第八至十节、D02 目标与证据边界、D08 资源与真实使用节点，以及 R01 第十五节、R05 第六／十三节、R06 E21—E23、E37—E38；定位见 [来源登记](../../../../resources/source-registry.json)。研究支持核查相应学习过程，不直接证明本框架、角色数或某个人的长期收益。日常可靠教学不逐轮启动验证工程。

## 先确定会改变什么决定

先写当前疑问及观察后会保留、修改、简化或停止什么。例如“陌生状态模型是否先给必要含义”“合法不同证明是否被错判”“复杂安排能否比直接讲解多解决一项必要工作”。沿现有目标、原活动、材料与记录取有限范围，已有够用实例直接用；不为覆盖表另加不需要的课程目标。

| 层次 | 实际要做什么 | 能支持的结论与限制 |
|---|---|---|
| V1 内容与用途 | 依据对象域核完整推导／合法多解，实际运行涉及的代码并对照规格，实际看所需图；另查标题、示范或题面是否代做拟观察操作 | 具体版本、内容与本用途是否可负责。有限算例不代替一般证明，引用齐全不等于核验完成 |
| V2 教学执行 | 从原始资料、真实请求和当时可取得的规则生成实际第一段教学／评审，保留展示顺序、学习者待做工作、取得的原答、帮助、分支、父产物返回和停止 | 该路径是否实际执行。只有第一段输出时仅能核到此处；预写理想方案或假设改答不能证明后续成功 |
| V3 真实学习 | 用户实际进入学习，保留其原答及帮助／接触条件，按原目标核当前作品；只有要求未来保持／新情境时再观察合法时点或自然使用 | 当前真实表现的条件化支持。虚构用户、同模型自答、AI 完整作品不替代；前后改善也须查任务可比性、帮助与练习影响 |
| V4 复杂度与收益 | 确有取舍需要时，以同目标、内容正确性、反馈功能和投入范围相当的简化路径比较；记录全过程成本和尚未解决的工作 | 是否值得保留额外编排。单次快慢、角色数、漂亮材料或不同任务不证明增益；没有可比观察时写未验证 |

源码／接口测试另列为软件检查，不能汇入真实 V1—V4“通过率”。同模型生成与评审注明共同背景；独立前向需实际授权、可用执行者和未提供理想答案的输入。换角色名不改变独立性，默认不自动启动其他 Agent。

## 从输入走到实际结果

1. 准备有限、当前可核的内容及原目标判据。正常开始、已有整体作品、Post 和必要异常分别从真实入口进入；执行者只取得原始资料、请求和可读规则，按需回源，不能先取得理想教学答案。现有活动够用时直接用，不固定加载全部方法包。
2. 保存实际输出和已发生顺序。陌生单元先给所需含义／框架／范例，已会或已有作品可直接工作；必要检查之后接可靠讲授。未有用户原答就停在待回应处，不代用户答。用户仅要解释时可完整示范并收束。
3. 按原判据核整体产物与接口，保留允许资源和被代做操作。原答够用直接采用；系统参考疑误先回核，再分别恢复材料、历史判断、实际教学误导和安排相容性。无关可靠学习继续，用户不为纠正系统而被迫重考。
4. 失败先限制受影响用途，修对应来源转译或内容；重放失败及关联正常分支。既有软件回归只在影响或集成需要时运行；结果、执行日期、输入／输出位置和未覆盖范围可以复查，不无限重跑。
5. 当前证据充分、预算结束、无新信息或用户停止则收束。未来条件仅在正式目标需要时留同一必要需求，按真实资源和使用日期取舍。未接收、未安排、未执行分别保留，不称已自动提醒。

程序 B7 的 preflight／软件切片可用于开发配置；人工学习不等它开放真实数据写入。现有 synthetic 接口不接真实个人记录，不能将真实记录改标虚构以绕过限制。

## 用户实际试用怎样记录

一次实际开始请求才启动学习。选课程中本就要学的一段及现有作品，沿课程当前协议保存原答、AI 输入、帮助顺序、修订、停止点；理论证明、实现行为和实验解释按各自判据。原目标中自然包含后续使用时再观察，不为验证框架新增必修延迟题。

验证结论用现有会话／复盘记录的一段索引，引用原件、条件、实际采用或修改决定。需要独立产物时放课程已有 artifacts／experiments 等相应位置，用户与 AI 代码都进课程代码目录；真实原答不复制到通用 validation、方法资源或公共演示。索引随依据的删除／停用同步处理，不能另建恢复已删个人内容的影子记录。

投入分别保留：首次准备／核验与稳定复用成本、用户主动学习、实际阻塞等待、系统工作／维护及费用。墙钟时间中并行的等待与操作不重复相加，系统工作时间也不直接加到用户墙钟；未测写未知，未发生与未知分开。没有宿主绑定就不许诺后台续写、未知完成时间或已发送提醒。

## 已填示例：第一段讲解没有原答

虚构任务是用已给模型 sₜ₊₁＝sₜ＋2uₜ 预测小车一步位置。教师已核“当前位置3、动作−2”得到−1，给了状态、动作、时间步的含义与另一个完整范例，然后交出上述一步工作，尚未收到学习者回应。

此时 V1 只支持这个理想模型、已核说明与算例；V2 只支持实际首段已展示所需输入和可完成工作，后续反馈未执行；V3 未执行；V4 没有可比观察。准备花费、用户实际耗时／等待和费用未计量就写未知，不能把题面15分钟上限写成实际耗时。拟用答案是教师参考，不能登记成用户已经预测正确。

## 如何收口

用有限观察决定：保留有具体必要功能的内容；修失败后重放；若额外编排没有相应工作、增加等待或重复读取，简化到单模型相容职责、稳定资料复用与一个连贯任务。基本内容、真实原答、可靠反馈、预算与用户控制继续保留。

当必要问题已有相称支持，可以关闭该验证投入；当缺真实观察且本轮不会取得时，也可以明确边界后结束本轮维护，列待验证条件。两种结束都不能伪称“真实闭环已全部通过”或保证所有模型都具有所需教学与专业核验能力。
