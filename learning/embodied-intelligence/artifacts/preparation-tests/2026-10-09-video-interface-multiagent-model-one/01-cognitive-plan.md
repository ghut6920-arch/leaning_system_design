备课审查稿，2026-10-09。沿 EMB-U-M0-VIDEO-20261006-02、Goal revision1 的 R1/R2/R3 组织；不采用新正式目标、不更新学习进度、不记录本稿已经教学。采用同一模型的多个子 Agent 分工，主 Agent 是唯一面向用户的呈现入口；子稿审查不增加学习样本，也不称独立盲评。未读取另外两次同提示词的对比备课。

## 1. 从当前真实记录确定起点

已核原件是 `sessions/2026-10-06-02/raw/` 的三份视频接口原答、`sessions/2026-10-07-01/raw/` 的初答、求助与最近修订，以及该会话 checkpoint revision4。只采用控制 revision11 所延续的新轮次；更早旧轮次的表现不进入本稿。

可保留的有限支持：学习者曾区别尺寸相容、像素对应违例与信息不足；在教师给定的接口下曾说出换轴与合并 B/T 的方向，但对两消费者用途的完整意义仍须给可靠输入；最近修订认识到视频分组和原帧次序、准备输入时像素值保持。整体两路线尚不能由这些局部原答充分支持。求助原话明确指出不懂帧归属的两种依据、两条路线、两类输入及组织/身份含义；最近修订把逐帧处理与打乱顺序混绑，也把特征编码与信息不变混绑。不能据这些话诊断“一般基础差”或固定学习类型。

本次从**同一帧经过哪些对象、哪种改变发生在哪一步**开始。视频轴与已经正确的局部关系可直接引用，不重开从轴计数到帧号猜测的练习链。需要对象、接口和完整路线的可靠输入时直接提供，不等学习者再次答错才讲。

## 2. 学完要能完成的工作

单元终点仍是一份可交接的接口说明：同一相机数据怎样进入给定视频消费者和逐帧图像消费者；每个阶段读什么对象、采用什么轴、来源对应依据是什么；若逐帧输出还要组成特征序列，何时能恢复、何时需要另找依据、何时只能说明信息不足。

解释的关键是：形状合法不自动给出语义合法；组织改变、内容表示改变、来源可追溯和时间关系须分别核对。特征段作为原 R3 的自然接口用途与必要澄清，沿旧目标开展开卷解释；本稿不把新的教学网格内容升级成旧记录的新成绩标准。允许查表、看示范、用可靠文档及请求帮助；不要求闭卷、独立实现、安装 PyTorch、训练模型、延迟保持或远迁移。

本次完整材料是 [02-materials-demo.md](02-materials-demo.md)。继续原相机规格 `BTHWC=(2,4,2,2,3)`，八帧名称为甲0—甲3、乙0—乙3，零基索引；沿当前已给的 toy 编码，取每帧左上角 R/G、D=2。新材料显式给出完整2×2网格，左上角表标为切片；不把旧局部两帧示范替换为整个单元，也不增加新的空间扫描前置。

## 3. 必须直接给出的语义

| 对象/词语 | 本题中的完整够用含义 | 不得暗含的推断 |
|---|---|---|
| 帧 frame | 某视频段在一个选定采样位置的一张图片；含 H×W 个像素，每个像素有 C 个通道值 | 帧不是一个数、一个颜色、一个特征值；单帧没有自动包含其他时刻 |
| 视频段 clip | 同一来源的一组按采样时间顺序排列的帧；本题每段四帧 | 整段不必等于全部原始拍摄；四帧不证明等间隔采样，物理时长须另有时间信息 |
| 批 batch/B | 本次一起送入处理的两段视频；b 区分甲/乙 | 批不是一个时间过程；把两段放在同一批不使它们成为一条八帧视频 |
| 时间位置 T/t | 每段内帧的采样位置顺序；本题 t=0,1,2,3 | T 轴存在不证明已经学习/利用时间依赖；t 不是物理秒数 |
| 通道 C/c | 同一像素的测量分量；本题 c=0/1/2 分别 R/G/蓝 | 通道不指另一帧；C 不等于下游向量的 D，字母 B 与蓝通道需用文字分开 |
| 高/宽 H/W | 一张帧内的空间网格行/列；本题 H=2,W=2 | 取左上角只是切片，不代表其余空间位置不存在 |
| 轴 axis | 张量一个索引方向及它在当前契约中的对象意义 | “第几轴”与“什么意义”分开；相同轴长可能代表不同对象 |
| shape | 按当前轴次序排列的各轴长度元组 | 数字本身没有标出轴意义、数值对应、来源或运算历史 |
| 布局 layout | 本题指逻辑轴的顺序，例如 BTHWC、BCTHW | 不据此推出物理连续内存、stride 或 view/copy 行为 |
| flatten B/T | 在已知遍历次序下把相邻 B,T 两个索引编码为一行 n；本题 n=b×4+t | 合并是重新组织索引，不是时间混合/像素平均，也不等于打乱；n 轴不给消费者自动附上 B/T |
| 逐帧图像输入 | 一个 `[C,H,W]` 帧作为一件图像样本，N 行可一起算；本题 f 对每帧独立处理 | 逐帧不要求串行八次调用，也不要求打乱；并行批处理仍可独立逐帧 |
| 特征 feature/D | 本题规定 f 读取左上角 R/G，写成2个分量：R00,G00 | f 是可检查的玩具函数，不是已训练视觉网络；不能从示范推出一般特征D总等于2 |
| 特征序列 | 同一视频每帧的向量按 t 放在一起，`S[B,T,D]` | 把结果排成序列本身不等于进行了时序建模、动作识别或动力学学习 |
| 来源身份 | 一个结果由哪段视频的哪帧产生，常用 `(clip_id,t)` 或受信行映射表示 | 特征数值相同不意味着来源相同；向量内容不会自动附带元数据 |

“恢复”每次注明恢复什么。本单元恢复的是**向量的来源位置和序列组织**。原图能否从向量还原是另一问题：本题 f 丢弃左上角蓝值，以及其余三个空间位置的全部RGB；即使序列全部放对，也不能凭向量还原整张原帧。

## 4. 四条分别核对的维度

| 维度 | 在本题问什么 | 可用依据 |
|---|---|---|
| 数值/表示 | 现在是完整 RGB 像素张量还是2维特征；每个输出数从哪里取得 | 坐标对应及明示 f 定义 |
| 信息保留 | 给定输出及约定能否还原输入内容；哪些内容不进入 f | 是否可逆；同 R/G、不同蓝的两张合法图给出同 f 的反例 |
| 来源身份 | 当前这一行属于甲/乙的哪帧；来源对应是否仍可靠 | 已知且兑现的保序契约，或与结果绑定的可信来源记录 |
| 时间关系/组织 | 下游是否把同一段帧按 t 放在一起；是否实际进行跨帧处理 | 序列接口与映射；跨帧计算需另有消费者定义 |

这四项可以不同组合。像素轴重排改变索引表达而可保持全部像素值和角色对应；保序的 f 改变表示、丢弃上述图像内容，同时仍可保持来源；行打乱后若结果/来源记录一起移动，来源可追溯但当前行序不再是采样时间次序；标签缺失不证明内容变了，只限制来源恢复。不能用“元素变了/信息没变/身份没变”一句话替代四项说明。

## 5. 连贯认知主线

| 连接 | 核心输入与教师已做的工作 | 学习者实际承担的工作 | 核对与返回 |
|---|---|---|---|
| 现实对象→张量 | 给两段视频、八帧、完整网格及 B/T/H/W/C 对应；标切片 | 在使用整份材料时保持对象指称，不另考轴计数 | 术语可查；若混指，补当前对象后回路线 |
| 原张量→两类消费者 | 连贯给视频轴重排和逐帧合法合并；说明给定接口各读什么 | 旧已对的部分复用；在整体说明中连接输入/输出，不只报 shape | 接口契约与像素来源坐标一致 |
| 像素→保序特征 | 用同一完整帧算 f；八行输入/输出逐行对应，先完全不打乱 | 比较表示变化与来源保持各由哪项条件决定 | 按 f 丢蓝但保行来源；不凭“提取特征”自行猜身份 |
| 保序特征→同段序列 | 给模块 F 输出 A 的行结构和下游 S 接口；提供必要 B/T | 首个桥接仅续写 A→S 的条件和理由；视频段保留既有示范，不立即重建全链 | S[b,t,:]=A[4b+t,:] 的合法域明确，回同一接口说明 |
| 条件变化→选择恢复/拒用 | 同一特征内容，仅改变行顺序及来源记录条件；具体题面及教师参考另备 | 选择可用依据、修订同一接口段，或指出缺条件；不靠特征数值猜身份 | 可信标签须逐行绑定、覆盖且唯一；未知行映射不得默认 n=4b+t |
| 局部连接→整体交接 | 给一份接口说明容器和允许的格式 | 让两条消费者线路与 S 的来源条件连续成立，说明各阶段四项变化；接受合法等价路线 | 全部必要接口相容；不能数小题正确次数当整体充分 |

这条主线不是六道逐项验收题。教师输入可以连贯交出，纯讲解处不设等待。只有学习者需要贡献桥接、条件判断或整体作品时才等待；常规反馈直接接下一已备材料/作品段，不设置逐题“继续”开关。

## 6. 从示范到整体的梯度与跨度

第一层提供完整而可信的外部结构：对象定义、两消费者用途、像素到特征的连续轨迹、行来源的现成对应。此时不要求从空白构造框架。第二层只留下一个真正关键的桥接：若输出 A 的来源次序仍是甲0…甲3、乙0…乙3，怎样满足序列消费者；为什么原图内容不能完整还原，仍可追溯向量来源并恢复序列位置。第三层在同一来源数据上改变一项关键契约，让学习者修订刚接好的接口，处理可信映射与信息不足。最后保留一份连续说明，核两路线与所需条件是否一起成立。实际题面和逐段教师参考见 [04-work-and-reference.md](04-work-and-reference.md)。

不按轮数撤帮助。首个桥接已经能合法完成，直接扩大到同一整体作品；仍被术语挡住时直接给解释；既有完整作品足够时跳过重写。示范和公式可查，保留给学习者的是条件绑定和端到端衔接，不把观看、复述或 AI 整理算自主实现。若所有答案已经展示，继续教学可以，但只解释为相应帮助下整合。

## 7. 整体作品义务与合法多解

作品可用自然语言、带标签表、式子或流程；不规定字数、不强制构图或代码。它应让一个接手者检查这些实际内容：

- 相机 `X[B,T,H,W,C]=(2,4,2,2,3)` 到给定视频消费者 `V[B,C,T,H,W]=(2,3,4,2,2)`；`V[b,c,t,h,w]=X[b,t,h,w,c]`。
- 相机到图像消费者的输入 `J[N,C,H,W]=(8,3,2,2)`；按给定次序 `J[4b+t,c,h,w]=X[b,t,h,w,c]`。可先合 B/T 后排轴，也可先排轴后合 B/T，语义对应合法即可。
- 模块 F 的输出 `A[n,:]=f(J[n,:,:,:])`、`A=(8,2)`；明确 f 的内容与逐帧独立、输出来源对应。形状变为 `[N,D]` 不代表 D 是原 C/H/W 中的某一轴。
- 保序条件下进入 `S[B,T,D]=(2,4,2)`；行不保序时采用可信行→来源映射；缺映射时说明哪些结论未定。必要来源记录不是“更大的特征向量”。
- 数值/表示、信息、来源和时间组织各自能查；不由行数、一个像素或一个帧的位置正确推整批全部正确。

整体参考须接受排序、查表、逐位赋值等路线；不强求一种 API。特别是来源恢复使用标签并不使标签成为特征内容；顺序保留也不要求每帧带显式标签。

## 8. 必要支持、停止与审查边界

定义不清先补本节语义；行/帧混指先用一条“结果—来源”的带头表，立刻回 A→S；误把逐帧等于乱序，用保序八行轨迹澄清；误把特征内容等于来源，用特征碰撞反例；只会 shape 时回一个具体坐标对应；局部都正确而整体不成时检查接口/组织/条件，不下钻到无关 Python 语法。每个支持在教师文件中有确切输入、够用条件和返回位置。

预算和设备仍未知。可在任一连续作品段停止，保留已经完成与未完成连接；不虚构分钟、长期排期或复习债务。整体义务在实际允许帮助下足够，或者用户暂停、真实预算结束、无增量、材料实质争议时收束。本次仅交审查稿，以上条件尚未发生为教学事实；G0/R3 不由备课、教师运行或审稿数产生通过。
