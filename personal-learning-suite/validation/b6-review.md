## 发现与修复

专业调用的目标对象从固定动作／专业载荷推导，工作单和接收范围必须覆盖实际目标。固定动作还校验对应决定类型，`material_read` 授权不能执行 `materials.inspect` 审查，专业载荷不能偷换接收者授权。原专业服务仍承担正式保存门。

完整嵌套对象仅允许位于专业 API 的明确输入位置，持久化前检查其自身 ID 的控制及当前修订；现有对象身份加入依据。已删对象不能藏进 memo 重新保存，候选结果及同一共享文件中的受控派生内容沿原删除范围清理。

有限或失败专业结果按 B5 的真实可继续条件解释，不把所有 `candidate/limited` 当作已经处理。结果只记录实际处理的范围，未覆盖保持待处理；重核回执本身不能再作为专业完成证明。网络采用不替代原目标／判断／计划的专业采用。

最小上下文拒绝专业载荷未使用的不相关对象。原件段只能来自当前授权对象的准确 path／locator／revision／origin，并受其原声明行界约束；没有行界时只允许定位行。共享原件文件不能借合法定位读出前后其他原答或教师参考。

执行门对实际上游依赖递归检查当前版本，调用方省略来源不能绕过失效。接管结束旧能力的同活动入口，旧执行者不能反向复用旧能力。删除关联索引后所有旧能力失效，须新随机执行者重新绑定；停用门已保存但清理失败时同样终止旧能力。

## 解释边界

本批完成四角色本地通道及工作单生命周期，保持串行范围。读取规则不启动独立模型，fixture 授权不变成真实身份认证。专业语义、内容核验、帮助事实、成本和采用依据仍是责任方的显式声明；软件行为通过不能证明学习效果。
