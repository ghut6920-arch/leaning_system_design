# 本次用户请求原文

本次任务是按照当前学习系统的既有工作流程，完成一次正常的学习单元备课，并保存可供事后复核的过程记录。

## 1. 原始学习请求

以下是学习者的请求，请作为本次备课的原始输入：

> 我正在学习机械臂模仿学习，已经有一定的 Python、机器学习和机器人仿真基础，也尝试过利用示范数据训练行为克隆（Behavior Cloning）策略。
>
> 我想系统地理解，为什么一个模仿学习策略在训练和初步测试时表现不错，但真正放进闭环控制后可能表现不稳定，以及面对这种问题时，应该怎样有依据地分析原因、设计实验和改进策略。
>
> 我希望理解的不只是常见术语或处理技巧，而是背后的工作原理，以及这些原理如何指导实际机器人项目中的判断。
>
> 请根据我的背景和学习目的，按照现有学习系统的正常机制准备适当范围的第一阶段教学。具体知识范围、教学组织、认知活动和学习任务由系统依据正常规则自主决定。

## 2. 备课执行要求

严格使用仓库当前的 Agent、Skill、职责分工和正常备课流程。

- 按实际流程进行学科研究、认知分析、教学材料生成和审查。
- 允许 Agent 根据现有规则自主选择教学范围、深度、示范、学习任务及必要的支持。
- 如现有流程需要反馈、修订、补充研究或再次审查，正常执行。
- 不要为本次任务额外引入教学设计原则、特殊审查标准或新 Agent。
- 不修改正式 Agent / Skill 规则、共享契约或系统架构。
- 不因这次需要保留记录，就额外要求教学 Agent 改变正常的决策方法。

##

为了能够在备课结束后复原实际工作过程，请额外保存过程记录。

记录应由执行层从已有的可观察输入、输出、文件变化和交接中取得，尽量不干预 Agent 的正常生成。

需要记录：

**A. 环境和原始输入**

- 本次原始学习请求的完整内容。
- 采用的实际执行流程和 Agent / Skill 版本。

**B. 每个阶段的实际工作**

对于实际发生的各阶段，保存：

- 阶段开始时接收到的任务与输入。
- 实际读取的主要文件和资料。
- 阶段产生的完整可观察成果。
- 向下一阶段交付的材料。
- 如果发生回问、修订或返工，保留前后版本及修改记录。

不要求暴露模型内部思考过程，只记录能够可靠观察、保存和复核的事实。

**C. 审查过程**

保留正常 AG3 审查的原始意见、被审查版本、修改后的版本，以及最终验收结果。

特别注意不要只保留最终通过的成品，而丢失之前的实际草稿及修改历史。

**D. 最终交付**

保留最终的教学材料、学习者可见问题、参考材料、认知设计及现有流程要求的其他产物。

## 4. 记录与工作隔离

将额外的过程记录存放在独立实验目录中，避免它们成为后续教学 Agent 的额外输入，除非原有流程本来就会传递这些内容。

不要读取或参考以往有关教学转换、学习深度损失、Agent 质量审查等专题的审计报告。它们不是本次原始备课的输入。

如果旧审计文档存在于仓库中，本次也不得使用其诊断结论指导备课。

不要为了让记录看起来完整而补写实际上未发生的交接或修订。缺失的观测信息直接标记为不可获得。

如果执行过程中出现无法继续的依赖问题，应真实记录，不要虚构正常完成。

## 5. 最终输出

完成备课后，提供：

1. 最终备课成果所在位置。
2. 完整过程记录所在位置。
3. 所有中间版本与最终版本的对应关系。
4. 实际完成和未完成的工作。
5. 仓库版本及执行过程中发生的文件修改。

过程记录仅作事实性归档，不需要额外撰写教学质量诊断报告，也不要基于本次备课提出系统改造建议。

请按现有系统正常执行。
