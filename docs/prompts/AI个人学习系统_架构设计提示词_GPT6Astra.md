# AI 个人学习系统：交给 GPT‑6 Astra 的架构设计提示词

你负责设计一个面向个人长期使用的、多 Agent 协作的 AI 学习系统。请依据项目中的学习研究报告与实践库，从学习机制、知识结构、学习者表现和现实约束推导系统架构，并说明关键设计为什么成立、何时失效、怎样验证。

**本轮交付整体学习流程与概念架构 v0，以及后续详细设计工作包。**先用简短说明确认足以影响设计的目标、范围和约束，随即展开流程骨架；二者在同一启动阶段内相互校正。现有目标已经足以启动，不必先完成详尽的需求访谈。

下文第 1—9 节是整套系统的设计依据与质量要求。本轮需说明这些要求在流程、能力、责任和关键信息中的落点，以及尚待解决的问题；具体交付深度以第 10 节为准。重点论证主要路径、关键判断、共享依据、交接与返回条件，不要求本轮完成全部教学规则。

不进入代码实现。具体数据字段、完整调度算法、模型与存储选型、数值阈值、完整题库及角色提示词留待对应工作包展开；只有某项细节会改变架构判断或可行性时，才在本轮深入并说明原因。模块边界和 Agent 分工由实际职责推导，不预设固定数量，也不把下文要求逐条转换成模块或 Agent。

保留充分的设计自由度。下文列举的问题、场景、材料形式与交互方式，用于表达希望系统具备的能力，不是必须逐项采用的功能清单或固定流程。请围绕学习目标与证据作取舍，可以提出更简洁或更合适的实现方式，并说明理由。

**1. 用户目标与已确定的约束**

系统用于学习人工智能、数学、金融、政治等不同科目。我会提供课程表，也可能提供课程大纲、教材、讲义、学习目标与已有笔记。系统应能据此组织学习计划，选择具体阅读和输入材料，准备必要的辅助材料，并通过阅读、提问、作答、反馈、修订与后续练习推动学习。

系统采用多 Agent 协作：高能力 Agent 主要负责学习评估、整体规划与关键教学设计，其参与深度可以延伸到具体问题、场景和材料；中等能力 Agent 主要承担日常交互、材料制作与教学执行。高层应对教学方向和质量承担主要责任，但不要求它逐一编写所有问题或预先规定全部细节。设计粒度、授权范围、动态调整与协作方式由你根据学习质量和成本论证，不预设固定角色名单。模型名称、价格和能力边界若影响方案，需要核验，不能仅凭型号推断教学能力。

核心成效是：在合理的时间、精力和费用内，我能减少对 AI 的依赖，准确理解、独立重建、长期保持，并在目标任务的新情境中选择和使用所学知识。阅读量、聊天轮数、回答长度、图表数量及有提示时的正确率只能作为过程信息。

课程进度、考核日期、可用时间、学习基础与兴趣共同构成约束。资料没有提供的个人情况标记为未知。需要补充的信息按“是否会改变架构判断”排序；能用明确假设继续的部分继续设计，不虚构个人画像或实际课程安排。不影响当前流程骨架的未知项保留到相应工作包；若缺失信息确实阻碍关键取舍，明确其影响及需要确认的内容。

**3. 从学习变化推导设计，不把研究框架实体化**

对关键设计选择，交代以下论证关系：

目标能力与使用情境 → 有依据的当前缺口及不确定性 → 学习者需要完成的认知操作 → 支持该操作的输入、任务和反馈 → 可观察的变化 → 后续检验与调整 → 为此确有必要的系统能力。

这是设计的可追溯性要求，不是规定每堂课按同一顺序运行。请区分候选认知机制、行为证据和软件实现；一个学习科学概念并不天然对应一个软件模块，更不天然对应一个 Agent。

同时区分四个层级：系统运行流程描述学习时发生什么；设计工作包描述后续需要确定哪些规则；系统能力描述为此需要什么功能与判断；Agent 分工描述由谁承担责任。工作包的推进顺序不等于学习顺序，同一能力可以服务多个环节，同一 Agent 也可以承担多项相容职责。

准确理解、事实访问、关系重建、概念区分、条件选择、程序执行、延迟保持与迁移可能出现不同表现。需要哪些状态维度、如何表示不确定性，由实际教学决策和可获得的证据决定；不强制照搬报告中的八维状态向量，也不把它当成可直接测得的脑内状态。形式化应帮助决策，避免为无法估计的参数伪造精确公式。

保留以下证据边界：六类 Encoding 动作是可重叠的操作索引；Encoding 与 Retrieval 可以交叠；Post-Encoding 过程存在循环和分支；快速矩阵的符号表示任务匹配，不能用于效果排名；策略家族有效不等于某张卡、某句提示或完整系统已经有效。不能由一次答对推断永久掌握，也不能由行为改变证明发生了特定神经过程或再巩固。

本轮说明操作数量、问题数量、输入输出比例、掌握阈值、复习间隔与升级条件应依据什么确定，具体默认值留待详细设计。必要的示例值须标明工程假设、适用范围及调整方式。不要把工程起点包装成科学最优值，也不要默认策略越多、问题越深、检索越难就越有效。

**4. 说明系统如何从不完整证据形成可修订的判断**

设计应区分：学科资料支持的知识、任务所需的前置条件、学习者实际表现、对表现原因的暂定解释，以及当前提供的帮助。它们的语义不能因为存入同一段聊天记录而混在一起。

同一个错误可能来自事实缺失、关系误解、条件误用、方法选择、执行失误、表征不熟，也可能受到题目歧义、疲劳或表达方式影响。请说明系统怎样保留多个合理解释，取得有区分力的后续证据，以及何时承认不知道、重审诊断或纠正题目本身。回答慢、自述“懂了”或一次流畅解释，都不足以单独决定学习状态。

学习证据需要保留其产生条件，包括是否看过材料、是否获得方法或答案提示、是否见过同题、延迟多久，以及关键判断由谁完成。系统还需要保留与后续决策有关的来源、错误修订和未解决项，避免把 AI 的完整解释写成学习者已经掌握的知识。

整合不只意味着增加连接，也包括区分易混概念与保留情境边界。更新需要区分旧错误和在原情境仍成立的知识，保留必要的新旧主张、来源与适用条件，并检查延迟或换情境后旧错误是否回归。

请由跨轮次、跨会话和跨 Agent 决策的需要，推导应保存、共享和更新的信息，以及冲突处理和过期信息处理方式；不要先假定必须采用知识图谱、某种数据库或无限保存全部对话。

当材料、生成解释、参考答案或评分规则被纠正时，应能够识别受影响的既有教学与掌握判断，决定重核、撤销或补测，并保留理解原判断所需的依据。本轮说明这种回查的责任和影响路径，具体版本管理方式后续再定。

**5. 让阅读、问答与辅助材料承担明确的学习功能**

请说明何时应提供可靠输入、示范或局部支架，何时应让学习者尝试恢复、预测、解释、比较、推导或应用，何时纠错、降低难度、撤除帮助、结束当前段落或返回原目标。依据应来自知识结构、前置条件、当前表现和预算，而不是统一规定“永远先问后讲”或“每段都做全套动作”。

一个问题需要能说明：它针对什么目标，要求恢复哪些内容、执行什么操作，什么回答构成有效证据，哪些回答仍有歧义，以及反馈如何回应错误所在层级。诊断、学习练习与验收的目的可以交叠，但证据用途和提示条件必须清楚。答案或方法已被提示后的成功不能冒充无提示能力。

教学设计需要能够落实为有效的学习体验。理解既可以通过解释形成，也可以在场景、应用、比较或探索中逐步建立；问题、材料与活动应共同服务于目标。高能力 Agent 应能够在关键处深入设计这些内容，而不是只给抽象目标；哪些细节需要它直接设计、哪些可以授权生成或在交互中形成，由你论证。交接应足以维持教学意图，同时保留执行中的适应空间。

让学习者承担与目标相符的关键认知工作。AI 可以提供节点、例题、候选解释、图表或模拟，但应保留值得由学习者完成的关系判断、条件选择、预测、修订或独立执行。可视化需要说明要帮助理解哪种关系、保留哪些条件、学习者要对它做什么，以及如何判断帮助是否有效。

实践库是有适用条件和证据边界的资源。请检查 JSON 的真实字段和内容形态，说明从已有条目到可执行教学决策还缺什么，不把机器可读等同于已具备可靠调度能力。策略选择要考虑前提、目标缺口、功能重复、反馈、退出与替代条件，并保留操作 ID 以便复盘。

局部追问和补基础应有返回原学习目标的条件；支架减少之后要能重新检验。时间耗尽与当前目标达到应分别记录。输入输出的平衡由这些需要决定，不固定为篇幅或时长的一比一。

将 Encoding 与 Post-Encoding 展开为可继续设计的工作包，并解释拆分或合并依据。检查是否覆盖理解目标与起点、输入与支架、建构活动、修订与收束，以及检索、关系加工与迁移、知识更新、动态转接、延迟维护等问题。它们是责任覆盖要求，不要求逐项设模块、独立章节或固定教学阶段。

明确跨阶段共享的内容依据、学习者状态、证据条件、材料与任务规范、反馈和评价标准，以及各阶段特有的使用条件与教学决策。说明本轮学习结束后怎样交出已观察表现、帮助条件、未解决项和后续检验需求；后续学习发现结构性缺口时，怎样返回重新理解与建构。当前确定信息含义和接口责任，不另行铺开完整字段或重复建立两套诊断、反馈与评价体系。

用户应能要求示范、调整目标或方式、缩短学习时间、暂停，以及质疑题目或评分、纠正个人记录。流程需保留这些主动介入的入口，说明其如何影响当前安排和既有判断；详细交互在后续工作包中展开。

**6. 从课程要求推导材料和长期计划**

请说明课程表、大纲、教材和考核要求分别能提供什么信息，哪些信息仍需确认。将章节主题转化为可检验能力时，要辨认前置依赖、内容覆盖与真正掌握之间的差别，并解释课程安排如何与个人状态协调。

计划应能够处理新内容、局部补缺、延迟检索、变式应用和综合任务之间的时间竞争，以及漏学、临时缩短时间、进度变化和复习积压。解释什么证据值得改变计划、如何保留调整理由，以及在预算不够时如何取舍，避免所有未完成任务不断累积。

材料选择需落实到适当的具体范围，如章节、段落、例题、图表或视频片段；说明其教学用途、前置要求、预期负担、可访问性和来源。区分原始材料与 AI 编写的桥接说明、例子和练习，并说明生成内容如何核验、出现来源冲突时如何处理。不能只给宽泛书单，也不能让未经核验的生成材料成为后续评分的唯一依据。

本轮确定上述材料选择的粒度、依据和核验责任；没有真实课程资料时，可用明确标注的假设示例检查流程，不生成整套实际课程资源或虚构教材范围。

解释课内即时表现如何影响后续学习，延迟和变式表现又如何反过来修正课程计划。区分初次编码至检索、检索至反馈、反馈至测验、相邻练习之间的间隔，并结合目标保持期限解释安排。间隔与巩固的研究可以约束安排，但不能据此给每个人规定统一的最佳复习表，或宣称等待和睡眠必然带来某种整合。

**7. 从决策责任与成本推导多 Agent 协作**

围绕高层主导关键教学设计、中层承担主要交互与执行的方向，按决策难度、影响范围、反馈时效、独立核验价值与成本推导职责边界。可以采用不同程度的预先设计、授权生成、即时调整和复核，只要能解释如何保持教学质量与责任清晰。不要预先把中层限定为逐字执行脚本，也不要让高层停留于空泛规划；具体分工由你论证。

需要回答：任务交接提供什么目标、依据和限制；执行者可调整到什么程度；何时上报不确定性、连续失败、内容错误或计划偏离；谁能修订学习状态和计划；多个 Agent 意见冲突时依靠什么证据裁决；如何避免矛盾反馈、重复问答、上下文遗漏和无边界委派。

高层负责关键教学决策，不意味着每轮对话都需要重新规划。具体调用时机与授权范围由你论证，同时考虑响应等待、模型调用费用和用户的认知负担。

协作质量应通过教学意图是否得到落实、是否能依据新证据调整以及评估是否有据可查来判断。高层评估需要能够追溯关键作答及其材料、提示条件，而不只依赖“已经理解”等总结。交接形式、复核时点与核验方式由你设计。

Agent 之间的一致意见不是正确性的独立证据。内容、题目和评分应有可追溯的核验依据；需要独立评估的地方，解释独立性如何成立。将多 Agent 的收益视为需要验证的工程假设，并用更简单的基线检查新增协调成本是否值得。

**8. 保持跨学科共性，也保留不同的正确性标准**

请区分通用的学习决策问题与学科特有的任务、材料和评价判据，避免每个学科复制一套完整系统，也避免用相同问答模板处理全部知识。

用人工智能、数学、金融与政治检验设计的适用范围。例如：数学需要合法推导与明确前提，类比不能代替证明；人工智能学习可能同时涉及概念、代码和实验；金融模型需要说明假设、不确定性和适用情境；政治学习需要区分事实、因果解释、价值判断和竞争理论，以证据与论证质量评价回答，不以迎合某种立场为掌握标准。

这些例子是覆盖要求，不是预先确定的学科模块。跨学科迁移也需要辨认关系映射、成立条件和失效之处，不能只因术语相似就建立连接。只涉及约定或事实时，允许准确记忆本身就是合适目标。

**9. 把效果验证与简化标准纳入设计**

分别验证内容与题目是否正确、教学过程是否按预期执行、学习者是否获益、多 Agent 协作是否值得其成本。这几个问题不能相互替代。

学习结果至少应按目标区分即时表现、减少帮助后的新题表现、延迟保持和迁移，并记录提示依赖、关键错误复发、用时与主观负担。保持测验可以恢复原内容；关系与迁移验收需要包含未练任务，避免泄露方法或仅凭重复已练答案得分。训练与测验任务的关系应清楚，迁移改变了哪些维度应说明。评分依据应事先清楚，允许合理的多解及有依据的“信息不足”。

对自适应策略和复杂协作，提出个人能够执行的、小规模比较方法。比较应尽量控制材料难度、先验水平、学习时间和反馈机会，并保留个人样本小、顺序效应、题目差异和学习不可逆的限制。不把演示对话、专家式评价或几个成功案例写成已验证的学习收益。

说明出现什么证据时应保留、调整、合并或删除某项策略或协作环节。优先提出足以检验关键假设的最小可用设计，同时说明哪些复杂能力可以等待证据再增加。

**10. 本轮交付与完成标准**

交付一份连贯的“整体学习流程与概念架构 v0”。先简要确认目标边界，再把流程骨架作为主体展示，随后展开支撑能力、责任与后续设计安排。文档应包含以下内容，可合并呈现以避免重复：

1. **最小目标与边界。** 已确定的目标、范围和约束；关键未知项及其对设计的影响；本轮作出的暂定假设。区分本轮设计完成标准与未来学习成效标准。
2. **三个尺度的整体流程。** 课程资料如何进入并形成目标和安排；单次学习如何准备、推进、检查、调整与结束；跨天如何延续未完成项、组织后续学习并修订计划。用简洁流程图或等效表达展示三者的联系。主要环节说明目的、输入、输出、关键判断与返回条件，包含用户主动调整和异常处理入口。
3. **支撑流程的概念架构。** 主要系统能力及其关系、共享依据和信息边界，高层与中层的决策责任、授权、交接、升级和核验原则。说明 Encoding、Post-Encoding 相关责任怎样覆盖、共享和衔接，保留跨学科不同的正确性标准。重点解释边界为什么这样划分，避免仅列角色或模块名称。
4. **关键设计选择与证据。** 对影响整体方案的重要取舍说明依据、替代方案、代价和不确定性；追溯到研究资料，并区分直接支持、设计推论与待验证假设。当前提出明确但可修订的选择，详细规则留给相应工作包。
5. **少量贯通检查。** 用明确标注为假设的学习轨迹，检查基础不足、同错反复、提示下会而独立不会、材料或题目有误、时间缩短和中断恢复等关键情况，可合并场景。至少用一个代表性活动说明目标、输入材料、学习者任务、帮助条件、反馈依据和后续检查怎样衔接，以及高层教学意图怎样落实、中层何时调整或上报。示例仅用于检验架构接口与分支，不扩展为完整教案，也不作为真实学习效果证据。
6. **后续设计工作包。** 提出可调整的分层目录，明确每项要解决的问题、依赖、预期产出、检查条件及未决事项。较大的教学领域应适度拆分，共享规则集中设计；说明哪些可以并行、哪些需要先对齐，以及新证据如何促成架构修订。评估、来源追溯、用户体验与成本从头贯穿，不能全部留到末尾。指出下一轮最应展开的工作。
7. **验证方向与首期范围。** 分别说明内容正确性、教学执行、学习收益和协作价值需要何种证据，提出个人可执行的小规模比较思路与简化依据。保留独立表现、延迟保持和迁移的区分，完整题库、评分细则和比较实施方案列入后续工作包。建议一条范围有限但覆盖后续检验与计划修订的首期学习路径。

本轮完成的标志是：三个尺度的流程能够贯通；关键判断有依据和责任归属；主要信息、共享关系、交接、退出和返回路径清楚；后续工作包具有依赖与产出；尚未解决的细节及其影响明确。无需在本轮确定全部教学规则、参数、技术选择或角色提示词。

方案应使我能沿着“为什么需要这项能力、它依据什么信息作判断、让学习者完成什么、凭什么确认有效、失败后如何改变”的路径检查系统，并知道下一步怎样继续设计。功能、技术和 Agent 的数量都应服从这条要求。
