# AI 个人学习系统：工作包 5／Encoding 顶层设计分析

日期：2026-09-29  
用途：为 Encoding 专项设计厘清问题、取舍与研究依据，并形成开放的设计提示词。  
状态：设计前分析；以下建议供后续模型评估，不冻结专项架构、流程、接口或策略规则。

**本轮最值得设计的是：面对一项具体学习目标，系统怎样帮助学习者建立、使用并修正目标所需的知识表征。**“知识表征”在这里指学习者如何组织概念、关系、条件和操作，不预设必须画图，也不表示系统能够直接读取脑内模型。

现有材料已经提供了丰富的认知操作和共同教学规则。接下来缺少的，是把这些资源转成有理由的教学选择：为什么此时需要这个工作、为什么由学习者完成这部分、出现不同表现时为什么改变安排。分析可以把这些问题展开；交给设计模型的提示词则应保留选择答案的空间。

## 二、Encoding 在当前阶段究竟需要增加什么

工作包 2 回答“最终需要完成什么”，3 回答“已有表现支持什么判断”，4 回答“哪些内容适合且可靠”，C0 回答“怎样组织和调整一次教学”。Encoding 应补足的主要是：**特定内容需要形成怎样的理解，以及哪些学习者活动可能促成这种理解。**

例如，C0 已经允许根据表现提供解释、提示或比较任务；Encoding 还需要说明，此处为什么比较比继续解释更合适，比较双方应保持什么、改变什么，学习者要发现哪项关系，以及什么表现会使这个选择失去依据。

因此，专项设计应有两种可辨认的贡献：一是把内容中的学习难点说具体，二是据此形成具有学科内容的活动及调整理由。仅把 C0 规则换成 Encoding 术语，无法填补这部分工作；只列策略名称，也无法指导教学。

“表征建构与修订”是我建议采用的工作视角，依据是研究报告第 1、4、5 节。后续模型可以采用其他更有解释力的组织方式，只要能说明如何从目标和内容走向学习者工作，并解释其取舍。它不必成为一个命名模块，更不必对应独立 Agent。

## 三、顶层设计最需要想清楚的七个问题

### 1. 设计的最小单位是什么，深度到哪里为止

教材章节通常过大，孤立术语又可能过小。一个更有用的候选单位是“为完成目标必须处理的一组关系、条件或操作”：例如会计算与会选择公式，需要处理的工作不同；会辨认符号与会说明变量依赖，也不是同一目标。

这种粒度应服务教学选择。若拆分能改变材料、支架或检查，就值得拆；若拆成很多节点仍产生同一种活动，可能只是增加维护成本。对综合目标，还要防止每个局部都会、组合起来不会。

深度同样由目标限定。事实和约定可以需要准确辨认与使用，不必强求因果机制；机制目标可能需要中介、时间和条件；证明目标则需要合法推导。研究报告第 5、7、8 节支持这些区别，但未确立统一深度等级。

需要留给设计模型的取舍是：什么情况下应建立显式的目标结构，什么情况下用简短任务说明已足够；哪些内部细节可以保留为黑箱，什么表现才值得把它展开。

### 2. 起点未知时，如何开始学习

研究报告强调当前表征缺口，但“缺口”不能成为启动教学前必须精确诊断出的前提。初学者可能尚无稳定模型，也可能只是没有相关表现记录。此时可靠解释、完整示范、部分补全或简短尝试都可能成为合理入口。

设计应同时解释正常建构和已有理解的修订。若所有示例都是“答错—诊断—修复”，Encoding 很容易退化成补错系统；若每次都先要求生成完整模型，又会给没有基础的人增加无效搜索。

值得设计的是：已有信息能否支持一个可调整的起点；是否确实需要额外证据才能选择；什么表现会推翻暂定解释。工作包 3 和 C0 已为“不知道”“多种解释仍成立”提供语义，不必再建立一套人格或能力标签。

相关依据：研究报告第 9—11 节，卡片 O06、S01、S05—S10，以及 C0 第二、五节。

### 3. 内容结构怎样改变教学选择

“解释、比较、举例、画图”是活动形式，仍不足以说明要学什么。同样叫比较，可以是寻找同类实例的共同关系，也可以是分开相近概念，还可以是判断两种方法的适用条件。

| 内容中需要处理的性质 | 值得追问的设计问题 | 策略库中的候选资源 |
|---|---|---|
| 类别与条件 | 学习者是在认典型外形，还是按条件作判断？不满足与信息不足如何区分？ | D02—D06、D10 |
| 关系与机制 | 需要建立的是定义、组成、函数依赖还是因果？哪些推断有依据？ | R01—R08、X05 |
| 程序与方法选择 | 只需执行，还是还要决定何时采用、如何处理例外？ | S05—S08、D09 |
| 抽象规则与实例 | 哪些变化保留目标结构，哪些变化应导致规则停用或改选？ | I02—I04、I07—I10、X07 |
| 多种表示 | 转换是在重表达已有信息，还是引入新数据和假设？ | I06、X03—X06 |
| 压缩与综合 | 精简后是否还能恢复目标推理？局部学习怎样回到整体使用？ | S09、R10、X10 |

这张表用于展示决策差异，不规定内容分类、卡片优先级或必用活动。一个目标可以同时涉及多个性质，策略也可以重叠；后续设计有权合并、重组或舍弃这些索引。

### 4. AI 提供什么，学习者还需要完成什么

应围绕目标操作判断帮助。AI 提供定义后让学习者比较实例，可以保留有意义的关系判断；AI 已经给出比较结论，再要求复述，则支持另一种更有限的表现。前者不必因为“AI 给得多”就被否定，后者也不能因为学习者输出很长就被视为独立理解。

顶层设计需要解释如何分配认知工作，而不只讨论输入输出比例。可供选择的安排包括提供材料、给出部分结构、展示范例、生成待评议候选，或让学习者自行构造。哪种合适，取决于已有基础、目标操作和可靠反馈条件。

关键问题是：这次支持减少了什么负担，也可能替代了什么工作；后续怎样观察学习者是否承担了那项工作。既有 C0 已规定实际帮助的记录与证据解释，专项应补足对具体内容的判断。

相关依据：研究报告第 3、10、14 节及卡片 X04、X06、X08。AI 支持、替代与学习收益的关系仍需在实际活动中检验。

### 5. 如何把操作卡变成真实任务

卡片提供的是可复用的设计意图。把“请解释为什么”换成课程术语，未必就形成合格任务。仍需理解具体对象、已有知识、合法变化、所需产物、可接受答案和错误来源。

尤其要分开三项判断：这项学科内容是否正确；这个任务是否真的要求目标操作；这项活动是否改善学习。策略文献主要帮助理解第三项的可能性及适用范围，不能直接证明生成的例题、反例或参考答案正确。

JSON 当前每条包含 ID、名称、类别、卡片正文、模板状态和证据编号。适用条件与约束主要写在正文中，尚非可直接运算的完整规则；它也没有独立承载 Markdown 首尾的共同执行与停止说明。由此可以讨论是否需要更易复用的组织方式，但没有必要现在就决定重建字段、规则引擎或全量转换策略库。

对于工作包 5，合理的设计深度应足以让人理解“怎样从候选操作得到有内容、可调整的活动”。统一的跨策略选择、组合、替换和长期优化属于工作包 6 还要继续解决的问题；二者交界需要说明，具体划分留给设计模型提出。

### 6. 怎样辨认学习发生了变化

一张更完整的图、一个更流畅的解释，只能说明外部产物发生了变化。更有信息的观察是：学习者改变了哪个判断、依据是什么，以及在相应条件下能否继续使用该关系。

这不意味着每次都必须要求“初稿—修改稿—新题”三件套。对于初学、事实学习或已经出现充分表现的活动，强加同一种轨迹会增加负担。顶层设计需要说明不同目标的合适证据，而不是统一产物清单。

新题也要看改变了什么。换数值可能仍沿用刚示范的方法；撤去材料不抹去刚才的暴露；在并列案例中辨认差异，与单独面对案例时选择规则，需要的工作不同。这里应引用工作包 2／3 和 C0 的条件化判断，不另造 Encoding 掌握分数。

活动收束、当前能力判断和长期保持是不同决定。研究报告第 11、15 节提出了较强的新例与延迟检验建议；当前 C0 第六、十二节进一步明确，只追踪目标内要求的证据。因此，后续设计应解释何种目标需要何种检查，而非把每张卡的“验收”原样升级成整套系统的通用门槛。

### 7. 什么时候继续深入，什么时候换路或停下

更多解释、例子和追问都应对应尚未解决的目标问题。比如增加实例可能帮助排除某个伪线索；若困难来自前置知识，再加同类实例可能并无帮助。局部修复是否有价值，也要回到原目标的表现判断。

需要区分当前目标足够、方法无进展、预算结束、材料存疑、用户暂停等情况。C0 已有这些共同规则；Encoding 要说明内容层面的触发理由：哪条关系尚缺，哪个条件仍混淆，为什么此时继续或换方法有价值。

研究报告的“两三个操作”、局部展开方式、五条深度轴和十二项检查均是设计综合；它们不能自动变成数量上限、统一量表或强制展开步骤。复杂性应由可观察的收益和成本支持。

## 四、四组值得深入考虑的专项能力

研究报告第 14 节已经给出四组值得试验的方向。它们能帮助设计模型看到 Encoding 的具体价值，但不宜预先升格为四个必建模块。

**条件敏感的辨析。**同一线索的意义取决于背景。例如卡片 D03 用“任意四边形”和“已知平行四边形”下一个直角的不同判别意义，说明不能只训练特征识别。设计挑战是怎样选择合法对照，使学习者使用联合条件，又不过度增加案例。

**跨表征的信息核查。**图、语言和公式不一定携带相同信息。卡片 X06 提醒，一条 A→B 的箭头不足以推出 B=kA。顶层设计可以考虑让学习者识别哪些是保留、丢失或新增的信息，但无需把每次转换都变成一张审计表。

**表面变化与结构变化的区分。**I03、I04、I09 同时关注应使用规则时没有使用，以及不适用时仍然套用。设计挑战是选择有辨别力的变化，并承认情境知识、符号和任务形式本身也可能带来困难；不能只用一个“迁移距离”概括所有差异。

**局部展开与整体返回。**S09、S10、R03、R10 提供了处理复杂机制的资源。值得讨论的是，哪些内部关系会改变当前推断，哪些可以暂时保留；补完局部之后，整体任务是否改善。其收益与返回时机尚未被整套验证。

## 五、与已有框架怎样衔接：先提出需要解释的问题

用户本轮要求引导衔接思考，因此这里不制定新接口。现有文档提供可引用的语义基础，设计模型仍需判断最简洁、最合理的衔接方式。

| 相邻设计 | 已有依据 | 留给专项设计的问题 |
|---|---|---|
| 工作包 2 | 目标、判据、前置与任务范围 | Encoding 所说的目标表征与能力目标是什么关系？何时只是教学细化，何时暴露目标拆分的问题？ |
| 工作包 3 | 原始表现、条件化判断与暂定诊断 | 专项需要提出哪些内容层面的解释？怎样使用它们而不把推测当作直接读出的内部状态？ |
| 工作包 4 | 材料用途、参考、核验与潜在帮助 | 哪些结构分析和实例设计可以复用，哪些要随教学意图改变？如何避免材料与活动重复完成同一工作？ |
| C0 | 活动、帮助、反馈、检查、返回与收束 | 共同规则能承载哪些专项需要？哪些只是实例化，哪些确实需要补充或修订？ |
| Post-Encoding | 恢复、再加工、反馈与更新 | 初学中的提取如何理解？后续失败何时需要重建结构，何时只需要恢复或练习？跨会话怎样接续？ |
| 工作包 6 | 策略使用规则的后续设计责任 | 专项须说明哪些策略判断才足以成立？哪些统一调度问题可以留待下一阶段？ |
| 工作包 7／8 | 长期计划、协作和记录的后续设计责任 | 哪些未完成信息会改变下一次安排？哪些决定值得高能力模型参与，哪些可由执行者即时处理？ |

特别需要保留的开放性是：Encoding 与 Post-Encoding 不必按“首次／非首次”机械切开。Encoding 报告第 1 节已说明它会调用已有记忆；之后的恢复也可能暴露需要重新建立的关系。可以按当前希望发生的学习变化理解二者，但具体返回方式仍应由后续设计论证。

C0 当前版本已修正审阅中的删除证据和时间记录问题，不能把审阅快照当作现存缺陷。当前方案第十二节还明确保留了专项内部步骤、操作组合和退出阈值的设计空间。

## 六、可能的组织方式及其取舍

下面比较的是工作视角，不是要求模型提交三套架构。

| 组织方式 | 可能的好处 | 需要面对的问题 |
|---|---|---|
| 以策略卡为中心 | 能快速调用现有资源，出处清楚 | 容易把“用了什么方法”代替“解决了什么学习问题”，并过早进入全量调度 |
| 以目标所需的表征变化为中心 | 更容易解释为何采用不同任务，并衔接内容、表现与活动 | 如果把表征建得过细，可能增加诊断假象、记录和维护成本 |
| 在 C0 中保留少量 Encoding 专项判断 | 结构轻，便于先验证真实活动 | 若只增加宽泛原则，可能仍无法支持有内容的任务设计 |

我的倾向是用“目标所需的表征变化”组织设计理由，用 C0 承载已有共同规则，用策略库提供候选方法。但这仍是待评估的设计建议：模型可以采用更轻的组合、提出另一种结构，或论证其中某层根本不需要独立存在。

顶层方案应明确核心判断和它们之间的关系，同时允许实现合并。当前没有必要决定数据库、字段、固定状态机、Agent 数量或每轮卡片数量。

## 七、怎样用有限情境检查设计有没有实质内容

案例的作用是揭示不同证据是否真的改变教学，不是展示模型能够写出一段流畅对话。可选择以下情境中的有辨别力者；不要求逐项覆盖。

| 假设情境 | 应能暴露的设计问题 |
|---|---|
| 初学者没有关键概念，尚未出现错误模型 | 能否直接提供可靠基础，并留下适合其当前条件的学习工作？ |
| 能复述条件，却在近邻案例中误用 | 是否需要条件对照、补前置或改变表示？什么证据会改变选择？ |
| 解释正确，但图或代码表达不对应 | 是表达形式不熟，还是关系理解有缺口？辅助形式会代做哪项目标工作？ |
| 看过完整示范后答对相似题 | 此结果究竟支持执行、重建还是选择？怎样避免把熟悉当成更广能力？ |
| 局部补课成功，返回整体仍失败 | 会不会重审原解释和综合要求，还是继续无限下钻？ |
| 后续学习中恢复失败，但给出局部信息后能继续推理 | 是否需要重新 Encoding，还是可以保留已有关系能力、处理访问困难？ |

一个好的示例应让读者看见目标内容、学习者工作、依据、关键分支和结论边界。方案不必把全部可能回应写成逐轮脚本，也不应要求每门学科复制整套流程。

后续真实试用可检验：专项设计是否比可靠的简单教学增加了值得保留的独立表现；增加的准备、交互和记录成本是否合理。具体比较由所选目标决定。纸上演练只能发现设计漏洞，不能证明学习效果；个人小样本也不足以建立普遍因果结论。

## 八、怎样把这些分析压缩成不过度规定的提示词

详细分析与执行提示词承担不同任务。分析展开候选与风险；提示词明确本轮任务、提供资料、提出少数关键矛盾，并说明什么样的成果值得采用。

提示词适合保留：Encoding 的专项问题、基于实际资料作判断、充分考虑学习者的关键工作、解释与既有框架的关系、给出能支持取舍的实例、区分证据与设计假设。

提示词不宜预置：本分析的章节结构、七个问题作为七个模块、四组能力作为四个子系统、六类动作顺序、固定诊断流程、统一深度评分、精确阈值、接口字段、角色数量，以及全部策略卡的逐项实施。

模型应能提出明确方案和可审查的选择，同时有权重组本文的问题、质疑本分析的建议、指出当前文档的不足。把“自由度”落实为对结构和方法的选择权，把“设计质量”落实为目标、理由、实例和可修订性，会比同时要求大量固定章节和表格更符合本轮目的。

配套提示词见 [Encoding 设计提示词](<E:/文献资料/学习系统架构设计/docs/prompts/AI个人学习系统_工作包5_Encoding_设计提示词.md>)。该提示词可单独使用；本分析是补充思考材料，不是必须逐项实现的规格。
