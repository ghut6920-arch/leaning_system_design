## 保留的结构与删去的结构

这是两层、单头、向量维度 2 的确定性 toy。固定五个输入向量和每层的四组矩阵，采用行向量约定 `x W`。第 ℓ 层由该层输入计算 `q=xWq`、`k=xWk`、`v=xWv`，输出为 `x + softmax(qKᵀ/√2) V Wo`。因果可见范围包括当前位置及其以前的位置。

第二层输入是第一层输出，所以第二层的 K/V 带有前层传入的上下文；不能把每层缓存都解释成最初 token 向量的同一投影。`Cache` 只保存本层 K/V；Q、权重和输出在 JSON 中是便于审查的轨迹，不是在线 KV Cache 的内容。

无位置编码，因而本例没有位置偏移或长度变化引起的位置重编码。没有训练、真实词义、LayerNorm、FFN、dropout、词表预测头。残差和逐层因果依赖仍在，但不能据此推断真实语言模型的理解、召回或输出质量。

Attention 公式、投影和因果遮罩的来源是 [Vaswani 等，Attention Is All You Need](https://arxiv.org/abs/1706.03762)，§3.1、§3.2.1（2026-10-11 已核验 [arXiv 正文](https://arxiv.org/html/1706.03762)）。缓存合法性的说明是据依赖关系作出的数学推论；不把这篇论文说成此代码或 KV Cache 实现的来源。

## 教师连贯示范路线

1. 先看 `full_prefix`：每层先由所有本层输入得到 Q/K/V，再让位置 j 只读 `0..j`。旧位置看不到追加的 token。
2. 再看 `append_token`：仅传播当前输入，每层生成并追加一个新的 K/V；当前 Q 读取这一层全部已有 K/V，重新生成权重与读出。
3. 对比五次追加后的缓存路径与全前缀重算路径。代码不仅比较新位置输出，还比较整个历史输出列表，以及各层全部 K/V；五个前缀的最大绝对误差均为 0，容差为 `1e-12`。
4. 固定前三个旧位置的第一层 K/V，仅改变两个候选新 Q，读出会变。接着删除同一旧 K/V 对，当前读出再变。由此连起来解释“可复用旧表示”与“新查询仍要重新评分、读取旧表示”。
5. 把第 0 个输入由 `[1,0]` 改为 `[1.3,-0.4]`。第一层第 1、2 个未编辑位置的 K 不变；它们的第一层输出已经受早期输入影响，所以第二层相同位置的 K 变了。继续用旧缓存得到错误的新位置输出；先重建编辑后的前缀缓存再追加，与重算一致。
6. 把因果范围换为双向范围并追加一个位置。旧位置输出及其第二层 K 会变，因果追加的缓存不变量在这个对照中不成立。
7. 最后用与 toy 数值无关的容量函数，从每层、每序列、每 KV 头、每头维度和元素字节数推导 payload。缓存等价、缓存容量与真实模型质量是不同证据。

以下是同一轨迹中的关键可审查数字。位置编号从 0 开始。

| 检查 | 实际结果 |
|---|---|
| 1 至 5 个 token 的缓存路径／重算路径 | 所有历史输出、各层 K/V 最大误差均 0 |
| 同旧 K/V，Q 从 `[0.03,-0.54]` 变为 `[-0.5,0.32]` | 读出由 `[0.526903,0.354161]` 变为 `[0.516410,0.456733]`；最大差 0.102572 |
| 固定前一 Q，删除旧位置 0 的 K/V 对 | 读出最大差 0.299386 |
| 编辑位置 0；第一层未编辑位置 1、2 的 K | 差均 0 |
| 同一编辑；第二层位置 1、2 的 K | 最大差分别 0.040617、0.041951 |
| 编辑后继续错用旧缓存 | 新位置输出与正确重算最大差 0.046408 |
| 重建编辑后的前缀缓存后追加 | 与正确重算最大差 0 |
| 双向范围追加 | 旧位置 0 输出最大差 0.247796；第二层旧 K 最大差 0.096266 |

新 Q 对照只计算对旧前缀的 attention 读出，排除了当前位置 K/V，以隔离 Q 的作用；完整 self-attention 中改变当前 token 通常还会改变当前 K/V，不能将这个局部对照误说成完整新 token 前向。删缓存对照证明这个输入下读出发生变化，不是对所有删法的质量评价。

缓存路径与重算等价的推理条件是：旧前缀、模型权重、位置表示、可见规则不变，计算确定性，旧位置各层输入只依赖不变的旧前缀。第一层旧输入不变，则其旧 K/V 和旧输出不变；逐层递推即得到每层旧 K/V 可复用。真实实现可能因浮点运算顺序出现微小误差。这里只做有限数值检查，不能用“误差 0”替代这些条件。

编辑旧 token、改位置或改可见范围后，应按实际依赖重算受影响部分。示范采用完整重建编辑后前缀的简单修复，不声称这是最少重算量；编辑点以前的不变因果前缀仍可能合法复用。

## 容量教师参考

所有层配置相同、每个序列缓存长度为 Tᵢ 时，逻辑 KV payload 为：

`bytes = 2 × L × sum(Tᵢ) × n_kv × d_h × s`

`2` 表示 K 和 V；s 是每个元素的字节数；`GiB = bytes / 2^30`。32 层、32 个 Q 头、8 个 KV 头、每头维度 128、BF16 每元素 2 字节时，每个缓存 token 需 131072 字节，即 128 KiB。容量公式使用 8 个 KV 头，不能代入 32 个 Q 头。

| 每序列缓存 token 数 | BF16，batch=1 | BF16，batch=4 | 理想 INT8，batch=1 |
|---:|---:|---:|---:|
| 16384 | 2 GiB | 8 GiB | 1 GiB |
| 32768 | 4 GiB | 16 GiB | 2 GiB |
| 65536 | 8 GiB | 32 GiB | 4 GiB |

长度 `[16384,32768]` 的两条独立序列逻辑 payload 为 6 GiB；若实际槽位都填充到 32768 则对应 8 GiB。相同其余条件、32 个 KV 头的 MHA 在 65536 token 时是 32 GiB。GQA 的 KV 头数是模型架构／权重兼容条件，不能把现有 MHA 模型的头数随意改成 8 再宣布语义不变。

这些数值不含权重、激活、临时工作区、分页或量化元数据、碎片、分配冗余；INT8 列只表示每元素 1 字节的理想 payload。共享物理前缀的实际分配应另算，不能把所有逻辑序列长度相加后当成其物理占用。没有实测真实模型量化误差、速度或某块 GPU 能容纳的总上下文。
