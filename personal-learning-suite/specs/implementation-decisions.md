## B2a 实现补充（2026-10-03）

模型依据 SK01 目标与版本规则编写目标；标准库程序仅检查结构化虚构候选，保持 `candidate`。本批未实现从全文自动抽取目标、学科真伪判定、正式采用或独立 AG1 宿主。输入嵌套表示在 `contracts/runtime-b2a.md` 细化，公共字段仍读唯一共享契约，不复制另一套 schema。

粗地图和 P-Goal／P-Change 本地视图随候选交付，不新建数据库或掌握度状态。程序不写记录；验证中的正式保存使用 B1 的现有串行入口、授权和采用依据。候选检查通过不绕过删除／限制或扩展真实权限。

目标资源有自己的 `pl-goals/0.1.0` 版本，与协议、目标内容和判据修订分开。会话缩时保持目标，实质变化列旧证据重核建议；程序比较不决定支持转移。B0 静态检查仅放行明确的 SK00／SK01 开发路径，未知专业包继续拒绝。B0/B1 历史报告保留，B2a 复验报告另存。

## B3a 实现补充（2026-10-03）

SK04/AG3 的精简专业规则与 `AssessmentService` 分工：模型从原件作评分，标准库程序只检查声明、资格、帮助条件、时间事实、授权与受控保存。适配版本 `pl-assessment/0.1.0`，数据库和共用协议不变。不增加 mastered 状态、独立样本、测验或复习队列。

选定响应点与操作级评分在 Judgment.conditions 内表示；时间线完整、材料核验及 active 授权是人工声明，不认证真实条件。检查器返回 expected_support/operation_conditions 和 submission_ready，不静默覆盖专业候选。缺时间条件时保留当前操作观察，限目标内时间用途；原答足够时复用，不要求重考。

重要复核不能靠空 review_triggers 绕过反证、标准重要用途或 grant 的升级信号；同 id 修订也检查相反评分。授权主体预检先于读表现上下文，递归旧材料／来源不得继续成为当前正常用途。专业门恢复与历史标准兼容仍需要当前责任依据；本切片不能解除 B1 的专业限制。

有限诊断只提出会改变安排的观察，零预算或停止信号返回不追加观察。明确无反证可以空列表，缺失／null 不推为无。提交只允许 Judgment/DiagnosticNote，并沿同一 CAS/幂等/权限/采用门；其余共享对象由相应批次维护。所有报告使用 B3a 名称，既有包和原文保留。

## B3b 实现补充（2026-10-03）

本批按 N00 第十二节实现 SK03 的 C0 共同教学核心。活动、原答、帮助、修订、父任务、需求和断点共用 `pl-contracts/0.1.0`；请求适配独立标记 `pl-teaching/0.1.0`，沿用原 SQLite 提交入口。B3a 完整判断引擎不在本批范围，C0 不自行生成正式 Judgment 或稳定诊断。

资格与内容读取优先复用 B2b 的精确用途声明。程序按显式活动分支和可定位观察组织反馈；学科评分与真实展示确认仍依实际责任方。备用帮助和教师参考保持后端，只有调用方声明实际发生的动作才记入相应暴露时序。未知显示、资源和接触保持未知。

收束不意味着达成，也不强制增加检查。局部修复够用返回同一父产物与连接，保留原帮助和共同预算；未完成工作交同一需求，保持待接收或待处置，不能自行排期。C0 仍采用单入口顺序开发范围，Skill 未安装，Encoding/Post、策略与正式计划按后续批次实现。

## B3c 实现补充（2026-10-03）

通用资源由标准库构建器可复现生成：60 卡轻索引、S07／X02／R09 完整双正文与共用规则、四份有出处的 Post 条件说明。资源修订 `pl-strategies/0.1.0` 和输入适配 `pl-strategies-input/0.1.0` 分开；共用字段仍由 `pl-contracts/0.1.0` 唯一维护。正文与文件指纹只检测变化，不证明内容或效果；原设计和研究文档不修改。

MethodConfig 的 resource_checks、精确 review 绑定和显式 adoption 是有限适配的新增表示；不另建状态表。保存沿用 B1 CAS／幂等／专业授权与采用。previous_config 保存合法旧配置定位，新活动不无条件继承旧结果。资源变化可通过已记录资源键或来源定位配置，再沿 ObjectRef 追踪；未知语义依赖保持未知，历史事件、目标、判断和计划不由策略辅助器重写。

资源缺失采用保守发布门禁，可靠已有活动短路不读取索引。辅助器不自动选择最优卡、核验学科真伪、评分、排期、修改通用Skill或宣称效果；真实实例与四角色绑定依旧待后续批次。

## B4 教学专项与计划（2026-10-03）

Encoding／Post 实现为 TeachingService 的有限专项层，初答扩展与 C0 事件同事务保存，局部切换／返回继续原事件和原样本。共享协议、存储、历史事实、策略资源版本不改变。design／commit_design 的模型内容与程序声明检查分开；无权限只候选。GoalSpec requirement.teaching_scope 给整体要求的专业来源；缺声明不按文字猜深度；完整活动不能自行取消整体要求，明确严格局部子范围仍保留整体缺项。新字段是既有对象的局部扩展，不复制共用字段表。

整体参考采用当前目标／判据、操作与义务范围的 whole_coverage 加受控原件；只引用局部锚点不足。连续整体产物交 SK04 重要复核，程序不判通过。旧目标与事件不批量补新声明，当前专项需要时交原责任补齐。reuse_evidence 复验已采用目标／判断和 B3a 原条件；本次简单够用就结束，未知未来时间不补造。

SK05 为同一 LearningNeed 提供实质处置，计划 metadata 存完整成本和分配，一个 BudgetEnvelope 下只有一个有效安排。接责保持 pending，正式计划显式权限／采用／CAS；AG0 仅允许缩时，重要重排处理旧计划全部受影响需求。已合并终结需求不留在有效安排 need_refs，避免阻止后续缩时。现有 C0 时长作支出下界，用最大值避免重复累计，不宣称已实现完整计时器；新执行消耗后需要更新范围，不能重发旧额度。

短路径关闭引用 adopted supported/usable、planning_closure 用途及原 material_context，SK04 复验真实帮助、授权、冲突和时间；合法常规 AG0 判断无需新增 AG3 会签。未知成本不能变零，估计留余量，完整费用／等待分轴；浮点会计容差为十亿分之一分钟。声明合格不证明微缩方案等效或真实学习收益。B5 单入口自动串接、B6 网络绑定与 B7 真实试用仍待实现。

最终独立复核后，授权 shrink 同时限制每个 allocation 的费用、等待与系统工作不超过原安排；不能减少主动时间却增其他投入。合并只准同一当前目标要求 ID 恒等映射，接收需求完整包含源要求，避免丢失整体工作；不同 ID 的专业等价不在本有限实现范围。负向用例先复现、后修正，最终 349 项行为回归通过，原始结果独立保存于本批 validation。

## B5 单入口集成（2026-10-03）

SK00 增加固定动作的显式串行 execute，局部适配为 pl-entry/0.1.0，共享协议与 SQLite 不变。模型／责任方提供内容、评分、采用和投入声明，程序连接前步准确引用并沿各专业授权门保存；根 CAS 过期不执行，不自动重放整链。部分失败不回滚已保存原答，保留成功前缀及未执行范围，不增影子进度库。

B2a 来源 Fact 与 B2b 模态来源采用不同有限适配，新增 AG2 goal.sources_submit 在完整目标候选审阅后原样保存来源；不转换或补造核验声明。AG1 goal.submit 只允许与审阅目标一致的内容及调用方显式采用字段；显式 GoalSpec 决定类型仅 goal_design，防止用计划授权改目标。已存来源／历史目标相同引用必须匹配原件，不能以改写候选覆盖原核验。

need.submit 仅新 ID 的 proposed/pending 提议；现有需求由 SK05 保留同一稳定 ID 接责／处置，不能回退已安排需求。教学收束未决按同链保存处置对账，仅 accept 仍 pending。学习者视图只本次关联范围，候选判断保持采用状态与双轴，不把活动完成或需求关闭等同目标通过。失败责任尊重专业 next_owner，常规评分升级交 AG3。

B5 仍为虚构开发源、单入口兼任；角色字符串不认证身份，后台工作单／真实接管和宿主展示门留 B6。完整学习效果及真实实例留 B7，不扩大数据库外请求、stdout 或宿主历史的删除承诺。

## B6 本地工作网络（2026-10-03）

选择有限受控串行 Python 宿主，使用 OS 单工作区锁与进程内能力对象，加载四角色/对应Skill开发源。工作单与结果仍使用规范 WorkOrder/WorkResult 和原 SQLite，专用 ControlState 执行门原子推进接管代次；共用协议不变，局部适配 pl-network/0.1.0。缺接收者授权的 proposed_unready 是可保存但不可接责/执行的明确候选。

宿主能力对象绑定工具调用身份，业务授权仍是 verified_for_fixture；不能声称自然人身份、host_verified 授权、独立模型运行或 Codex 输出拦截。工作单范围、专业调用和返回分开，网络采用不替代原专业对象采用或 SK05 的实际安排。普通可靠活动与常规授权仍可由 AG0 直接调用，避免每题四方工作单。

删除结束相关通道，沿原依赖图清理工作单/候选/执行记录，不保留全文结果缓存。删除关联索引后代次历史可移除，以旧能力失效和新随机执行者身份共同阻止旧票据复用。外部响应副本、调用者变量与模型上下文无法由本地函数擦除；需要由调用方结束含被删内容的任务。异步后台和并行展示保持禁用，真实课程、模型、个人记录和效果结论仍留 B7。

## B7 第一切片：试用准备与分层验证（2026-10-04）

依据 N00 第十二节和 D11 第二、三、六至九节，先交付无持久化的 `pl-pilot/0.1.0` 只读适配。输入显式区分 `unconfigured/synthetic/real`，复用共享 `LearningInstance`、`GoalSpec`、`BudgetEnvelope`、`ValidationDecision` 与原学习事件，字段唯一源和 SQLite 保持原版。真实输入缺失不填写个人事实；真实模式也不将 `FIX-*`、虚构原件或 `verified_for_fixture` 转成真实依据。

配置就绪、软件切片通过、专业核验声明和真实试用分别记录。试用配置检查只说明调用方声明及引用在有限范围内相容；V1—V4 报告按原引用和真实条件分别保留未知，不自动评分、不合并有效率、不把同题修订算作新样本，也不把未知成本当零。B10 覆盖索引只定位本批实际回归中的有限切片，不修改 B0 的完整情境 `not_executed`。

本切片没有为整个 B1—B6 专业链增加真实写入模式；不能仅关闭 `synthetic_only` 就安全获得真实身份、授权和控制。新增主入口 `pilot` 可以不指定工作区，因为它不创建或打开数据库；其余原命令仍必须显式指定虚构工作区。真实试用下一步由用户选课程、用途、投入和记录目录，落实可靠参考及实际承载后进入 S3；本次交付覆盖准备工具和受控软件验收，不宣称 S3—S5 已完成。
