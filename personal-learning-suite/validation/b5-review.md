# B5 独立审查与修复复验

日期：2026-10-03。审查者：开发审查子代理 `/root/b5_scope`；实施和修复由主开发者及其他开发子代理完成。本审查只读取运行代码、契约、任务单和正式方案，并在系统临时目录建立、清理人工虚构 SQLite 空间；唯一写入交付为本报告，没有修改运行器或学习资料。

## 审查范围与依据

主要审查 [entry_b5.py](../src/runtime/entry_b5.py) 及 [personal_learning.py](../src/runtime/personal_learning.py) 的 B5 追加，按 [单入口接口](../contracts/entry-b5.md)、[共享契约](../contracts/shared-contracts.md) 和 [有限验收](../specs/b5-acceptance.md) 检查顺序调用、专业责任、授权与采用、原答及展示分区、控制、CAS、精确绑定、幂等和多步失败。

正式依据为 N00 的 B5、正常流程 A—E、异常网络及验收；D00 的对象分离、权限、采用、双链纠错和恢复；D01 的最小上下文、串行提交与宿主边界；D10 的用户控制和常规展示；D11 的 B10-01—12 与 V1—V4 分开报告。开发子代理不等于已部署的学习角色，也不提供学科独立核验。

## 发现、修复和实际重放

| 问题 | 修复前的可复现行为 | 修复与重放结果 |
|---|---|---|
| P1：决定类型可把计划权限升级成目标写权 | 预置 AG1 授权只含 `decision_types=[planning]`、`object_scope=[FIX-*]`；`goal.submit` 中给 GoalSpec 写 `decision_type=planning`，入口原先排除该字段的一致性比较，原 Store 又使用其声明决定类型，结果为 `completed/committed`，目标实际保存。 | B5 对类型化专业对象检查决定类型白名单，GoalSpec 只允许目标决定；同一负向探针现在返回 `rejected/professional_decision_type_mismatch`，无状态变化。 |
| P2：非字符串动作造成异常逃出入口 | 合法 envelope 的 `operation=[]`，或 `teaching.run` 的 `action=[]`，集合成员检查抛出未捕获的 `TypeError`，无法输出约定 JSON 失败回执。 | 集合成员检查前核字符串类型。两项原探针分别返回 `rejected/explicit_professional_request_required` 与 `rejected/unknown_teaching_action`，无状态变化。 |
| P2：学习者视图混入其他目标需求 | 只审阅新目标 `FIX-b2a-goal`，原 `_view` 仍显示旧 `FIX-goal` 下 `FIX-need` 的接责、去向、未覆盖影响和触发，且没有目标引用帮助区分。 | 视图按本链相关对象与目标限定需求，并保留 `goal_ref`。同一只读新目标探针现在返回零项无关需求。 |
| P2：已处置的需求仍显示待实质处置 | 普通七步公共链已把同一需求接责并保存为 `deferred`，顶层 `pending` 仍保留 close 生成的“同一教学后续需求尚需实质处置”。 | 待处理项带原需求及新事件引用，并依据本链实际已保存计划结果对账。七步重放为 `completed/pending=[]`；只运行至 accept 的五步对照仍保留一项 pending，去向仍为 pending，不把接责当成安排。 |
| P2：下一专业责任被调用角色覆盖 | `teaching.run/open` 缺目标 `teaching_scope` 时原服务给 `next_owner=AG1`，缺整体参考时给 `next_owner=AG2`，入口原先均把待处理责任写 AG0。常规评分触发重要复核时也不能继续留给 AG0 裁决。 | 入口优先保留专业服务 `next_owner`；没有该字段的重要常规复核映射 AG3。三个独立探针现分别为 `pending.owner=AG1/AG2/AG3`，调用步骤的 `owner` 仍为 AG0，全部不变更状态。 |
| 纵向来源接入缺口 | AG1 的 `goal.submit` 不能合法保存 AG2 来源；B2a 整体 Fact 来源与 B2b 材料来源的模态／核验格式不同，不能假定现有材料提交器会自动转换。 | 新增 `goal.sources_submit`，固定 AG2，先核完整 B2a package，来源变化只取包中原来源，沿原授权、采用、CAS 和控制门，不转译核验。独立新空间只导入 AG1 目标授权与 AG2 来源授权，再一次公共调用 `goal.review → goal.sources_submit → goal.submit`，结果为 AG1/candidate、AG2/committed、AG1/committed；状态修订 1→3，实际保存两份来源与一份显式采用目标。 |

此外核查了 `need.submit` 的新 ID 限制：对已经安排的需求，尝试以更高修订覆盖成 proposed/pending 被拒绝为 `existing_need_requires_planning_disposition`，原有效承诺和 scheduled 去向保留，完整性检查为 ok。已有来源同一引用而不同声明必须拒绝，不能借候选 payload 绕过精确原件。

## 独立执行检查

本审查独立运行了八项现有 B5 行为测试，全部通过：计划授权不能伪造目标决定；非字符串动作 JSON 拒绝；已有需求不能重置；已有来源同引用不能换声明；中途失败保留已保存前缀且不回显失败载荷；根 CAS 过期先拒绝；删除材料后不能复活；未来／缺字段／控制字段绑定拒绝。

上述结果之外，表中权限、输入异常、视图范围、处置对账、仅接责对照、新来源接入及三项下一责任分支均使用独立 inline Python 探针在临时空间实际重放。探针中的参考、评分、原答、成本、显示与授权都是人工声明；通过只证明当前软件切片的行为。最终专项及全套数量以主开发者生成的 runtime 报告为准，本报告不重复填写尚未取得的统计。

## 最终边界

审查发现的上述问题已按原反例重放修复；所选正常与异常检查没有发现尚未处理的权限、控制或原答覆盖问题。B5 仍是显式请求的单入口顺序开发串接：候选、检查、保存、专业采用和计划实质处置保持不同阶段，完整技术回执不能直接作为未经筛选的教学展示。

每个专业写步骤自身为事务，整条链不是原子事务；失败后保存前缀保持真实，继续须在当前控制和修订下重新确认剩余步骤。合法初答、实际帮助、同一事件／样本及父任务继续使用共享记录，结构检查不替代内容评分，也不自动制造复测或复习债务。

真实角色身份、工具权限隔离、后台接责、旧执行者展示拦截、受影响宿主上下文终止及完整 B10 网络情境仍属于 B6。真实课程、合格延迟、学习收益和协作净价值仍属于 B7／V1—V4；本审查不将虚构软件通过写成这些验证已完成。
