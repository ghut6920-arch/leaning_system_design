# AI 个人学习系统：工作包 2 与 3 联合设计方案 v0

日期：2026-09-27  
对应范围：工作包 2／B1「课程要求—能力目标—验收证据」；工作包 3／B2「学习者状态、诊断与证据更新」  
交付状态：可供工作包 4—8 继续设计的联合顶层方案；尚未进行真实课程运行或学习成效验证。

**本方案采用一个共同决策链：材料与用途确定目标，任务表现提供带条件的证据，证据支持有限的判断，判断形成近期内容展开依据；后续表现和内容纠错再回到这条链上。**工作包 2 负责说明“准备证明什么、怎样证明”，工作包 3 负责说明“现在证明到了哪里、还存在什么解释”，两者共同交出后续教学可以执行和修订的安排。

本轮按用户指定范围，阅读了联合设计提示词、联合顶层设计分析、整体学习流程与概念架构 v0、设计流程与工作包，以及 Encoding 研究报告、Post-Encoding 深度增量研究、快速矩阵、证据台账，共八份文件。未读取微操作与提问库、策略库、架构设计提示词和检查记录，也不把已读文档对这些文件的转述算作本轮直接阅读。参考文献没有在本轮重新进行外部核验；研究相关表述均指项目报告的论述及其边界。文末提供可定位的项目出处。

文中 **【依据】** 表示项目已给定的要求或项目报告中有限定的论述；**【设计】** 表示本方案选择，可修订；**【假设】** 表示需要实际试用的预期或示例设定。其余规则性表述默认属于【设计】，不表示已有实验验证。

## 一、共同成果与本轮边界

### 1. 交付给后续工作的是什么

本轮形成三项相互引用的成果：

| 成果 | 要回答的问题 | 主要责任 |
|---|---|---|
| 目标与验收规格 | 什么来源支持这个目标？在什么范围、条件下，什么表现算满足要求？ | 工作包 2 |
| 学习证据与当前判断 | 用户实际完成了什么？谁提供了什么帮助？结论适用于哪里？还有哪些合理解释？ | 工作包 3 |
| 近期内容展开单 | 现在从哪里开始、重点处理什么、需要何种材料和帮助、如何检查、什么结果会改变安排？ | 两包共同形成内容依据；计划责任方维护当前有效版本，供 4—8 使用 |

这些成果是信息责任，不要求三套软件、三个数据库或三个 Agent。初期可以用相互引用的文档和表格承载。

**联合设计的通过标准是：执行者能够沿一项近期安排，反查到目标、判据、证据和未知，并知道何时改道。**课程目标清单与个人诊断报告若不能导出安排，就不算闭合。

### 2. 明确采用的五项选择

| 选择 | 理由 | 代价与边界 |
|---|---|---|
| 全课程先建粗地图，近期目标再细化，同时检查通向最终任务的关键依赖 | 避免导入时逐句拆解整本教材，又减少遗漏远处关键前置的风险 | 远期深度仍暂定；每次进入新主题需补齐规格 |
| 以“会改变证据或安排的能力差异”划分目标 | 让诊断可以直接影响教学，避免知识点数量失控 | 粒度要随实际任务修订；综合能力仍须单独检查 |
| 保存条件化判断，采用按需证据面，不设置统一掌握总分 | 即时、延迟、帮助和迁移并非可互换的同一维度 | 展示略复杂；用户视图需压缩为少量有范围的结论 |
| 用对近期决策的影响决定是否继续诊断 | 把诊断成本花在可能改变安排的未知上 | 初期可能保留多种解释，需选择可回退的活动 |
| 用近期内容展开单衔接目标、证据与教学 | 执行者获得明确理由、认知工作和改道条件 | 增加少量记录成本；不提前编写整学期逐轮脚本 |

【依据】用户已确认“时间不足时独立掌握优先，可缩小覆盖范围”，同时保有目标与投入的最终决定权；高能力 Agent 负责关键评估、规划和教学设计，中等能力 Agent 承担主要交互与执行。[架构边界]

本方案继承这一方向。**较差表现可以促使系统建议缩小近期范围，但不能把原目标的标准悄悄改低后宣布达成。**用户若选择较浅目标，形成新的目标版本；旧目标明确标为延期、替换或放弃。

### 3. 与相邻工作的边界

本轮确定材料需求、任务证据要求、帮助限制、复核触发和回流含义。工作包 4 再设计分段、检索、来源核验和内容制作；5—6 再设计教学骨架、活动与策略；7 再决定时间分配；8 再落实协作协议。

本轮不制定完整题库、逐轮问答、策略卡调度算法、模型选型、存储方案或统一数值阈值。但凡后续工作现在就需要的信息，本轮给出暂定约定，不以“属于别的工作包”为由留下交接空白。

## 二、主流程：先形成可用安排，再持续修订

~~~mermaid
flowchart TD
    A["上传材料、学习用途、时间与资源约束"] --> B["课程粗地图与近期目标规格"]
    B --> C["验收要求与关键前置"]
    C --> D["读取已有证据，识别影响近期安排的未知"]
    D --> E{"是否需要补充诊断？"}
    E -->|"需要区分安排"| F["有限任务或学习活动"]
    F --> G["原始表现、帮助、时间、来源"]
    E -->|"已有依据足以行动"| H["条件化判断与近期内容展开单"]
    G --> H
    H --> I["材料组织、教学与统一计划"]
    I --> J["教学中、撤除帮助、延迟及新情境表现"]
    J --> G
    H -->|"目标拆分或依赖不合适"| B
    J -->|"题目、资料或评分有疑点"| K["隔离受影响判断并核验"]
    K --> B
    K --> H
~~~

图中的诊断是可选分支。用户没有历史记录，可以从短任务进入，也可以直接要求示范。先看示范不会导致系统无法继续，只会改变随后证据的含义。

首次导入到近期安排的推荐过程如下：

1. **辨认输入。**记录有哪些资料、覆盖哪里、哪些属于课程要求，哪些是个人补充。用途或截止节点若会改变当前目标，提出少量必要问题。
2. **建立粗地图。**列出课程主要能力、重要综合任务、范围外内容、关键依赖和依据不足之处。此时不替学习者填“会／不会”。
3. **细化近期目标。**为即将安排的目标写清表现、条件、判据和必要前置；远期目标保持暂定。
4. **读已有证据。**检查自述、历史表现、来源和适用条件，避免换会话就重复诊断。
5. **补足决策所需信息。**只调查会改变进入、补基础、帮助或跳过安排的未知；达到可以采取有限行动的程度即进入教学。
6. **形成并落实近期内容展开单。**把理由、材料需求、学习者必须完成的工作、检查与改道条件一并交出；计划责任方汇总必要返回信息，将条件已落实的范围纳入当前有效安排，其余保留为候选。
7. **接收新证据并更新。**按目标范围修订判断；必要时重审目标、前置关系、材料和计划。

过程可中断。恢复时读取当前目标版本、关键原答及帮助、待解决项和返回位置，而非重新读完全部聊天。

## 三、工作包 2：从材料和用途形成目标

### 1. 先辨认材料的作用，再抽取要求

材料分析先保留五类信息：**内容对象与条件、课程明确要求、任务形式与深度线索、可定位出处、缺失或冲突。**材料只提到某个概念，不能推定已完整讲授，也不能据此推定用户应能证明其全部理论。

| 输入 | 可以据此形成什么 | 暂不能据此确定什么 |
|---|---|---|
| 课程表 | 主题地图、课程节点、先后安排线索 | 全部能力深度、必要前置、验收标准 |
| 课程大纲、正式目标 | 课程范围、明确要求、考核方向 | 每个目标的可观察判据、个人起点 |
| 教材、讲义、视频 | 定义、关系、条件、例题及解释资源 | 学习者掌握程度；所有内容是否都是课程必修 |
| 作业、考试样题、评分说明 | 任务形式、预期深度、允许资源和评分线索 | 长期保持、陌生情境应用；整门课全部目标 |
| 个人笔记、旧作业、代码产物 | 接触经历、候选表现及需追问的条件 | 未知帮助条件下的独立能力 |
| AI 补充或桥接内容 | 目标缺口的候选补充 | 未经核验的权威依据或正式课程要求 |

【依据】前四类输入及局限继承工作包 2；对个人产物和生成内容的处理延续 v0 的来源身份区分。[工作包2]、[共享语义]

抽取时给要求标明身份：**课程明确要求、用户明确用途、系统建议、尚待澄清。**另标内容根据是原文给出、可核验推导还是暂缺依据。两组标记用途不同：一项能力可以是用户明确要求，但当前没有足够教材支持；也可以教材讲得充分，却不属于用户近期用途。

### 2. 用途决定选择，依据约束结论

课程原有要求与个人目标分别保留。用户只为工作中使用某方法学习，可以先学接口、条件和使用判断，把完整证明列为延期；若正式考试要求证明，系统必须显示这个个人取舍留下的课程缺口。

不设置一个适用于所有争议的“教材高于讲义”顺序：

| 分歧 | 处理 |
|---|---|
| 课程覆盖、截止时间或考核形式不一致 | 查当前课程发布者及版本；暂不能确认时保留不同要求及影响 |
| 同一数学命题或程序结果矛盾 | 依据定义、合法推导、可复现结果核验；不因某来源写得正式就接受 |
| 新旧材料适用条件不同 | 保留条件和版本，判断是否其实都成立 |
| 用户用途与课程要求不同 | 展示两条要求及取舍，由用户决定个人范围 |
| 理论解释或价值立场不同 | 明确分歧类型和论证标准，允许有依据的多个答案 |

若官方评分要求与核验后的学科结论冲突，分别记录“课程可能如何评分”与“内容如何成立”，建议澄清评分；不把已知错误写成学科事实，也不因用户指出错误给其记负面能力结论。

### 3. 目标形成采用两层推进

**课程层先覆盖全景。**把主要主题映射到最终希望完成的任务，保留课程必需、服务个人用途、可延期以及范围外内容。检查最终任务是否存在跨章节依赖，特别是不能临时替代的前提。课程顺序只是线索，不直接等于认知依赖。

**近期层达到可教学程度。**只对准备进入的目标及其关键前置形成完整规格；同时检查新目标是否改变粗地图。例如综合任务需要程序实现，而近期一直只安排概念解释，应提早暴露这种能力覆盖缺口。

远期目标须显示“暂定到何种程度、何时细化”。进入新主题、用途变化、材料更新或综合任务失败时重审，避免“以后再细化”变成长期漏项。

### 4. 材料不足时仍然可以启动什么

| 缺口 | 可继续的工作 | 不能作出的结论 | 下一步 |
|---|---|---|---|
| 只有课程表 | 形成主题地图，提出用途相关的暂定目标，选熟悉主题作为起点 | 课程完整深度已确定、验收设计已完成 | 请求近期章节或一份代表性作业；用户暂不提供时采用标明来源的独立学习目标 |
| 有教材，无正式考核要求 | 形成个人能力目标与学科判据 | 这些判据等同官方评分 | 标明个人验收，后续获得课程规则再对齐 |
| 有题目，无可靠答案 | 定义候选证据要求，交材料方核验答案与判据 | 以未经核验的生成答案评分并确认掌握 | 能独立推导或测试则核验；否则暂缓相关验收 |
| 材料缺前置 | 明确缺哪一项、为什么需要、补到什么程度 | 直接认定用户基础不足 | 先查相关表现，再决定是否补材料或提供局部桥接 |
| 来源相互矛盾 | 隔离受影响命题，继续不依赖争议的内容 | 对受影响能力作确定正负判断 | 发出可定位的核验请求 |

**进入规则：**一个近期目标必须已有足以开展当前活动的内容依据和目标说明；准备评分时还必须具备可靠判据。未解决问题如果影响当前活动的关键正确性，就暂停该活动；仅影响远期部分，则保留限制继续。

## 四、目标粒度、前置关系与目标版本

### 1. 用可观察表现写目标规格

每个近期目标使用同一语法：

> 在【范围／情境】中，使用【允许资源】，由学习者独立完成【关键操作并产生可检查产物】，满足【关键判据】；结论只覆盖【适用边界】，并在【需要的时间或情境变化】下另行取得证据。

“独立”指目标要求的关键判断由学习者完成。目标可以允许教材、计算器、编程文档或某类工具；允许工具并不自动等于有提示，禁止 AI 代做关键判断也不自动要求闭卷。背诵目标、查资料解决问题目标与有工具编程目标须分别规定资源条件。

近期目标最小规格如下；稳定标识用于追溯，不规定具体编码方式。

| 项目 | 必须表达的含义 |
|---|---|
| 标识、版本、归属 | 属于哪门课程或个人用途，何时为何改变 |
| 目标陈述与范围 | 对象、条件、关键操作、产物、明确不覆盖什么 |
| 要求依据 | 课程要求或用户用途的出处；系统补充建议须标明 |
| 内容依据 | 定义、规则、材料位置与版本；缺失或争议 |
| 判据及允许资源 | 哪些是不可缺的关键要求，什么帮助改变证据含义 |
| 任务覆盖与后续证据 | 要观察的典型情况、边界、综合操作、保持或迁移范围 |
| 前置与关系 | 真正必需的前提、可随学随补项、所属综合目标 |

例如“理解等价变形”应具体为：在约定数域的未练方程中，自主选择合法变形，说明必要条件并保留完整解集。若目标只是识别等价变形的定义，则无需把求解、证明和迁移全部塞进去。

### 2. 只在存在决策差异时拆分

以下任一情况成立，值得拆出子目标：

- 某部分需要不同的可观察证据，例如说清原理与让程序按要求运行。
- 某部分可以得到不同的判断，例如能执行公式但不能自主选择公式。
- 某部分需要不同的帮助或补充材料，并可能改变学习顺序。
- 综合失败需要定位到有限环节，否则只能重复整章。

若拆开后总是共同教学、共同检查且没有不同安排，优先合并。不能仅因教材有多个段落就创建多个能力目标。

保留**局部目标与综合任务**两层。局部证据可减少不必要的基础教学，但子目标全部通过不自动证明能组织完整证明、完成端到端实现或综合比较。综合任务也不应无条件替代所有子项检查：只有任务实际调用且能从产物辨认的部分才有支持。

这避免把“题目总分较高”误写成“所有组成能力均掌握”。关键条件错误不能被无关项目的高分抵消。

### 3. 前置关系是一项可检验的依赖判断

前置说明采用三种用途：

| 用途 | 判断问题 | 安排含义 |
|---|---|---|
| 必要前置 | 缺少它是否无法完成当前目标的关键操作，且允许资源不能替代？ | 进入前补足、核查或显式提供；仍未独立可用时限制父目标结论 |
| 可伴随补充 | 是否只在某一步需要，能有限补充后返回？ | 保存父目标后局部修复 |
| 有益背景 | 是否主要增加解释深度、效率或兴趣？ | 不作为强制进入门槛 |

每条关键依赖保留：**针对哪个目标版本、依赖哪项能力、为什么需要、根据什么判断、是否可由工具或提示替代、补足后怎样返回。**“必要”针对任务和资源条件成立，不能升级为整个学科的固定学习顺序。

判断依据可来自任务结构、可靠学科分析或实际作答；学习者失败只能支持某种解释，不能单凭失败就证明前置依赖。出现互相依赖时，先判断是否目标太粗，或可以用一个带明确接口的支架让两部分共同学习，不强行展开无限前置链。

**局部修复的返回规则：**子目标达到当前父任务所需程度后，回到未暴露答案的父目标任务。若子目标成功而父目标仍失败，重审原诊断或综合组织要求，不继续沿同一前置无限下钻。[局部修复]

### 4. 修改目标时，已有证据怎样处理

| 变动 | 证据与判断处理 |
|---|---|
| 只改措辞或材料定位，任务要求不变 | 记录等价性，原支持关系可保留 |
| 拆分原目标 | 只向实际观察到的子能力建立支持关系；未观察部分为未知 |
| 合并多个目标 | 保留子项证据；新增的协调与综合要求等待证据 |
| 扩大情境、提高深度或减少允许帮助 | 旧证据保留其原范围，不能自动满足新要求 |
| 缩小个人目标 | 为新范围重新判断；旧范围明确延期或替换，不改写历史达成状态 |
| 判据或内容实质纠错 | 暂停受影响结论，重评相关原答；是否需要新作答取决于原答是否足够 |

调整表示粒度、纠正事实等维护工作由目标责任方处理。改变用户最终用途、承诺范围或投入需要用户决定，已有明确授权的范围内调整可以直接执行。

## 五、验收框架：先限定结论，再设计能支持它的任务

### 1. 每个目标建立“证据要求”

证据要求先于验收结果确定，至少说明六件事：**要支持的结论、任务必须调用的操作、观察什么产物、允许资源与帮助、正确性判据、不能据此推出什么。**

不必预先写完所有题目，但必须写出任务变化的意义。例如方法选择目标要避免题干提示方法名称；边界理解要包含容易误用的情况；综合能力要保留由学习者组织各步骤的机会。

| 能力目标 | 有用证据 | 常见误验 |
|---|---|---|
| 恢复事实、定义或约定 | 在约定线索下准确恢复；允许合理措辞差异 | 看着原文复述就记为独立恢复 |
| 解释关系、理由或推导 | 关键关系、条件和必要步骤可核验；允许有依据的替代解法 | 用流畅度、篇幅或术语数量代替正确性 |
| 辨析与边界判断 | 识别成立与不成立情形，说明区分依据 | 只测典型正例，无法识别过度泛化 |
| 程序执行或实现 | 学习者产物满足任务要求，关键过程和边界可检查 | AI 给出完整实现后照抄运行就记为独立实现 |
| 方法识别与选择 | 无目标原理提示时识别何时使用、何时拒绝使用 | 告诉公式后算对，便推断能自主选择 |
| 综合运用 | 自主组织子技能完成整体任务，说明关键取舍 | 子项分别通过便自动验收整体 |
| 新情境应用 | 明确变化维度、共享关系及新增前置，检查适用性与实施 | 仅换数字或措辞就称远迁移 |

延迟保持和新情境应用不是所有目标的附加最高等级，而是按使用要求选择的证据条件。若目标确实要求跨天使用，当前阶段可以收束，但完整目标仍保留相应待证部分。

### 2. 把任务质量和学习者表现分别判断

在形成能力结论前先检查：

1. 任务是否真的调用了目标操作，是否能靠无关线索、猜测或复述完成。
2. 参考答案与评分依据是否可靠，是否允许合理不同解法。
3. 所给帮助是否完成了正在评价的关键工作。
4. 产物是否足以支撑结论，以及任务是否引入了未声明的新前置。

任务不合格时修正任务或缩小可支持结论，不能把系统的测量缺陷归因于用户。

对正确答案，也要识别证据范围。选择正确选项可支持该项选择表现；若要进一步声称会解释、会推导，应取得对应证据。无需为了所有简单事实都强制追问理由。

### 3. 证据充分性按决策后果分层

采用以下质量检查，不设置固定“连续答对几题即掌握”规则：

| 决策 | 至少需要什么 | 不足时怎样继续 |
|---|---|---|
| 选择一个短、可回退的教学起点 | 有限表现或自述足以说明该起点合理；保留替代解释 | 带着待检验假设开始学习 |
| 减少当前重复或进入后续学习 | 已核验表现覆盖当前关键要求，帮助条件合适，已知关键缺口有处置 | 有条件进入，保留未证部分与检查需求 |
| 跳过必要基础，或确认较宽范围的当前能力 | 覆盖关键任务类别、关键边界与必要综合操作；排除同题记忆、提示或单一偶然成功的主要解释 | 缩小结论，补最能改变判断的证据 |
| 确认某保持期限或新情境能力 | 取得相应延迟、间隔背景或明确变化维度的表现 | 写明尚未证明，不以即时结果替代 |

“覆盖关键类别”由目标决定，例如规则理解需要区分合法使用与不合法使用，事实恢复可能不需要复杂边界题。若证据相互依赖、只有同一题的多次修正，不因记录多而自动提高充分性。

**行动与能力结论分开：可以先继续学习，同时保留延迟未知；不能因为教学已继续，就把长期掌握记为完成。**风险更高的跳过决定需要更完整依据，但不把每次普通练习都变成审查流程。

### 4. 保留学科正确性标准

| 学科 | 目标与验收须保留的差异 | 示例性的可检查产物 |
|---|---|---|
| 数学 | 数域、前提、量词、推导合法性、解集或证明完整性；类比不能替代证明 | 保留条件的推导、合法反例、完整解集 |
| 人工智能 | 概念解释、实现行为、实验设计、结果解释分别给证据；标明环境与工具帮助 | 解释、可检查程序、实验记录及不过度外推的结论 |
| 金融 | 模型假设、适用范围、数据时点和不确定性；课程任务与实际决策成效分开 | 对给定案例说明假设、计算和失效条件 |
| 政治 | 事实主张、因果解释和价值判断分别评价；允许有依据的竞争解释 | 可追溯论证、反对证据、替代解释和条件性结论 |

学科差异继承 v0。[学科差异] 此处不提供真实金融决策或现实政治事实判定，具体课程必须使用对应来源核验。

## 六、工作包 3：用证据与判断表示学习者状态

### 1. 学习者模型保存什么

学习者模型按当前课程任务组织，不建立“逻辑能力弱”“记忆力好”等稳定一般标签。只有对后续决策有作用的信息进入当前摘要：

| 信息层 | 内容 | 不能替代什么 |
|---|---|---|
| 用户主动信息 | 用途、接触经历、可用时间、兴趣、资源偏好、当前感受 | 不能替代实际能力表现 |
| 表现事件 | 原答、推导、程序或其他产物，完成顺序和修订 | 不能由 AI 总结代替原证据 |
| 表现条件 | 可见资料、工具、提示、示范、同题暴露、时间与情境 | 不能折算成一个笼统的“提示次数” |
| 条件化判断 | 哪项目标、哪种条件下获得了什么支持 | 不能自动推广到整章或其他领域 |
| 暂定诊断 | 对失败或成功条件的解释、支持、反证、替代解释 | 不能当作观察事实 |
| 教学与恢复状态 | 当前支架、父目标、预算停止、下一项检查与返回位置 | “已讲过”不能转成“已掌握” |

【依据】这些区别落实工作包 3 和 v0 共享语义。[工作包3]、[共享语义] Encoding 的五轴和 Post-Encoding 的八维均只作为检查遗漏的分析资源；前者是设计综合，后者自称尚未经整体拟合验证，不直接成为每个目标的必填分数。[EN维度]、[PE状态]

### 2. 一次表现怎样形成可复核证据

一份表现事件至少让评估者恢复以下事实：

| 记录 | 必须保留的内容 |
|---|---|
| 事件身份 | 一次作答或活动的稳定标识、发生时间，关联目标与任务版本 |
| 原始产物 | 关键原答、过程或产物位置；AI 和学习者各自完成的部分 |
| 帮助时间线 | 初答前、作答中、反馈后分别看到什么；修订与初答分开 |
| 资源与暴露 | 允许资源、实际可见材料、是否看过同题或关键解法；不清楚就标未知 |
| 时间与变化 | 初学、最近相关练习／反馈、此次作答的时间分别记录，说明期间复习、重新讲解和答案暴露是否已知；题目改变了哪些维度 |
| 评分依据 | 判据版本、核验过的依据、逐项支持与问题；未评分或有争议也可保存 |
| 使用限制 | 来源可信程度、记录缺失、适用范围和待复核原因 |

不强制保存整段聊天。保留原始任务及足以复核关键操作的上下文；较大产物可引用文件。正常修订不覆盖原答，追加评分或解释版本；用户删除个人记录时按其控制权处理，不能借“不可改写”拒绝删除。

历史作业与外部产物可以进入，但分别标明来源和帮助条件可信度。例如用户自述“独立写的代码”可影响起点选择；如果帮助历史无法确认，重要跳过决定仍需有限的新证据。系统不靠偷偷监测来推定独立性。

延迟证据须说明保持发生在怎样的练习背景下。初学一周后测验、但测前刚复习，不能按“一周未复习保持”解释；可以记录为含期间练习的后测表现。期间活动不明时，保留当次表现，暂不确认需要排除近期再学习的保持结论。准确记录间隔与再暴露，不要求用户每次回忆全部日常活动。

### 3. 帮助按“影响了什么操作”记录

不同帮助不能简单排成统一强度等级。同一句提示可能只解释符号，也可能泄露整题方法。记录至少区分：

- **任务澄清或呈现调整：**是否只改变理解题意、阅读或输入形式。
- **内容供给：**给出事实、公式、前置结果、选项或中间步骤。
- **关键判断供给：**指出方法、条件、错误位置、关系或完整解法。

评价帮助对当前目标的实际影响。若目标是理解关系，提供已知前提可帮助区分“前提暂不能恢复”和“关系推理有困难”；但不能因此认定其已能独立恢复前提。若目标就是识别那个前提，提供它会直接限制结论。

一次事件可支持多个局部目标，但每项支持分别说明。例如 AI 提供公式后用户独立完成计算，可以支持“给定公式时的执行”，不支持“自主选公式”，也不支持“无提示恢复公式”。

初答、提示后修正、反馈后重做都保留，但属于同一学习经历的相关证据。换 Agent 评分、换一份摘要或同题重算，不能变成多份相互独立的成功。

### 4. 当前判断采用“结论范围＋证据状况”

推荐写法：

> 对目标 G 的【具体要求】，在【资源、帮助、时间与情境】下，已有【支持／未达到／混合表现／未知】。根据事件 E……；尚不能判断……。当前安排为……；出现……时重审。

“证据状况”区分：

| 状况 | 含义 |
|---|---|
| 未知 | 未取得对应表现，或缺少足以解释的条件 |
| 已有支持 | 指定要求在记录条件下得到正面支持，范围随覆盖限定 |
| 已观察到未达到 | 指定任务的某项要求未满足；不等于永久不会 |
| 混合或冲突 | 可比条件下结果不一致，或存在关键未解反证 |

再单独记录是否**可使用、待复核、已撤销**。待复核不是能力变差，而是证据、评分或来源受到质疑；已撤销的判断保留修订关系，不再驱动安排。

必要时对同一目标展开三个证据面：当前独立表现、目标保持期限下的表现、指定新情境下的表现。帮助下表现作为有价值的条件化记录并列保留。它们不是一条只能逐级升级的阶梯；可以有“此前延迟通过、今天新任务失败”，也可以有“会在新例现场推理、事实恢复仍不稳定”。

不适用的证据面写“不要求”或省略，目标内尚无证据的写“未知”，两者不同。范围外能力不自动进入待检清单，只有扩展目标后才确定相应取证需求。用户摘要可以简写为：“本次新题独立完成；跨天保持待检查；参数情境未纳入当前目标，扩展目标时再取证。”

### 5. 证据累积不靠简单加总

更新判断时先看四件事：**是否针对同一要求，条件是否可比，来源是否有效，新增事件究竟提供了什么新信息。**

新的异型任务可能扩大支持范围；相同错误的重复出现可能支持更稳定的困难假设；大量同题重复则可能只证明在该暴露条件下熟练。它们都不应只转成加分或扣分。

时间过去本身不会把过去真实表现改写为失败。系统保留“当时表现”，再判断它对当前安排是否仍足够相关。课程版本、工具、情境或长时间未使用等变化触发适用性复查；本轮不设置所有知识共用的证据失效天数。

## 七、冷启动与局部诊断：围绕会改变安排的未知取证

### 1. 冷启动只收集足以选择起点的信息

首次最有价值的输入通常是：**近期要用来做什么、正在学习哪一部分、能投入什么、是否有相关历史产物。**已有资料能够回答的不再问；与当前安排无关的远期信息暂不收集。

用途没有明确时，可提出“先按理解当前课程并完成对应任务拟定”的暂定目标，展示假设与影响；不替用户承诺考核范围、保持期限或每周投入。未获必要约束前，仍可整理材料和起草有限目标。

冷启动允许三条入口：

| 情况 | 推荐入口 | 证据解释 |
|---|---|---|
| 有相关且条件清楚的历史表现 | 先复用证据，仅补当前决策需要的缺项 | 不重复考已经有充分依据的相同能力 |
| 自述学过但无可靠表现 | 选择一个能区分“直接进入”与“局部支持”的起点任务 | 自述决定试探起点，不决定通过 |
| 用户自述陌生、要求示范或暂不愿测查 | 先提供有限输入或示范，保留关键部分给学习者尝试 | 当前证据从接受帮助后的表现开始，不能反推课前已会 |

首次接触的内容上答不出，记录为当前缺少可观察成功；不称“遗忘”或“检索失败”，除非已有学习经历支持这种解释。

### 2. 每次追加诊断都要有一个决策问题

诊断开始前写一句内部理由：

> 我需要区分【解释甲／乙】，因为它们分别会导致【安排甲／乙】；用【任务】能观察【差异】，其成本和帮助影响可接受。

如果两种解释都会导向同一个短、可回退的活动，就可以先学习，不必为给错误命名而追加测试。若分歧影响跳过必要基础、改变承诺范围或重要能力结论，则优先补证据。

一个诊断记录只保留当前有行动意义的候选解释：观察事实、主要解释及合理替代、已有支持与反证、下一项有区分力的证据、不同结果的安排。无需罗列所有心理机制。

### 3. 通过改变一个条件，缩小解释范围

| 观察事实 | 合理解释 | 有区分力的下一步 | 可作出的有限判断 |
|---|---|---|---|
| 关系题失败 | 前提暂不可用；关系规则有缺口；题意不清 | 提供必要前提但不解释关系，再观察推理 | 成功支持“给定前提时能推理”；仍不直接确定原失败只来自提取 |
| 给定公式会算，自主选择错误 | 条件辨认有缺口；候选方法不熟；题目语言误解 | 使用未标方法的对照情境，检查选择及排除理由 | 分开更新执行与选择；不靠更多同型计算替代 |
| 数字答案正确，过程不清 | 正确推理；偶然命中；过程省略 | 若目标需要过程，要求关键步骤或一个有区分力的变式 | 只补足当前结论需要的证据，不一律追加长解释 |
| 会口头解释，程序不满足要求 | 实现、规格理解、工具使用或实验设置问题 | 看实际产物和失败位置，先核对任务规格与可运行环境 | 定位有限缺口，不撤销已有概念解释证据 |
| 回答慢或多次中断 | 需要思考、输入困难、环境干扰或疲劳等 | 询问当前感受，调整呈现或允许暂停 | 不据时长单独推断认知能力或负荷 |
| 新情境失败 | 未识别方法、关系映射困难、执行问题或新前置不足 | 分别观察选择、映射和执行；必要时提供新领域背景 | 只定位已观察到的障碍，不给一般迁移能力标签 |

这些是诊断方向，不是每次必走的测试套餐。条件改变本身可能教学：提供前提、解释词义或给候选方法后，后续成功均须附带新条件。

### 4. 何时停止诊断

重要决定缺少关键证据时，先暂不作该决定；这本身不是停止诊断的理由。在用户愿意继续、证据可取得、预算允许且取证值得成本时，应继续补证据。满足以下停止条件时，才结束本轮诊断并给出明确去向：

| 停止原因 | 处理 |
|---|---|
| 已有依据足以选择有限、可回退的下一步 | 进入教学，把剩余解释交给后续活动区分 |
| 新任务不大可能改变当前安排 | 停止追问，记录为什么不继续取证 |
| 用户要求示范、缩时或暂停，或本轮预算用尽 | 转教学或收束；保留未知和恢复位置 |
| 题目、资料或评分依据有问题 | 暂停相关判断，交材料／评估核验 |
| 当前解释多次预测落空，继续同类任务无新增信息 | 重审诊断、目标粒度或任务；必要时由高层介入 |
| 重要决定所需证据暂时无法取得、取证预算耗尽，或继续取证不值得成本 | 暂不作该决定；记录停止理由及恢复取证的条件，选择不依赖这一结论的安排 |

本轮不规定统一题量、连续失败次数或分钟数。实际运行时，由当前目标、用户时间和后果设定一次诊断的有限预算，并在开始前明确；到点后允许保留未知。缺少数字阈值不代表允许无限诊断。

### 5. 对诊断质量的检查

每次修复后问：**原解释预期会出现的变化是否发生？**若给出某前提后用户仍不能处理关系，原先“只缺前提”的解释便受到反证；若换一种清晰表述后成功，题意或表征问题得到支持，但仍需检查能否回到原任务。

诊断的价值看它是否帮助选择更合适的下一步、减少无效重复，而非看系统输出了多少错误类型。用户可以直接纠正背景和感受；系统据此更新信息，不把这种纠正当作“抗拒诊断”。

## 八、让判断真正改变内容展开

### 1. 近期内容展开单是两包的共同输出

展开单围绕一项有限学习目标或紧密相连的一组目标，注明维护者、版本及候选／有效／暂停的范围，包含以下七个部分。它可以短到一屏，不要求每次生成长报告。

| 部分 | 交给执行者什么 |
|---|---|
| 范围与承诺状态 | 目标版本、范围、用途、时间或资源边界；候选部分只作建议，生效部分才构成本次承诺；哪些内容暂缓 |
| 当前依据 | 关键证据及其条件、待复核项、尚未知的部分 |
| 起点与重点 | 为什么从此处开始，先处理哪一个有限缺口 |
| 材料需求 | 需要哪些原文、示例、对照、桥接或核验；各自目的及来源要求 |
| 学习者工作与帮助 | 哪项选择、推理或执行必须留给学习者；允许提供什么，何时撤除 |
| 检查与改道 | 接下来需要什么证据；成功、失败、冲突分别怎样调整 |
| 收束与返回 | 父目标、返回条件、暂停位置、后续检查需求及接收方 |

展开单引用目标和证据，不重新复制一套掌握状态。**计划责任方兼任展开单的最终维护者**，汇总目标方、评估方、材料方及执行者的更新，维护唯一的当前版本；它不能覆盖这些责任方的内容判断或越过用户授权。此职责并入现有计划工作，不新增 Agent 或审批环节。

**生效条件按实际要执行的范围判断：**所用目标、判据和判断版本一致，当前活动必需的材料及核验条件已落实，时间与资源安排可用，且处于用户及执行者的既有授权内，方可标为有效。必要条件尚未落实的部分保留为候选，不计入本次承诺；远期或无关材料尚未准备，不阻止已具备条件的活动开始。

**关键依据变化立即限制受影响安排的效力。**执行者获知判断撤销、材料失效或预算收缩时，先暂停依赖被撤销依据或已超出预算的部分，继续不受影响且仍在授权内的活动；不等新版本发布才停用失效安排。维护者再依据各方最新结果合并修订，检查生效条件后标明新的有效范围，保留理由并通知执行者。若评估方撤销跳过基础的依据，同时计划预算缩小，就同时暂停该跳过安排与超预算活动，待必要补证或范围取舍落实后再更新有效安排。

执行者在有效范围内调整表述、局部支架等，仍按已有授权直接进行并回写记录，无需逐次等待维护者批准。

### 2. 证据如何改变近期安排

| 证据或未知 | 近期改变 | 保留的边界／再次改变的条件 |
|---|---|---|
| 只有接触经历，无表现 | 选有限起点任务，或按用户选择从示范开始 | 不默认零基础；出现独立成功可减少重复 |
| 已能在给定前提下推理，独立前提调用不足 | 聚焦前提的恢复或准备，减少整章重讲 | 返回无前提供给的父任务再检查 |
| 执行正确，方法选择不足 | 强调情境线索、成立条件和对照；减少纯计算重复 | 未提示方法的新任务成功后再扩大结论 |
| 依赖关键提示才成功 | 保留当前支架，设计撤除帮助后的新任务 | 提示下成功不能代替该检查 |
| 当前独立表现覆盖关键要求，延迟未知 | 可以进入下一内容，将保持需求交计划 | 尚不能宣布目标期限下保持 |
| 延迟失败、提示恢复成功 | 检查调用线索与关键前提，安排有限恢复 | 不直接重学全部内容，也不确定只有提取问题 |
| 新情境失败、旧情境仍成功 | 检查情境识别、映射及新增前置，保留原范围表现 | 若旧情境也受影响，再扩大回查范围 |
| 只有部分目标可在预算内完成 | 优先保留必要补缺与当前独立检查，建议缩小新内容范围 | 延期部分明确列出；不把未完成标为通过 |
| 材料或评分有争议 | 暂停受影响判断，换到有依据的任务或来源核验 | 争议解决后重评，不让错误标签继续驱动教学 |

内容展开既包含“学什么”，也包含“怎样进入”。材料篇幅长短只是一种结果，不能用“基础弱则解释更详细”代替上述差异。

### 3. 执行者保留适应空间

执行者可以在核验过的范围内调整呈现、选择等价材料、改变局部支架、插入有信息价值的短检查，也可在用户缩时后收束。具体选择由工作包 5—6 深化。

以下变化必须回到目标或评估责任方：改变能力要求或判据；改变任务定义域、核心假设或答案而未完成核验；超出授权补基础；重要证据冲突；原诊断持续失效；预算已无法支撑承诺范围。

实际发生的关键帮助不能经高层批准后追认为未发生。只有原标注与原始记录不符时，才可依据记录更正并保留理由；否则，新的独立支持必须来自符合相应条件的表现。

**教学意图交接必须包括“不可代做的关键工作”。**若目标是选择方法，讲解可以支持背景理解，却不能先给方法再把执行成功当选择成功；若用户此时需要方法提示，允许给，但本次活动转为相应帮助下的学习证据。

## 九、新证据、纠错和变化的更新规则

### 1. 每次更新按同一顺序处理

1. **登记事件。**先保存原答、实际条件和关联版本；缺字段时保留事件，但限制结论。
2. **检查任务与评分。**内容是否正确、判据是否对应目标、帮助是否改变观察含义。
3. **匹配支持范围。**新证据对应哪项要求，是否与旧条件可比，有无重复或明显依赖。
4. **修订判断与解释。**追加支持、缩小范围、记录冲突、撤销失效结论或重审诊断。
5. **检查安排是否要变。**无需每次微小变化都重做全部计划；只修改受影响的起点、支架、范围、材料需求或待检项。
6. **记录理由和接收状态。**说明改了什么、依据什么，后续工作是否已接收。

### 2. 常见变化怎样更新

| 触发 | 判断变化 | 安排变化 |
|---|---|---|
| 教学中提示后修正 | 新增帮助下修复证据；修复后的独立表现仍待检查，原初答作为历史证据保留 | 准备符合目标资源条件的新任务 |
| 未暴露关键解法的新任务独立完成 | 在任务覆盖范围内增加当前独立支持 | 可收束当前教学，交出未完成的延迟／情境检查 |
| 延迟任务通过 | 按实际间隔、期间练习／再暴露和作答条件解释；背景不明时不确认要求排除再学习的保持结论 | 依据可支持范围减少重复，由计划决定何时再检查 |
| 延迟任务失败 | 保留过去成功，当前保持判断受限或冲突 | 诊断恢复、前提、结构或状态因素，安排有限修复 |
| 新情境成功或失败 | 只扩展或限制测过的变化范围 | 相应扩大应用，或定位情境识别／映射／新前置 |
| 同条件结果冲突 | 不机械取平均，也不只保留最后一次 | 查评分、暴露、条件和产物；补最有区分力的证据 |
| 用户改用途或目标期限 | 形成新目标要求，重审旧证据可比性 | 重新选择近期内容与所需检查 |
| 资料、工具或规则版本改变 | 判断变动是否触及原目标和产物 | 仅重核受影响部分，保留其他有效结论 |
| 用户纠正自述或删除个人证据 | 更正背景；删除后重审所有依赖它的判断，剩余证据充分则保留，覆盖不足则收窄，失去依据则撤销 | 同步更新展开单及个人摘要；允许带未知继续，不从遗留副本恢复已删除内容 |

对明显不可比的两次表现，先分条件保存，而非制造冲突。例如一次允许查文档、一次禁止查文档，不能只因结果不同就说能力下降。

### 3. 内容纠错单独走回查路径

沿以下依赖回查：

~~~mermaid
flowchart LR
    S["来源或规则版本被纠正"] --> T["依赖它的解释、任务和参考答案"]
    T --> R["受影响的评分"]
    R --> J["依赖该评分的能力判断"]
    J --> P["跳过、补缺、材料与后续计划"]
~~~

处理分三步：

**先隔离。**标出争议的具体内容和受影响范围；暂停依赖它的确定判断，避免继续向用户强化错误或追加错误标签。其他目标照常推进。

**再重评。**保留原答当时的语境。若原答足以按正确判据判断，直接重评；若任务本身无效或原产物不足以说明能力，才安排新的必要证据。纠正参考答案本身不会凭空产生未观察到的能力。

**最后修复安排。**撤销错误补课、恢复被错误阻止的进入条件，或追回因错误通过而跳过的必要检查。若错误教学已经影响用户，还要给出纠正说明及相应新任务，后续关注旧错误是否复发；不能只改后台评分。

如果新旧知识分别适用于不同条件，更新为条件化共存，而非一律覆盖；复查旧错误是否复发时，也检查仍正确的旧情境，避免学成过度禁用。一次纠错后答对只说明行为修复，不能宣称原错误记忆被擦除或发生了特定神经机制。[PE测量]、[PE机制]

### 4. 首期只维护必要依赖

至少能追溯：**目标版本引用哪些内容；任务用了哪些内容和判据；事件属于哪个任务；判断用了哪些事件；展开单用了哪些判断。**

这些关系足以支持人工辅助回查，不必先建设通用知识图谱。内容变化先判断是否实质相关：修正错字或链接，不应让全部历史能力失效；定义、条件、评分要求改变，则要核查依赖链。

并行 Agent 可以提交表现事件、评分建议和诊断建议；当前目标结论由明确责任方维护。使用旧版本产生的结果先检查兼容性，不以最后写入覆盖，也不因为多个 Agent 同意就增加独立证据数量。

## 十、与工作包 4—8 的交接与责任

### 1. 每项交接都有返回信息

| 接收工作包 | 本轮交出 | 对方返回 | 缺项或失败时 |
|---|---|---|---|
| 4：材料与来源 | 目标版本、需要支持的内容与深度、片段用途、前置要求、来源缺失或冲突 | 可定位片段及版本、来源性质、支持范围、核验结果、纠正涉及的内容标识 | 缺关键依据则暂缓相关评分；可以继续有依据的部分 |
| 5：教学骨架及 Encoding／Post-Encoding | 近期内容展开单、关键原答位置、判据、不可代做的工作、帮助和调整边界 | 实际任务、原答、提示与反馈顺序、产物、父目标返回结果、停止原因和待检需求 | 帮助超出验收条件则保留为教学证据；任务改变关键条件则重核 |
| 6：策略使用 | 当前要改变的缺口、替代诊断、材料保障、期望观察的变化 | 选择理由、实际活动及策略标识、支持条件、进展、负担和退出理由 | 无进展时审查材料、诊断和执行，不自动给用户降能力结论 |
| 7：长期计划 | 补缺／保持／变式／综合检查需求、重要性与依赖、目标期限、预算、恢复位置 | 已安排、延期、缩小、合并或移出的处理结果及影响；下一次承诺范围 | 资源不足时重新取舍，不无限追加；必要要求未能安排时明确未完成 |
| 8：协作与共享状态 | 信息含义、当前版本、责任归属、最小恢复材料、争议项 | 更新来源与理由、接任确认、冲突处理、授权和升级结果 | 缺原答或帮助条件时降低结论权限；争议不靠最后写入裁决 |

【设计】交接至少具有“提出—接收—处理结果”的可追踪状态。各方返回结果由计划责任方合并进当前展开单，执行者以其中有效范围及已收到的暂停通知为准，不将候选稿或各方单独建议视为另一份有效安排。特别是延迟检查不能只写“以后复习”：计划方必须说明已安排或暂不安排及其影响。未安排不等于该证据不再需要，计划延后也不等于目标已通过。

计划方可以把兼容的多个检查合并进一项活动；仍须分别说明实际观察到了哪些目标要求。具体日期、提醒和积压清理规则留给工作包 7。

### 2. 关键决定由谁负责

| 决定或动作 | 责任 |
|---|---|
| 学习用途、最终范围、投入与个人记录控制 | 用户决定；系统说明取舍影响，沿既有授权执行 |
| 目标、判据、关键依赖、阶段范围建议 | 高能力 Agent 担任目标责任方 |
| 重要能力结论、重大诊断变化、来源或评分争议 | 高能力 Agent 担任评估责任方，读取原答和依据 |
| 常规互动、材料制作、局部支架、按授权判据记录表现 | 中等能力 Agent 执行，并如实交回实际条件 |
| 常规评分与范围内调整 | 可由执行者按核验过的规则处理；重要跳过或冲突交责任方 |
| 时间安排与取舍 | 计划责任方在用户预算和目标约定内执行，越界时提出明确选择 |
| 当前展开单的维护与生效 | 计划责任方汇总各方最新依据和约束，维护唯一当前版本及有效范围；执行者即时暂停受影响部分并回报，责任方的专业判断不由维护者覆盖 |

角色可以合并到同一 Agent，但教学时主动帮助与评估时核对帮助影响的职责仍需区分。无需每道题多 Agent 复审；高层介入由后果、争议和授权边界触发。[协作责任]

高层暂不可用时，执行者可以继续不依赖争议的已授权活动，保留新证据、待复核判断和暂停理由；不能代为修改验收标准或作超出授权的重要结论。

### 3. 用户看到什么

每次关键变化只需清楚呈现：

> 当前目标是什么；已有哪种表现；还没证明什么；所以接下来安排什么；哪些结果会让我改安排。

用户可展开查看来源、关键原答和修改理由，也可要求示范、跳过诊断进入学习、缩时、改目标、质疑评分或更正背景。用户选择跳过检查时，系统可以继续其选择的学习活动；保留此前有效证据及其支持范围，本次尚未取得的部分仍未知或待检，不因跳过而新增达标结论。这是一项控制权与证据含义的同时保留。

## 十一、三个假设情境：检查这套设计能否产生不同安排

以下全部为**【假设】纸上走查**，不代表用户水平，不是实际教学结果。数学情境继承 v0 的主题并扩展信息链；AI 与政治情境为虚构课程条件。文中已经展示题目和答案，未来真实验收不得把这些例子当成用户未见的任务。

### 情境一：同一份等价变形材料，四种表现

**材料与用途。**假设某课程当前涉及实数范围内方程的等价变形，近期用途是独立求解并检查变形条件。正式使用时需绑定实际教材位置；本例仅使用可直接核验的代数规则，不虚构教材出处。

**目标 M1。**在未暴露关键解法的方程任务中，自主选择合法变形，保留定义域和完整解集，并说明关键条件。允许草稿，不允许在独立检查中先提示“某因子可能为零”。当前覆盖变量因子消去与分式定义域，参数分类和其他变形尚未纳入。因式分解为候选前置；是否需要补充根据表现决定。

**证据要求。**既要观察可能丢解的消去，也要观察可以合法约分的情况，防止只学到“不能除以变量”。完整解集和关键条件不可被计算步骤的其他得分抵消。近期通过只涉及约定的当前任务范围，延迟保持另取证据。

| 假设表现 | 证据与判断 | 内容展开变化 |
|---|---|---|
| A：解 y²＝3y 时直接除以 y，只答 3；提示“检查 y＝0”后补出 0 | 事件 A1 初答未满足解集完整性；A1 的修订支持提示下纠正。条件规则不熟、注意遗漏等解释仍待区分 | 聚焦消去条件与漏解，准备合法／不合法消去的对照。独立条件检查仍待取得，不能因修订正确而跳过 |
| B：主动指出除以 y 可能丢失零解，但不会完成因式分解；得到 y(y－3)＝0 后给出 0、3 | 保留该任务的条件检查证据；提供分解后的求解表现有效。分解的独立执行尚未得到支持，综合求解未通过 | 只补当前需要的分解操作，达到局部要求后返回父目标。无需从“不能除以零”重新讲起 |
| C：独立完成求解；在其他任务中能处理消去限制，也能识别分式的原定义域 | 若产物与条件已核验，可支持已覆盖范围的当前独立表现 | 减少重复教学，进入后续内容；延迟保持待检；参数情境未纳入当前目标，扩展目标时再取证 |
| D：学习者给出 0、3，参考答案却只有 3 | 先出现的是评分依据争议；不能据参考答案给用户记“多解错误” | 暂停该评分，核验参考答案并回查受影响安排 |

**给 A 的一份可交接展开单：**

本例为候选稿，由计划责任方维护；材料核验和本次预算落实后，相应范围才能生效，不能仅因已经写出下表便视为本次承诺。

| 项目 | 本次内容 |
|---|---|
| 目标与范围 | M1 当前版本；聚焦变形条件与完整解集，暂不扩展参数讨论 |
| 当前依据 | A1 初答漏零解，提示后修正；不知道条件遗漏是否稳定，也未取得撤除提示后的对应证据 |
| 起点和重点 | 以原答暴露的消去条件为起点；先查是否知道适用条件，再决定解释或有限对照 |
| 材料需求 | 可核验的消去规则、保留零因子分支的例子、定义域已排除零值的对照；不需要整章重写 |
| 学习者工作 | 自己指出何时能除、何时需保留分支，并给出理由；系统可示范，但示范后的表现单列 |
| 检查与改道 | 新任务中自行检查条件则增加对应支持；仍失败且前提已可用则重审边界理解；若卡在分解则转有限子目标 |
| 收束与后续 | 到预算即保存当前证据和父目标位置；当前独立通过后提交保持检查需求给计划方 |

**B 的局部返回。**假设 B 在有限帮助后能独立完成当前需要的因式分解，则回到父任务，例如处理 (u－1)(u＋2)＝2(u－1)。整理得 u(u－1)＝0，解为 0、1；直接除以 u－1 会遗漏 1。若 B 又遗漏 1，原来“只缺分解”的诊断需要修订，不能把子目标通过自动传播为 M1 通过。这个变式仍是近邻代数任务，不称远迁移。

**C 的边界证据。**对于 (x²－x)/x＝0，原定义域 x≠0，约分后得到 x＝1。能够说明这里允许约分，才补上“条件许可时仍会正确使用”的证据。仅对 y²＝3y 答对还不覆盖这一差异。[代数锚点]

**A 的跨天更新。**再假设 A 后续取得了相应新题的当前独立支持，七天后检查时又遗漏零因子情形，提示后恢复。七天只是本走查安排，不是推荐间隔。系统记录距最近学习、练习和反馈的实际间隔，以及期间活动是否已知；将“本次延迟条件下未达到”与过去即时成功并存。安排回到有限的条件恢复与边界检查，不将整章清零，也不能确定其内部原因仅为遗忘。

**临时缩时。**若 A 本轮只够完成局部修订，就保存“提示后已改正、独立检查未做”，把新增主题延期或移出近期承诺。下一次先恢复这个状态，不能因上次活动已结束而进入“已掌握”分支。

**D 的纠错链。**代入可知 0、3 都满足原方程，因式分解也给出完整解集。修正参考答案后，原答足以支持的要求直接重评；若用户只写了答案、没有显示条件检查，则只能恢复完整解集这一项支持，仍不能凭空确认全部 M1。撤销由错误评分引起的补课；若错误答案此前被教给用户，则另外修复相关教学影响。

这组分支的区别发生在**补哪里、保留什么、是否进入新内容、下次测什么**，而非只改变“基础较好／较弱”的标签。

### 情境二：AI 课程中，会解释与会实现分开

**【假设】材料与要求。**某入门 AI 课程给出一个二分类模型的输入、得分计算和阈值决策规则，要求学生解释规则并独立完成按规格运行的程序。该课程明确约定：得分大于或等于阈值时输出类别 1。此约定仅是本假设任务规格，不表示所有分类系统都使用相同规则。

目标拆为 I1「解释给定规则的输入、输出和边界」与 I2「按规格实现并检验程序」，同时保留综合目标 I3「从要求形成实现，并解释实际输出」。允许查语言语法文档，不允许 AI 提供完整任务实现后仍记为独立实现。

**观察。**学习者能准确解释等于阈值也输出 1，但程序把比较写成严格大于，常规输入通过，边界输入失败。

**初始判断。**I1 在已观察范围内有支持；I2 当前产物未满足边界要求。保留规格落实失误、边界测试遗漏、语言使用问题等解释，不由一处程序错误推断其概念整体不懂。

**有区分力的证据。**让学习者在未指出具体代码行前，预测等于阈值的输出并核对实际输出。如果能自行定位和修正，可支持“给定边界检查方向后能定位与修复”；自主选择测试输入的证据仍待取得。若 AI 又指出比较符或直接给出修改代码，则进一步限定为该帮助条件下修复。随后用未暴露具体解法的新规格变化检查实现，并把需要评价的测试输入选择留给学习者，不把原程序重跑成功当新任务。

**材料与安排。**若只缺边界检查，材料方提供任务规格与边界输入构造所需信息；教学方把关键工作留给学习者定位和核对，不重讲整个模型。若学习者连语法错误都无法辨认，则提供局部工具支持，再回 I2；I1 的已有支持保留。I3 仍需整体任务证据。

**反证更新。**如果所谓“等于阈值失败”来自测试脚本错误，而学生程序符合已确认规格，就回查评分工具，修正 I2 判断及补课安排。程序、解释与测试结果是不同产物，任何一个都不能无条件证明另一个正确。

这说明同一套目标—证据结构能接收代码产物，而不把能力评价限于文字问答，也不需要在本轮选择编程语言、框架或自动测试平台。

### 情境三：政治课程中的材料冲突与论证评价

**【假设】材料与用途。**某课程两篇材料对一个虚构政策结果给出不同解释；用户用途是比较论证质量。甲材料使用前后对比，乙材料强调同期背景变化，但暂未给出能区分两种解释的证据。

目标 P1 是区分各自的事实主张、解释和价值立场，准确重建论证，指出能支持或削弱它的证据，并说明当前能够判断到哪里。允许查原文；查阅本身符合目标条件。能否脱离原文准确复述是另一目标，不混进本次验收。

**表现一。**学习者偏好甲，但准确指出甲证据不足以排除背景变化，并提出有针对性的补充证据。可以支持相应论证评价表现，不能因其立场与 AI 不同扣分。

**表现二。**学习者列出两篇材料的结论，却不能区分事实与解释。安排转向有限的论证拆解和来源对照，不把阅读篇数增加当作直接解决办法。

**表现三。**AI 认为某条引用来自甲，用户指出原文并没有该句。先核查出处；若确为生成错误，撤回该引用及其支撑的评分和诊断，重新判断原答。原答不足以评价的部分保持未知，不能要求用户接受不存在的依据。

**新材料到来。**若补充材料能排除一个解释，修订内容依据及当前判断；若只是增加另一种可能，保留并列解释。用户先前在原有证据下给出的合理不确定结论，不因后来信息增加而被追认为当时答错。

该情境检验开放答案、允许资料的独立工作和内容纠错。评分锚点是论证与证据要求，不能是“是否选择了 AI 偏好的解释”。

## 十二、首期落地、验收与待验证选择

### 1. 最小落地范围

首期选择一门课程的有限主题，维护以下五类记录即可：

1. **目标规格及课程粗地图：**近期完整、远期暂定，目标与判据一起版本化。
2. **表现事件：**任务、原答或产物、帮助、时间和评分依据。
3. **当前判断与诊断：**有范围的结论、支持与反证、待解问题。
4. **近期内容展开单：**材料、教学、检查和返回条件。
5. **变化与交接记录：**重要修订的影响，以及核验和检查需求是否被接收处理。

上述数量只是本方案的组织方式，不是必须建设五个模块。初期允许人工辅助定位来源、评分复核和纠错回查；只有遇到明确的重复劳动或遗漏，再增加自动化。

### 2. 本轮设计验收

| 检查问题 | 本方案的处理位置 | 本轮能够确认什么 |
|---|---|---|
| 材料如何支持范围和深度；只有课程表怎么办 | 第三节 | 已给可运行的暂定路径与结论边界 |
| 目标如何拆分、组合并保留前置返回 | 第四节、情境一和二 | 已给决策标准、版本继承和父目标回测规则 |
| 同一答案在不同帮助下会不会被混同 | 第五、六节、情境一 A／B | 规则明确区分初答、提示修正与独立表现 |
| 系统怎样承认未知并停止诊断 | 第六、七节 | 已给未知含义与停止后的去向 |
| 诊断怎样改变材料和教学 | 第八节、情境一展开单 | 安排变化可追溯至具体证据 |
| 新证据和纠错怎样改变结论 | 第九节、三个情境 | 能定向修订，保留有效部分，必要时撤销安排 |
| 检查需求交出以后是否有人处理 | 第十节 | 已规定接收与处理结果，详细日程仍归工作包 7 |
| 跨学科能否保持正确性差异 | 第五节、情境二和三 | 表示可容纳不同产物和判据；实际可靠性待试用 |

本轮完成的是概念规则、信息交接与假设走查。尚未运行真实教学，没有据此确认学习收益、评分准确率或协作成本优势。

### 3. 需要实际试用的假设

| 待验证假设 | 观察办法 | 何时修订 |
|---|---|---|
| 课程粗地图＋近期细化能兼顾启动成本和前置完整性 | 记录准备耗时、临时发现关键前置的次数及返工影响 | 若总在学习中发现重大依赖，扩大前期分析；若准备过重，缩小不影响决策的细节 |
| 围绕决策的诊断能减少负担且不频繁误选起点 | 记录诊断用时、安排改变、很快返工及用户感受 | 反复误跳基础则补关键证据；追加问题常不改变安排则精简 |
| 条件化记录足够指导接任者 | 让另一执行者依据记录恢复，核对是否重复问、漏检或误判帮助条件 | 缺少关键上下文则补记录；大量无用字段则删减 |
| 目标粒度能定位局部缺口，同时支持综合表现 | 检查子项通过而父任务失败的情况与诊断去向 | 若反复失配，调整粒度或增加综合要求 |
| 高层关键介入、中层有界执行值得成本 | 在尽量相同的材料和判据下与较简单流程比较等待、误判、修复成本和学习表现 | 无质量或成本收益时合并重复职责，保留必要评估边界 |

个人试用的证据有限，不承诺由一次比较得出普遍因果结论。先检查内容、评分和流程是否正确，再检验减少帮助后的新任务、延迟保持与目标情境应用；课程覆盖、完成率、交互轮数另行报告。[验证边界]

可对少量关键原答进行第二次独立评分，发现判据歧义；这种复核用于检查评分一致性，不增加学习者的表现证据数量。若将来引入概率、量表或自动掌握估计，需另行校准并说明其在何种目标和条件下有效。

### 4. 真正进入课程前优先补什么

当前没有真实课程与作答记录，以下信息不阻碍本次顶层设计，但影响运行中的关键取舍：

| 优先信息 | 影响什么 | 取得时机 |
|---|---|---|
| 一份近期课程材料及代表性作业或任务 | 目标粒度、内容依据和验收深度 | 首次实例化目标时 |
| 用户这次学习最想独立完成什么 | 课程要求与个人用途的取舍 | 选择首期主题时 |

| 可选的旧作业、自述与相关产物 | 减少重复诊断、选择起点 | 仅在会影响当前安排时 |

本轮不要求先全面访谈，也不据文档主题推断用户的实际能力。

### 5. 对 v0 的具体细化与下一步

本方案保留 v0 的六项能力和三个学习尺度，作出以下细化：

- B1 与 B2 联合交付，通过同一目标版本、任务要求和证据事件关联；不另设 Encoding／Post-Encoding 掌握体系。
- 把 v0 的“有范围判断”落实为目标要求、表现条件、支持范围及可使用状态；避免单一掌握等级。
- 把“评估之后展开”落实为近期内容展开单，增加父目标返回、改道条件和接收结果。
- 把纠错链落实为必要依赖和定向重评，并明确目标拆合、标准改变与用户删除记录的影响。

这些是对 v0 的深化；现有架构文档保持其历史版本。本轮不提前发布架构 v1，也不宣称工作包 4—8 已完成。
