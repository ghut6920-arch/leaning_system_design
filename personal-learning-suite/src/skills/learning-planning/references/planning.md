# 需求处置、范围与完整投入

依据 D08 第三至八节、D07 策略／计划边界、D00/D09 采用与控制。目标判据、内容正确性和证据结论仍由原责任方维护。

人工文件模式按 [SK05](../SKILL.md)及课程协议保留同一含义的短视图，不要求程序授权对象、关闭用途字段或 material_context JSON。下文 B4、评估接口和精确程序字段的校验仅在实际调用 [运行接口](runtime.md)时适用；人工仍须定位原答、帮助、材料用途和真实采用，不能省略影响结论的条件。

先辨认需求是否目标内必要、其不做影响、已有支持和父任务；可靠原答已够用则交已有证据检查，不先排新题。比较使用价值、阻塞、延期后果和用户优先；比较真正可行范围及完整成本，解释未选后果。无需构造通用收益权重、长期必修表或隐含成功率。

去向可以是安排、部分安排、合并、暂缓、不再投入、关闭或退回。每项都有理由、未覆盖影响与触发。合并保留要求映射、目标／条件／父任务；两个不同独立条件不能按主题名合并。accept 只确认由谁在何范围承担，disposition 仍 pending；scheduled 必须有实际有效 PlanCommitment。

每次用一个 BudgetEnvelope 检查所有实际安排，包含已经花费和留给不确定性的余量。准备核验、恢复、教学、反馈检查、收束切换、维护纠错分别说明；不需要的类别写 not_required 及理由，未知保持 unknown。已观察、有限试行、估计要说明来源；估计必须保留余量。不可省掉必要反馈／收束后声称等效压缩。费用和等待同样有上限；程序的会计检查不是精确收益预测。

安排只用当前、已采用且可靠的目标／活动／材料／配置。B4 复杂任务保持 GoalSpec 的整体教学范围，核验引用须覆盖目标义务；缺整体参考时可交 AG2 或承诺明确局部子范围，不能降整体要求。计划软件沿用 C0/B4 的执行准备检查，计划通过不等目标通过。

新课程、阶段／周变化或短期承诺与长程方向冲突时，用 [多尺度计划实例](multi-scale-plan.md)协调课程、阶段、周、会话四种视图。它们是同一安排的不同细化程度，不是四份额度或四个复习队列。阶段围绕目标内综合作品和依赖，周在真实剩余资源内选需求，会话只承诺可靠可反馈工作；正式目标不因缩时降级。已有稳定上层引用无需每轮重新排。

关闭投资引用 SK04 已采用的 supported/usable 判断、planning_closure 用途及原活动的 material_context，由 SK04 复验原答响应点、实际帮助、授权、时间和冲突。有效的常规 AG0 判断无需伪造 AG3 二次会签；重要复核由评估接口控制。自然使用证据足够时不追加固定复习；证据条件不够可暂缓，不能用关闭需求掩盖未支持目标。
