# AI 个人学习系统：工作包 5／C0 共同教学框架设计提示词

我正在建立一个面向个人长期使用、多 Agent 协作的 AI 学习系统。整体架构 v0、工作包 2／3 联合方案和工作包 4 方案已经形成；本轮进入阶段 C 的 **C0「共同教学框架」**。

请交付一份中文共同教学框架设计方案，回答：**怎样把近期学习的目标与判断、可用材料及其条件，组织为有明确意图、能实际执行、能依据表现调整的学习活动，并把执行结果交回原有依据体系？**

本轮设计课前准备、通用任务、交互与帮助、反馈、独立检查、调整、退出和交接的共同规则。Encoding、Post-Encoding 只作为共同规则未来的使用方；不编写二者的专项方案、子工作包提示词或角色提示词。无需重新交付架构 v0，也不执行旧提示词中的历史任务。

## 一、适用阶段、要求继承与输入状态

**适用阶段。**当前从阶段 B 的共同依据进入 C0。交付深度应足以指导后续教学设计和有限活动试用，不要求完整课程教案、逐轮脚本、技术实现或全量策略调度。

**要求继承。**延续原架构提示词中面向整套系统的目标、证据边界、用户控制、跨学科正确性、材料核验和高低层协作方向。旧提示词中的“本轮交付架构 v0”和架构阶段的细节限制，不替代本轮任务：本轮需要把共同教学判断设计得足够具体。共享规则集中维护；需要修订既有选择时，指出理由、受影响的产出和责任方，不能另建一套目标、掌握状态或验收标准。

**输入状态。**现有文档是可修订的设计基线，交接说明已经对齐接口含义；它们不是已经填好的真实课程目标、个人诊断或材料包，也未证明系统有效。目标、判据、证据条件、材料用途及责任边界作为当前起点；内部表单、状态名称和角色数量不冻结。真实课程、用户基础、帮助历史与预算未提供时保持未知，按其影响采用有限假设继续设计。只有缺失会阻碍关键取舍时才提出必要问题，不先做全面访谈。

## 三、已对齐的交接与责任

三类产出共同支持一次学习：

| 产出 | 向教学提供什么 | 决定由谁维护 |
|---|---|---|
| 近期内容展开单 | 近期目标与有效范围、起点理由、当前证据与未知、材料需求、不可代做工作、检查改道及返回条件 | 2 维护目标／判据，3 维护证据／判断；计划责任方汇总唯一当前展开单及有效范围 |
| 材料使用安排 | 具体内容和版本、用途与核验范围、当前入口、备用帮助、参考依据、潜在泄露与重选信号 | 4 维护材料内容、可靠性和用途限制 |
| 学习活动安排 | 将上述依据落实为任务、呈现、帮助、反馈、检查和调整分支 | 教学责任方维护关键教学设计，执行者在授权内适应；本轮设计其共同规范 |

这些是决定的归属，允许合并记录和实际角色。材料方可以指出完整例题会暴露解法；教学方决定何时展示；执行者记录实际暴露；3 解释由此产生的证据。教学执行发现前置缺口时，先保存表现和替代解释，3 维护诊断，2 维护前置关系，4 补足材料，必要的范围变化由计划方汇总。

当前展开单、材料安排和活动须在目标、判据、用途、预算及授权上相容。材料可用不自动意味着本轮采用，也不意味着已经展示。局部常规调整沿既有授权直接进行；关键依据失效时立即停止受影响部分，再由相应方更新，不等待所有文档同步。目标验收标准不能由执行者为适应表现或剩余时间而自行改低。

## 四、共同框架需要解决的教学问题

以下表达需要解决的事情，不规定章节数量、运行顺序、固定教学步骤或 Agent 划分。请围绕真正影响活动选择与证据解释的判断形成明确而可修订的方案。

### 1. 怎样把依据准备成一次可以开始的学习

说明教学方从展开单和材料安排中还需要作哪些判断，怎样确定本次可完成的目标工作、活动用途、起点和必要准备。区分必须具备的信息、可以带着未知开始的内容、需要限定或暂缓的用途。

材料与活动需要共同准备，不能互相等待完整成品。说明怎样以目标和展开单提出暂定活动意图、接收 4 的材料可行性和限制、调整活动或材料需求；已有材料也可先提供用途建议。应能在必要条件落实后结束准备，或将无法解决的缺项转为明确的替代／范围取舍。

准备程度以能够开展有依据的活动为准。说明何时直接阅读或示范、何时先尝试或短检查，何时请求补充材料，何时现有内容已经足够。诊断、练习与验收可以在一次互动中转换，但用途、帮助变化和证据限制应清楚。

### 2. 什么信息足以定义一个可执行的活动

设计一份轻量、可审查的共同活动规格，至少能看出：针对的目标和缺口、学习者必须完成的操作及产物、实际输入与任务、允许资源与帮助、反馈和评分依据、可能分支、当前退出与返回条件，以及执行者可调整的范围。

同一任务可兼有学习与检查用途，但要分别说明支持什么结论。解释如何检查题目是否真的调用目标操作、是否被题干或材料泄露、是否引入未声明前置，以及参考是否合格。将上游的验收要求落实为具体任务，保留原判据来源和版本，不用活动自身的完成率重定义目标。

任务可采用解释、推导、代码、图式转换、判断或案例分析等形式。选择由目标决定，不能把所有学习转成文字问答。可视化必须留下可观察的预测、解释、操作或转换工作；形式丰富或回答流畅不能代替目标表现。

### 3. 怎样安排输入、尝试、帮助和反馈

说明选择输入、示范、预测、尝试、提示、纠错、重做或减少帮助的依据，以及不同表现为什么会导致不同下一步。高能力 Agent 应在关键处给出足以落实意图的具体设计；执行者应保有合理的即时适应空间。

反馈需要对应可观察的问题及其可能原因：事实或答案、关系与步骤、条件与边界、方法选择、表征障碍或题目自身缺陷。不要从一次错误直接推定原因，也不要求每个错误都完成全套诊断。设计怎样取得能改变下一步的少量证据，怎样给出必要支持，并在缺乏进展时更换解释或安排。

区分计划可提供的帮助和实际提供的帮助。用户要求示范、直接解释或查看答案时，应能继续学习，同时保留初答、展示时点与此后表现的条件。帮助可以完成教学功能；后来隐藏答案、换题措辞或换 Agent 不能抹去既有暴露。

不设通用的“永远先问后讲”、固定输入输出比例、提示等级、轮数或连续答对阈值。若提出默认做法，交代适用条件、例外、代价和验证方式。

检查呈现本身是否改变帮助：增加标题、着色、步骤编号或折叠位置即使没有改写内容，也可能提示方法或暴露答案。意外提前展示按实际发生处理，不能沿用原来的独立检查解释。

### 4. 怎样把教学进展与能力证据接起来

设计从原始任务、作答和帮助时间线，到按既有判据进行常规评价、提交重要判断复核的路径。复用 3 的证据与更新规则，不在教学记录里另存一套互相竞争的掌握结论。

解释学习练习、帮助后修正、符合目标资源条件的独立检查分别能支持什么。独立指关键操作由学习者完成，不自动等于闭卷或禁用工具。目标要求新任务、延迟或特定情境时，相应证据仍需取得；目标未要求的部分不自动加入无限待检清单。

需要让执行者知道：什么时候当前活动可以收束；什么时候只是时间结束、证据不足、材料有疑误或用户暂停；哪些结论可按授权记录，哪些应交评估责任方。当前学习可以继续，而保持或更广范围能力仍为未知。

### 5. 怎样调整活动而不混淆修改权限

对关键调整说明触发信息、执行者可做的动作、需要返回的责任方及恢复条件。覆盖局部表达与支架、等价材料替换、临时补前置、任务变式、目标或判据变化、来源／评分争议和预算收缩。

局部修复保留父目标，补足后检验能否返回原来的关键工作；父任务已暴露答案时，采用符合所需证据条件的任务。修复后仍失败，应能重审诊断或综合要求，避免无限沿前置下钻。

内容出错时沿 4 的核验与回查路径处理；错误若进入目标或判据，交 2 重审，3 复核受影响判断，教学方修复已经造成的教学影响。原答足以重评时不默认重考；内容恢复可用也不自动恢复能力结论。高层暂不可用时，明确哪些已授权活动可以继续、哪些事项等待处理。

用户可以要求换方式、缩时、暂停、调整目标、质疑题目与评分或纠正记录。沿既有授权处理普通变化；超出授权的用途、承诺范围或投入变化交用户决定，并说明对未完成要求的影响。

### 6. 学习结束后交出什么，下一次怎样接着做

共同收束至少能交出：实际任务与关键产物、已观察表现及帮助条件、尚未支持的目标内要求、材料问题、父目标与恢复位置、停止原因、后续检查需求及接收方。

3 接收表现和证据，4 接收材料使用与纠错反馈，2 接收涉及目标／前置／判据的问题，计划方接收范围变化和后续需求并返回处理结果。提出检查需求不等于已经安排，更不等于相应目标已通过。中断恢复需确认当前有效依据、已发生的暴露和未完成位置，不能从旧摘要重新宣告独立性。

工作包 6 继续负责策略选择、组合、替换和退出的专项规则；C0 给出活动和反馈需要的共同约束，并可使用少量策略作为例子。7 负责全局日程与资源竞争；8 负责完整协作与共享记录实现。C0 应提供它们现在需要的输入与责任要求，不因后续尚未细化就留下无人处理的交接，也不在本轮展开其完整方案。

## 五、设计边界与交付期待

系统面向人工智能、数学、金融、政治等学科。共同框架共享活动和证据语义，保留学科的正确性要求：例如数学步骤与前提、代码和实验规格、模型假设与情境、事实与解释和价值判断。不要为每门学科复制一套框架，也不要用统一答案模板抹平差异。

保留项目研究的证据边界：两套证据分级各按原意使用；策略索引和矩阵不是效果排序或固定流程；一次成功不能证明长期掌握；行为变化不能证明特定神经机制；多个 Agent 同意不能替代内容核验。复杂协作和自适应安排的收益需要实际验证。

请用清楚而连贯的结构交付，形式可自行选择，至少提供：

1. **共同框架与关键取舍。**展示从依据准备、活动组织到执行反馈、判断回流和收束的关系；解释重要选择、替代方案、代价与未知。
2. **可使用的活动与交接规范。**提供轻量规格及一份具体填好的示例，能让执行者知道做什么、为何这样做、何时调整、哪些决定交回谁。信息可以合并，不为形式完整增加重复表单。
3. **调整和异常的责任规则。**明确材料、诊断、目标／判据和计划各由谁维护；普通调整、实质变化、暂停和恢复有可执行边界。
4. **少量有区分力的贯通检查。**至少一条完整的假设轨迹贯穿展开单、材料安排、活动、实际帮助、表现解释和回写；比较不同基础或不同表现如何改变活动。可合并覆盖解法暴露、疑似前置缺口、材料／评分错误、缩时和中断恢复，并用另一学科检查共同规则是否仍适用。展示关键活动即可，不扩写完整逐轮教案。
5. **当前通过标准与待验证项。**区分内容正确、教学意图落实、学习结果和协调成本。说明首期可怎样小规模检验、何种现象应促使简化，以及后续工作需要接收的具体事项；不把纸上走查当成真实效果证据。

建议将正式产出保存为 `AI个人学习系统_工作包5_C0共同教学框架_设计方案_v0.md`。需要改动既有上游约定时，明确提出具体修订及影响，避免静默覆盖责任边界。

完成时，应能从一个目标和一组材料看出：**为何安排这项活动、关键工作由谁完成、帮助怎样改变证据、什么表现促使下一步改变、哪些改变由谁决定、收束后哪些信息已被接收。**请在这些关键处深入，其余细节保留必要的设计自由度。
