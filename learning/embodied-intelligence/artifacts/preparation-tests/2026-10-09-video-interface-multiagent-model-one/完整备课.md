## 对此次重备课的直接约束

主要材料须明确“谁接收什么、结果是什么、目标为什么需要这一步”。视频消费者按组接收帧，逐帧消费者分别处理图片；两者是此题指定的输入契约，不以某种真实网络内部性质为通用定义。模型输入可以是已经整理的数据，不把“转布局”写成模型内部编码。

形状/轴语义、当前排列、数值表示、保留的信息、来源身份及恢复依据分别写清。逐帧处理不要求打乱；打乱不要求编码；编码可以丢信息而仍有来源；同一个特征值可来自多帧，来源不能从值自动反推。保序+分组结构和可信标签是可替代的对应依据，不要求两者同时存在。

连贯示范应沿一个有名称的帧从相机像素，到两输入组织，再到toy向量与序列位置，不只给相邻shape箭头。完整示范之后留给学习者的主要工作应是一个接口条件或中间连接，再逐步归入原整体说明；不要刚补术语就要求重建全链。可继续查示范，也可用文字；不为每条定义设置停点。

本次从**同一帧经过哪些对象、哪种改变发生在哪一步**开始。视频轴与已经正确的局部关系可直接引用，不重开从轴计数到帧号猜测的练习链。需要对象、接口和完整路线的可靠输入时直接提供，不等学习者再次答错才讲。

## 2. 学完要能完成的工作

单元终点仍是一份可交接的接口说明：同一相机数据怎样进入给定视频消费者和逐帧图像消费者；每个阶段读什么对象、采用什么轴、来源对应依据是什么；若逐帧输出还要组成特征序列，何时能恢复、何时需要另找依据、何时只能说明信息不足。

解释的关键是：形状合法不自动给出语义合法；组织改变、内容表示改变、来源可追溯和时间关系须分别核对。特征段作为原 R3 的自然接口用途与必要澄清，沿旧目标开展开卷解释；本稿不把新的教学网格内容升级成旧记录的新成绩标准。允许查表、看示范、用可靠文档及请求帮助；不要求闭卷、独立实现、安装 PyTorch、训练模型、延迟保持或远迁移。

本次完整材料是 [02-materials-demo.md](02-materials-demo.md)。继续原相机规格 `BTHWC=(2,4,2,2,3)`，八帧名称为甲0—甲3、乙0—乙3，零基索引；沿当前已给的 toy 编码，取每帧左上角 R/G、D=2。新材料显式给出完整2×2网格，左上角表标为切片；不把旧局部两帧示范替换为整个单元，也不增加新的空间扫描前置。

## 3. 必须直接给出的语义

| 对象/词语 | 本题中的完整够用含义 | 不得暗含的推断 |
|---|---|---|
| 帧 frame | 某视频段在一个选定采样位置的一张图片；含 H×W 个像素，每个像素有 C 个通道值 | 帧不是一个数、一个颜色、一个特征值；单帧没有自动包含其他时刻 |
| 视频段 clip | 同一来源的一组按采样时间顺序排列的帧；本题每段四帧 | 整段不必等于全部原始拍摄；四帧不证明等间隔采样，物理时长须另有时间信息 |
| 批 batch/B | 本次一起送入处理的两段视频；b 区分甲/乙 | 批不是一个时间过程；把两段放在同一批不使它们成为一条八帧视频 |
| 时间位置 T/t | 每段内帧的采样位置顺序；本题 t=0,1,2,3 | T 轴存在不证明已经学习/利用时间依赖；t 不是物理秒数 |
| 通道 C/c | 同一像素的测量分量；本题 c=0/1/2 分别 R/G/蓝 | 通道不指另一帧；C 不等于下游向量的 D，字母 B 与蓝通道需用文字分开 |
| 高/宽 H/W | 一张帧内的空间网格行/列；本题 H=2,W=2 | 取左上角只是切片，不代表其余空间位置不存在 |
| 轴 axis | 张量一个索引方向及它在当前契约中的对象意义 | “第几轴”与“什么意义”分开；相同轴长可能代表不同对象 |
| shape | 按当前轴次序排列的各轴长度元组 | 数字本身没有标出轴意义、数值对应、来源或运算历史 |
| 布局 layout | 本题指逻辑轴的顺序，例如 BTHWC、BCTHW | 不据此推出物理连续内存、stride 或 view/copy 行为 |
| flatten B/T | 在已知遍历次序下把相邻 B,T 两个索引编码为一行 n；本题 n=b×4+t | 合并是重新组织索引，不是时间混合/像素平均，也不等于打乱；n 轴不给消费者自动附上 B/T |
| 逐帧图像输入 | 一个 `[C,H,W]` 帧作为一件图像样本，N 行可一起算；本题 f 对每帧独立处理 | 逐帧不要求串行八次调用，也不要求打乱；并行批处理仍可独立逐帧 |
| 特征 feature/D | 本题规定 f 读取左上角 R/G，写成2个分量：R00,G00 | f 是可检查的玩具函数，不是已训练视觉网络；不能从示范推出一般特征D总等于2 |
| 特征序列 | 同一视频每帧的向量按 t 放在一起，`S[B,T,D]` | 把结果排成序列本身不等于进行了时序建模、动作识别或动力学学习 |
| 来源身份 | 一个结果由哪段视频的哪帧产生，常用 `(clip_id,t)` 或受信行映射表示 | 特征数值相同不意味着来源相同；向量内容不会自动附带元数据 |

“恢复”每次注明恢复什么。本单元恢复的是**向量的来源位置和序列组织**。原图能否从向量还原是另一问题：本题 f 丢弃左上角蓝值，以及其余三个空间位置的全部RGB；即使序列全部放对，也不能凭向量还原整张原帧。

## 4. 四条分别核对的维度

| 维度 | 在本题问什么 | 可用依据 |
|---|---|---|
| 数值/表示 | 现在是完整 RGB 像素张量还是2维特征；每个输出数从哪里取得 | 坐标对应及明示 f 定义 |
| 信息保留 | 给定输出及约定能否还原输入内容；哪些内容不进入 f | 是否可逆；同 R/G、不同蓝的两张合法图给出同 f 的反例 |
| 来源身份 | 当前这一行属于甲/乙的哪帧；来源对应是否仍可靠 | 已知且兑现的保序契约，或与结果绑定的可信来源记录 |
| 时间关系/组织 | 下游是否把同一段帧按 t 放在一起；是否实际进行跨帧处理 | 序列接口与映射；跨帧计算需另有消费者定义 |

这四项可以不同组合。像素轴重排改变索引表达而可保持全部像素值和角色对应；保序的 f 改变表示、丢弃上述图像内容，同时仍可保持来源；行打乱后若结果/来源记录一起移动，来源可追溯但当前行序不再是采样时间次序；标签缺失不证明内容变了，只限制来源恢复。不能用“元素变了/信息没变/身份没变”一句话替代四项说明。

## 5. 连贯认知主线

| 连接 | 核心输入与教师已做的工作 | 学习者实际承担的工作 | 核对与返回 |
|---|---|---|---|
| 现实对象→张量 | 给两段视频、八帧、完整网格及 B/T/H/W/C 对应；标切片 | 在使用整份材料时保持对象指称，不另考轴计数 | 术语可查；若混指，补当前对象后回路线 |
| 原张量→两类消费者 | 连贯给视频轴重排和逐帧合法合并；说明给定接口各读什么 | 旧已对的部分复用；在整体说明中连接输入/输出，不只报 shape | 接口契约与像素来源坐标一致 |
| 像素→保序特征 | 用同一完整帧算 f；八行输入/输出逐行对应，先完全不打乱 | 比较表示变化与来源保持各由哪项条件决定 | 按 f 丢蓝但保行来源；不凭“提取特征”自行猜身份 |
| 保序特征→同段序列 | 给模块 F 输出 A 的行结构和下游 S 接口；提供必要 B/T | 首个桥接仅续写 A→S 的条件和理由；视频段保留既有示范，不立即重建全链 | S[b,t,:]=A[4b+t,:] 的合法域明确，回同一接口说明 |
| 条件变化→选择恢复/拒用 | 同一特征内容，仅改变行顺序及来源记录条件；具体题面及教师参考另备 | 选择可用依据、修订同一接口段，或指出缺条件；不靠特征数值猜身份 | 可信标签须逐行绑定、覆盖且唯一；未知行映射不得默认 n=4b+t |
| 局部连接→整体交接 | 给一份接口说明容器和允许的格式 | 让两条消费者线路与 S 的来源条件连续成立，说明各阶段四项变化；接受合法等价路线 | 全部必要接口相容；不能数小题正确次数当整体充分 |

这条主线不是六道逐项验收题。教师输入可以连贯交出，纯讲解处不设等待。只有学习者需要贡献桥接、条件判断或整体作品时才等待；常规反馈直接接下一已备材料/作品段，不设置逐题“继续”开关。

## 6. 从示范到整体的梯度与跨度

第一层提供完整而可信的外部结构：对象定义、两消费者用途、像素到特征的连续轨迹、行来源的现成对应。此时不要求从空白构造框架。第二层只留下一个真正关键的桥接：若输出 A 的来源次序仍是甲0…甲3、乙0…乙3，怎样满足序列消费者；为什么原图内容不能完整还原，仍可追溯向量来源并恢复序列位置。第三层在同一来源数据上改变一项关键契约，让学习者修订刚接好的接口，处理可信映射与信息不足。最后保留一份连续说明，核两路线与所需条件是否一起成立。实际题面和逐段教师参考见 [04-work-and-reference.md](04-work-and-reference.md)。

## 7. 整体作品义务与合法多解

作品可用自然语言、带标签表、式子或流程；不规定字数、不强制构图或代码。它应让一个接手者检查这些实际内容：

- 相机 `X[B,T,H,W,C]=(2,4,2,2,3)` 到给定视频消费者 `V[B,C,T,H,W]=(2,3,4,2,2)`；`V[b,c,t,h,w]=X[b,t,h,w,c]`。
- 相机到图像消费者的输入 `J[N,C,H,W]=(8,3,2,2)`；按给定次序 `J[4b+t,c,h,w]=X[b,t,h,w,c]`。可先合 B/T 后排轴，也可先排轴后合 B/T，语义对应合法即可。
- 模块 F 的输出 `A[n,:]=f(J[n,:,:,:])`、`A=(8,2)`；明确 f 的内容与逐帧独立、输出来源对应。形状变为 `[N,D]` 不代表 D 是原 C/H/W 中的某一轴。
- 保序条件下进入 `S[B,T,D]=(2,4,2)`；行不保序时采用可信行→来源映射；缺映射时说明哪些结论未定。必要来源记录不是“更大的特征向量”。
- 数值/表示、信息、来源和时间组织各自能查；不由行数、一个像素或一个帧的位置正确推整批全部正确。

整体参考须接受排序、查表、逐位赋值等路线；不强求一种 API。特别是来源恢复使用标签并不使标签成为特征内容；顺序保留也不要求每帧带显式标签。

## 8. 必要支持、停止与审查边界

## 1. 学习者当前需要得到的语义

“视频”是一段连续拍摄的帧；“帧”是某一时刻的一张图像。“来源身份”回答这张图来自哪次片段、片段中的第几帧，例如甲2；“画面内容”回答画面出现什么。两次片段可能拍到同样画面，所以像素或特征相同也不能确定来自同一帧。

本例用很小的网格表达机器人夹爪移动方块。甲段从左上往右侧搬，乙段从右侧回左上。下列是教学构造 RGB 网格，不是照片、真实相机数据或机器人检测/训练实验。颜色只是帮助看到画面对象的位置，不是来源编号。

`B` 是一起提交的片段数；`T` 是每段帧数，`t` 是该段内的帧位置索引；`H/W` 是图像空间轴长度，`h/w` 定位具体行列；`C` 是通道数，`c` 定位 RGB 分量。本例固定 `c=0/1/2` 分别为 R/G/蓝，批次轴 B 与蓝色通道不同。形状只告诉每条轴有多少位置，还必须知道各轴代表什么。

相机按 `[B,T,H,W,C]` 放数据，`X.shape=(2,4,2,2,3)`。零基索引中 `b=0` 为甲段、`b=1` 为乙段；各段 `t=0,1,2,3`，不是秒数。`X[0,0,0,0,1]=20` 指甲0帧、第一行第一列的绿色值。

两个消费者是题目给定的接口，不能推广成所有视频或图像模型的要求：

- 视频消费者需要 `[B,C,T,H,W]`：同一片段的时间轴直接保留在输入中，供接收完整片段的模型使用。
- 逐帧编码模块需要 `[N,C,H,W]`：N条输入各是一张图；本例各自独立用同一个函数 f，每条输入输出一条 `[D]` 向量。逐帧处理可以完全保序。
- 后续序列消费者需要 `[B,T,D]`：每帧结果放回原片段和时间位置，让后续模型可以比较/联合使用多帧。组织成这种形状只使接口与顺序相容，不证明模型已经会识别动作或做机器人决策。

“恢复来源”是把一个结果放回甲2位置；“恢复 RGB”是重建原图全部 RGB 数值。前者可以成立而后者不成立。

## 2. 完整实际输入：八帧、每帧四个位置

每格是 `(R,G,蓝)`。背景 `(2,3,5)`、方块 `(80,20,10)`、夹爪 `(10,70,90)`；这些数值没有夹带片段号或帧号。允许的通道值域为整数 `0..255`。每帧4个像素、12个通道标量；八帧共32个像素、96个通道标量。f输出共16个特征分量。

| 来源（旁路元数据） | 上行 h=0：左/右 | 下行 h=1：左/右 | 给定的场景说明 |
|---|---|---|---|
| 甲0 `(0,0)` | `(80,20,10) (2,3,5)` | `(10,70,90) (2,3,5)` | 方块左上，夹爪左下 |
| 甲1 `(0,1)` | `(80,20,10) (10,70,90)` | `(2,3,5) (2,3,5)` | 方块仍左上，夹爪到右上 |
| 甲2 `(0,2)` | `(2,3,5) (80,20,10)` | `(2,3,5) (10,70,90)` | 方块到右上，夹爪右下 |
| 甲3 `(0,3)` | `(2,3,5) (2,3,5)` | `(10,70,90) (80,20,10)` | 方块到右下，夹爪左下 |
| 乙0 `(1,0)` | `(2,3,5) (2,3,5)` | `(10,70,90) (80,20,10)` | 乙段从右下开始 |
| 乙1 `(1,1)` | `(10,70,90) (2,3,5)` | `(2,3,5) (80,20,10)` | 夹爪到左上，方块仍右下 |
| 乙2 `(1,2)` | `(2,3,5) (80,20,10)` | `(2,3,5) (10,70,90)` | 方块到右上，夹爪右下 |
| 乙3 `(1,3)` | `(80,20,10) (2,3,5)` | `(10,70,90) (2,3,5)` | 方块到左上，夹爪左下 |

旁路元数据意味着来源身份和图像数组一同管理，身份不藏在颜色数值里。甲2与乙2画面相同，甲0与乙3也相同；它们仍是不同片段中的不同帧。

## 3. 连贯示范：相机 → 两个消费者 → 特征序列

### 3.1 视频线：换轴位置，保持每个像素对应

从原轴 `[B0,T1,H2,W3,C4]` 排成 `[B,C,T,H,W]`，新轴来自原轴 `(0,4,1,2,3)`，结果 `V.shape=(2,3,4,2,2)`。

全部像素必须满足：`V[b,c,t,h,w]=X[b,t,h,w,c]`。

甲0左上绿色由 `X[0,0,0,0,1]=20` 变成 `V[0,1,0,0,0]=20`。变化的是索引表达；它仍属于甲0、绿色、左上位置。每段 `t=0→1→2→3` 的先后没有改变。

把 X 直接 reshape 为同样的 `(2,3,4,2,2)` 并不承担这种换轴。在本例，该绿色位置实际得到 `70` 而不是 `20`，它错拿了甲1右上绿色。轴重排的官方接口是 [torch.permute](https://docs.pytorch.org/docs/2.14/generated/torch.permute.html)，等元素数的新形状接口是 [torch.reshape](https://docs.pytorch.org/docs/2.14/generated/torch.reshape.html)；它们解决不同的操作。

### 3.2 逐帧线第一步：换轴并合法合并 B/T

先把 X 轴排为 `[B,T,C,H,W]`，来自原轴 `(0,1,4,2,3)`，得到 `(2,4,3,2,2)`。再合并相邻 B/T：`N=B*T=8`，行按 `n=4*b+t` 排，得到 `J.shape=(8,3,2,2)`。

全部像素对应：`J[4*b+t,c,h,w]=X[b,t,h,w,c]`。

| 行 n | 原帧 | 逆定位 b=n//4,t=n%4 |
|---|---|---|
| 0 | 甲0 | `(0,0)` |
| 1 | 甲1 | `(0,1)` |
| 2 | 甲2 | `(0,2)` |
| 3 | 甲3 | `(0,3)` |
| 4 | 乙0 | `(1,0)` |
| 5 | 乙1 | `(1,1)` |
| 6 | 乙2 | `(1,2)` |
| 7 | 乙3 | `(1,3)` |

`J[6,1,0,1]=20` 仍是乙2右上绿色。合并 B/T 没改 RGB 数值、空间对应或行次序。在已知 B=2/T=4、原批次身份与这条行规则时，可以还原分组；如果这些条件丢失，N=8本身不能说明原来是两段四帧还是四段两帧。

### 3.3 逐帧线第二步：同一个 f 产生一条帧向量

本 toy 函数 f 只取每帧左上角的 R/G：`f(图像)=[R00,G00]`，`D=2`；代码原件中名称为 `encode_left_rg`。每帧其他三个位置的全部 RGB 和左上蓝值都没有进入输出。d0/d1是本例定义的内容坐标；真实神经网络特征坐标未必对应单一颜色或像素。

本示范明确承诺：每条输入一条输出，输出与输入行对应，同一个 f、同一个特征定义，不重排、不删行、不聚合不同帧。这些是题目条件，不能仅凭现实模型的 shape 假定。

`A[n,d]=f(J[n])[d]`，`A.shape=(8,2)`。

| 保序输出行 | 原帧 | 左上原 RGB | 完整 f 输出 |
|---|---|---|---|
| A0 | 甲0 | `(80,20,10)` | `[80,20]` |
| A1 | 甲1 | `(80,20,10)` | `[80,20]` |
| A2 | 甲2 | `(2,3,5)` | `[2,3]` |
| A3 | 甲3 | `(2,3,5)` | `[2,3]` |
| A4 | 乙0 | `(2,3,5)` | `[2,3]` |
| A5 | 乙1 | `(10,70,90)` | `[10,70]` |
| A6 | 乙2 | `(2,3,5)` | `[2,3]` |
| A7 | 乙3 | `(80,20,10)` | `[80,20]` |

甲0与甲1夹爪的位置不同，但 f 输出相同，因为 f 没有看那些位置。特征向量是函数结果，不能凭 `[80,20]` 自动判它来自甲0、甲1或乙3。

这里“编码后数值有没有变化”要说清比较什么。被选出的左上 R/G 值没有做算术变化；每帧的表示从12个RGB数变成2个数，完整图像信息减少。一般编码器可以计算新数值，其信息保留性质也依具体函数，不能由本 toy 推广。逐帧说的是处理单位，既不表示打乱，也不承诺信息不变。

### 3.4 保序结果回到 `[B,T,D]`

因为原输入 `n=4*b+t`、输出逐行保序、每帧一行，而且片段身份、B/T和d定义已知：

`S[b,t,d]=A[4*b+t,d]`，`S.shape=(2,4,2)`。

完整结果为：

- 甲段 `S[0]=[[80,20],[80,20],[2,3],[2,3]]`，来自甲0→甲1→甲2→甲3。
- 乙段 `S[1]=[[2,3],[10,70],[2,3],[80,20]]`，来自乙0→乙1→乙2→乙3。

例如 `S[1,2]=A6=[2,3]` 来自乙2，`S[1,2,1]=3` 来自乙2左上绿色。这一整理只重新组织16个特征数，没有执行第二次 f，也没有补回未进入 f 的像素。S可以把乙2放对时间位置，仍不能从 `[2,3]` 重建乙2完整 RGB。后续模型能否正确使用序列尚未检验。

## 4. 同一 f 改处理队列：可信标签是另一条恢复依据

打乱是额外调度变化，独立于逐帧函数。若为并行或调度采用下列处理/返回队列 Q，每个输出仍要和它所来自的输入帧绑定。给定的标签由相机原批次产生并随帧/结果同行传递。j是当前队列行，不是原帧号。

| 当前输出行 j | 真实原标签 `(b,t)` | 完整向量 Q[j] | 应放回 S 的位置 |
|---|---|---|---|
| 0 | `(1,2)` 乙2 | `[2,3]` | `S[1,2]` |
| 1 | `(0,0)` 甲0 | `[80,20]` | `S[0,0]` |
| 2 | `(1,0)` 乙0 | `[2,3]` | `S[1,0]` |
| 3 | `(0,3)` 甲3 | `[2,3]` | `S[0,3]` |
| 4 | `(0,1)` 甲1 | `[80,20]` | `S[0,1]` |
| 5 | `(1,3)` 乙3 | `[80,20]` | `S[1,3]` |
| 6 | `(0,2)` 甲2 | `[2,3]` | `S[0,2]` |
| 7 | `(1,1)` 乙1 | `[10,70]` | `S[1,1]` |

恢复操作是按每行真实 `(b,t)`，把整条 `[D]` 向量放入对应 `S[b,t]`，最终与第3.4节相同。直接把当前八行 reshape 为两段四帧，会把 j0=乙2当成甲0；shape依然吻合，但来源对应违例。真实调度的逆置换已知时也能恢复，不必强制字符串标签。

充分条件须整体成立：预期原帧集合及片段/时间含义已知；每个原帧恰有一条有效结果；结果与原帧身份可追溯绑定；标签/已知置换真实、有效、完整覆盖且无重复；本题还固定同一 f 和 d含义。标签在文本上长得像 `(b,t)` 并不能证明它真实。

## 5. 信息不足、违例与不可逆：教师参考边界

| 给定条件 | 可以作出的结论 | 不得补造的条件 |
|---|---|---|
| 仅 Q.shape=(8,2)，要恢复 (2,4,2) | 容量相容，来源与先后未定 | 不能默认 n=4b+t、输出保序或未混入别批 |
| 输入行规则、输出逐行保序、每帧一行，B/T与身份已知 | 可按规则恢复来源分组/时间 | 不证明可以恢复被 f 丢掉的 RGB |
| 顺序已变，但真实标签或置换已知且逐结果绑定 | 可按标签/逆置换恢复 | 不能依特征数值识别甲/乙来源 |
| 顺序已变，没有真实标签或已知置换 | 题目不能唯一确定原身份 | 重编 j//4,j%4不是获得原标签 |
| 标签重复、漏帧或越界 | 当前整批恢复规格不成立，须定位问题 | 不能默填八帧或任意挑一条覆盖 |
| 标签恰好全覆盖，但两条真实身份被互换 | 内部格式检查可通过，恢复仍可能错 | 不从覆盖/唯一性推出标签真实 |

不可逆反例只改甲0左上蓝值：原 `X[0,0,0,0,2]=10`；另一个合法输入 `X′[0,0,0,0,2]=11`，其余95个数不变。RGB不同，全部 f 输出仍相同，因为 f 没取该蓝值。这一对合法输入足以证明本 f 在允许 RGB 域上非单射，不能仅凭 A唯一恢复完整RGB。反例展示左上蓝这一类损失；全部遗漏范围由 f定义确定，还包括其他三个位置的全部RGB。它没有证明所有编码器都会丢信息，也没有证明轴数减少必然丢信息。

第3.2节把五轴整理成四轴，96个数仍全在，已知映射可逆。第3.3节的信息减少来自具体 f。整理成三轴 `[B,T,D]` 可以恢复来源位置，却不把遗漏像素补回来。三种结论分别由索引映射、函数反例和元数据条件支持。

| 环节 | 本例 shape | 轴/位置变化 | 数值与内容 | 来源依据 |
|---|---|---|---|---|
| 相机 X | BTHWC `(2,4,2,2,3)` | B/T/H/W/C各自定义给定 | 96个RGB数 | 原批次与帧序 |
| 视频 V | BCTHW `(2,3,4,2,2)` | C移至T之前；B/T/H/W仍对应原对象 | 96个数全保留，空间/通道/帧对应不变 | `V[b,c,t,h,w]=X[b,t,h,w,c]` |

| 特征 A | ND `(8,2)` | 每帧只取左上R/G为d0/d1，N与源行绑定 | 16个左上RG数保留，其他像素不保留 | 输出与输入行对应/真实标签 |

张量轴数、每轴长度和每个数的语义须分开：D=2是向量长度；A的张量轴数也是2（N,D），本例数字巧合相等，含义仍不同。布局相容、来源恢复、信号可逆和后续模型效果也分别判断。

## 1. 本题工作与方法取舍

当前需要处理的是：帧/视频段/消费者指称；像素布局变化到逐帧特征生成的连续接口；来源身份与内容表示/信息保留分开；在不同来源记录条件下决定是否可恢复序列。真实末修订已提供混绑的依据，可靠输入是必要工作，不再用重复猜帧号定位同一困难。

Encoding 采用直接语义输入＋S05 连贯范例＋S09 接口组装。Post 采用 retrieve-relation 的开卷桥接/整体协调、select-method 的当前条件选择与拒用、conditional-update 的保留旧合法域的修订。功能分工决定顺序，它们不是五次独立活动，更不是一份“按顺序完成五张卡”的作业清单。

## 3. Encoding：真正交付的讲授与示范

### E1 对象与路线语义

直接使用01的必要语义及02的实际图片网格。讲清一帧含四个像素，每个像素RGB三数；两段各四帧；一次输入两段是 B=2；t 是段内时间位置。给视频模块与帧模块的合同，说明前者输入保留“段内时间轴”，后者把一帧作为一件图像处理，帧结果再去序列消费者。

教师不是让学习者猜“视频输入意味着什么”。三条箭头的现实用途先讲全：整段视频进视频模块；每帧图像进 f；按时间组织向量进 S。D 是 f 输出分量，不自动等同一个像素的 C，也不与 B/T 身份记录合并成一个维度。

### E2 带不变量的连贯范例

02按同一八帧数据从 X 追踪到 V/J，再从 J 到 A，首次轨迹全程保序。示范必须同时有实际值、语义对象、尺寸和对应规则：X 的左上切片不是整图，完整2×2网格仍存在；轴重排/合法 B/T 合并没有修改原像素值；f 只留下左上 R/G。A 的每行仍对应原提交的一帧，这份对应由输入输出合同保持，不依赖是否可从向量还原图像。

主示范的甲0/甲1都输出 `[80,20]`，但完整图的夹爪位置不同。这是合法的“同特征、异图像内容/异来源”对照：f 没有读取其他位置，所以它们相同不表示原帧相同。另可用左上蓝10→11而 R/G不改的碰撞，清楚证明 f非单射；这只是具体反例，不把全部信息损失范围缩成蓝色。实际损失包括左上蓝，以及其余三个位置的全部RGB。

此 toy f 中保留的 R/G 数值并未重新计算，**表示和可还原内容仍改变**。一般编码函数可重新计算数值，可损失信息；不能由这个玩具推出所有特征生成都取两个颜色，也不说所有编码必损。帧来源保持、原图可还原与时序计算分别核。

### E3 只留一处桥，再返回整体

直接使用04“先接一处”的真实题面。示范后首个学习者工作是续写 A→S 一条连接：八行怎样组织成两段各四帧、根据哪条合同知道来源、为什么内容损失不阻碍这份对应。已给视频线和逐帧像素线可以引用，不要求立即从空白重写全链。

桥接够用后沿同一接口说明补成04“工作一”，核完整两路线与信息/来源条件。S09的增量是**检查前一接口输出是否满足后一接口合同**，不是多看两张局部表。理论对象、数组表示和题面用途用同一 X/J/A/S 对齐，不增加代码独立实现或训练前置。

如果学习者已有连续完整说明，直接复用；只缺一个词就提供对应，继续原剩余工作。完整讲解后的复述只支持已给输入下追踪，不能倒记自主构造。

## 4. Post：沿同一作品开展三种工作

### P1 关系桥接与整体协调

恢复对象是当前接口前提、来源约定和一份说明中的位置；这些可从允许材料获得，不安排闭卷名称回忆。学习者将 f输出和 S输入接通，再把两条像素路线与这条特征路线连成同一作品。参考见04先接一处/工作一。正确性锚点是全链对象对应与消费者约束，不能用若干局部 shape 正确代替。

学习者只忘记 `n=4b+t`，允许直接查或给此式；随后形成的接口理由保留，公式恢复不倒算成功。前提已经可用仍混淆“来源恢复=原图还原”，直接重建这一最小关系再回 A→S；不重考整章术语。

### P2 条件选择、拒用和信息不足

04“工作二”给 Q shape `(8,2)` 和两段各四帧都已处理这一事实，同时不给可信逐行来源与保序合同。学生修改原说明“恢复条件”栏：能容纳八条向量，与能合法组成 S 是两件事；内容值能否识别来源必须有可靠约定，不能默认特征唯一。

任务不题名为“必须按标签重排练习”，也不把 method名作为答案发给学习者；允许说信息不足、要求补关联、列多种可能。当前正向示范已讲来源路径，成功只说明在这组候选与实际输入条件下正确选用/拒用。不是远迁移或广泛自发选择的观察。

新增的认知工作是**原来的合法桥接在什么条件下还能用**，不是改几行数字再重复应用公式。原 B/T/D 都保持；变化的是返回行序及可信映射是否可得，因此不从失败直接诊断算术/编码函数不懂。

### P3 新依据更新与旧合法域保留

04“工作三”补交经核对的逐行 `(b,t)` 来源标识，每行随实际输入和结果共同移动，八个位置完整、唯一；学生只修订受影响段。可采用散射、排序/查找或先恢复行序再合法 reshape，参考覆盖全部八行。

## 共同输入与产物

同一个相机输入 `X`，布局 `[B,T,H,W,C]`，shape `(2,4,2,2,3)`：两段视频，每段四帧；每帧 2 行×2 列，RGB 三通道。保持原单元规格，不把教师构造的网格当真实相机采集。`b,t,h,w,c` 都从 0 编号；甲为 b=0，乙为 b=1。t 表示各自视频内的时间次序；本题同一段内没有缺帧，没有跨视频统一时间轴的约定。

两个接收模块的合同已给定：

- 模块 V 接收 `[B,C,T,H,W]`，要保留视频分组及每段帧次序。
- 模块 F 每次接收 `[N,C,H,W]` 中的一张帧图；对每个输入帧输出一条向量，与该输入行一一关联。沿用当前教学函数：只取每帧左上角 R、G，`D=2`；左上角蓝色和其余三个位置的全部 RGB 都不进入输出。它只用于明确接口和信息边界；不是已训练的视觉网络。
- 后续模块 S 接收 `[B,T,D]`，第 `(b,t)` 个向量必须来自该段的第 t 帧。它需要时间有序的特征，不能因为形状吻合就把任意队列当视频。

唯一学习者产物是一份“相机→V／F→S 的接口说明”。可以用箭头、表、自然语言或索引公式；不规定措辞和字数，也不用另画一份图交第二次作业。每个环节写输入、输出、对应依据，以及它能保证什么。已给的 shape 可以直接引用；剩余工作是把关系连起来、说明条件、判断可行性。

我们接着处理视频接口里尚未接好的部分：一张张图片变成特征以后，怎样组成每段视频的有序序列。最终仍是一份“相机到两个接收模块”的接口说明；先接这一段，不必从头重写，也不需要运行代码。你可以看表、查资料或请求示范，随时停下。

先把对象说清楚。一段视频是同一次过程按时间拍出的多张图片，一张图片叫一帧。这里有甲、乙两段，每段四帧；甲0是甲的第一张，甲1是第二张，依此类推。每张图片有2行、2列，每个像素有红、绿、蓝三个数。

“输入”就是交给某个模块的那份数据。“接口”规定它要怎样收这些数据。我们给定两种接收合同：

- 视频模块 V 要把同一段的四帧作为一组接收；它的输入是 `[B,C,T,H,W]`。
- 帧模块 F 接收 `[N,C,H,W]` 中的一张张图片，每张输出一个向量；随后 S 要把这些向量按视频归组、按时间排列。

两路都从同一个相机输入出发。V的合同保留帧组；F先逐张处理。**逐帧不要求打乱图片，输出也可以始终保持原顺序。**

符号只是在说明每条轴的用途：B是有几段视频，T是每段几帧，H/W是图片行/列，C是颜色通道。把B和T暂时合在一起后，N=8表示八张帧图；它不表示八段视频。D表示每张图的输出向量有几个分量。`shape`只给尺寸，必须和这些轴义一起读。

整条路径可以先这样看：

```text
相机 X：[B,T,H,W,C] = (2,4,2,2,3)
├─ 调整轴位置 → V：[B,C,T,H,W] = (2,3,4,2,2)
└─ 调整轴位置，八张图片各占一行
       → F输入：[N,C,H,W] = (8,3,2,2)
       → F每张图输出两个数：[N,D] = (8,2)
       → S需要两组各四个有序向量：[B,T,D] = (2,4,2)
```

先调整布局、合并B/T时，没有改动原像素值。八行按甲0、甲1、甲2、甲3、乙0、乙1、乙2、乙3排列，帧的归属和次序仍可沿这个规则追溯。

现在具体看F做了什么。我们沿用示范函数：**只取每张图左上角的红、绿值，组成两个数的向量。**它不取左上角蓝色，也不取另外三个像素位置的任何颜色。

下面是教学构造的两张2×2图片，每格写 `[红,绿,蓝]`：

| 甲0的像素 | 左列 | 右列 |
|---|---|---|
| 上行 | `[80,20,10]` 方块 | `[2,3,5]` 背景 |
| 下行 | `[10,70,90]` 夹爪 | `[2,3,5]` 背景 |

| 甲1的像素 | 左列 | 右列 |
|---|---|---|
| 上行 | `[80,20,10]` 方块 | `[10,70,90]` 夹爪 |
| 下行 | `[2,3,5]` 背景 | `[2,3,5]` 背景 |

甲0先处理，得到 `[80,20]`；甲1接着处理，也得到 `[80,20]`。顺序没打乱，保留的这两个数也没重新计算；但图片已经变成向量，夹爪位置等内容没有进入输出。两张不同图片得到相同向量，说明它没有保存完整画面。

来源另有依据：我们知道第0个输出与输入甲0对应，第1个输出与甲1对应。**向量数值相同，不妨碍这份处理记录说明它们来自不同帧。**我们是沿输入输出关联认来源，并没有用两个数猜“它是哪张图片”。

把这几件事分开：布局调整改变轴的组织；特征函数改变表示和留下的内容；帧归属靠顺序或可信记录保持；时间序列则要求把对应同一段的结果放回正确时间位置。这四项不能由一个shape共同保证。

现在只接原说明中的一个箭头：**F的八行输出怎样进入S的两条四帧序列？**已知F每帧恰好输出一行，输出与输入同序，八行仍来自甲0—甲3、乙0—乙3。请用帧名字或已给尺寸说明怎么放、凭什么能放；再说说没有保留完整图片，为什么仍能知道向量来自哪帧。可以只写这一段，卡住的地方直接标出来。

提交后若还在等待，可圈出自己说明里最不确定的条件；做完即可停，回复到达后回到这里。
