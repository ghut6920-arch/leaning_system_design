# AI 个人学习系统：工作包 5／Post-Encoding 顶层设计分析

日期：2026-09-29  
定位：为下一轮专项设计澄清问题、依据与取舍，配套一份开放式设计提示词。本文提出的组织视角是可讨论的建议，不是已经确定的 Post-Encoding 方案，也不冻结它与 C0、Encoding 的具体接口。

**核心判断：Post-Encoding 应围绕知识在后续使用中需要发生的变化展开——能否恢复、是否准确、能否区分和组织、能否选用，以及这些表现能否跨时间成立。检索、比较、解释、更新和应用是实现这些变化的候选操作。顶层设计的重点，是让操作选择、学习者实际工作与后续证据形成有理由的联系。**

## 二、这一专项真正需要增加什么

### 1. 在共同框架之上增加内容与时间上的教学判断

C0 已经处理怎样组织活动、保留原答、提供帮助、反馈、评价、停止和交接。2／3 已经处理目标、证据与判断，4 已经处理内容和材料。Post-Encoding 若再次从头设计这些能力，会扩大维护成本，并产生同一表现被不同模块赋予不同含义的问题。

它需要补出的专项价值更具体：

- 当前真正需要恢复的是哪些内容：名称、命题、关系、条件、程序、源例，还是整体论证中的关键连接。
- 当前是否需要恢复，以及是否还需要比较、分化、解释、更新、抽象或应用；这些工作分别针对什么尚未满足的要求。
- 新表现说明了什么，哪些替代解释仍然存在，下一项活动为什么值得做。
- 什么变化需要跨延迟、线索或情境再次观察，结果应怎样影响后续教学需求。

这些是设计问题，不要求各自成为一个模块。其价值应体现在同样“答对”或“答错”之后，系统能给出更合适的下一步，而非增加更多术语。

依据：架构第二、三节；C0 第四至八、十二节；Encoding 第一、八节；路线工作包 5。

### 2. Post-Encoding 是工作视角，不是不可返回的学习阶段

“初学结束后开始复习”方便描述时间，却不足以划分教学职责。同一次会话可能先恢复旧知识，再发现需要重建一段关系；一次初学也可能大量调用既有知识。

Encoding 已明确按“当前需要恢复，还是建立／修订什么”划分工作，而不是按首次或再次接触划分。后续设计可以进一步解释二者如何连续协作，但本次不需要预定统一的入口门槛、转接协议或返回阈值。

需要保留的认识是：**一次恢复失败不等于整个知识结构失效；一次重新讲解成功也不自动补足独立恢复和延迟保持的证据。**局部能力可以仍然成立，目标内的另一项要求也可以仍未支持。

依据：Encoding 第七节情境 D、第八节；PE §3.2、§7.3。

## 三、以什么作为顶层设计的组织中心

### 1. 较有解释力的候选中心：目标所需变化及其证据

相比直接以“检索策略清单”组织系统，围绕“这次希望知识的可用性发生什么变化”更容易连接前序方案。例如，同样围绕加权平均：

| 当前目标或表现 | 值得设计的工作 | 后续需要区分的证据 |
|---|---|---|
| 需要独立恢复计算关系，但暂时想不起 | 恢复入口、必要内容及其使用 | 无提示恢复与提供前提后的推理分别怎样 |
| 会写公式，却把两个组均值直接平均 | 权重、总量与数量之间的关系及适用条件 | 组规模改变时，是否仍能作出合法判断 |
| 会处理明示“加权平均”的题 | 在混合案例中辨认是否需要按权重组合 | 没有方法名提示时能否选择，提示后是否只剩执行 |
| 原题熟练，但换表达就失败 | 表征转换、线索依赖或额外前置的辨别 | 失败由哪项条件改变引起，是否需要重新教学 |
| 延迟后仍能可靠完成目标工作 | 可能直接补足所需证据并结束本次活动 | 是否确有目标内的其他缺口，而非自动追加更难题 |

表中是设计推演，不是诊断规则或真实用户表现。同一现象可能有多个原因，实际任务及判据仍由具体目标决定。

这个组织视角也不意味着系统要直接测量大脑中的知识状态。它关注可观察表现以及对表现的有限解释，让后续设计模型自行选择最合适的概念结构。

### 2. 研究中的八维状态是分析视角，不是八项必填评分

PE §3.1 提出 Accessibility、Fidelity、Stability、Relational structure、Differentiation、Abstraction/schema、Conditionalization、Context/source binding。它们帮助发现“记得住”和“用得对”之间的差异，但报告明确说明：模型尚未经整体拟合验证，维度不独立，测量也不一一对应。

因此，顶层设计可以借它们审查遗漏，却不宜直接要求每个知识点都维护八个分数。一个事实目标可能只需要可靠恢复及准确性；一个综合目标则可能需要关系、条件、来源与跨时间证据。是否拆分，取决于这种区分会不会改变教学或判断。

还应区分三个对象：学科内容中哪些关系成立；学习者在具体条件下实际做了什么；系统据此提出了怎样的解释。外部知识图谱、学习者画出的图和关于学习者的诊断不能互相替代。这个区分已存在于 Encoding 与 2／3，无需另建一套。

### 3. 七类检索和七类整合不能机械配成软件结构

矩阵的行是任务类型，列是目标方向，◎／○表示匹配关系。它们既不是效应量，也不是互斥分类。例如解释一道新题，可能同时恢复事实、关系与条件，并包含生成和应用。

矩阵与状态向量的层级也不完全相同：Transfer 更接近多个能力在新任务中的联合表现，不宜把它简单当作与八维并列的又一个可直接读取的状态槽。快速矩阵没有覆盖的忠实性、稳定性和来源等问题，在完整报告中仍然重要。

矩阵最有用的转译是帮助说明：**实际恢复了什么，对这些内容做了什么，反馈提供了什么，以及据何种后续表现判断其价值。**这是一种审查活动的视角，不是要求每次都依序完成四个环节。

依据：PE §3—5、§12—13；矩阵开头读法及“六种组合如何判断”。

## 四、关系整合应当包含连接、区分和有条件的更新

### 1. 连接更多并不必然学得更好

整合可能体现为建立桥接关系、识别因果与层级、抽取跨实例结构，也可能体现为把相似概念分开、给不同版本保留适用情境。后一类工作对长期学习尤其重要：知识体系越丰富，选择错误关系和混用条件的机会也越多。

设计需要能够处理“哪些内容应联系”和“哪些内容必须保持区别”这两类问题。若只要求生成更多联想、更完整的概念图或更流畅的解释，可能奖励错误绑定和事后合理化。

对于因果与开放问题，生成一个可行解释不等于恢复已知事实。学习者提出的假设可以很有价值，但应保留它与材料陈述、经验证结论的区别。

依据：PE §4、§7.2、§13.1；矩阵“三个使用边界”。

### 2. 高理论上限可以延续，但不能变成每项内容的必修深度

Encoding 已明确系统可以支持严密证明、复杂机制、跨层推演和方法构造。Post-Encoding 也应能承接这些目标：后续学习不应只能背定义、重复例题。

例如，数学目标可能要求重新构造论证、识别关键假设并处理条件变化；代码目标可能要求自主选用方法、实现和验证；理论目标可能要求在竞争解释之间作出有依据的判断。复杂度应来自原目标与内容，而不是来自回答字数、题目数量或“高级检索”标签。

与此同时，恢复证明不一定意味着逐字记忆既有证明。若目标允许重建论证，合法的另一条证明也可支持能力判断。恢复知识、现场重建与借助允许资源解决问题，应依目标分别解释。

本次建议后续模型思考如何让简单目标轻量完成、复杂目标充分展开。无需现在确定深度等级、策略配方或逐级升级规则。

### 3. 更新要识别新旧知识为何不同

遇到新信息时，可能需要纠正事实，修补关系，收窄适用条件，或保留不同情境下都有效的版本。不能把所有变化都表述为“覆盖旧知识”。

后续设计值得回答：何种证据支持新答案可靠可用；旧错误是否会换线索后再次出现；仍然正确的旧知识是否被误删；看似模型重构的表现是否只是背会了一个反例。

这些问题支持持久更新的设计，却不要求系统为每个目标建立复杂的版本网络，更不证明神经痕迹已经被擦除。

依据：PE §7.3、§8、§10.3、§13.1；路线第六节。

## 五、动态选择的关键在于区分值得采取的不同行动

### 1. 观察到的失败只能缩小解释范围

| 可观察表现 | 需要保留的解释 | 对活动设计的启发 |
|---|---|---|
| 无提示失败，给出内容后能够推理 | 访问困难、原线索不合适、部分知识不稳等 | 可以保留推理表现，另看目标是否要求独立恢复 |
| 提供必要前提后仍不能建立关系 | 关系缺口，也可能是表达、工具或任务理解负担 | 局部重建值得考虑，但先排除任务本身的问题 |
| 给出方法名后会做，自己不会选 | 条件识别、检索入口或跨表征映射尚不可靠 | 将方法选择与执行分别观察，不把后者补记为前者 |
| 当时纠正，后来又出现旧答案 | 更新不稳、情境混淆、竞争、后续输入等 | 检查旧答案出现的条件，而非只重复一次正确答案 |
| 答对但理由错误 | 偶合、猜测、规则误用，或理由表达有误 | 选择能区分解释的证据，不直接升级掌握结论 |

这些分支的意义在于改变下一步；如果不同解释都指向同一项必要帮助，就未必值得先追加一串诊断。C0 已提供停止无效诊断与局部返回的共同原则，Post-Encoding 只需把它落实到具体内容问题。

### 2. 操作顺序应允许由条件决定

PE 对“先检索再生成”的证据给出混合结果；部分解释反馈研究也未发现必须先自主作答才有收益。比较任务若缺少一侧前提，先补输入可能比继续追问更可执行；已有前提可用时，检索又可能帮助暴露缺口并准备后续加工。

因此，合理设计应解释为什么选当前操作、预期增加哪项有效工作，以及何时换路。单项恢复可以独立有价值，开卷比较也可以有价值，检索与整合的组合并不天然更优。

这同时构成与工作包 6 的分界：本专项需要说清代表性活动为何适用、怎样动态转接；全策略库的选择、组合与优化规则仍可由后续工作集中设计。边界不能成为只写“调用策略”的理由。

依据：PE §8.2—8.3、§9；路线 P4 与工作包 6；C0 第五节。

### 3. 反馈的深度由错误层级与目标决定

简单事实错误可以需要一个可靠纠正；边界误用需要诊断性条件；方法选择错误需要看清为什么该方法适用或不适用；模型冲突可能需要比较预测与证据。

反馈之后是否有变化，要看学习者能否使用所给信息完成目标相关工作。不能用 AI 解释的完整度替代学习者的变化，也不必对每个错误都安排反例、长篇自我解释和延迟测验。

高置信错误、低置信正确等现象可以帮助选择反馈，但置信度本身不是掌握指标，也不支持把所有学习者分成固定处理类型。

依据：PE §7.3、§8；C0 第五节。

## 六、时间是证据条件和教学变量，不是自动完成机制

Post-Encoding 与单次教学最显著的差异之一，是很多判断必须在时间展开后才成立。即时成功无法直接证明稳定保持；一个月后答对，也可能受期间复习和刚刚看到的提示影响。

PE §6 区分四种时距：初始编码至检索、检索至反馈、反馈至后测、相邻练习之间。已有方案还要求保留相关事件时间及已知再接触。这些信息影响证据解释，但不要求逐句计时，更不意味着所有目标都采用同一套复习日历。

需要留给后续设计的问题包括：

- 目标要求保持到什么时候、在什么情境使用，怎样影响后续检验需求？
- 怎样区分一次延迟检查、一次重新教学和一次帮助后的复测各自能支持什么？
- 已有延迟证据足够时，是否可以减少重复投入；证据缺失时，怎样表达未知？
- 已知最近再次接触内容时，哪些“长期保持”结论需要限定？
- 教学方怎样说明后续任务的理由与必要条件，使计划方能与新学、补缺和其他目标协调？

本专项应有足够的时间视角，但不需要接管工作包 7 的全局预算、日期安排与积压处理。提出延迟检验需求，与实际排入计划是两件事；当前项目已明确这一点，具体衔接方式仍可设计。

Consolidation 提醒系统关注离线变化与长期结果；Reconsolidation 为知识更新提供候选机制解释。二者都不宜转成“系统可检测已经完成”的节点。报告支持睡眠参与记忆巩固的宏观认识，同时不支持每次睡眠都自动促进抽象、每次检索都打开固定更新窗口的推断。

依据：PE §6、§10、§13；架构第二节第 4 项；C0 第五、八节；路线 P5 与工作包 7。

## 七、教学成功与证据充分需要分别设计

### 1. 学习活动可能有效，却不足以支持更宽的能力结论

开卷比较、提示后解释、观看示范都可能帮助学习。问题在于它们留下的是哪种表现，而不是活动是否被贴上“主动学习”标签。

比如 AI 先给出两个概念的诊断差异，学习者随后准确复述，这支持其在当前输入下的表现；若目标要求自行发现差异，仍需相应证据。AI 提供“请用贝叶斯定理分析”的题目标题，可能已经完成了本来要测的方法选择，即使没有给出答案。

反过来，独立也不必等同全程闭卷。目标允许查阅文档、计算器或编译器时，使用这些资源本身不取消独立性；关键是目标操作由谁完成。Post-Encoding 不能把所有知识都改造成背诵要求。

依据：2／3 第五、六节；4 关于材料用途及帮助暴露的规定；C0 第四至六节。

### 2. 后续检查要与声称的变化相称

如果声称辨析改善，下一次只问定义就不充分；如果声称方法选择改善，却在题干里明确方法，也无法区分；如果声称能迁移，至少需要说明新任务改变了什么、保留了什么，以及是否混入新的前置负担。

关系题答对可以表明学习者能够在该条件下形成有效推理，未必证明某个完整整合表征已经永久储存。现场可靠重建本身可以是目标认可的能力，不必强行归因于特定内部机制。

训练和检验可以在合格条件下合一，但同一表现只能算一份证据。反复询问相似题、多个 Agent 重评同一答案、帮助后再次答对，不能简单累积为多份相互独立的支持。测验本身也会影响后续学习，解释长期变化时要保留这一背景。

依据：PE §3.1、§13；2／3 第六节；C0 第六节。

## 八、与前序方案的衔接：明确要解决的问题，保留具体形式

以下是下一轮模型应思考的衔接问题，不是本轮确定的接口合同。

| 关联部分 | 已经存在的依据 | 值得让设计模型自行解决的问题 |
|---|---|---|
| 架构与工作包 2 | 目标、资源条件、验收范围和独立掌握优先 | 怎样让专项活动始终服务当前目标，避免自行提高或降低要求？ |
| 工作包 3 | 条件化证据、暂定诊断及正式判断 | 专项活动产生哪些新观察，怎样支持已有判断，而不是另建“记忆掌握度”？ |
| 工作包 4 | 内容依据、用途核验、潜在帮助与版本 | 如何准备恢复、比较、变式和反馈材料，并处理方法泄露、新前置及来源变化？ |
| C0 | 通用活动、帮助、评价、收束和恢复 | 哪些共同能力可以直接复用，哪些专项需要要求共同框架作出修订？ |
| Encoding | 建立／修订关系与操作结构、已有帮助和表现历史 | 哪些工作可以沿用，何时考虑局部重建，重建后的哪些后续要求仍需保留？ |
| 工作包 6 | 后续负责策略使用体系 | 本专项需要把哪些局部选择讲清，哪些跨策略规则适合后续统一处理？ |
| 工作包 7／8 | 后续负责持续计划和协作实现 | 怎样把教学需求、未支持要求与恢复信息交给持续运行设计，而不预先决定日历和 Agent 配置？ |

尤其需要避免两种极端：为了“复用”而把专项写成没有内容的转交说明；为了“完整”而复制整个系统。好的衔接应使当前活动的理由和结果可理解，同时继续引用已有目标、证据和材料。

前序方案也不是不可修改的定稿。若发现具体情境无法处理，设计模型可以提出修订理由与影响范围；区别在于明确提出变更，而不是悄悄生成一套平行规则。

## 九、P1—P5 应作为覆盖检查，而非强制骨架

现有路线已经列出检索任务与提示、关系加工与迁移、错误修复与更新、活动组合与动态转接、延迟复习与持续验证。这个划分有助于检查缺项，但不必决定最终方案的章节、模块或执行顺序。

后续模型可以合并重复部分，也可以在理由充分时将关系整合与迁移分开。关键区别在于：前者可以在明确提供相关知识后观察结构工作；后者常常还包含在新情境中自主识别、提取、映射与执行。两者的教学任务和证据条件不完全相同。

另一种可能的组织方式，是围绕“当前需要取得什么进展或证据”展开不同路径，再把研究操作映射进去。是否采用这种方式，应由模型根据清晰性、教学解释力和与已有方案的兼容性判断。本文不指定某一种组织方式为唯一正确答案。

几种候选组织方式各有代价，值得在设计时作出实质取舍：

| 组织方式 | 容易做好的部分 | 需要解决的代价或缺口 |
|---|---|---|
| 以复习排程为中心 | 已明确内容的重复恢复和保持 | 容易低估关系、条件与更新问题，并与工作包 7 重叠 |
| 以检索和整合的操作家族为中心 | 方法资源容易查找，便于准备任务 | 容易由“可用策略”驱动教学；混合活动和共同职责不易归类 |
| 以固定活动循环为中心 | 执行简单，容易发现某个环节是否缺失 | 可能反复进行不必要活动，难以容纳直接输入、现成证据和不同入口 |
| 以目标需要与当前证据组织活动 | 更容易容纳多种入口，复用前序依据 | 更依赖任务和诊断质量；若追求穷尽所有情况，可能膨胀为复杂规则树 |

本文较倾向最后一种视角，但它的自适应收益尚待验证。顶层方案应让必要区分产生行动差异，同时允许在信息不足或常规任务中采取简单、可修订的安排。模型也可以提出混合或更简洁的替代结构。

## 十、用情境区分设计质量，而不是用流程图的完整度

下列情境用于检验设计能否产生有区别的决定，不要求成为下一轮方案的固定案例或固定测试集。

| 情境 | 顶层设计应能解释什么 |
|---|---|
| 一个术语在目标要求的延迟条件下已可独立恢复 | 为什么可以结束本次工作，无需强制追加整合与迁移 |
| 加权平均关系已理解，公式一时想不起 | 如何保留已有推理表现，并根据目标判断是否还需要独立恢复 |
| 公式熟悉，题目不标方法就选错 | 为什么“执行成功”不足以支持“自主选择”，活动应怎样改变 |
| 能解释训练例，遇到表面相似但结构不同的例子就误用 | 如何区分抽象不足、边界混淆和新前置，而不只加难度 |
| 修正过的概念在新情境再次出现旧答案 | 如何检验更新持久性、版本选择及仍有效的旧知识 |
| 跨会话继续，但最近反馈与外部再学习情况不清 | 哪些判断仍可保留，哪些时间性结论应保持未知 |
| AI 的反馈或参考答案被学习者指出有误 | 如何回到内容核验并修订受影响判断，不把问题归为学习者缺口 |

一个有价值的贯通示例应呈现：目标与条件、实际任务、学习者作答、关键帮助、为何调整以及仍未支持什么。它不需要展示每个内部角色之间的全部通信，也不能把假设走查写成真实效果验证。

## 十一、证据边界如何影响设计取舍

| 研究材料中的判断 | 对本轮顶层设计的合理支持 | 不能据此冻结的内容 |
|---|---|---|
| 检索与间隔支持保持，反馈有广泛价值 | 保留恢复、可信反馈和跨时间观察的能力 | 全目标统一的间隔表、成功率或必先检索规则 |
| 比较、解释、变式等会产生不同结果谱 | 根据目标选择加工，并检查对应表现 | 七类检索的普遍排名、◎转成权重、固定组合优越性 |
| 某些关系检索出现负向推理结果 | 检查整体关系是否真的改善，保留失败反例 | 宣称所有关系检索有害或所有检索必然促进整合 |
| 一些组合有互补收益，但顺序结果混合 | 说明每个活动增加了什么，考虑时间与反馈条件 | 所有人都走相同顺序，组合收益等于超加成协同 |
| 更新可能保留新旧痕迹并改善选择 | 检查新答案、旧答案侵入和适用情境 | 旧知识已擦除、再巩固已完成、固定可塑窗口 |
| 八维状态与完整循环属于分析综合 | 用来提出可检验的设计问题 | 已验证认知模型、可直接观测的内部状态或效果保证 |

证据强度属于具体主张，不属于某项策略永久不变的标签。台账还显示研究场景与核查深度不同；课堂总体收益不能直接证明复杂 AI 对话中的某种微观组合。

有限试用可以分别观察学习表现、活动匹配是否有用、判断是否误升以及时间和负担。若与更简单安排比较，应尽量保持内容难度、时间与反馈机会相当，并承认个人学习中顺序效应和学习不可逆带来的限制。高理论上限需要在真正复杂的目标上检验，轻量路径则需要在简单目标上检验；两者不能相互代替。

## 十二、如何把分析转成不过度规定的提示词

提示词需要明确三件事：本轮要产出什么、哪些已有成果是背景、设计质量如何体现。其余内容应主要写成值得解决的问题，而不是预填答案。

| 在提示词中保留 | 留给设计模型决定 |
|---|---|
| 项目目标、所处工作包、限定阅读范围 | 方案组织方式、设计单位、是否以及如何拆分 |
| 与前序方案保持语义连续，并允许有理由地提出修订 | 具体衔接形式、转接条件和记录表达 |
| 分清操作、表现、诊断与研究机制 | 如何表示关键差异、采用哪些任务与反馈组合 |
| 关注跨时间可用性、整合与目标所需应用 | 何时检索、开卷加工、示范、重建或结束 |
| 给出足以审查关键选择的情境与依据 | 案例学科、数量、流程图和章节结构 |
| 区分研究支持、设计推论与待验证收益 | 首期简化方式、后续验证重点 |

不把本文的八维讨论、分支表、衔接表或案例集合逐项复制成提示词的硬要求。它们的作用是帮助发现问题，而不是占据模型本应完成的设计工作。

配套提示词可以独立使用，直接指向原始方案和研究材料；本分析若一并提供，应被视为可质疑的讨论稿。设计交付可以具体到关键任务与分支，仍然保留内部结构、活动组织和衔接方式的自由度。
