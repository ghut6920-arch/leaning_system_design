## 设计依据与自由度

前序 v0 方案是当前设计依据。请先理解各包已解决的问题与衔接关系，再判断协作层需要增加什么。具体责任划分、组织方式和记录流程都可以讨论；若发现冲突、冗余或更简单的办法，可以提出有理由的修订，说明涉及的原文、收益和影响，区分当前方案与修订建议。

请保留以下用户方向和基本边界：

- 用户保留用途、最终范围、投入和个人记录的控制权。高能力模型承担关键目标、重要评价、复杂参考和教学设计；执行者拥有边界内的局部自主性。保持高理论上限，投入不足时合理缩小本次范围。
- 专业决定应有清楚的责任归属。前包分别负责目标与判据、证据与诊断、内容与材料、教学活动、策略使用和计划安排；8 解决这些责任如何协作，以及授权和有效状态如何延续。
- 证据诚实：区分原始表现、实际帮助和接触条件、条件化判断及暂定诊断。摘要要能回溯相关原答和条件；换 Agent、重新评分或多个模型意见一致，都不会自动增加独立证据。材料可提供、已展示和学习者已掌握也应区分。
- 错误、失效和记录删除要影响后续使用。相关结论按仍有效的支持保留、收窄或撤销，不能让旧摘要或副本恢复已删除的个人证据。系统自身的内容或评分错误应优先由系统修复；已有原答足够时，避免让用户重新作答。

这些边界之外，由你选择适合本项目的设计。以概念层面为主；必要的实现例子可以帮助解释取舍，但本轮不需要编写代码或完整展开工作包 9—10。

## 可用于展开思考的问题

以下问题帮助定位设计难点，可以自行拆分、合并、调整顺序或补充，不要求逐题作答。

- **哪些学习决定值得协作？**哪些适合由同一执行者完成，哪些需要更高能力或不同职责参与？如何兼顾专业质量、局部自主性和成本，并让重要决定的责任清楚可追溯？也请考虑减少 Agent 或合并职责是否更有效。
- **需要共享什么，才能可靠接续？**不同执行者怎样理解当前目标、材料用途、学习证据和计划状态？哪些信息适合摘要，哪些需要保留原始依据，哪些没有保存价值？如何处理信息不完整、过时或彼此矛盾？
- **委派和交接怎样真正完成？**执行者如何理解目的、权限及完成条件，接收方如何知道还有什么未处理？遇到中断、无人接手、并行分歧或旧版本结果时，怎样继续、暂停或重新决定，避免协作本身成为负担？
- **如何承接工作包 7？**从教学需求到预算内安排，再到跨会话恢复，7 与 8 各应承担什么？如何让学习安排、有效依据与执行权限保持一致，同时允许计划随新信息调整？
- **纠错和用户控制如何贯穿协作？**内容、评分、判断或计划出错时，怎样识别受影响的使用并修复？用户查看、纠正或删除个人记录后，如何使相关摘要、结论与安排如实变化？
