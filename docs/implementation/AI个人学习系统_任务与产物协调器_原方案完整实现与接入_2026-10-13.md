## 对照原方案

| 原要求 | 实现和验收 |
|---|---|
| 小型确定性机制，保留AG0规划和采用 | Python/SQLite协调元数据；没有调度LLM、后台Agent、界面平台或自动专业采用 |
| 谁修改什么、输入版本和执行状态 | register/start、稳定草稿修订、明确base_ref、draft路径；报告running/submitted/blocked与实际产物回执，不填写百分比 |
| 五种版本状态 | Draft、Candidate、Verified、Adopted、Superseded查询；按用途/范围分状态，旧采用版不会回变候选 |
| 旧采用版仍可用 | 草稿/候选不动指针；current取采用指针而非最高修订；snapshot固定实际字节 |
| 依赖感知与条件等待 | adopted/exact/after_task三种策略；只等指定任务，失败/取消/超时交回责任方，无关工作继续 |
| 明确暂定条件 | 未采用exact输入必须声明provisional_conditions，候选不能混称正式输入 |
| 上游变更影响下游 | 候选预警、采用后待复核，含尚未开始任务、直接/传递依赖及未知范围保守处理；历史退休产物不列为待修工作 |
| 不悄悄混用v1/v2 | 输入快照固定；新的消费者继承已明确复核的新来源，同时保留原引用和相容回执定位 |
| 完整写入验证后原子发布 | 非空/指纹/选定结构校验；指针、整组记录、回执和事件同事务。文件安装失败/中断只留未登记文件，不自动采用 |
| 提交前与采用前检查 | submit返回输入问题；确认/采用必须处理相关变化。采用必带旧指针条件，冲突不能通过刷新状态号绕开 |
| AG3意见绑定版本和依据 | target_ref、target_sha256、basis_signature、用途/范围；局部补核区分直接读取与明确继承，receipt可查询 |
| AG0短状态摘要 | brief提供状态、下一责任人和动作；state提供回执/依赖边/影响；diff定位确切版本文本变化 |
| 程序管理真实事实 | 明确创建/接责/提交/回执更新，不用文件存在、角色消息或LLM猜完成；recover不推断进程死亡 |
| 不建立全局任务等待锁 | 专业工作不持有长数据库事务，SQLite短写锁与任务等待分开；新草稿分支按真实基版比较，不按数字相邻推断继承 |
| 复用现有状态，无第二套真相 | 共享契约继续唯一语义来源；数据库唯一管理登记集合协调字段，原control/current/plan继续控制、学习事实和安排 |
| 宿主事件和关键节点检查 | AGENTS、MODEL_ENTRY、FRAMEWORK及AG0–AG3正式入口接入CLI；inbox→显式ack游标，四关键节点有确定性门禁 |

## 真实目录试运行

按原AG0备课收口与明确v1→v2相容声明登记8个历史文件版本，保留Goal/认知设计原v1依据；没有把“最高文件名”当当前版或把历史审查迁成新审查。历史采用及相容性均附原文路径、指纹、唯一锚点，程序核事实定位，登记含义由现有AG0职责负责。

两份新增产物是[BC备课协作导航v1](../../learning/embodied-intelligence/artifacts/coordinator-integration/bc-preparation-navigation-v1.md)及[v2](../../learning/embodied-intelligence/artifacts/coordinator-integration/bc-preparation-navigation-v2.md)，只支持版本路由与审查边界，不重新裁定原学科内容。真实目录完成任务→固定输入→完整候选→AG2确认→AG3版本意见→AG0采用。尝试以v1审查采用v2被receipt_version_mismatch拒绝；明确补核审查边界、继承未变路由后采用v2，v1显示Superseded。

本维护模型顺序兼任职责，记录并非独立专业审查。程序读取锁定原件字节；本次专业决定仅核导航、已取原文定位与审查限制，不据文件哈希宣称全部学科全文核验。原学习控制、断点、备课正文及历史审查不改，没有学习者原答/能力、授课、训练或机器人实验事件。

## 验收与边界

新增32项功能检查，与前三批72项合计104项；包括实际进程并发提交、文件安装后硬退出/恢复、版本分支、范围、回执、控制和消费游标。实际目录9次CLI查询覆盖brief/state/inbox/boundary/current/diff/operation/receipt/recover；共享契约/来源基线另行检查。具体运行结果以所链接的本次验收记录为准。

角色为可信本地操作员声明，没有恶意文件系统隔离或模型身份认证。采用字节变动会被拒绝，指纹不能恢复原文。宿主工具及关键节点路径已接入，但磁盘变化不会自动进入正在推理的模型上下文；无需也没有常驻调度模型。旧B6和LearningStore仍仅接受各自虚构开发数据，不借真实协调接入改变其授权边界。

历史BC索引采用保守整体范围；细粒度工作需要明确登记稳定范围与依赖，程序不从学科正文自动发现M3影响。范围相容、充分性和是否需要AG3仍由原职责决定。真实试运行证明工具链工作，尚不声称协作时间节省或教学效果改善。
