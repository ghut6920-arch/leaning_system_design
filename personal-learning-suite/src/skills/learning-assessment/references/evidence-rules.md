# 证据规则

用于授权常规评价、重要复核和重评的证据解释。依据 D02 第五／六／九节、D04 第四至七节、D06 第七节和 D11 第六／八节；对象与枚举只维护在 [共享契约](../../../../contracts/shared-contracts.md)，局部运行表示见 [assessment-b3a.md](../../../../contracts/assessment-b3a.md)。资源与真实课程原件分开，设计案例不是学习者表现。

## 先限定要支持的决定

取得 `GoalSpec` 的要求、关键操作、产物、先定判据及其修订、允许资源、证据与时间／情境要求，再明确本次用途。短且可回退的教学起点可以使用有限表现或可信自述；重要跳过或宽范围结论须覆盖对应关键类别、边界和整体操作。没有固定连续答对题数，也不能把更多同题记录当更充分证据。

在评分前分别核任务与参考：

| 资格面 | 检查及不足时处理 |
|---|---|
| 目标操作调用 | 产物是否必须调用该要求的关键工作；只能抄写／猜测完成的部分缩小结论 |
| 输入未代做 | 题干、示例、标题、编号、着色、箭头、默认值、折叠位置及采用理由是否提供了正在评价的方法或关系 |
| 前置负担 | 区分目标必要前置与未声明的新符号／工具／领域背景；系统任务缺陷不能记成能力失败 |
| 参考可评分 | 有可靠来源、合法推导／测试或适当专业核验，接受有依据的替代解和正确的“信息不足” |
| 证据条件 | 允许资源、实际帮助、暴露历史、任务变化、目标内时间／情境是否成立；不足只限制依赖该条件的用途 |

活动设计合格、参考已核、答对和使用资格是不同决定。`task_qualification` 或材料核验声明不能取代实际专业检查；辅助器只能核结构、引用和声明相容。目标无过程要求时，正确简单答案可以够用；若目标需推导、整体组织或条件检查，答案数字不能自动证明这些操作。

## 原答、帮助与样本身份

回查原任务及足以评审关键操作的原答／完整 `ArtifactRef`；较大产物按定位读取，不能用教学摘要补造原件。分清谁完成了哪些部分，保留原答与修订，不将润色稿或反馈后产物回写为初答。发生时间、实际资源、相关学习／练习／反馈和接触信息可复用已有引用，缺失用共享 `Fact` 的 `unknown`，没有记录不等于没有帮助。

按具体操作解释实际帮助，保留 `初始可见输入 → 初答 → 帮助或反馈 → 修订` 的顺序。例如公式供给可能代做选择或恢复，但仍留下计算工作；给必要前提可能留下关系推理，但不支持独立恢复该前提。允许教材、计算器或编译器不自动取消独立性，关键工作由工具完成时则改变对应解释。

帮助发生在初答后，不撤销此前可独立解释的原答；帮助发生在初答前，被代做的操作只得帮助条件下的支持，其他操作可保留。暂存备用参考且未展示不计实际暴露，外部接触未知不能填成无接触。隐藏答案、换题名、换 Agent 或声称“未练”不能重置已知暴露。

同一 `PerformanceEvent` 的初答、提示后修订、反馈后重做沿用其 `independent_sample_id`。同一原答用于多个要求可以各留判断，仍只有一个相关样本；重评分、另存摘要、同题重算和多角色同意不新增观察。异型任务要说明变化维度、共同关系和新增前置，换数字或措辞本身不证明远迁移。

## 条件化双轴与反证

每项 `Judgment` 指向确切目标／判据／事件修订，说明条件和实际依赖。在两条轴上分别判断：

| 轴 | 含义 |
|---|---|
| `support` | `unknown` 未取得或条件不足；`supported` 范围内正面支持；`observed_not_met` 该次要求未达；`mixed_or_conflicting` 可比条件结果不一致或关键反证未解 |
| `eligibility` | `usable` 可用于所列用途；`pending_review` 当前待复核；`withdrawn` 已撤销用途 |

参考疑误可以保留历史正面支持而限制其用途，待复核不表示能力下降。未达是这项要求在记录条件下的表现，不能推为永久不会。自述清楚、流畅解释、已讲过、活动结束与计划排期均不新增能力支持。新的判据不倒判旧答，版本变化先检查适用性。

比较新旧依据时看同一要求、条件可比、来源合法、新信息是什么。同原答同条件相反评分回原件与先定判据，不能平均、投票或以最后写入为准；不同条件分别保留支持，不机械合成冲突或清零整主题。有限能力解释须有原答中的对应观察，复杂证明／构造／代码系统／开放论证保留整体约束和可接受替代路线，子项通过不自动通过父产物。

整体结论的实质评审按 [整体作品评审](product-review.md)执行：回连续原件，将每项原有义务和关键接口对应到实际推理／代码／论据，检查条件与结论的衔接。缺失的关键连接明示未完成，保留无关局部支持；目标本就仅需公式计算时按其标准结束，不追加一般证明。`whole_required`、参考覆盖声明和结构检查通过都不能自行生成整体 supported。

## 时间只服务 GoalSpec 的实际要求

未要求延迟／新情境时写 `not_required` 或作为结论边界，不新增欠项。目标内要求尚未取得才是待证，当前教学仍可结束。日期过去、睡眠、完成计划复习次数或即时流畅不能成为保持通过或能力衰退的依据。

按相关内容的实际初学、练习、帮助／反馈和本次表现解释时间，可使用已存事件引用，不要求逐句计时。一项条件昨天修订、其他关系一个月前形成，分别保留历史；不能把全部称为一个月保持，也不清零未受影响旧支持。

仅当 GoalSpec 明确要求无相关再学习间隔时，按最近相关接触重查该间隔。已知接触只影响实际提供的信息及相应操作，持续使用可以是目标允许条件；接触未知则不确认需要排除再学习的保持结论，保留其他当前表现。检查本身也是练习，反馈后再答带新条件，不能将多次后测当未干预保持。

已有自然使用具备所需条件，可复用其原产物，不为整齐另造测验。只有目标内且会改变下一决定的缺口形成必要 `LearningNeed`，AG1 决定其日期、资源取舍与承诺。充分合法支持时明确“不追加检查”；目标时间条件未到，记录待证／触发，不用即时加题补足。
