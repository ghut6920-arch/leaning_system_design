# AI 个人学习系统：工作包 7／长期计划与学习连续性顶层设计分析

日期：2026-09-30  
定位：为下一轮工作包 7 设计方案划定问题、边界和验收要求。本文件提出设计方向与待决项，不是已经生效的计划规则，也不是软件实现规格。

**工作包 7 的核心增量，是把不同教学来源提出的必要工作，变成资源可兑现、取舍可解释、跨会话能接续的计划承诺。**前六包已经规定目标、证据、材料和教学怎样成立；本包要解决“值得做的事超过可用资源时，究竟做什么、何时做、做到哪里，以及暂时不做会怎样”。

工作包 7 与 8 分别设计，共用同一套交接含义：7 决定投入和下一步安排；8 决定谁有权使它生效、怎样接管、怎样处理版本与责任冲突。两者均不新建掌握标准。

## 二、先守住三条边界

**计划范围、正式目标、能力结论分别变化。**本周暂不投入一般证明，只表示当前承诺缩小；一般证明仍是有效目标内的未完成要求。若用户决定不再追求它，由 2 正式修订目标并保留历史关系。取消一条重复或失效需求可以不改目标；放弃一个仍有效目标必须与前者分开。停排也不代表已掌握，逾期也不代表不会。

**教学完成后可以没有新的必修待办。**保持、迁移、闭卷恢复只有在目标或具体使用需要中有依据，才形成必要工作。仅缺未来时间条件时停止即时加题；已有合格自然使用记录时优先复用。未知是否需要补测，取决于它会不会改变重要决定，不能把所有未知都转为补课。

**7 给执行边界，5 决定边界内怎样教。**5 可以在原授权和预算内换方法、补最小前置、收束；6 提供替代与可拆性。影响当前承诺才回到 7。7 缩时后须把改变交回 5／6 检查可执行性，不能直接删掉必要反馈、关键操作或核验后照常宣布“任务可做”。8 负责落实这种授权，不要求每次局部调整跨 Agent 审批。

有效安排不能使无效依据继续生效。获知材料失效、判断撤销或预算缩减时，先暂停受影响执行，再处理重排；不等待完整新计划才停止。其余不依赖争议依据且仍在授权内的工作可以继续。

## 三、建议按七项设计问题展开

这七项是需要分别回答的问题，不对应七个模块或固定步骤。

| 设计问题 | 下一轮必须作出的具体选择 | 应形成的产物与检查 |
|---|---|---|
| 1. 多时间尺度怎样连接 | 学期／课程承诺、阶段里程碑、每周分配、单次展开各管什么；哪些变化只动下一次，哪些要回看课程可行性 | 同一目标贯穿各尺度的例子；保留课程进度与个人掌握进度两条信息 |
| 2. 需求怎样进入同一计划 | 区分有效目标内的工作、建议探索、重复需求、失效需求；缺少理由或条件时补什么才值得继续 | 从提交到明确处理结果的规则及短记录；不以“先收进列表”代替判断 |
| 3. 竞争时怎样取舍 | 综合使用时点、前置阻塞、尚缺证据、延期后果、用户优先和可行性；处理新学、补缺、检索、变式与综合任务 | 展示入选及未入选项的理由、代价与返回条件；不预设固定比例或加权分 |
| 4. 预算怎样成为可信承诺 | 计入准备、学习、反馈、核验、切换与恢复成本；区分已知、粗估和未知；确认可完整收束的范围 | 缩时后的真实新承诺；预算不足时能暂停、分段或改等效形式 |
| 5. 时间性证据怎样安排 | 必需时间／资源／线索条件与建议时窗分开；自然使用能否替代专项检查；冲突条件怎样另排或保持未知 | 一次延迟需求的完整处理例，说明为什么该安排能够或不能支持所需结论 |
| 6. 中断与积压怎样消化 | 分清暂缓、取消重复项、不再投入、待核验和待用户决定；连续漏学时重评剩余目标、可用资源及投入 | 不把全部欠项平移至明天；恢复点包括父任务和完整产物的未完成连接 |
| 7. 什么新信息触发重排 | 合格新证据、目标变更、材料失效、持续超支、用户改变投入分别影响什么 | 计划变更前后对照；有明确不重排情形，避免每次答题都扰动长期安排 |

候选主线可以是“确认有效目标与资源 → 接入必要需求 → 判断可行性与竞争 → 形成有限承诺 → 执行并收束 → 根据新事实重排”。箭头表达依赖；稳定内容直接复用，不要求每次重新规划学期。

## 四、真正困难的取舍应在方案中正面解决

### 1. 掌握优先与课程期限冲突

已确认的独立掌握优先应表现为：优先保住选定核心范围的合格工作，明确其他覆盖暂缓及后果。真实截止日期不可通过改日历消除；若既定目标与资源不可同时满足，方案应给出可执行的缩范围、改变投入或正式改目标选项。常规授权内可直接调整；涉及用户目标或新增投入的取舍才请用户决定，不把每次排课都做成确认流程。

### 2. 复习有用与复习债务失控

不能把“需要未来检查”理解为永不结束的复习队列。方案应规定需求何时被已有证据覆盖、与其他真实工作合并、因目标变化取消，或因投入取舍明确保留未支持边界。持续延期必须触发需求与资源复核；不能仅反复延后日期，也不能机械删除所有旧项。下一轮需要给出清理积压的实质例子。

### 3. 合并节省时间与证据条件冲突

同一任务可以同时观察恢复和应用，但必须由教学责任确认兼容。上午给完整方法、下午紧接同题，不能为了满足日历上的两个标签，分别称独立选用与无再学习保持。7 提出合并安排，5 核对关键工作与暴露，3 限定证据结论；一份原答不因挂接多个需求变成多次独立成功。

### 4. 长任务连续性与短时段可用

复杂证明、代码或综合报告可以推进到可核查中间状态，并保留整体产物。不能强拆成全部各自验收的小题，也不应在无法提供必要反馈与收束时启动一段高成本活动。需明确哪些部分可以暂停、恢复需要何种上下文，以及片段完成为何仍未完成原目标。

### 5. 计划稳定与及时纠错

普通局部错误在本次授权内处理，不必全局改计划；重要新证据、材料失效或预算持续不足才可能改变承诺。内容纠错时，4 恢复可靠依据、3 用历史原答重评、教学方修复已经造成的误导，7 调整由误判产生的补课。不能让用户重考替系统修正旧判断，也不能因删去无效待办而宣称学习成本下降。

**用于检验设计的预算例。**假设某次剩余总时间由 60 分钟降为 25 分钟。原候选 A 为继续证明：准备／核验 5 分钟、推进 30 分钟、反馈／收束 10 分钟，共 45 分钟；候选 B 为一项检查，共 15 分钟。假设教学方确认 A 可在本次只推进到已定义的中间论证：准备／核验 5 分钟、推进 10 分钟、反馈／收束 10 分钟，恰为 25 分钟；则本次只承诺 A 的这一范围，B 明确暂缓，A 的一般证明仍未完成。若中间论证成本尚不确定，不能因算术合计等于 25 就满额承诺，应再缩范围或只做必要收束。这里的数值仅用于验证预算口径，不是通用参数；若切换、材料制作或恢复另有成本，必须计入。下一轮方案还应给出因期限重要性而反过来选择 B 的合法分支，证明取舍依目标而非固定偏爱长任务。

## 五、与工作包 8 共用的最小接口

以下是待两包共同落实的语义契约，不规定表结构、消息协议或角色数量。

| 交接对象 | 最少需要表达什么 | 责任边界 |
|---|---|---|
| 后续学习需求 | 目标及版本、必要工作与已有支持、理由与延期影响；必需条件与建议时窗；原答、帮助、接触及父任务引用；材料准备状况 | 5 形成一份需求，6 按需补配置、成本与可拆性；不重复提交同一缺口 |
| 计划承诺／当前展开单 | 有效依据、入选范围、预算或投入边界、顺序或时窗、允许调整范围、受影响而未入选的工作及后果 | 7 维护唯一有效结果；8 保证责任、授权及版本生效清楚 |
| 需求处理结果 | 待接收、已接收待处理与已安排须区分；合并、延后、不再投入或退回补充须说明去向、理由和重新考虑条件 | 7 作实质决定；8 保证结果来自有权责任方、能与原需求对应。状态措辞不是强制定稿的机器枚举 |
| 中断与恢复 | 当前有效依据、已完成与未完成、停止原因、父任务、中间产物、实际帮助／暴露、依赖争议与下一次可执行起点 | 5 保存教学事实；7 重新确认现在做什么；8 保证接管者取得有效上下文与授权 |
| 变更与纠错影响 | 什么依据变了、影响哪些承诺与需求、哪些仍有效、需要原责任方重新判断什么 | 7 不越权改目标或能力；8 处理旧版本写入、遗漏通知和并发冲突 |

实际接收结果未发生时，只能写“拟定接口”或“待接收”。下一轮方案应处理迟到结果、旧版本建议、重复提交及接收后无人处理：不能声称这些问题已由某个不存在的 Agent 自动解决。

两包方案可以先后形成；某包尚未定稿不阻塞另一包给出可审查选择。接口先列为待对齐，8 处理拒收、暂不能接、条件不全与无回应的责任去向，7 保留未承诺工作及其影响。

恢复也不等于重新冷启动。等待时间本身不将能力清零；换会话不清除帮助历史。上次无进展则处理已有反证或换路；参考争议未解除则限制受影响用途，其他已授权工作可继续。用户删除记录后不得从摘要恢复被删内容；3 据剩余支持保留、收窄或撤销判断，7 只调整受影响安排，不能把失去依据直接写成能力下降。

## 六、下一轮交付物与验收

下一轮应交付完整的《工作包 7／长期计划与学习连续性设计方案 v0》，至少包含：多尺度原则；需求准入与处理；取舍重排；预算与复杂工作分段；时间性检查；漏学积压与恢复；接口与待决项。除规则外，给出可审查的计划承诺、需求处理和恢复记录样例。

必须用以下情境证明规则能够作出不同决定，案例可合并，但不能只列场景名称：

| 走查输入 | 应看见的方案输出 |
|---|---|
| 原定长时段突然只余收束时间 | 保存当前工作，取消本次新增投入，重排有真实取舍；原标准仍在 |
| 连续漏学且新课、补基础、复习同时竞争 | 有入选、合并、暂缓或不再投入；明确剩余目标与期限后果 |
| 只缺延迟条件，期间又看到相关解答 | 按受影响内容解释时间，保留其他有效证据，必要时改变检查用途或安排 |
| 高级证明停在构造成功而一般论证未完 | 保存完整中间产物，从断点恢复；不给目标补记通过 |
| 教学与策略端提出同一需求，或处理结果迟到 | 只有一个有效承诺，旧结果不覆盖当前计划，未落实状态真实可见 |
| 内容参考错误、目标变更或记录被删除 | 沿原责任重评，撤回或调整受影响工作，保留无关有效部分 |
| 已有自然使用满足目标，简单目标已完成 | 允许需求关闭、结束重复投入，不制造额外复习债务 |

每个重点案例至少说明输入依据、取舍理由、实际承诺、未做事项及后果、记录／责任和下一次改变条件。报告分别表达课程覆盖、计划执行和目标条件下的独立掌握；若使用比例必须说明分母，不能把三者合成一个进度分。

真实收益仍交工作包 9—10 验证：恢复是否少重复、积压是否受控、准备和等待是否相称、独立表现是否保持。可先沿一条完整且狭窄的真实课程路径试用，未知预算保留粗估或未知；本包不需要提前确定最佳复习间隔、固定新学比例、效用权重、模型名单或数据库。

| 成熟度 | 本轮应怎样处理 |
|---|---|
| 已由前包确定 | 独立掌握优先、唯一有效安排、证据与帮助语义、专业责任和用户控制直接继承 |
| 工作包 7 必须决定 | 多尺度更新、需求去向、取舍与重排、预算、积压和恢复规则；不能都留成开放问题 |
| 待真实输入校准 | 具体期限、投入、任务成本、个人偏好及当前有效证据；缺失时标未知，保留调整空间 |
| 实现阶段再定 | 调度算法与参数、模型／Agent 配置、数据库、通信、界面和自动化实现 |
