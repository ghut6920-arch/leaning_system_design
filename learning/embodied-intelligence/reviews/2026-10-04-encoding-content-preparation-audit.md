# Encoding 内容准备、材料接入与实际教学审查

日期：2026-10-04。范围：研究报告、顶层分析、工作包 4／C0／Encoding 设计、运行版 Agent／Skill、具身学习启动提示词，以及已读取的聊天“启动第一次学习”12 个完成轮次和对应文件。此报告延续 [首次执行审查](2026-10-04-first-session-audit.md)，重点检查内容准备怎样转为教学。

这是对本地文件及实际执行的一致性审查；未重新核验报告引用的外部论文，不声称验证整套教学的因果收益。涉及真实学习的内容属于本学习目录的个人记录范围。本轮只增加审查报告，不修改公共 Skill、课程当前状态、原答或既有评价，也不向学习聊天发送消息。

## 1. 判断

现有设计有内容分析、初始输入、完整范例、多表征和条件化适配的依据。运行版也允许这些工作。WM 实际执行读取了相关 Skill，并准备了题目与参考，不能认定完全未加载规则。

主要缺口是：**题目级准备落实得较具体，单元级内容分析和正向教学准备缺少足够清楚的执行要求；必要输入容易延后成为答题失败后的备用帮助。** 记录与证据规则不能替代这两项教学工作。

实际执行还出现了可辨认的问题：没有决策价值依据的微检查、未先说明数例语义就让学习者运行和比较、没有及时把局部重新组织成具身任务中的完整工作。最后一轮已经补出整体图，不能把已发生的修正忽略掉。

### 软件与资源的实际边界

[B4 实现](../../../personal-learning-suite/src/runtime/learning_teaching_b4.py)确实要求 `needed_structure`、合法变化、可接受产物、分支和材料依据，也允许 `explain` 路由。它不是一个强制问答算法。实现检查非空描述、引用、声明及兼容性，不能证明描述充分、例子有意义、前置真正可用或课堂因材施教。

[策略资源](../../../personal-learning-suite/resources/strategies/README.md)为 60 卡建立索引，目前只有 S07、X02、R09 的完整包及四份 Post 条件说明已编译。O07 结构预览、S05 正确范例追踪等内容仍可从原始库读取，并非不存在；但入门教学尚未形成同样方便复用的运行示例。WM 记录没有显示采用这些卡的配置，因此不能声称本次微题链由卡片路由直接造成。

现有测试证明的是有限开发程序及声明检查；[B7 验收](../../../personal-learning-suite/specs/b7-acceptance.md)也明确真实学习收益待试用。通过开发测试不能证明教好了一门课。

## 3. 因材施教应该体现为哪些具体工作

有 AG1、AG2 的责任名称，不等于已经执行内容分析。进入一个新单元时，教师至少应能交出下面这些简短、可审查的判断，已有准备有效则直接复用，不逐题重做。

1. **目标和位置。**这段内容服务哪项完整判断或操作，与当前主任务有什么关系。
2. **内容结构。**关键对象、定义、关系类型、条件、程序分支或不变量；哪些关系有依据，哪些尚未知。
3. **关键前置。**完成这段工作真正需要哪些概念和工具；已有证据、教师将提供的输入、尚未知分别是什么。
4. **学习起点。**利用已有原答和作品，不把未测当不会。只有回答会改变入口时，才补一个相应观察；各答案都导向同一必要说明时直接说明。
5. **材料和表征。**原文能否直接用，是否需桥接、完整示范、带标签的图表或可运行例子；当前必要输入不能全部放在备用区。
6. **学习者工作和调整。**AI 已提供什么，学习者还有哪项有意义的建构、判断或实践；不同实际障碍怎样改变材料与下一步。

WM 首次活动有整数乘法、轴释义、短答和参考等题目级分析；后续 API 参考也有核验。未见充分的单元级准备来说明为何从张量走向轴转换、数例中每个数的身份、Python 操作与具身数据接口的关系。此判断限于可见文件与聊天，不推断模型隐藏思考，也不泛化为所有 Skill 永远没有分析能力。

## 4. Encoding 的基本顺序

下面是针对陌生内容、当前用户希望先建立初步理解的默认安排。它是有条件的教学方案，不是对所有知识的固定认知流水线。

**教学准备：**读取当前材料和可靠依据 → 明确目标关系及关键前置 → 利用已有学习记录选择起点 → 准备当前必要输入、示范及反馈依据。

**实际学习：**任务用途与整体定位 → 必要术语和对象 → 一个含义完整的范例／可操作表示 → 学习者完成连贯工作 → 针对真实表现反馈修订 → 回到完整任务使用 → 整理本次关系及下次连接。

这里“初步表征”是教学目的，不表示 AI 能直接知道脑内发生了什么。教师提供的框架、图和例子是外部支架；学习者逐渐能定位、解释、操作和修订，才提供相应范围的表现依据。无需先要求学习者从空白自行画全课图，也无需每讲一个词立即考试。

| 当前条件 | 入口怎样变化 |
|---|---|
| 关键术语、符号、对象意义尚未提供 | 先解释和示范，再参与；不要要求无依据生成 |
| 有完整范例，但不懂步骤用途 | 将目标、条件和选择点对应起来，再补一项关键连接 |
| 已有可用关系及可靠作品 | 可以直接复杂实践、条件比较或检查现有产物，省去重复讲解 |
| 有具体错误模型或边界混淆 | 用有依据的对照、反例、模型修订；不用通用问题串代替 |
| 先尝试确有设计价值 | 可以先尝试，但需有可理解的对象、适当任务和后续讲解；不能无期限猜测 |
| 后续使用暴露关系缺口 | Post 返回所需 Encoding 局部，补够即回同一主任务 |

Orient、Scaffold、Relate、Differentiate、Instantiate、Re-represent 是可组合的操作家族，不是要求逐个打卡的六个课时。理论深度也不是问题数量；目标需要证明时保留合法推导，需要动态预测时保留时间、状态和条件，需要工程实践时保留接口、数据与验证。

## 5. 学习材料什么时候接入

| 材料 | 默认接入时点与用途 | 如何调整 |
|---|---|---|
| 课程框架、当前单元位置 | 陌生方向进入时，先提供够用任务结构和局部位置 | 已能定位则复用；没有必要就不制作全领域知识图谱 |
| 定义、符号、变量、轴和单位 | 要求解释、比较或操作之前，提供目标所需的最低语义 | 既有证据足够可省；只补实际需要的前置 |
| 完整范例与步骤目的 | 新程序或当前对象陌生时，作为当前输入 | 已有可用程序则减少范例，转向分支、条件或完整实践 |
| 对照表、图、数据与代码 | 它们所支持的判断发生之前 | 先说明标签和对象映射；语义未清时，不先让用户运行无意义数列 |
| 动态／交互可视化 | 目标确需观察时间过程或参数变化，且收益值得制作和操作成本时 | 静态表足够就用静态表；图动起来不自动证明理解 |
| 局部修复材料 | 实际障碍出现，且相应补充能改变工作时 | 必要初始说明不应等到此时才展示；修复够用后回主任务 |
| 整理稿、关系摘要及后续题 | 单元收束或后续使用时 | 区分 AI 整理、学习者原产物与待完成工作，不制造统一题量 |

学习大纲主要提供范围、目标和资源线索，不能自动充当教学正文。AI 需要读取当前章节对应的实际内容，或依据可核验的定义／推导准备课程材料；已有合格材料就直接组织使用。

展示定义、完整解释或范例是正常教学。其影响的是“之后能支持什么独立性结论”，不应成为拒绝提供教学输入的理由。没有学习者初答时，可以直接记录教学输入，不必为了满足“先保存初答”制造前测或假表现事件。

## 6. WM 本次应该怎样组织

保留当前已补出的 [整体框架](../materials/embodied-framework-v1.md)，以“把一段视频按正确的帧／颜色身份送入指定模型接口”为连贯单元。

先定位相机观测在具身任务中的用途，再解释张量坐标和轴意义。用一个两帧、三通道的缩小表，明确行、列、数值身份和新接口要求。教师完整示范：轴交换保持每个值的帧／通道身份；只改变尺寸解释的 reshape 在该例中不能实现这种对应。随后让学习者修改或解释同一完整转换，检查一个坐标的对应，并根据实际困难补充。

这样安排仍包含必要实践和反馈，却不需要把乘积、`len(shape)`、颜色含义、轴编号逐项拆成等待轮次。代码运行输出、含义解释和接口正确性分别观察；根据目标保留理论条件，不用“代码跑通”替代关系理解。

最后一轮的框架图已经改善入口；后续应接着它组织真实工作，保留既有原答和帮助，不把修复系统体验变成重新考试。

## 7. 修订应覆盖的文件和验收

| 修订层次 | 文件与具体要求 |
|---|---|
| 内容准备 | AG1、SK03 的 design-whole／Encoding：补目标结构、必要前置、连贯单元和入口选择的短指南；解释未知起点怎样开始，而不要求完整个人画像 |
| 输入制作 | AG2、SK02 materials-workflow：按用途把必要框架、语义说明、完整范例放进当前输入；备用支持留给尚未发生的条件性困难 |
| 课堂执行 | AG0、SK03 C0：区分教学输入与独立证据用途；问之前检查对象是否已可理解、回答是否改变安排、能否整合进完整实践 |
| 启动配置 | START_PROMPT、MODEL_ENTRY：一次一项指连贯工作；陌生单元先具备用途、对象、关系和示范；用户不理解时先回查材料与讲解 |
| 资源覆盖 | 给结构预览、完整范例、带语义的多表征准备有限的运行示例；不为了覆盖 60 卡扩建庞大规则引擎 |
| 真实验证 | 增加实际内容准备及教学兑现审查，不能仅检查字段、文件数量和题目答对数 |

这些是本轮形成的可执行修订要求，尚未写入公共规则。修改时应同步来源登记／指纹及使用入口，保留设计来源原件；无需改写历史学习表现。

修订后的真实单元至少要能够核查：

- 当前任务的用途和位置已呈现，学习者无需在多个文件里自行拼出关系。
- 题目所需对象、术语、表示和操作有已提供输入或既有证据支持；有意先尝试时能说明任务条件和后续教学。
- 范例的数值、标签、图和代码一致，足以解释每一步在做什么。
- 学习者承担的是目标内的连贯工作；额外小检查能指出哪项安排会因答案而变。
- 出现“不理解”时，先核查材料语义、讲解跳步、前置和任务，允许调整教师方案。
- 局部补充回到同一主任务；深度扩展有目标理由，广度扩展有条件、实例或接口理由。
- 真实等待与准备成本进入审查；把可自然合并的操作留在同一产物中，避免每个微步骤都造成一次长往返。

这些检查是对教学兑现的审查，不是新增一套掌握评分，也不能凭一次合格课堂保证长期学习效果。
