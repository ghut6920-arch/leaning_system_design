# 单元学科分析工作底稿

日期：2026-10-10。性质：研究建议与可复用工作模板，尚未接入现有 Agent／Skill，也不是新的审批要求。配套说明见同目录《研究报告.md》。

使用方式：围绕一个实际学习用途完成连贯分析；不要求每个单元填满所有栏目，也不要求按固定顺序逐项执行。已有可靠内容直接复用。分析应为内容选择、解释、案例、任务或评价提供可说明的决定依据，包括修改、保留、删除或暂缓；核实原材料已足够同样有价值。没有依据时标“候选／待核”，不让模型用流畅文字补造。

## 1. 把单元放回学科问题中

- 学习者想最终看懂、解释、判断或完成什么？保留原用途，不先缩成容易出题的小目标。
- 本单元围绕哪个真实问题组织？这个问题为何困难？
- 不掌握本单元，哪项解释、判断或行动会做不好？
- 它体现了哪种更一般的思想？与哪些先前、后续工作相连？
- 本次哪些认识必须建立，哪些可作为明确接口暂时使用，哪些不在当前范围？

输出一段完整论述，避免只有关键词。例如：“本单元研究……；旧方法在……条件下不足；引入……后能够……；但仍不能据此……。”这一句式适合有问题—方法结构的主题；文学欣赏、语言交际等主题可改为对象—体验／表达目的—解释标准。

## 2. 让学科整体与代表任务互相校验

先从独立专业资料梳理本主题的主要问题、解释框架和典型实践，再选与目标一致、依据可核的任务或作品，实际求解／解释／分析。必要时加入改变关键条件的相邻案例。数量随内容决定。

代表任务必须回对原用途及专业资料，检查它遗漏了哪些必要关系；选择依据不足时保留候选，不把该任务调用的知识等同于单元全部结构。

| 任务中的关键位置 | 专家看到什么线索 | 作什么判断／选择 | 理由及成立条件 | 新手可能省略什么 |
|---|---|---|---|---|
| 待写具体内容 |  |  |  |  |

检查：如果只把这列写成“分析、比较、评价、迁移”，说明还没有进入学科内容。应写出比较对象、决定性差异、推论与边界。

无真人专家时，可从权威解例、原论文、证明、真实代码与实验、带评分理由的作品反向分析。所得内容标为“基于资料的专家实践重建”，不能冒充访谈或专家实测。

## 3. 写出支撑判断的知识结构

| 核心命题／关系 | 类型与依据 | 为什么对当前任务重要 | 条件／例外／竞争解释 | 可定位来源 |
|---|---|---|---|---|
| 必须是一句有实质内容的判断 | 定义、推导、模型假设、经验结论、解释立场或教学假设 |  |  |  |

不要只写“A 与 B 有联系”。说明是推出、构成、因果机制、统计关联、证据支持、近似、类比、限制还是方法替代。区分：

- 数学成立的前提与某个学生学习时需要的前置知识。
- 模型表达能力、实际可学性、计算成本与已观察效果。
- 证据支持一种解释与已经排除所有其他解释。
- 教材编排顺序与学习过程的可能路径。

对关键关系做一次压力检查：删掉它，哪一步会无法成立？改变哪个条件，判断可能改变？若没有任何解释、预测或选择受影响，它可能只是背景联想。

再做覆盖反查：还有哪些核心问题、重要解释或实践未被代表任务覆盖？这是有理由暂缓，还是分析遗漏？

## 4. 找到“会做”背后的理由

适合程序、方法、证明和模型类主题时，使用以下四项联查；不是所有主题都必须套四栏。

| 任务族：要解决什么 | 技法：怎样做 | 理由：为什么这套做法成立 | 理论：哪些更一般结构支持或限制它 |
|---|---|---|---|
|  |  |  |  |

补充真正有意义的替代：在同一需求和条件下，另一方案的输入、表示、计算或证据要求是什么？何时它更合适？不要为了衬托目标方法，构造被故意削弱的对手。

## 5. 把内容重构成学习者可获得的输入

| 必须建立的具体认识 | 专家版本中隐含的一跳 | 采用的教学表示／案例／推导 | 简化了什么 | 必须保留的关系与限制 |
|---|---|---|---|---|
|  |  |  |  |  |

逐项检查：

- 每个关键量、判断或证据从哪里来？是否已在学习者可见内容中出现？
- 图、公式、文字和代码的对象是否一致？转换保留了什么、丢失了什么？
- 一个玩具例子实际说明什么？它不能说明什么？
- 对照案例到底改变了哪个决定性条件？如果结论相同，是否仍揭示目标关系？
- 有依据的典型困难、对本学习者已观察到的困难和分析者猜测，是否分开？

这里可以直接提供解释和示范。并不要求先给学习者做诊断，也不要求每个概念都变成一道题。

## 6. 与 Encoding／Post-Encoding 交接

上游先提供学科对象和理由，下游再选择认知操作。以下表格只保留会影响本单元设计的行。

| 上游已确认的内容／关系 | 可用输入和参考 | 留给学习者的实质工作 | 下游设计需要解决什么 | 什么表现支持目标，什么仍不能证明 |
|---|---|---|---|---|
|  |  |  | 如何呈现、组织、比较、恢复、整合或选用 |  |

若下游发现内容难以解释、对照无法区分、任务靠标题即可答对，应回改上游分析。不要通过换一个认知策略名来掩盖内容缺口。

## 7. 设计能改变判断的证据

为当前关键能力准备具体任务；真实表现出现前，以下都只是证据设计。

| 能力主张 | 可观察表现 | 具体任务及帮助条件 | 可能碰巧答对的途径 | 如何区分其他错误原因 |
|---|---|---|---|---|
|  |  |  |  |  |

不要将一次正确答案直接写成“掌握”。同一错答也可能由多个原因造成。仅当判断会影响下一步教学时，再补一个有区分力的观察。

## 8. 用作品验收分析

先读实际讲解、任务和参考，再看作者的质量声明。

1. 能否沿一条具体关系从问题、依据一直走到判断，不靠专家自行补桥？
2. 核心假设、证据类型和适用边界是否明确？
3. 材料简化是否保留了本次需要理解的结构？
4. 任务是否真让学习者承担目标判断，还是已由题目代做？
5. 与分析前相比，哪些解释、例子或任务的修改、保留、删除、暂缓决定获得了更可靠的依据？

发现缺口后回查对应资料或具体作品，不统一扩展为整门学科研究。

结束记录只需说明：本次内容上已核实什么；哪些教学判断仍是假设；尚缺什么依据；对当前范围是否构成障碍。内容审查通过不等于实际教学效果已经验证。
