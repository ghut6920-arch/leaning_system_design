# 跨次复用与变更

依据 D07 第九、十一、十二节，D06 第七、八节，D08 第三至六节，以及共享契约的控制、删除和纠错。

## 依原记录维护

分开通用资源、本次配置、实际活动与效果解释。通用包保存原 ID、完整约束、版本和研究边界；个人 `MethodConfig` 保存在学习工作区，引用当前工作和实际借用；活动、原答、帮助和时间只由 C0 原事件维护；能力判断由 AG3 维护。候选不算执行，推荐不算采用，采用也不算学习已发生。

复用前核当前目标／判据、材料用途、允许资源、前置、实际暴露、预算、父任务及限制是否相容。没有变化就引用稳定配置，不重新冷启动。恢复依据是有效安排和最后可信原件；无记录的最后帮助或动作保留未知，换会话或换执行者不重置暴露。

使用反馈至少能定位实际采用与未采用部分、任务／事件修订、帮助、返回结果、结束原因和成本。精确用时取不到时写有来源的粗估或未知；准备、核验、反馈、恢复与收束都属于成本，不能只算对话轮数，也不把延期报成节省。时间按目标操作和相关接触解释，一处新帮助不机械重置整个主题历史，未知接触不等于无接触。

维护决定可为复用、调整、合并、暂停某用途、退出当前个人配置或保持未知。给决定的条件、证据边界和下次触发，不形成“此人不适合某策略”的稳定标签。成本或用户偏好可以支持实践更换；单次重大内容问题足以限制有关用途。有限成功或先 A 后 B 的改答不能证明 B 的因果优势，条件不可比时保留未知。

## 来源及配置变化

改动前后保留具体来源／配置修订及差异，区分措辞、前置、关键操作、反馈与证据条件。`previous_config` 指确切旧修订，不能只写旧名称。兼容部分可继续引用；实质冲突先限制有关用途，由 AG1 复核配置，AG2 核内容，AG3 审历史判断，AG0 修实际误导，影响承诺时才交 SK05。

`change` 只从已记录引用定位依赖，不等于找齐语义影响；未能排除的依赖保持未知。通用资源修订不会自动改历史事件、原答、判断或日期，也不会自动解除旧限制。JSON 与 Markdown 若出现实质冲突，记录冲突位置和影响，不默选永远权威载体；不冲突且有据的部分可继续。

删除先限制，然后清受控范围内个人配置、使用分析、候选／临时摘录和验证副本，并终止受影响上下文。策略摘要不能重建已删原答；迟到旧配置在读取／落盘前重新查删除与当前控制。通用原始策略不是用户个人档案，退出个人配置不删除原卡；若通用资源曾混入个人正文，应作为受影响副本清理。

通用 Skill、角色和资源的修改应形成开发维护改动，经原文核对与验证后发布；学习使用反馈只成为维护依据，不自动修改当前安装包。开发态共享文件系统与角色名不能认证专业维护者。真实宿主的身份、输出隔离、外部副本和上下文清理仍须单独落实。
