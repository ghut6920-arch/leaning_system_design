# 实际学习材料与连贯示范 / revision 1

身份：待审查备课输入，尚未作为正式教学呈现。允许分段使用；本文件不是学习者原答。文中的小数、张量与教师代码都是教学材料，不能转为用户已理解／已运行的证据。

## 1. 从一个新位置的工作看 Attention

考虑一个固定参数的因果 decoder。输入 token 经嵌入与位置处理成为向量，各层将当前位置的表示转成 Query、Key、Value。Query 用来向当前可见历史寻求相关信息，Key 参与匹配，Value 是被加权混合的向量。它们是学习到的表示；“键”和“值”并非把原文原封不动存进字典。[原 Transformer §3.2](https://arxiv.org/abs/1706.03762)。

对某层、某个 head，第 t 个位置的运算为

\[
s_{tj}=q_t k_j^\top/\sqrt{d_h}+m_{tj},\qquad
\alpha_{tj}=\frac{\exp(s_{tj})}{\sum_{r\le t}\exp(s_{tr})},\qquad
o_t=\sum_{j\le t}\alpha_{tj}v_j.
\]

合法历史位置的 m 为0，未来位置为−∞；等价布尔 mask 必须让非法项完全退出 softmax。把非法 score 乘0会令其变成0，exp(0)=1，仍然获得权重。多头把各头结果合并再投影，之后残差、逐位置归一化与 FFN 接到下一层；本单元只展开会影响缓存正确性的依赖。

全序列 Q 的行对应查询位置，K/V 的行对应可读取位置。一种常见逻辑布局：每层 K、V 各为 [B,H_kv,T,d_h]；Q 为 [B,H_q,q_len,d_h]。MHA 的 H_q=H_kv；GQA 每组多个 Query heads 使用同一 KV head。库的具体轴序可不同，语义与位置映射必须相同。

## 2. 一行完整示范：旧 KV 不变，新权重会变

为看清运算，给定一个单头的局部输入，d_h=1。这里直接给 Q/K/V，暂把投影当黑箱：历史 k=[1,0]，v=[2,6]；新增第3个位置的 q_3=ln2，k_3=1，v_3=10。

| 步骤 | 对象与操作 | 结果 |
|---|---|---|
| 读缓存并追加 | 保留 k_1,k_2,v_1,v_2，追加 k_3,v_3 | K=[1,0,1]，V=[2,6,10] |
| 新 Query 匹配 | ln2×[1,0,1]，缩放因子√1=1 | score=[ln2,0,ln2] |
| softmax | exp 得 [2,1,2]，总量为5 | α=[2/5,1/5,2/5] |
| 混合 Value | (2/5)×2+(1/5)×6+(2/5)×10 | o_3=6 |

无缓存版本若重算该完整前缀，再取第3行，只要得到同样的 q_3、K、V，就得到同一输出6。缓存版本节省历史 KV 的重新生成及历史位置的重复层计算；它仍计算新的 score、softmax 和 V 混合。

保持同一 q，假如只对旧两项算 attention，权重为 [2/3,1/3]，输出10/3。加入新项后，旧两项权重成为 [2/5,1/5]，不是直接沿用旧值。通常新位置的 q 也会变化；这里特意固定 q，隔离“softmax 分母改变”这一关系。旧 Query 的旧输出也没有被“改写”：它仍受其原来的因果可见范围约束。我们比较的是新查询行，不是让旧位置回头看未来。

本例只核一层一头的运算。两层代码使用另一组固定参数，负责让上下文化 K/V、位置及层间依赖可见；两者解释同一机制，数值不能跨模型混用。

## 3. 为什么高层的 KV 也能保留

令 h_i^0 为 token i 的嵌入及固定位置处理结果。第 l 层的 k_i^l、v_i^l 来自 h_i^{l−1}（含该层规定的逐位置归一化／位置变换）；高层输入已经包含前文信息，不只是静态词向量。

先固定模型权重、token 前缀、位置编号及位置算法、因果可见关系、逐位置运算和推理数值约定；关闭会引入不一致随机性的训练 dropout。追加 token 时：

1. 对旧 i，h_i^0 不变，因为 token 与位置没变。
2. 假设全部旧位置的第 l−1 层输入不变。该层旧 i 的 Q/K/V 不变；它依旧只能读取 j≤i 的相同 K/V，softmax 集合与 FFN 等操作相同，因此 h_i^l 不变。
3. 沿层归纳，所有旧位置的逐层 KV 不变。新 t 在第一层用第一层缓存求 h_t^1，再由它生成第二层新 Q/K/V，如此向上；每层各追加一行，得到与全前缀同一新位置输出。

这是理想确定性计算的等价理由；实际浮点运算因内核和累加顺序可能有小差别，要用恰当容差检查 logits。数学等价不承诺任何硬件上的 bitwise equality，缓存也不要求 Q 从来不存，而是标准自回归下一步无需历史 Q 来计算新行。

“只保存 token 嵌入便能替代所有层 cache”不成立。第二层 K/V 来自第一层的上下文化表示；少了逐层历史状态，仍需重新建立它们。细节可对照代码中的 layers、full_forward 和 append，以及教师运行摘要。

## 4. 一条生成时间线

设 prompt=[A,B]。模型在 prefill 中同时处理这两项，但通过因果 mask 保持各位置的可见范围。

| 时刻 | 本次送入模型 | 完成后各层缓存位置 | 最后 logits 用途 |
|---|---|---|---|
| Prefill | A,B | A,B，长度2 | 预测第一个生成 token C |
| 选择 C 后 | 暂无新 forward | 仍为 A,B，长度2 | C 尚未因“被选择”自动入 cache |
| Decode 第一步 | C，位置2（从0编号） | A,B,C，长度3 | 预测下一 token D |
| Decode 第二步 | D，位置3 | A,B,C,D，长度4 | 预测下一 token E |

因此，生成 G 个输出 token 时，通常先由 prefill 选第一个，再处理 G−1 个生成 token 来预测余下输出；若要把最后输出也纳入缓存或继续预测，再送它一次。材料中的 N 专指 prefill 后实际送入模型的新增位置数，不偷偷把它与输出个数混成同一变量。[PagedAttention §2.2](https://arxiv.org/abs/2309.06180)。

## 5. 节省什么，长历史仍付出什么

只比较固定层数与维度的普通 dense causal attention。Prefill 长P时有 Θ(P²H_qd_h) 的 attention 算术；投影与 FFN 还有对P线性的成本。Decode 新输入一行、当前可见长度T时，该行 attention 是 Θ(TH_qd_h)，新 Q/K/V 投影与 FFN 只做这一行。

定义无缓存基线为“每次重新运行整个增长前缀”，包含初始prefill的累计attention成本为 Θ(P²H_qd_h)+Σ_{r=1}^N Θ((P+r)²H_qd_h)。缓存路径为 Θ(P²H_qd_h)+Σ_{r=1}^N Θ((P+r)H_qd_h)，即 attention 部分 Θ((P²+NP+N²)H_qd_h)。N=0时两者均只做prefill。投影／FFN 的累计新位置工作也由重复全前缀降为处理P+N行。具体 head／层常数、算术精度和实现不同，不由这些式子推实测加速倍数。

缓存并没有把长上下文 decode 变成常数时间：新 Query 仍需读取本应可见的历史。逻辑 KV 读取规模随T增长；GQA 可以降低需要读取的不同 KV 数据量，但真实 HBM 流量还依赖内核复用、batch、布局等。显存带宽常是重要约束，但判断“本机就是带宽瓶颈”须有 profiling。小 Python 算例只统计逻辑工作，不测 GPU 吞吐。

教师程序按允许的因果 pair 实际计数，不计算被 mask 的上三角；普通密集矩阵内核可能仍执行相关算术。三角有效 pair、矩阵尺寸、真实 FLOPs 与墙钟时间分别解释。

## 6. 逻辑 KV 容量

每层每个位置有 K、V 两份向量；batch B、层数L、KV头数H_kv、每头维度d_h、每元素s字节：

\[
M_{KV}=2LBTH_{kv}d_hs\quad\text{bytes}.
\]

T 包含 prompt 和已送入模型的生成位置。若 batch 中有效长度不同，应按各请求 T_b 求和；矩形 padding／预分配可能按最大长度分配，实际容量还需查实现。1GiB=2³⁰ bytes。[GQA §2](https://arxiv.org/abs/2305.13245)。

主例 L=32，B=1，T=32768，H_q=32，d_h=128，fp16 的 s=2：

| 架构 | H_kv | 逻辑 KV | 对照的成立条件 |
|---|---:|---:|---|
| MHA | 32 | 16GiB | 每个 Query head 对应独立 KV head |
| GQA | 8 | 4GiB | 每组4个 Query heads 共享 KV |
| MQA | 1 | 0.5GiB | 全部 Query heads 共享一组 KV |

这张表比较三种架构的容量，不证明其相同质量或同一权重。现有 MHA 转 GQA/MQA 通常涉及模型权重转换／再训练和质量验证；不能删除几个 head 的缓存当作等价实现。

![不同KV头数的逻辑容量及双请求长上下文对照](E:/文献资料/学习系统架构设计/learning/embodied-intelligence/artifacts/lesson-preparation/2026-10-11-transformer-kv-cache-r1/figures/kv-capacity.png)

容量式未计权重、临时激活、attention workspace、页表、分配器碎片、量化比例因子、对齐与设备副本。因此“KV 低于卡容量”不足以判可运行。若量化到8bit，纯数据项s=1，但额外元数据与质量误差仍需计入；若 offload 到主存，GPU KV 压力可降，传输成本仍在。[HF 固定版本 Cache strategies](https://huggingface.co/docs/transformers/v4.57.1/en/kv_cache)。

## 7. 优化方案改变的对象

| 做法 | 实际改变／节省 | 成立条件和代价 |
|---|---|---|
| KV Cache | 复用已算出的逐层历史 KV，避免重复旧位置计算 | 需要有效前缀；容量随长度与并发增长 |
| FlashAttention | 对 exact dense attention 分块并合并 softmax，减少中间矩阵的 HBM 访问／物化 | 仍处理 dense 配对，算术量不会因此变为线性；不删除持久 KV；内核／硬件决定收益 |
| PagedAttention | KV 按块管理、逻辑到物理映射及合法共享，改善碎片与分配效率 | 单条唯一序列的逻辑 KV 数据量不因分页消失；共享要满足相同前缀状态，页管理也有开销 |
| GQA/MQA | 减少不同 KV heads 的数量 | 是模型结构选择，不能默认为原 MHA 语义等价；质量取决于训练／转换与用途 |
| KV 量化 | 降低数据字节数 | 有元数据、量化误差及内核成本；不能默认 logits 完全相同 |
| KV offload | 将部分缓存放主存等设备 | 传输和调度影响延迟，主存也有容量限制 |
| Sliding window／丢弃旧 KV | 减少可见历史或近似状态 | 原模型若本就规定窗口，可按原 mask 精确实现该模型；原 full attention 改为丢历史则改变依赖，不再等价 |
| RAG／摘要／压缩 | 改变送入模型的文本、选择外部证据或表示 | 可能省 token，但检索遗漏、摘要丢信息与生成质量须核；不等于持久 KV 管理 |

FlashAttention 与分页、GQA 等可以组合，因为它们作用的对象不同。组合是否有净收益要查实际内核、工作负载和资源，不以方案数量判断。[FlashAttention §3](https://arxiv.org/abs/2205.14135)，[PagedAttention §3–4](https://arxiv.org/abs/2309.06180)。

## 8. 长上下文推理需要三类不同证据

模型接受某个长度，是位置机制、训练分布与实现上限的问题。机器装得下并能处理，是容量与计算／传输问题。任务能可靠利用远处证据，是行为质量问题。KV Cache 解决重复运算的一部分，不能独自保证后两者，更不能改变模型已训练出的能力。

位置编号与位置变换也进入缓存条件：固定规则下相同 token 在不同位置未必有相同 key；若运行中更换 RoPE 配置或重编号，必须核旧缓存是否还对应新计算，不能只拼接shape。RoPE 等技术与长度外推的实际质量要按具体模型、配置和任务验证，不因出现某个位置编码公式就保证无限外推。

Lost in the Middle 在特定多文档问答和 key-value 检索任务、模型与设置中，检验相关信息位置和长度怎样影响表现；它提醒“存在上下文”与“可稳定利用”不同，不能把所有模型／任务都判定为同一 U 型。[论文 §2–4](https://arxiv.org/abs/2307.03172)。该论文的字符串 key-value 检索任务与 attention 的向量 K/V 不是同一个概念。

若真实任务是依据长操作日志解释一项机器人异常，应明确相关证据、干扰信息、必须跨片段连接的条件及答案核验。比较长度和位置时尽可能保持内容、模型、tokenization、生成设置和问题相同；记录实际正确性、引用依据、时延及资源。若同时换模型、上下文、检索策略和提示，单次提升无法确定是哪项造成。这个教学用途是离线推理说明，不证明机器人闭环效果。

## A 的完整连接

Prefill输入IDs [1,4,2]，位置0,1,2，各层缓存长3，位置2的logits预测位置3。固定选定token5但未输入时cache仍长3；输入5、位置3后各层长4，新的logits预测位置4。随后IDs 0,6,3送入位置4,5,6，对应长5,6,7，预测位置5,6,7。IDs为固定控制续接，不是模型能力输出。

第1层KV来自该层输入（toy中token embedding＋固定PE，经逐token pre-LN）；第2层KV来自第1层输出的上下文化表示，经第2层pre-LN投影。不能拿原token embedding投影代替第2层历史KV。教师运行的具体反证：位置1从token4改成6后，未改的token位置2，其第一层KV差0，第二层KV最大差0.02410763630481827；这说明“token本身未改”不足以保证高层KV未改。第一层特例不应扩大到整个模型。

归纳参考：固定旧token、位置、参数、mask/可见范围及逐位置确定性运算，旧h⁰相同；若旧h^{l−1}相同，则旧Q/K/V相同，旧query只看相同前缀，attention与后续逐位置运算相同，故旧hˡ相同；逐层可保留KV。新位置仍要产生当前Q/K/V，匹配全部当前可见Keys、重新softmax、混合Values及做后续层。归纳是一般机制依据，有限代码运行只是对应规格的行为检查。

使cache失效的合法答案包括：旧prefix编辑、模型／adapter改变、不兼容的位置／RoPE变换、改变可见范围、混入另一个上下文的cache、丢失本应读取的KV、与训练随机运算混用等。并非每个改动必使所有输出数值不同；判据是是否保有同函数依据，不能靠某次碰巧相同批准整个实现。

手算锚点：d_h=1，score=[ln2,0,ln2]，exp=[2,1,2]，weights=[.4,.2,.4]，output=6；同一q只看旧两项output=10/3。错误乘mask时非法项变0仍有exp(0)，必须退出归一化。q_len=2、past3的绝对位置mask=[11110;11111]；两层toy chunk logits与full对应行差0。

## B1 容量与共享

每请求：2×32×65536×8×128×2=8589934592 bytes=8GiB。两请求16GiB，已经高于12GiB，管理开销只会进一步增加当前预算占用。

每请求8192-token共有prefix：2×32×8192×8×128×2=1073741824 bytes=1GiB；存一份供两个请求合法共享，相比复制两份只省1GiB，故16−1=15GiB（未计管理开销），仍超过预算。不能把“每份prefix1GiB”误认为总共节省2GiB；两请求共享后的后缀仍各自存。相同token、模型、位置与先前上下文保证状态共享资格，引用计数／copy-on-write等实现仍需核。

T为容量规划上界。若只生成16384个输出且最后一个不再forward，最终实际cache可比该上界少一个位置；保守预留不改变结论，不能因off-by-one省几十KiB就声称16GiB可进入12GiB。batch长度不等时用ΣT_b；实际padding／static预分配另核。

## B2 方案及合法多解

一个直接基线是降低同时活动请求数到B=1：逻辑8GiB，小于12GiB，剩余4GiB留给管理／缓冲；这为容量提供候选可行路径，须确认真实峰值开销。允许排队／顺序处理但不保证吞吐或延迟满足另一未给指标。选择更多GPU／分片也可作为条件方案，需说明硬件投入与通信条件未授权或未给，不能在本轮自动执行。

其他候选：

- Offload：保留完整KV及可见集合，将部分层缓存放主存、适时传输；数值搬运本身不必有损，但GPU峰值含当前层、预取／缓冲及管理，不能许诺“只驻留一层”。要测主存容量、host↔device带宽、prefill／decode峰值及请求延迟。
- 8bit KV量化：仅纯数据项由16降到8GiB，管理、scales、residual与workspace另计；量化改变数值，需质量验证。若要求原精度严格同函数，它不满足；本题允许提出待验证有损候选，不能当已采用。
- 合法prefix共享＋分页：减少共有prefix复制与分配浪费，本规格仅省1GiB仍不足；可与B降低／offload组合。碎片是否是本机瓶颈尚无测量，不称paging必提速。
- 改为更少KV头的模型：对固定GQA不能直接开关成MQA；涉及模型变化、训练／转换和质量验证，作为另方案必须说明这些前提。
- RAG／摘要／输入压缩／截断：可能省token，但改变业务证据或输入，当前不能无验证上线。若有可靠可查原文且召回评估，可讨论检索式替代；所有日志都必须进full attention时则拒用。

无法独自满足当前容量硬条件的做法：FlashAttention减少attention中间物化／IO，但不把16GiB持久KV变小；分页不删除唯一请求的逻辑数据，当前共享后仍15GiB；“启用cache”已经是容量式前提，不能再当减容量方案。有损删旧KV破坏原full-attention依赖。以上任一有依据说明即可，不要求逐名复述整表。

评分看约束→资源计算→方案作用对象→边界／未定→验证这条链。合理且可解释的组合可合格；不以教师首选B=1排斥其他条件成立的路线。没有延迟上限、硬件带宽或实际开销时，应保留相应决定未定。

## B3 成本与证据

固定H_q与d_h，单步新的attention行对T项做score和混合，Θ(TH_qd_h)；新投影／FFN只做一行，不能推出整个模型该步为常数。Prefill attention Θ(P²H_qd_h)，累计N个已处理新位置的缓存attention Θ((P²+NP+N²)H_qd_h)；重复全前缀基线含初始prefill，为Θ(P²H_qd_h)+ΣΘ((P+r)²H_qd_h)，并含重复投影与FFN。N为真正forward的新位置数，通常G个输出token对应N=G−1；是否把最后输出再处理须声明。允许用求和表达而不化简；N=0只剩prefill。

长T时历史KV读取量增长，与日志相容；现有日志只能确定耗时随长度上升，不足以判明memory-bandwidth瓶颈、分页碎片、kernel效率或各部分占比。可靠观察包括相同模型／batch／precision下分别测TTFT或prefill时间、inter-token latency、tokens/s、GPU峰值memory，利用profiling查看kernel与HBM/transfer；同步／预热与重复条件需声明。若只研究逻辑机制，不必实际执行profiling。

教师toy实际统计：长度3,4,5,6,7五次观察，Q/K/V跨层合计行数150→42；理论dense score元素540→124；实际合法causal pair320→112。完整prefix复算并非最优无cache实现，这个明确基线用于展示重复工作；不将该比值写成生产加速倍率。

## B4 长上下文质量比较

可接受设计：先选一个答案可核查、必须跨两片段才能成立的问题及明确原文证据；固定模型版本／位置配置／tokenization／问题／解码设置与证据内容。控制相同长度下把证据整体放首／中／末（保持两片段关系，不用偷改问题难度），再在保留证据的情况下改变干扰长度；标注实际token位置。记录正确性、关键理由是否由证据支持、引用定位及资源失败／耗时。短且只含必要证据的oracle输入帮助区分知识／推理困难与长输入干扰；如果oracle也错，不把长上下文视作唯一原因。

合法替代可以固定目标位置、改变长度，或分别研究两片段距离，但需说明新增难度与不能完全独立的因素。单次正确、字符串检索正确或上下文被接受都不足以证明多跳推理可靠；统计样本与真实基准范围未知就只提出有限观察计划，不填准确率。KV函数等价验证与任务质量比较是两个不同层面。

04的实际日志例子参考为permit=false：E1要求三个条件同时成立；E2中前两项满足，但L7≠L8，第三项不满足。应引用规则与当前快照共同说明，不将历史报表中的旧检查值替换当前快照。该微型例子核给定规则的跨片段条件组合；不能把一个例子当真实机器人安全、复杂多跳或全部长上下文能力的保证。用它拟定B4比较时，原文及问题保持、位置／干扰变化、oracle与资源失败记录都可回查；没有实际模型运行就只交观察方案。

## C 的条件更新

C1：对一般多层因果decoder，所有层可共同沿用的位置0…999；从1000起按新token与旧不变token序列重建各层受影响后缀。1001以后的token虽未改，其高层状态可能依赖1000，不能只补单token。可以保留更细的某层未受影响项，前提是有具体依赖证据与正确接口；本题保守有效前缀重算是可靠方案。

C2：不能直接认定旧cache适配新位置规则。按新规则重建相应前缀是保守路径；若提出合法变换算法，须证明它同时保持各层上下文化状态和目标得分，不只改旧K的外层旋转。个别同规则位移／可逆变换或长度独立配置可能有特例，已知信息未提供相应证明，应写未定，不武断声称所有变换都不可能。

C3：窗口是新部署模型本来的语义，严格按每层可见范围保留KV可精确实现该窗口函数；与“把原full模型突然砍成窗口”不同。当前Query对4096个位置可为attention Θ(4096H_qd_h)，KV有相应窗口上界，但层数、prefill实现、位置策略及其他开销仍在。窗口外信息若通过此前层状态已经传递，不能把有界缓存说成模型完全没有远历史影响；也不保证原full模型质量或无限上下文能力。若混有full层、sink/global token或其他attention规则，需按具体层保留，题面已声明各层严格窗口，不能自行补成另架构。

## 先于成品提出的专业问题

### R1：新增 token 后，为什么旧 K/V 仍代表同一个计算对象？

应能够把“因果遮罩禁止看未来”连到“固定前缀的旧位置在每层的表示不因后续 token 追加而改变”，再连到“每层旧 K/V 可复用”。只说 K/V 是历史记忆或计算很贵，不承担这一连接。模型参数、既有 token、位置／位置变换和注意力条件一致，推理计算确定；前缀被编辑、权重变更或位置解释变化时必须重审。双向 self-attention 不能未经限定套用同一增量复用理由。无需将全部条件另出题，但正文和参考应保留必要成立条件。

关系检查也包括：新位置仍须产生当前 Q/K/V；新 Q 与缓存 K 得到当步权重，再混合缓存 V。旧 Q 对“只求最新位置输出”的当步目标无必要，不能误说 Q 无法缓存。缓存按层存储，不是一个跨层通用 token 字典。[官方缓存说明](https://huggingface.co/docs/transformers/main/cache_explanation)与[原 Transformer 论文](https://arxiv.org/abs/1706.03762)提供对象依据；逐层不变性须在成品中用因果依赖关系解释。

### R2：一次 prefill 和一次 decode 的输入、输出、cache 长度如何连起来？

长度为 P 的 prompt 经过 prefill 后，最后位置输出预测第一个新 token y1；y1 尚未进入缓存。再以 y1 为新输入得到其表示／K/V，并预测 y2，此时 cache 长度为 P+1。材料中的 token 名称、当前位置、序列长度、输出预测对象应一致，防止把“预测出来”与“已送入模型”混为一件事。若示范是固定 Q/K/V 的 attention 内核，必须说明它没有演示词表 logits、采样或完整多层语言模型。

### R3：示范能否让一个新 Q 的计算与无缓存路径逐项对应？

需要实际输入、维度、scores、softmax 与 V 混合，以及追加后的 K/V。足够小的可核数值、清楚的矩阵／表或实际图可以承担，不统一要求交互媒体或程序实现。应把旧结果不变与新行注意力改变分开：新 token 可以改变当前行的权重和结果，却不回写旧行。若展示缓存／无缓存结果一致，参考应查相同权重、位置、掩码与精度条件；有限数值运行只核该实例，不能代替一般理由。遮罩在 softmax 前排除不可见位置，不能只把未遮罩分数乘零而使其仍获得概率。

### R4：“长上下文快了”究竟省掉什么，仍须做什么？

应区分 prefill 全序列的注意力工作、一次 cached decode 的当前行工作，以及生成 G 个 token 的累计工作。标准 dense causal attention 的 prefill 仍有二次长度项；cache 使最新位置不必重算全部历史层状态，但新 Q 仍读取／比较可见历史 K/V。注意力项可写为单步约 O(T d_h)，累计为 O(GP+G²) 的长度项，而不是“缓存后长上下文整体线性／常数时间”。未缓存的比较基线须明确是否每步重跑整个前缀；不能把某个 attention 项直接当整模型延迟或硬件测速结果。FlashAttention 改变访存和中间矩阵保存，标准精确 dense 算术的二次长度项仍在。[FlashAttention 原论文](https://arxiv.org/abs/2205.14135)支持访存与精确注意力的区别。

### R5：容量变化为何改变选择，算出的是什么容量？

在各层配置相同、完整 dense KV、key/value 头维相同的约定下，逻辑数据量为 2×B×L×T×H_kv×d_h×s 字节。长度、并发批量与每元素字节数的变化要能回到实际存储对象。MHA、GQA、MQA 比较用 KV 头数，不能误用 Q 头数；真实显存还包括参数、工作区、分配／分页开销等。逻辑容量／剩余显存足够不构成速度或整体服务可行性证明。公式、单位和假设有可靠参考，具体材料应容纳预算不足或信息不足的可靠结论。[GQA 原论文](https://arxiv.org/html/2305.13245v3)说明共享 KV 头以及 checkpoint 转换和后续训练；原 MHA 模型不能只在推理时删头就宣称无损切换 GQA。

### R6：上下文已进入 cache，为什么仍不能保证任务信息被可靠利用？

需要区分可存储、可计算、位置／模型支持范围和实际任务质量。缓存保存计算状态不能证明模型正确检索、整合或推理。长输入的任务证据可受信息位置、干扰内容、任务类型影响；判断应限定到所用模型／任务与比较条件。若采用 Lost in the Middle，只能说明其已测模型与任务上出现的位置敏感现象，不能推出所有当前模型永远同样失败或“中间位置必然没用”。[Lost in the Middle 原文](https://arxiv.org/html/2307.03172v3)提供这种证据边界，不提供当前单元的学习者表现。

### R7：优化方案改变的对象与代价是否匹配当前瓶颈和任务？

成品应能够在已介绍的少量方案中作有条件判断：访存／中间矩阵、逻辑 KV 数据量、物理分配／共享、跨设备搬运、可见上下文分别是不同对象。不能把页式管理、FlashAttention、GQA、低精度、offload 与滑窗全部说成同一种“压缩”。某方案可保持给定注意力语义，另一些改变数值精度、模型架构或可见 token；质量和延迟收益须有相应证据。审查不要求囊括所有工程技术，但实际主线采用的方案应有足够输入供比较，题面不能只给名称后让学习者猜关键前提。

# 学科实质研究：KV Cache 与长上下文推理

日期：2026-10-11。用途：测试备课成品审查。实际职责：备课子 Agent 按 AG2/SK02 承担有限学科研究；本稿是教师备课依据，没有学习者作答、学习效果或真实进度判断。实际读取的框架规则及原始专业来源见 [02-source-register.md](02-source-register.md)。本稿早期的核心结论已交主入口，再由主入口完成认知设计与成品编排；不声称本稿自身完成全部教学转换。

## 1. 从原用途确定研究对象

本单元要解释的工程问题是：同一份长前缀的因果 Transformer 每生成一个 token，为何有的计算可保留，有的工作必须再做；省去重算后，长上下文为何仍可能占满显存、变慢，甚至回答失败。方法选择必须同时守住三个不同判据：与指定模型的全量推理结果一致；存储与时延满足约束；在实际任务上能使用远处信息。一个判据满足不能替另两个作答。

限定模型：标准自回归 decoder，固定模型权重，确定性推理，因果自注意力，逐 token 的归一化、残差和前馈模块；以下主公式取各层同样的头维度且 K/V 维度相同。不是任意 Transformer、双向 encoder、跨 token 归一化或所有特殊 cache 实现的通用结论。MQA/GQA、分块 kernel、缓存淘汰、量化与检索分别讨论，不把它们归为同一种优化。

## 2. 可复用的理由：层内公式与跨层不变量

令第 l 层输入到位置 i 的状态为 h_i^(l-1)，Q/K/V 是相应输入的投影，可能还按该模型加入位置变换。单头因果注意力写为：

\[
s_{ij}=q_i k_j^T/\sqrt{d_h}+M_{ij},\qquad
M_{ij}=\begin{cases}0,&j\le i\text{ 且未被其他规则遮罩}\\-\infty,&\text{其他情况}\end{cases},
\]
\[
a_{ij}=\frac{e^{s_{ij}}}{\sum_{r\le i\text{ 且可见}}e^{s_{ir}}},\qquad o_i=\sum_{j\le i\text{ 且可见}}a_{ij}v_j.
\]

至少须有一个可见位置，使 softmax 有定义。工程上允许等价的 Boolean mask，不能以把非法 score 乘 0 代替遮罩；0 经指数得到 1，仍会获得权重。[原 Transformer §3.2.1–3.2.3](https://arxiv.org/html/1706.03762v7#S3.SS2) 支持上述注意力定义和因果约束；公式中的本稿记号与条件陈述为局部重组。

只说“旧 token 没变”不能推出多层缓存合法。旧 K/V 来自被前缀上下文化的层输入。以下是基于上述结构的本稿推导：

1. 第 0 层，固定的旧 token、位置及嵌入配置给出相同的旧 h_i^0。
2. 假设第 l-1 层在前缀内相同。第 l 层位置 i 可见的集合仍只有 1:i，其 Q/K/V 与得分都相同，所以注意力输出相同。
3. tokenwise 归一化、残差和前馈没有引入新增位置的依赖，因此 h_i^l 相同。对层数归纳，所有旧位置的各层状态以及 K/V 保持相同。

因此，追加位置 t 时，每层可保留 K_1:t-1、V_1:t-1，只对新输入计算 q_t、k_t、v_t，追加 k_t/v_t，再让 q_t 与当前全部可见 K_1:t 做注意力。这是因果结构下的计算复用，不是近似压缩。[HF v4.57.1 cache 正文](https://huggingface.co/docs/transformers/v4.57.1/cache_explanation) 提供逐层追加和生成循环的工程对应。

未来查询不需要历史 q_i 或历史注意力行，所以标准 KV Cache 不保存历史 Q/权重作为其核心状态。旧位置自身的注意力行可保持不变；新位置的行必须重新算。即使新 q 数值恰好等于一个旧 q，新加入的可见 key 也会改变 softmax 分母，旧权重不能直接拿来用。

缓存有效性要求前缀 token、顺序、位置定义、遮罩、模型/adapter 权重、推理配置和缓存表示保持兼容；数学同一性以相同算术为前提，浮点 kernel 的求和顺序差异通常只能要求容差内一致，不能直接要求 bitwise 相等。精度变化另作有损或数值差异评估。对使用 RoPE 的实现，存储的 K 可能已经旋转，也可能由特定实现保留另一表示；复用必须与其表示契约一致。

编辑前缀位置 j 后，至少 1:j-1 在上述条件下仍可复用；一般不能沿用 j 及之后的多层 KV，应从编辑位置重算受影响后缀。第 1 层某些后继投影可能碰巧不变，不能据此宣布整个多层 cache 有效。把同一个 token 放入不同前缀、改变 RoPE scaling 或把局部窗口重新从位置 0 编号，都需要重审兼容性。对固定双向 encoder 的一次计算，可以保存其结果供 cross-attention 复用；这不能证明不断扩展双向 encoder 输入时，旧状态也不变。

若一次处理 C 个新增 token，chunk 第 r 行只允许看旧 T 个位置及 chunk 内第 1:r 个位置，mask 对齐条件是 j≤T+r。它是带旧前缀偏移的矩形 mask，不能把普通 C×C 下三角图直接套到 C×(T+C) 的分数矩阵上。

## 3. Prefill/Decode 的状态与预测时序

对长度 P 的已知 prompt x_1:P：prefill 可在每层并行计算全部 prompt 位置，但仍使用因果 mask；它保存 P 个位置的各层 KV。最后位置的输出 logits 表示 p(x_(P+1)|x_1:P)，可据此选第 1 个生成 token。刚选出的 x_(P+1) 尚未输入模型，因而这一步结束时 cache 长度仍为 P。

下一次 forward 输入 x_(P+1) 及其合法位置，保存其 KV 后长度为 P+1，再产生预测 x_(P+2) 的 logits。必须区分“选出了 token”与“已计算该 token 的 KV”。需要 G 个输出 token 的通常循环，一次 prefill 后再需 G-1 次单 token forward；最后选出的 token 如未继续使用，不必为它再做一次 forward。[PagedAttention 原论文 §2.2](https://arxiv.org/pdf/2309.06180v1) 明确区分 prompt phase 与 autoregressive phase，并给出该预测索引。

这个时序把三种对象接起来：输入 token 的绝对位置；cache 中已经处理的位置；输出 logits 所预测的下一位置。多 token、padding、batch 和特殊缓存策略必须按所用 API 的契约处理，不能凭张量长度推测位置。固定版本 HF 文档的 `cache_position` 是缓存写入位置接口；模型的 `position_ids` 是位置编码输入接口，两者在无 padding 的简单情形可对应，但不应普遍当成同一个量。

## 4. 一个可接到实际材料的局部数值锚点

采用主入口协调后的单头例：d_h=1，当前 q=ln2，当前完整 K=[1,0,1]，V=[2,6,10]。这里是已给 Q/K/V 的层内算例，不用它证明真实模型中投影的来源。

\[
s=[\ln2,0,\ln2],\quad e^s=[2,1,2],\quad a=[2/5,1/5,2/5],\quad o=6.
\]

假设前两个 K/V 已缓存，新输入的第三个 K/V 必须先追加到可见集合。若误将新位置排除，算得 a=[2/3,1/3]，o=10/3。该对照承担“缓存历史，但当前 token 自己的 K/V 也属于其可见前缀”这一关系；不是另一种合法全量注意力答案。主入口可将它接到 mask、cache 追加及 logits 的具体轨迹。

本稿以 PowerShell 独立核对权重和为 1、输出为 6、排除自身的输出为 3.33333333333333；数值只验证此算例。跨层一般同一性仍由第 2 节归纳承担；主入口另外组织两层代码验证，其随机参数与此算例不同，不声称是一组参数的不同表示。

## 5. 省去什么、仍付出什么

以下为按本稿规格计数的渐近推导，固定模型宽度/层数，不是本机性能实测：

| 对象 | 常见全前缀重复 forward 基线 | KV 复用路径 |
|---|---|---|
| 长度 n 时 Q/K/V 与逐位置模块 | 重新处理 n 个位置 | 一次 decode 只处理新位置 |
| dense attention 每次 forward | 处理前缀全部 query 行，约 Θ(n²H_qd_h) | 新 query 行对 n 个 key，Θ(nH_qd_h) |
| 持久 KV | 基线不复用 | 随已处理长度线性增长 |
| 当前 q 的历史读取 | 重新获得历史 K/V | 从 cache 读取历史 K/V，读取没有消失 |

KV 之后，每个新 token 的 dense 注意力工作仍随上下文长度增加；不能说 decode 从二次变成“整个推理 O(1)”。以 prompt P、输出 G 计，缓存路径的 attention 总量约 Θ(P²+GP+G²)，其中单 token forwards 实际只到 G-1；全前缀重复 baseline 约 Θ(GP²+PG²+G³)。这些式子仅比较同一 dense attention 算法结构，省略层数、头数、维度常数与投影/FFN成本。不同 baseline、chunking 或稀疏/窗口模型不能直接套这项比较。

Prefill 已知多 query 行，更容易形成矩阵乘法；串行 decode 少 query 行，过去 KV 和模型权重的搬运可能成为瓶颈。[MQA 原论文 §2.3–2.4](https://arxiv.org/html/1911.02150v1) 分析这项算术/读取差异。带宽瓶颈是依 workload、硬件、batch、kernel 和实际存储布局而定的判断。不能把“KV 大”直接等同于“此处已经测得 bandwidth-bound”，也不能把 FLOPs 降低比例当成时延缩短比例。

## 6. 逻辑容量与头结构选择

固定 L 层、B 条等长序列、已处理长度 T、H_kv 个 KV 头、头维度 d_h、每元素 s 字节：

\[
M_{KV}=2LBTH_{kv}d_hs.
\]

2 表示 K 与 V。MHA：H_kv=H_q；MQA：H_kv=1；GQA：query 分组，每组共享一组 K/V，1<H_kv<H_q，通常 H_q 可被 H_kv 整除。[GQA §2.1–2.2](https://arxiv.org/html/2305.13245v3#S2) 给出这种结构及从 MHA checkpoint 转换后继续训练的路径。它是模型结构选择；对固定训练好的 MHA 把历史头删掉/求均值，不能声称还是原模型的 exact KV 复用。

主例采用教学假设：L=32，H_q=32，d_h=128，B=1，T=32768，s=2。独立计数与数值核对得到：

| 模型头结构 | H_kv | 逻辑 KV 字节数 | 二进制容量 |
|---|---:|---:|---:|
| MHA | 32 | 17179869184 | 16 GiB |
| GQA | 8 | 4294967296 | 4 GiB |
| MQA | 1 | 536870912 | 0.5 GiB |

同一 GQA 的 T=65536、B=2 情形为 16 GiB；不是 4 GiB。KiB/MiB/GiB 使用 2 的幂，若报告 GB 必须另说明十进制口径。

这些是实际 KV 张量元素的逻辑量；不包括模型权重、工作空间、中间激活、分配器碎片、padding、page 元数据、量化比例尺和 residual 高精度区域，也不直接等于单 GPU 占用。不同层窗口/头维度时应求和；不等长请求是按各 T_b 求和；跨 GPU 分片与 KV 头复制需要据具体部署另算。若量化只有 q bits/元素，不能在未计其他数据时直接把总显存乘 q/16。若因 kernel 把共享 KV 物化成 H_q 头，实际临时量也需另计。

## 7. 合法替代与改变判断的条件

| 方法 | 直接改变的对象与理由 | 本用途的正确性/选择边界 |
|---|---|---|
| KV Cache | 保存因果前缀每层已有 K/V，避免重复投影及旧 query 行计算 | 同前缀/位置/模型等条件下复用；不消除新 query 的历史 attention |
| FlashAttention | 对 attention 分块，以小规模中间状态计算/合并 softmax，避免在 HBM 物化完整 attention 矩阵 | 原 dense 语义可保持 exact（浮点容差另论）；dense算术关系仍二次，不把缓存历史的信息删除 |
| PagedAttention | 用逻辑块到物理块映射保存同一串 KV，避免大连续预留与碎片，并可管理共享 | 不更改逻辑可见 token 集；主要改变实际管理/利用率，不减少单份有效 KV 的元素数 |
| Cache offload | 将大部分层 KV 放 CPU，按层取回并异步预取下一层，减少 GPU 驻留需求 | 保留同样值和可见集合时，搬运本身不属于有损压缩；CPU↔GPU传输和调度可能增时延，峰值GPU驻留还包括预取/缓冲 |
| 淘汰、滑窗、稀疏可见集合 | 减少保留或读取的 token 数 | 对原 full attention 通常改变答案；原模型本来就是窗口注意力时，丢掉今后不再可见项可与该窗口模型一致 |
| KV 量化 | 减少每元素位宽 | 需要包括 metadata/residual 的容量核算及误差/任务质量评估；不凭较好benchmark称数学 exact |
| RAG/检索筛选 | 从外部材料取选定证据组成输入 | 改变信息组织和召回约束，可减少输入负担，但不替代输入后 attention/KV 计算；遗漏证据可能改变答案 |

支持关系分别来自 [FlashAttention §1、§3.1–3.2](https://arxiv.org/html/2205.14135v2)、[PagedAttention §4.1–4.3](https://arxiv.org/pdf/2309.06180v1)、[HF v4.57.1 Cache offloading/Quantized cache](https://huggingface.co/docs/transformers/v4.57.1/en/kv_cache)、[H₂O §2、§3.2](https://arxiv.org/html/2306.14048v3)、[KIVI §3.1–3.3](https://arxiv.org/pdf/2402.02750)、[RAG §2](https://arxiv.org/html/2005.11401v4)。本表是针对本单元问题的比较，不把不同论文的吞吐数字拼成同条件排行榜。

若问题是连续预留/碎片导致多请求装不下，page 管理是有根据的候选；若单份有效 KV 已经超过预算，单纯 paging 不够。若保持原 full-attention 输出是硬约束，淘汰本来可见的历史行不能自动合格。若结构已固定，不可把 GQA 当成无需模型改造的 cache 选项。上述条件变化有区分力；“所有方法都能提速”不能支持选法。

Offload 降低的是 GPU 驻留需求，逻辑 KV 总量没有因此消失；有足够CPU容量但链路慢时，可成为装得下且较慢的合法选择。量化亦有转换开销，不能承诺显存减少一定带来单请求更快；固定版本HF文档特别指出短上下文且显存充足时量化可能伤害时延。本机未运行该库或GPU，不把文档行为当成本机验证结果。

## 8. 长上下文：存得下、位置合法、使用得好

以 RoPE 为必要位置锚点：在二维子空间，R_p 是旋转角 pθ 的矩阵，q'_p=R_pq_p、k'_j=R_jk_j，故 (q'_p)^Tk'_j=q_p^TR_(j-p)k_j。相对位置进入得分；旧旋转 K 与新 q 必须使用兼容的坐标和频率。[RoFormer §3.1–3.2](https://arxiv.org/html/2104.09864v5#S3) 提供此构造。定义对大位置可计算，并不证明训练模型对未见长度可靠。

[Position Interpolation §2.1–2.3](https://arxiv.org/pdf/2306.15595v2) 将位置 m 映为 mL/L'，使扩展窗口回到原位置范围，并结合模型适配实验；这是位置机制与训练/评估的问题。不能仅加显存或改 max length 得到其质量保证。改变位置映射后，缓存里的表示契约也必须重新兼容，不能一边保留旧 scaling 的 K，一边给新 q 用另一 scaling。

[Lost in the Middle v3 §2–4](https://arxiv.org/html/2307.03172v3#S2) 在特定模型的多文档 QA 与 JSON UUID 检索中控制相关信息位置、输入长度，观察到部分情形中间位置表现较弱；部分模型在 UUID 任务近乎完美。该发现支持做位置/长度控制评估，不是“所有模型必然遗忘中间”的定理，也没有证成单一因果解释。这里 JSON 的 key/value 是文本任务数据，和 attention 投影 K/V 不同。

针对本单元用途，必要检验候选是：固定问题与证据内容，移动证据到首/中/末；改变干扰量而保留关键证据；分别记录正确性与资源行为，增加单一证据 oracle 对照。若增加多跳关系，题目本身也改变难度，不能把全部差异归因于“长度”。这些是教师准备的评估设计候选，没有本机模型实验结果，也不新增真实学习任务。

## 9. 教学转换的内容交接与收口

建议主线保留的必要连接是：因果依赖→按层旧状态不变→每层 KV 追加→当前 query 对完整可见集合重算→prefill/decode预测错一位辨认→线性 KV 容量与历史读取→按瓶颈比较方法→位置/任务质量边界。主入口决定认知顺序、学习者工作和支架，不能把这串学科关系名称当成已经提供的讲解。

可直接使用的学科对象：第 2 节公式与归纳连接；第 3 节输入/缓存/logits时序；第 4 节已核手算；第 6 节已核容量规格；第 7 节改变方法适用性的条件；第 8 节有原始研究支持的质量边界。教师参考应能容纳“给定信息不足以判断实际瓶颈”及有条件的组合方案，不能只接受一个技术名。

研究已取得当前有限单元所需核心依据，停止继续扩大全部长上下文技术。未核范围：真实模型/GPU性能、最新kernel兼容表、模型实际长上下文正确率、特殊cache API/分片行为、论文附录证明与全部图表。数值检查与来源核对分别成立，不证明主入口成品已展示、学习者已掌握或学习系统已获得实际教学效果。

## 原件缺口、生成内容和核验身份

1. 实际发生的缺口：PagedAttention、PI、KIVI特定HTML版本失败，改读可访问PDF；这些替代没有冒称缺失版本。截图请求未在当前工具通道获得可读图像，台账保留未核图像边界。核心数学由可读HTML与本稿推导支持，不依赖图片数值。
2. 主稿第2节按层归纳、第3节G个输出的forward计数、第5节求和复杂度、第6节容量和第8节二维旋转是基于限定规格自行推导；不是论文原文翻译、不是新实验发现。
3. 第4节q=ln2、K=[1,0,1]、V=[2,6,10]是主入口协调后采用的教学生成数值对象。独立PowerShell算术核对完成，输出6与排除自身10/3已读回。早期二维候选未采用，主成品使用同一单头手算规格。
4. 容量已独立核对：32768长度B=1的MHA16GiB/GQA4GiB/MQA0.5GiB；65536长度B=2的GQA16GiB。最初另一候选检查出现PowerShell数组语法错误，仅候选算术部分失败；已用带括号的采用例完成成功核算，未把失败称通过。
5. 学科研究、来源读取、数值核对、认知设计、实际成品显示和真实学习证据各有身份。本文没有正式教学呈现或学习者评价；来源与数值核验不支持“学习系统验证有效”的结果陈述。
