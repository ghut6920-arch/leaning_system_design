# 诊断与复核

用于有限诊断、重要复核、争议／纠错重评和删除后的证据维护。依据 N00 的 AG3、SK04、交付与异常，D02 第七至十节、D04 第六至八节、D06 第七节与 D11 第六／八／九节。状态、授权和对象按 [共享契约](../../../../contracts/shared-contracts.md)，受控操作按 [assessment-b3a.md](../../../../contracts/assessment-b3a.md)。

## 常规授权与重要复核

人工文件模式沿用户当前请求、既有授权及专业责任开展检查，见 [SK00](../../personal-learning/references/session-entry.md)；常规评价可在有效边界内直接完成，重要复核仍由具备能力的 AG3 职能承担，角色兼任不增加独立性。以下 `AuthorizationGrant` 结构与模板要求适用于实际调用虚构受控程序，不能当成人工检查先填写对象的门槛，也不能把人工授权冒称宿主认证绑定。

程序中的常规评分授权由 AG3 在自身真实权限范围内授予 AG0；`AuthorizationGrant` 必须限定 grantee、`routine_scoring`／需要时的 `limited_diagnosis`、对象范围、确切判据、可支持结论、升级信号、共享预算、有效性、绑定及是否允许再委派。[常规评分模板](../../../../templates/routine-scoring-grant.json) 只提供可填写的 unbound 授权形状，不是有效授权；角色名、模式名或字段签名也不认证执行者。

重要跳过、复杂完整产物结论、非标准解、评分异议、相反证据、删除影响、重大诊断和结论扩展交 AG3 的相容重要复核授权。AG0 可以保存合法事实并立即限制受影响用途，不凭常规授权自己解除这些限制。当前无人能接重要复核则保持该项待查，已授权且不依赖它的工作可继续或收束。

重要复核先回原任务、原答／完整产物、真实帮助与资源、接触时序、GoalSpec 和先定判据、AG2 的内容核验；尚未读过旧结论时，再读第一评分与教学总结。第二评分尽可能不见旧评分与流程分组，但仍提供评价必需的帮助条件；已经读过则如实作依原件的自查／重评，不假装能忘掉或改称盲评。第二模型重述和共同赞同不构成独立内容核验或新学习者样本。

新合法解应依据原题和原判据验证，不因偏离参考路径判错；必要时交 AG2 重推／测试及多解核验。事实疑误与评分要求分开，判据不清交 AG1。评分冲突用对应操作与依据说明分歧，不按多数、模型级别或到达顺序选结论。

## 有限诊断为当前决定服务

先核原话所指对象、条件及题面／参考，再说清哪些合理解释会改变哪项支持或安排；没有必要强凑两种解释或排除合法第三种解释。观察只需足以改变当前决定且成本相称，先复用已有作品，必要时作指称澄清或有区分力的对照。若解释都导向同一项可靠帮助，直接提供；已有依据充分则继续原工作或结束。不能可靠区分时保留未知，不为命名错误而增加测验。缺关键证据的重要决定保持未作，不能将暂缓本身当已完成诊断。

人工文件记录需要保留诊断决定时，可在既有原答／帮助事件留短段落：可回查观察、暂定解释与反证、实际支持及代做范围、后续反应和父任务返回位置，必要观察、预算、授权及停止条件可引用原活动。实际程序的 `DiagnosticNote` 仍按共享契约与受控接口保存所需字段。两者都不另建心理画像；预备困难不成为个体诊断，慢答或中断不能单独诊断认知能力、疲劳或负荷，提供前提后成功也不能断定原失败“只是提取问题”。

下一观察尽量改变一个相关条件。例如提供必要前提但保留关系推理，或看实现失败位置而保留已合格口头解释。新的帮助本身可能教学，所得成功保留新条件。局部修复后回父产物，反应不符合预测时修订原解释，不能继续沿同一前置无限下钻。

| 停止原因 | 交付及去向 |
|---|---|
| 已有依据够选有限可回退下一步 | 停止追加诊断，保留其他解释及未来区分触发 |
| 下一观察不会改变安排，或继续同类无新增信息 | 明确“不追加检查”及理由；必要时重审任务／解释 |
| 用户要示范、缩时、暂停或预算耗尽 | 转授权教学或收束，保留未知、父任务位置和预算停止 |
| 任务、材料或判据有问题 | 限制依赖范围并交 AG2／AG1，不归为能力缺口 |
| 重要证据暂不可得，或继续取证不值得成本 | 暂不作该重要决定，记录恢复条件，保留不依赖它的范围 |

不设全局题数、失败次数或固定分钟数。有限预算缺失就保持候选，不能无限追问。必要补证提出到同一 `LearningNeed`；连续同类错误更新原需求，已有自然任务能提供证据可复用。需求接责、专业采用、实际安排分别记录，AG3 不自行创建复习队列、调整日期或降低目标。

## 重评、纠错与四个恢复面

疑误出现先立即限制具体受影响用途，再回查合法原答。沿实际引用看两条链：来源／规则到材料、任务、参考、评分、能力判断和安排；以及来源／规则到目标、前置、判据、任务、评价和安排。主题相近不等于依赖，找不到引用不证明无影响；已确认无关范围继续，未知关键依赖保留待查与责任。

| 恢复面 | 主责与结束依据 |
|---|---|
| 当前材料用途 | AG2 对更正内容、版本和当前用途核验，不能替代评分恢复 |
| 历史评分与判断 | AG3 回当时原答、资源、帮助和判据重评，保留修订及限制 |
| 已造成的教学误导 | AG0 说明具体更正，完成必要教学修复；需要时以真实表现观察影响 |
| 当前计划与需求 | AG1 重审要求及错误补课／跳过／承诺，返回实际处置与未覆盖影响 |

四面可分别完成；材料恢复不自动解除其他三面，完成回查也不证明误导已修复。原答已足够就直接重评，不要求用户重考来修系统错误；足够支持答案而未显示推理时，只恢复有据部分。真正缺失且会改变决定的证据才形成需求；新要求不倒判旧答，更正答案不凭空产生能力支持。

## 删除、迟到与失败返回

删除先停用，再通过共享组件清可控原件、摘要、派生、候选、临时、验证与导出范围。停止含删除内容的任务及迟到回传，必要时用仅剩合法材料的新上下文；不能从旧摘要、哈希、测试摘录或“等价原答”恢复已删内容。清理报告区别可控磁盘与不可控宿主历史／外部备份。

AG3 仅以仍合法且可回查的证据作三种专业结果：充分则保留并改合法引用；部分充分则收窄；无有效依据则撤销失去依据的用途并保留能力未知。删除不等于答错或能力下降，不自动补测。迟到“通过”先查当前控制、授权和版本，不能复活已删引用或抢占当前判断。

原件、条件、核验工具或责任不可得时，返回缺项、受影响具体用途、可用部分、未决责任和下一触发。状态冲突重读当前状态重新决定；保存失败保留待保存，不能以程序调用成功宣称采用。接管继承父产物、授权、真实帮助／接触及剩余预算，不能重置样本或暴露。

`WorkResult` 或同字段视图写明处理与未处理范围、结果引用、限制、采用需要及下一责任。后台只交专业结果，由 AG0 按当前条件采用并展示；宿主无法保障身份、输出和写入隔离时，保留单入口顺序范围。开发子代理或测试用 `verified_for_fixture` 不证明 AG0—AG3 已部署。
