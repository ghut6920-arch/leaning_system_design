# AI 个人学习系统：设计流程与工作包

日期：2026-09-26  
定位：依据项目研究与实践库制定的设计路线图。回答“架构之后，怎样把设计方案逐步补完整”，不预先确定系统实现、模型型号、Agent 数量、数据库、调度算法或具体课程方案。

**修订后的核心建议：把“最小目标边界确认＋整体学习流程骨架”合为第一个设计阶段，再以五个主阶段组织后续工作。**原来的十项保留为详细工作包，不再视为十个同等大小、依次完成的阶段。工作包不要求分别对应一个软件模块、Agent 或独立文件。

## 当前设计组织：五个主阶段，以及教学内部的进一步拆分

### 第一项正式设计是什么

对本项目，下一步可以直接开始整体学习流程骨架。用户已明确学习领域、课程驱动、阅读与问答结合、多 Agent 协作及高低层分工方向，足以启动概念设计。先用简短说明确认这些信息，并标出会影响判断的未知项；不必先完成一份详尽的需求文档。

目标、范围和约束是流程设计的依据，流程骨架是第一个主要交付物。二者在同一阶段内相互校正：流程暴露出新的取舍，再补充相应目标或约束。

此时应描述三个尺度的骨架：课程怎样进入并形成学习安排；一次学习怎样开始、推进、检查和结束；学习证据怎样跨天影响复习与后续安排。每个主要环节只说明目的、输入、输出、关键判断及返回路径，暂不细化题目模板、调度阈值和 Agent 名单。

### 五个主阶段

| 主阶段 | 主要工作 | 主要产出 | 下文对应工作包 |
|---|---|---|---|
| A. 建立整体全景 | 最小目标边界、关键场景、三个尺度的流程骨架与主要能力关系 | 整体流程与概念架构 v0；未知项清单 | 1 |
| B. 建立共同依据 | 课程能力与验收、学习者证据与诊断、材料与来源规则；共同术语和记录含义 | 各教学板块共享的基础规范 | 2—4 |
| C. 展开教学设计 | 课前教学准备、通用任务/反馈/测评框架，Encoding、Post-Encoding 子工作包及策略使用 | 教学规则、活动规格、分支与交接条件 | 5—6，按下表进一步拆分 |
| D. 设计持续运行与协作 | 多时间尺度计划、预算、中断恢复、共享状态、Agent 授权与交接 | 连续运行和协作规范 | 7—8 |
| E. 贯通检验与设计收口 | 跨学科和异常场景检查、效果验证、首期范围、架构修订 | 完整设计包与架构 v1 | 9—10 |

这些阶段按成熟程度推进，并非全部串行。B 的三个方向可并行；C 用到的状态与交接需求应同步交给 D；验证、学科差异、用户体验与成本始终贯穿，E 负责综合审查。

### Encoding 的五个子工作包

| 子工作包 | 主要设计问题 | 交付物与边界 |
|---|---|---|
| E1. 本次理解目标与内容结构 | 需要形成哪些关系、条件和推断能力？理解到什么深度足够？ | 本次目标规格；调用共享课程与内容依据，不另建知识库 |
| E2. 初始理解与支架 | 如何依据当前证据选择输入、示范、预测或局部补全？ | 进入条件、帮助配置与撤除原则；使用共享诊断结果 |
| E3. 表征建构任务 | 如何设计比较、解释、实例化、关系补全、表征转换？哪些工作由学习者完成？ | 具体活动的设计规范与组合原则；六类操作作为候选方法 |
| E4. 修订与局部修复 | 错误发生在哪个层级？何时补前置、重审诊断并返回原目标？ | 修订分支与返回条件；复用共享反馈标准 |
| E5. 当前编码收束与交接 | 哪些独立表现足以结束本轮？哪些仍需后续检索、保持或迁移检查？ | 当前退出判据、未解决项和后续检查需求；不直接宣告长期掌握 |

这些是需要分别讨论和交付的设计问题，不是每次学习都必须依次执行的五步。报告的六类操作适合作为方法索引，也不必分别成为设计阶段或 Agent。

### Post-Encoding 的五个子工作包

| 子工作包 | 主要设计问题 | 交付物与边界 |
|---|---|---|
| P1. 检索任务与提示 | 恢复事实、关系、条件还是程序？怎样区分独立恢复、提示恢复与猜测？ | 检索任务规范、线索与提示原则、失败后的处理入口 |
| P2. 关系加工与迁移 | 怎样比较、辨析、抽象、建立关系和应用到新问题？怎样避免错误连接？ | 整合与变式任务规范；复杂时可继续拆为结构整合、迁移应用两个子包 |
| P3. 错误修复与知识更新 | 改答案、关系、规则还是条件？新旧知识应替换还是按情境共存？ | 更新路径、反馈要求、旧错误复发检查；共用反馈与评估标准 |
| P4. 活动组合与动态转接 | 何时检索、开卷加工、补例题或回到 Encoding？何时停止？ | 条件化组合与返回规则；共用策略资源及其定义 |
| P5. 延迟复习与持续验证 | 什么内容需要再次练习或延迟检查？什么结果值得调整后续安排？ | 复习需求、优先理由和检验要求；全局计划统一安排时间 |

P2 若目标和评价差异较大，可进一步拆为“关系整合、辨析与抽象”和“新情境识别、方法选择与迁移应用”。不是为了对称而固定子包数量。

巩固、再巩固可以作为研究约束与机制解释，不要求各设一个系统环节。系统直接设计的对象是可安排的学习活动、间隔、反馈和检验。

### 哪些内容应共享，哪些需要保留差异

共享设计包括：学科内容与来源、学习者状态、证据条件、任务规格、反馈标准、评估判据、策略资源、材料制作、时间预算及记录规则。Encoding 与 Post-Encoding 分别设计这些能力的使用条件和阶段目标，不重复建立两套体系。

学科内容、学习者证据、暂定诊断和当前支架即使统一存储，也要保留语义区别。教学反馈与独立验收即使采用相似题目，也要区分目的与证据条件。

决定是否拆分时，检查是否存在不同的核心问题、输出、判据或错误处理方式；决定是否合并时，检查是否在重复维护相同的状态、标准和资源。一个工作包足够小的标志，是能写清自己的输入、关键判断、输出和检查办法，而不需要临时补齐多个庞大子系统。

## 二、先区分学习顺序与设计顺序

实际学习可能是“阅读—尝试—反馈—再阅读—比较—检索—应用”，也可能从诊断或例题开始。Encoding 与 Retrieval 会交叠，Post-Encoding 也包含循环和分支。

设计工作则应先回答：

**希望形成什么能力 → 什么表现能证明这项能力 → 当前已有何种证据 → 需要安排什么学习活动 → 怎样组织长期计划与协作。**

因此，“评估设计前置”十分关键。它是提前定义证据和判据，不是要求用户在学习前完成一次庞大的认知能力测评。学习者评估既发生在课前，也发生在交互中、撤除帮助后和延迟之后。

总体架构先提供暂定地图。后面的详细设计一旦发现目标、信息或责任存在缺口，就应修订架构，不能把第一次画出的架构当成不可更改的约束。

## 三、十项详细工作包（按上述五个主阶段组织）

### 工作包 1：确定目标、范围、约束，形成流程与架构 v0

**本工作包回答：这个系统首先要帮你完成什么，什么算成功？**

需要设计：

- 区分考试准备、课程理解、研究准备、独立解决问题等目标，以及它们冲突时的优先级。
- 明确覆盖尺度：一个知识单元、一次学习、一周课程、一个学期，分别负责什么。
- 确认时间、精力、费用、课程进度和交互偏好构成哪些约束；未提供的信息保持未知。
- 将“高能力 Agent 主导评估与关键教学设计、中等能力 Agent 承担主要交互与制作”作为已确定方向；具体角色和授权暂不锁定。
- 描述初次导入课程、开始学习、学习中卡住、延迟复习、中断恢复等核心使用场景。

**产出：**目标与范围说明、关键场景、假设清单、总体架构 v0。

**通过条件：**可以用用户最终能够独立完成的任务描述成功；能说明第一版范围，并区分已确定约束和待验证假设。架构图中的每项主要能力都有存在理由。

### 工作包 2：设计“课程要求—能力目标—验收证据”

**本工作包回答：课程表怎样成为有明确学习结果的任务集合？**

需要分清四类输入：

| 输入 | 主要提供的信息 | 单靠它难以确定的信息 |
|---|---|---|
| 课程表 | 时间、主题、课程顺序 | 完整范围、深度、前置知识、评价标准 |
| 大纲 | 内容范围、课程目标、进度 | 用户当前基础、每段材料的具体困难 |
| 教材与讲义 | 具体内容、例题、符号、解释路径 | 用户是否理解、是否能独立应用 |
| 作业与考核要求 | 目标任务形式及预期深度 | 长期保持、真实迁移及个体薄弱点 |

设计重点：把“学习某章”进一步描述为记住什么、区分什么、解释什么、证明什么、执行什么、在何种情境下选择什么。辨认前置关系，但允许随实际表现修订，避免把整个学科都变成前置课程。

能力目标要与验收一起设计。背公式、解释公式条件、自主选择公式、完成推导，需要不同的证据。训练题、诊断题和验收题可以共享目标，但用途和帮助条件必须明确。

同时建立学科差异清单：数学的合法推导，AI 的代码与实验，金融模型的假设与情境，政治讨论中事实、解释和价值判断的区分。这里只确定需要哪些判据，不设计整套题库。

**产出：**课程到能力目标的分解规范、前置关系说明、验收框架、输入资料缺失时的处理原则。

**通过条件：**每类重要目标都有相应的可观察表现；仅有课程表时能够提出暂定安排，并明确哪些内容尚无依据。

### 工作包 3：设计学习者状态、诊断与证据更新

**本工作包回答：系统根据什么判断你现在需要什么？**

至少区分：

- 用户主动提供的目标、背景、兴趣、时间和当前感受。
- 某个领域、主题和子技能上的实际表现。
- 表现条件：是否开卷、是否看过同题、获得多少提示、间隔多久。
- 对错误原因的暂定解释，以及尚未排除的其他解释。

需要设计冷启动、局部诊断、证据累积、判断修订与撤销。一次答错可能来自知识缺失，也可能来自题目歧义、符号不熟、执行失误或当前状态；下一步应取得有区分力的证据，而不是自动贴标签。

“在提示下完成”和“独立完成”都值得记录，但代表不同能力条件。AI 给出的完整解释不能变成用户已经掌握的记录；没有证据时应保存“未知”。

关于认知能力，本系统首先应评估与课程任务相关的理解、辨析、推理、执行和独立重建表现。若未来要讨论一般认知能力，应另立目标与测量方案，不把少量问答升级成稳定能力诊断。

**产出：**学习者信息说明、表现证据规则、诊断与更新原则、暂定判断及不确定性的表达方式。

**通过条件：**相同答案在不同帮助条件下不会被错误地视为同等掌握；系统可以承认不知道，并根据新证据修改原判断。

### 工作包 4：设计材料选择、输入组织与生成内容核验

**本工作包回答：你具体读什么，AI 凭什么认为这些内容适合且可靠？**

这里需要设计的不是一份宽泛书单，而是材料如何落实为可学习的范围，如某节、某个例题、某张图或一段视频，并说明其用途、前置条件、负担和可访问性。

需要区分教材原文、外部补充来源、AI 桥接解释、AI 生成的例题与可视化、评分参考。这些内容的来源和可靠性不能混在一起。

设计问题包括：如何选择可靠材料；阅读困难源于文字、符号还是知识；何时提供简化解释；材料冲突怎样处理；AI 生成错误怎样撤回；原材料更新后是否需要重审先前教学和评分。

材料与教学活动要共同设计。例如，可视化必须说明要帮助辨认哪条关系，以及学习者需要预测、补全、操作或解释什么。制作精美本身不能证明学习有效。

**产出：**材料选择与分段原则、来源和版本规则、生成内容核验原则、材料与教学用途的对应说明。

**通过条件：**能够追溯内容和评分依据；不能用未经核验的生成答案作为证明其自身正确的唯一依据。

### 工作包 5：设计单次教学的共同骨架，再分别展开 Encoding 与 Post-Encoding

**本工作包回答：输入、问答、修订与独立尝试怎样共同促成学习？**

先写清共同的教学判断：何时输入或示范，何时让学习者尝试，何时给提示，何时纠错，何时减少帮助，何时停止或暂缓。再展开两个研究重点。

| 设计范围 | 需要补全的内容 |
|---|---|
| Encoding | 目标知识结构、前置准备、定向与生成条件、关系建立、辨析、具体与抽象转换、局部支架、修订、撤除帮助后的新例检查 |
| Post-Encoding | 需要恢复的内容、恢复后执行的比较/解释/应用等操作、反馈对应的错误层级、更新与边界保留、延迟和变式检验、旧错误复发后的处理 |
| 两者的接口 | 复习中发现结构性误解时怎样回到重新学习；初学时如何调用已有知识；同一目标跨多个会话怎样继续 |

不要给所有课程设定固定的“先问后讲”或固定输入输出比例。需要设计比例变化的依据：知识是否可用、任务是否足够明确、是否需要范例、帮助是否已经过多。

提问设计要说明目标、要求的认知操作、有效回答证据、容易误判的回答、相应反馈和下一步。不能只写一串通用的“为什么”。输出也不局限于文字问答，可以是推导、代码、图、判断、案例分析或真实任务产物。

**产出：**单次教学规范、Encoding 设计说明、Post-Encoding 设计说明、二者的返回与交接规则。

**通过条件：**同一主题面对不同基础和不同错误时，能说明下一步为何不同；“答完所有问题”和“达到当前目标”不再被混为一谈。

### 工作包 6：把实践库变成可审查的策略使用规则

**本工作包回答：面对一个具体缺口，为什么选这项方法，而不是另一项？**

已有报告包含选择与停止的启发式，这一阶段把它们结合课程、学习者证据和教学活动，整理成一致规则。需要覆盖：

- 目标和当前缺口与策略的匹配关系。
- 使用所需的前置条件、可用材料与反馈保障。
- 功能重复、组合顺序和互相干扰的判断。
- 从通用操作卡到具体材料、题目与判据的转换。
- 无进展、负荷升高、前置不足或诊断可疑时如何回退。
- 达到当前目标、预算用完和证据不足时，分别怎样收束。
- 保留哪些策略 ID 与结果，以便复盘策略是否值得继续使用。

快速矩阵可帮助选择任务的方向；60 张操作卡可帮助形成活动。二者都不应直接成为固定流程，矩阵符号也不是效果权重。

可以先用少量有代表性的操作验证规范是否说得清楚，再决定是否覆盖全部条目。这里不需要确定算法、精确阈值或每轮固定操作数量。

**产出：**策略选择、组合、任务化、替换和退出规范；代表性策略的使用示例。

**通过条件：**每项策略能说明针对什么变化、为何适用、如何检查、何时停止；不能因“库里有”就安排使用。

### 工作包 7：设计长期计划、时间竞争与学习连续性

**本工作包回答：单次教学怎样组成可持续的一周、一个课程和一个学期？**

需要区分学期目标、阶段目标、每周资源分配和单次学习安排，明确哪些信息可以改变它们。

重点处理新内容、补基础、检索、变式应用、综合任务之间的时间竞争。课程进度和个人掌握进度可能不同；设计中必须有缩小范围、暂缓、补缺、调整目标和放弃低优先任务的规则，避免所有未完成事项无限累积。

复习设计还需区分第一次学习到检索、检索到反馈、反馈到再测、相邻练习之间的间隔。这里只明确需要哪些判断和证据，不规定所有学科共用的最佳复习时间表。

中断恢复也在本工作包开始设计：本次停在哪里、哪些目标已完成、哪些因预算停止、下一次从哪里继续。完成率、课程覆盖和独立掌握应分别报告。

**产出：**多时间尺度规划原则、任务取舍与重排规则、复习和应用安排原则、中断与积压处理办法。

**通过条件：**时间突然缩短或连续漏学时，计划能够收缩而不是只把任务挪到明天；延迟证据能够反过来修正未来安排。

### 工作包 8：落实多 Agent 责任、共享状态与交接

**本工作包回答：哪些判断交给谁，如何保证换人后教学仍然连贯？**

高能力与中等能力的分工方向可在架构 v0 中确定；此时再依据前面形成的具体教学决策，落实授权与责任。

应设计：高层需要亲自参与的关键判断与材料设计；中层可以自主生成和调整的范围；何时升级；谁能改目标、计划、评分和学习状态；内容分歧如何核验；如何控制重复问答和无边界委派。

高层可以深入设计关键问题、案例和可视化意图，不能只给抽象目标。中层也需要合理的局部调整权，否则实时问答难以适应实际作答。具体边界应由错误后果、反馈时效和成本决定。

共享记录应至少在语义上分清学科参考、任务前置、学习者实际作答、暂定诊断、当前帮助、计划与未完成项。保存范围由后续判断需要决定，不预设无限保存全部聊天。

需要同时确定记录的修改权限、版本冲突、过期处理、恢复时应读取的内容，以及用户查看、纠正、导出和删除个人记录的方式。无需在本工作包决定数据库种类。

**产出：**责任与授权说明、交接要求、升级与冲突处理原则、必要共享信息及跨会话恢复规则。

**通过条件：**关键判断有最终责任归属；高层能追溯关键作答和帮助条件；多个 Agent 的一致意见不被视为独立正确性证据。

### 工作包 9：做跨学科、用户体验与异常场景的贯通审查

**本工作包回答：各板块连在一起后，是否仍然能服务真实学习？**

这一步不是到此才考虑学科与体验，而是将前面持续记录的问题集中审查。选择少量代表性主题进行纸上演练，不需要完整开发课程。

| 审查面 | 需要发现的缺口 |
|---|---|
| 数学 | 是否把类比当证明，是否能核验前提和推导合法性 |
| 人工智能 | 是否只会讨论概念，却无法连接代码、实验、结果解释和诊断 |
| 金融 | 是否保留模型假设、适用条件、数据时间与不确定性 |
| 政治 | 是否区分事实、因果解释、规范判断和竞争理论；是否按证据与论证评价 |
| 交互体验 | 用户是否知道为何阅读或作答，能否要求示范、缩时、暂停、质疑评分 |
| 学习自主性 | AI 是否代替用户完成了目标要求的关键判断；帮助减少后是否仍需检验 |
| 连续运行 | 换 Agent 或会话后是否重复教、漏教，或者把已讲过写成已掌握 |

至少演练基础不足、同错反复、提示下会而独立不会、材料冲突、用户指出题目错误、临时缩时、复习积压和中断恢复。每个案例都追问：依据是什么、谁决定、用户做什么、保存什么、下一步如何改变。

**产出：**学科适配说明、关键交互流程、异常场景清单、跨板块缺口与修订记录。

**通过条件：**核心路径可贯通，异常不依赖临时编造原则；纸上演练仅用于发现设计漏洞，不被当作有效学习的证据。

### 工作包 10：制定验证计划，收束首期范围与完整设计

**本工作包回答：怎样知道设计值得实现，又怎样知道做出来后有效？**

应分别验证四件事：

1. 内容与评价是否正确：资料、例题、参考答案、评分和生成辅助材料能否核查。
2. 教学过程是否符合意图：执行 Agent 是否保留目标要求的认知操作，能否根据新证据调整。
3. 学习者是否获益：减少帮助后的新题、延迟保持、条件选择、迁移、错误复发和提示依赖如何变化。
4. 多 Agent 是否值得：在学习质量之外，检查时间、等待、费用、交接损失和维护负担，并与更简单的流程比较。

评价原则在前面已确定，此处补齐实际试用和比较办法。个人样本有限，内容难度、先验、学习时间和顺序效应会影响解释；不能用几个流畅演示宣布整套系统已被验证。

首期范围应是一条完整而狭窄的学习路径：从课程资料到目标、材料、教学、独立检查、延迟回访和计划修订都覆盖，但只选择有限主题与策略。跨学科适用性可以先用纸上案例审查，再逐步实际试用。

最后修订架构 v0，形成架构 v1、相互一致的板块规格、接口与异常处理、待验证假设、试用办法、首期范围和后续路线。此时再进入模型选型、提示词、存储、工具、界面和实现任务的详细设计。

**产出：**系统验证计划、保留/调整/合并/删除规则、首期设计、完整设计包、后续实施顺序。

**通过条件：**关键承诺可以被实际证据支持或推翻；哪些问题已决定、哪些留待试验和哪些延后都有明确记录。

## 四、顺序有依赖，但不应变成十道串行审批

建议按下列关系组织工作：

**目标与架构 v0 → 课程能力及验收 + 学习者证据 + 材料原则 → 教学骨架与策略使用 → 长期计划及协作连续性 → 贯通审查与架构 v1。**

课程与验收、学习者状态、材料原则可以在共同目标下并行起草。Encoding 和 Post-Encoding 应共享目标、表现条件与反馈语义，再分别细化，最后审查返回路径。

长期计划和 Agent 分工需要教学决策作为依据，可以并行完善；交接所需信息不能拖到最后才想，应随着每个教学判断一起记录。

验证、学科差异、用户控制、证据追溯和成本约束从主阶段 A 贯穿。工作包 9—10 是综合审查与收口，不是首次考虑这些问题。

不必等所有板块写得非常详细才检查衔接。每完成一组关键规则，就用一个小型学习情境走一遍，发现不一致便修订。

## 五、建议设置四个设计检查点

| 检查点 | 应能回答的问题 | 主要对应工作包 |
|---|---|---|
| 目标与证据成立 | 用户要独立完成什么？什么表现算有效证据？资料与状态还有哪些未知？ | 1—4 |
| 教学选择成立 | 面对不同缺口，为什么选不同活动？反馈怎样改变下一步？何时停止或返回？ | 5—6 |
| 连续协作成立 | 计划变化、换 Agent、暂停恢复和资料冲突时，目标、证据和责任能否保持一致？ | 7—9 |
| 验证与范围成立 | 核心假设怎样检验？第一版保留什么？哪些复杂能力可以等待证据？ | 10 |

“通过”指关键问题已经可审查，不表示所有参数已找到最优值，也不要求为了检查点增加重复审批。

## 六、特别容易遗漏的设计工作

**内容纠错与学习者纠错是两条不同路径。** 用户答错时要有补救；题目、资料、AI 解释或评分错时，也必须有撤销判断和重新评估的路径。

**学习评价与系统评价是两件事。** 用户没有学好可能来自教学失配、任务歧义或资源不足；不能只把问题记为个人能力低。

**局部深入必须有返回条件。** 补基础、追问和绘图都可能无限扩展，需要说明原目标是什么、补到何种程度就回去，以及预算结束时保留什么。

**知识更新要保留有效边界。** 新材料可能修正旧结论，也可能只适用于另一情境；不能一律覆盖旧知识。理论、教材、数据和评分规则的版本变化也会影响旧记录的可比性。

**学习自主性要作为可观察目标。** 用户能够自己提出问题、选择方法、识别不知道和判断解释质量，是可逐步纳入的目标；应与具体学科任务结合，不凭自述直接宣布元认知提升。

**长期使用需要维护规则。** 哪些策略反复无效、哪些可视化成本过高、哪些角色应合并、哪些材料失效，需要能据证据简化。保存个人记录的范围与控制权也应设计。

**动机、兴趣和负担会影响实际可用性。** 可以记录用户主动表达的感受、允许选择任务形式，并审查交互是否造成疲惫；不把点击、时长或回答速度直接当成兴趣和认知负荷的可靠测量。

## 七、每个板块都使用同一个简短设计模板

| 项目 | 应写清的内容 |
|---|---|
| 目的 | 解决哪项具体学习或运行问题，与总目标有什么关系 |
| 输入与依据 | 需要哪些资料和表现证据，其可信度、时效及缺失情况 |
| 核心判断 | 需要区分哪些情况，哪些仍有歧义 |
| 行动与边界 | 对应安排什么，何时不适用，什么必须保留给学习者完成 |
| 输出与衔接 | 交给谁、产生何种产物、更新哪些判断 |
| 责任与权限 | 谁可作决定、修改、复核或升级 |
| 停止与失败 | 目标达成、预算结束、证据不足、内容错误时分别怎么办 |
| 验证与未知 | 如何检查设计是否有效，哪些是文档支持、设计推论或待验证假设 |

关键设计可以用一句话串起来：**基于什么证据，为解决什么缺口，安排什么活动，由谁执行，观察什么变化，结果不符时怎样调整。**

## 八、接下来如何安排设计讨论

建议把后续工作分成以下专题，每次完成一个可审查的小版本：

1. 目标、关键场景、资料边界与总体架构 v0。
2. 课程目标、学科任务与掌握证据标准。
3. 学习者状态、诊断、表现条件与记录原则。
4. 具体材料的选择、组织、生成与核验。
5. 单次教学骨架及 Encoding 详细设计。
6. Post-Encoding、延迟检验及二者的返回路径。
7. 策略使用规则与有限策略的教学示例。
8. 长期计划、预算、漏学、积压与恢复。
9. 多 Agent 的授权、交接、复核与共享信息。
10. 跨学科和异常场景演练、验证计划、架构修订与首期范围。

这些专题可合并或交错，不必各写一份长文。最值得先完成的是前两项：它们决定后续所有教学技巧究竟要服务什么。

设计完整的标志是：拿到一项课程要求后，能够追溯到目标与材料，再到学习者证据、教学选择、具体活动、复核与后续计划；任一处失败都能找到处理路径和责任。尚未验证的参数可以保留，但不能有关键判断没有依据、没有负责人或没有检验办法。
