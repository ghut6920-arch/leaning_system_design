## 一、目标、范围与设计依据

本方案对应设计流程的**阶段 A／工作包 1**。核心选择是：**围绕可检验的学习目标组织教学，用带有帮助条件和时间信息的表现证据调整判断，再让这些判断改变后续活动与课程安排。**

系统贯通三个尺度：课程安排、单次学习、跨天延续。Encoding 与 Post-Encoding 共用内容依据、学习证据、任务、反馈和评估能力，分别保留初步理解、独立恢复、关系加工、延迟保持和迁移的不同判断要求。

### 1. 已确定的目标与边界

- 面向个人长期学习，覆盖人工智能、数学、金融、政治等学科。
- 以课程资料为起点，结合阅读、示范、问答、推导、代码、案例和其他合适的学习活动。
- 高能力 Agent 负责整体规划、评估与关键教学设计；中等能力 Agent 承担主要交互、制作及教学执行。
- **用户已确认：时间不足时，独立掌握优先，必要时缩小覆盖范围。**
- 成效以减少帮助后的独立表现、延迟保持和目标情境中的应用为依据。课程覆盖、完成率和交流轮数分别记录。
- 本阶段确定流程、能力边界、责任、信息含义和返回路径。模型、数据库、完整字段、调度算法、数值阈值、题库与角色提示词进入后续设计。

“独立掌握优先”不意味着必须无限追问到完全理解。每次学习都有目标范围和资源边界；预算耗尽时可以暂停，但必须准确保留未达成部分。用户对目标、范围与投入拥有最终决定权；系统给出取舍建议及其影响。

**本轮设计完成**指流程和责任可以被审查、关键分支有去向。**未来学习成功**则必须由实际独立表现、延迟保持和目标所需的迁移证据支持。设计走查不能替代后者。

## 二、三个尺度的整体学习流程

### 1. 总体关系

【设计】下图表达主要判断和返回关系，不规定所有学习必须经过相同教学动作。暂停、缩时和依据争议可以发生在任一活动或检查节点。

~~~mermaid
flowchart TD
    A["课程表、大纲、教材、考核要求"] --> B["形成目标、验收依据与暂定前置关系"]
    B --> C["结合学习证据和预算，确定阶段范围"]
    C --> D["恢复上下文，确定本次目标"]
    D --> E["组织输入、学习者任务与反馈"]
    E --> F{"现有表现支持什么判断？"}
    F -->|"缺口仍在，诊断需修订"| E
    F -->|"需要局部补基础"| G["保存父目标，完成必要修复"]
    G -->|"回到原目标的新任务"| E
    F -->|"具备独立检查条件"| H["按验收条件取得独立表现"]
    H -->|"暴露相关缺口"| E
    H -->|"按证据范围形成结论"| I["收束：当前结果、帮助条件、未解决项"]
    E -->|"预算结束、用户暂停或依据不足"| I
    G -->|"预算结束或需要重审"| I
    H -->|"请求帮助，转回教学"| E
    H -->|"暂停或评分待核实"| I
    I --> J["形成延迟检验与后续学习需求"]
    J --> K["跨天恢复、重新确定范围并取得新证据"]
    K --> C
    K -->|"目标或前置关系需要修订"| B
~~~

用户要求示范、改变目标、缩短时间、暂停或质疑评分，都是正式流程入口。材料或评分依据发生纠正时，进入内容回查路径，再影响目标、教学、判断与计划。

### 2. 课程尺度：把课程安排变成可检验的学习目标

| 环节 | 目的与输入 | 输出 | 关键判断及返回路径 |
|---|---|---|---|
| 接收与辨认资料 | 区分课程表、大纲、教材、作业分别提供的信息 | 内容范围、时间约束、可用依据与缺失项 | 只有课程表时可形成暂定安排，但不能推定完整深度和评分标准 |
| 联合定义目标与验收 | 将章节主题转成解释、辨析、推导、执行、选择或应用任务 | 能力目标、验收方向、暂定前置关系 | 无法描述可观察表现时，返回澄清目标；避免把全部相关知识列为前置 |
| 形成阶段范围 | 合并目标价值、当前证据、课程节点和资源限制 | 本阶段承诺范围、候选学习任务及取舍理由 | 必要补缺与检验超出预算时，缩小可选新内容 |
| 准备近期学习 | 为近期目标选择具体材料范围和适当任务 | 本次教学准备与待核验内容 | 依据不足时补资料或收缩目标，不用生成内容填成“已知事实” |

高层负责目标、验收和阶段范围，执行者依授权准备材料与近期任务。材料范围落实到章节、段落、例题、图表或视频片段，并说明用途、前置要求、预期负担及可访问性。教材原文、外部补充、AI 桥接说明、生成练习和评分参考分别标识。

课程进度与个人掌握分别维护。延迟检验发现问题后，系统可以修改目标拆分、前置关系和阶段范围，不能只追加一条“待复习”。学期或阶段规定目标范围与重要节点；每周在可用资源内分配新学、补缺和检验；单次学习落实到有限目标；知识单元承载具体关系、条件和任务证据。这些尺度共享依据，不各自另建掌握结论。

### 3. 单次学习尺度：围绕当前缺口循环

**开始。**读取本次目标、上次关键表现、提示历史、未解决项和返回位置；结合用户本次时间与意愿，确定本轮范围。既有证据不足以选择教学起点时，安排一个能够区分不同解释的小任务。过期、来源已变或适用情境不同的旧证据先标明限制，不直接沿用。

**推进。**根据目标和现有证据选择可靠输入、示范、预测、解释、比较、推导或应用。前置不足时允许先给示范和局部支架；已有相关知识时，可以先尝试。每项活动必须保留由学习者完成的关键认知工作。可视化须指出要帮助理解的关系、保留的条件以及学习者需要预测、补全、操作或解释的内容。

**反馈与修订。**先检查题目和依据，再判断作答。区分事实缺失、关系误解、条件误用、方法选择、执行失误和表征不熟；疲劳、歧义等合理解释也保留。没有足够证据时，结论保持暂定。回答慢、自述“懂了”或一次流畅解释均不能单独确定学习状态。

**局部修复。**转入子问题前保存父目标、转入理由和返回条件。子问题通过后，回到原目标的新任务检查；连续失败时重新审查诊断，不沿同一解释无限下钻。只补当前目标真正需要的前提；接口和条件已足够时，允许内部细节暂时作为黑箱。

**检查。**区分两种用途：

- 撤除帮助后的练习，用于判断是否继续教学。
- 独立验收，用于取得预定条件下的能力证据；关系与应用目标使用未练任务，记录此前是否暴露对应方法或答案。保持检验可以恢复原内容，不能把熟悉原题本身误标为新情境迁移。

一次活动若事先具备独立验收所需的题目新颖性、材料可见性、提示暴露和判据条件，可以同时承担两种用途；同一表现只记作一份证据。不能在帮助已经给出后，追认该表现为无帮助验收。若用户在验收中请求示范，可以转回教学，并如实记录帮助条件。

**结束。**至少区分以下结果：

| 结束原因 | 应保存的结论 | 后续去向 |
|---|---|---|
| 当前目标达到 | 当前范围、任务条件下获得了什么支持 | 安排所需延迟或变式检验 |
| 预算结束或用户暂停 | 完成部分、未完成部分、恢复位置 | 重新评估下一次范围 |
| 依据不足或评分争议 | 哪些判断暂不能成立 | 核验依据后再决定 |
| 当前方法无进展 | 尝试过什么、哪些诊断受到反证 | 改变诊断、活动或目标粒度 |

任何一种结束都不能自动登记为“长期掌握”。执行者及时记录观察与停止原因；重要判断和范围变化由高层按授权与升级规则处理。

### 4. 跨天尺度：重新确定范围，再组织学习

【设计】新学、补基础、纠错、检索、关系加工和迁移，共同竞争有限时间。每次恢复时重新确定本轮承诺范围，避免旧任务不断叠加。

优先判断：

1. 是否存在会影响后续学习或评分的内容错误、关键误解。
2. 当前目标真正依赖的前置条件是否可用。
3. 缺少的是独立、延迟还是新情境证据，能否直接补相应检验。
4. 哪个小任务最能区分目前的几种解释。
5. 为完成必要工作，需要延期、缩小或移出哪些可选内容。

这些是符合用户目标的工程取舍，不是研究已经确定的最优调度顺序。

跨天结果应产生不同调整：

| 新表现 | 暂定判断与计划调整 | 需要保留的边界 |
|---|---|---|
| 无提示失败、提示后成功 | 保留提示下表现，继续检查独立调用条件 | 不等于完全不会，也不等于独立掌握 |
| 前提提供后能推理 | 补前提访问，保留已有推理证据 | 不清空整个主题的已有表现 |
| 前提提供后仍无法解释关系 | 返回局部 Encoding，必要时拆分目标 | 更频繁地重复原题未必解决结构性缺口 |
| 原题正确、新例混淆 | 增加边界辨析，减少无差别重复 | 同时检查新情境是否带来额外前置要求 |
| 延迟独立表现稳定 | 降低当前训练强度，释放新学资源 | 不宣布永久掌握，后续仍可因新证据修订 |
| 多次投入仍超出预算 | 明确修订阶段范围与延期原因 | 不默默降低验收要求或把原目标记为完成 |

系统分别记录初学至检索、检索至反馈、反馈至后测、相邻练习的间隔。具体安排由目标保持期限、表现、错误风险和可用时间决定，当前不设统一复习日历。不从等待、睡眠或一次行为改善推断特定神经过程已经完成。

【依据】EN §9、§11；PE §3、§6—9、§11—13；流程工作包 7。上述统一预算、范围重定与回写课程的组织方式属于【设计】。

## 三、概念架构、共享信息与协作责任

### 1. 六项主要能力

【设计】以下是职责边界，不要求各自对应软件服务或 Agent。

| 能力 | 为什么需要 | 主要输入 → 输出 |
|---|---|---|
| **课程目标与验收设计** | 防止把“读完一章”作为最终能力目标 | 课程要求、使用情境、约束 → 目标、验收依据、前置关系与范围 |
| **内容与材料管理** | 使学习内容、任务和评分有可追溯依据 | 原始资料、补充来源、生成内容 → 可定位材料、可靠性说明、核验结果 |
| **学习证据与诊断** | 区分观察事实和对错误原因的解释 | 原始作答、帮助条件、时间、判据 → 条件化表现、暂定诊断与待查问题 |
| **教学设计与执行** | 把目标缺口变成实际学习活动 | 目标、证据、材料、策略资源 → 输入、任务、反馈、局部修复与学习产物 |
| **评估与复核** | 判断表现能支持什么结论，发现内容或评分问题 | 验收要求、原始表现、可靠依据 → 有范围的判断、争议和复核需求 |
| **持续计划与恢复** | 协调新学与后续检验，并维持学习连续性 | 当前目标、证据、预算、未解决项 → 本轮安排、范围调整及恢复上下文 |

来源追溯、用户控制和成本记录贯穿六项能力。

~~~mermaid
flowchart LR
    G["课程目标与验收设计"] --> P["持续计划与恢复"]
    G --> T["教学设计与执行"]
    G --> V["评估与复核"]
    M["内容与材料管理"] --> T
    M --> V
    P --> T
    R["策略资源与共同使用约定"] --> T
    T -->|"任务、原答和帮助条件"| E["学习证据与诊断"]
    E -->|"当前证据与暂定缺口"| T
    E --> V
    V -->|"有范围的结论与待复核项"| E
    E --> P
    V -->|"需重核的依据"| M
    P -->|"范围与目标修订需求"| G
~~~

“教学执行”和“评估复核”分开，是因为前者可以主动提供帮助，后者必须检查这种帮助对证据含义的影响。两项能力可以由同一 Agent 在不同任务中承担，但用途、输入和判据必须明确。

Encoding 和 Post-Encoding 使用相同能力，任务目的和证据含义有所区别：前者关注建立或修正当前表征，后者根据已学内容的恢复、关系加工、更新和跨时表现继续安排学习。同一活动可以包含检索和建构，不要求互斥归类。

### 2. 共享信息的语义边界

统一保存或共享信息时，必须区分：

- **学科内容依据**：命题、定义、条件、来源和当前有效范围。
- **目标与前置关系**：希望独立完成什么，哪些条件对当前任务必要。
- **实际表现**：学习者原答、过程、修订及关键判断由谁完成。
- **表现条件**：材料可见性、提示、同题暴露、时间间隔和任务变化。
- **暂定诊断**：当前解释、支持与反证、尚未排除的解释。
- **教学与计划状态**：当前支架、父子目标、停止原因、未解决项和下一步。

【设计】能力判断以“某目标在某条件下获得何种支持”表示，允许未知和待复核；不建立一个代表全部学习状态的总分，也不把报告的八维分析框架直接做成精确数值。

保留足以复核关键判断的原始证据及上下文，不预设无限保存全部对话。学习者的事实陈述、AI 生成解释和经核验的学科依据即使内容相似，也保持来源身份。个人自述与任务表现互为补充，不能用少量问答形成一般认知能力或稳定人格诊断。

### 3. 概念交接接口

| 交接 | 必须传达的含义 | 责任 |
|---|---|---|
| **课程到教学** | 目标、内容边界、验收方向、关键前置、材料依据和资源约束 | 高层确定；执行者检查资料是否足以开展 |
| **高层到执行者** | 教学意图、关键认知工作、当前证据、可调整范围、反馈依据及升级条件 | 高层交出可执行意图；执行者保留实际调整理由 |
| **执行到评估** | 原始关键作答、任务依据、帮助过程、反馈前后差异及待解释现象 | 执行者记录；评估者核对证据适用条件 |
| **本轮到后续学习** | 当前获得的证据、未证明的能力、未解决项、返回位置和后续检验需求 | 执行者收束；计划能力将需求纳入统一预算 |
| **内容纠错到相关判断** | 什么依据发生变化、影响哪些任务和评分、哪些结论需要重核 | 内容核验发现问题；高层决定影响范围和处置 |

这些接口先确定信息含义和责任；字段、格式与版本机制由后续共同规范和协作工作包细化。交接缺少关键依据时，接收者要求补足或保留待确认，不能从流畅摘要推定已掌握。

### 4. 高层与中层的责任

**高能力 Agent 负责：**

- 建立或修改课程目标、验收标准、主要诊断与阶段范围。
- 设计关键解释、问题、案例、变式和可视化意图。
- 裁决重要掌握判断、内容争议和相互冲突的证据。
- 审查教学效果与协作成本，决定保留、调整或简化哪些环节。

**中等能力 Agent 可以：**

- 在已确定目标和依据内组织阅读、提问、反馈及材料制作。
- 调整表述、局部支架和已界定范围内的变式。
- 按授权判据处理常规表现，追加原始证据并提出暂定诊断。
- 执行预定的暂停、恢复和范围内调整。

中层自主生成变式时，要保留目标关系和适用条件；如果改变定义域、关键假设或正确答案，需要重新核验。中层可以按已核验规则给出常规反馈，但不能擅自修改验收标准、回写历史作答，或将有提示成功改记为独立掌握。

【设计】高层在以下情况介入：目标或范围需要改变；来源或评分冲突；重复失败使原诊断受到怀疑；所需帮助超出授权；当前预算无法完成约定目标；准备作出重要能力判断。具体重复次数和预算阈值留待详细设计。

高层读取触发相关的原答、帮助记录和判据，不能只读取“已经理解”等总结。意见冲突依据来源、推导、测试和表现裁决；Agent 一致意见本身不构成正确性证明。高层暂不可用时，执行者保留争议、暂停超出授权的判断，并可继续不依赖争议的已授权活动。

【设计】同一学习目标的当前结论和计划有明确责任归属。并行 Agent 提交证据和建议；发生冲突时，不以“最后写入”覆盖前一结论，而由责任方比较适用范围与依据后修订。跨 Agent 委派沿原教学目标和授权范围展开，不能自行扩张新目标或反复重复诊断。

独立作答与可靠评分分别保障：验收依据先于结果明确；关系与应用任务保留未练变式；评估先看原答、帮助条件与判据，再看教学总结。关键判断或争议内容通过教材、推导、工具结果等核验；多个模型互相赞同不能代替这种核验，也无需每道题都建立多 Agent 评审。

### 5. 内容纠错与记录恢复

【设计】建立如下回查关系：

**材料或规则纠正 → 受影响的解释与任务 → 评分结果 → 能力判断 → 后续计划。**

历史原始作答保留其当时语境；派生评分和能力判断可以撤销或标为待复核。只有受影响部分需要重审，引用格式的小修改不应导致整章证据清零。新旧知识若在不同条件下仍有效，保留适用范围；纠错后检查旧错误复发，也检查仍正确的旧情境，避免一律覆盖。

首期只需保存少量稳定标识与依赖依据，不建设通用知识图谱。高层负责确定影响范围，中层暂停使用有争议的内容，整理待重核项目。依据过期或暂不可访问时，先判断其是否实质影响内容和评分，再决定重核或保持有限结论。

用户可以要求示范、改变目标、暂停、质疑评分以及查看、纠正、导出或删除个人记录。被删除的证据不能继续作为不可追溯的确定结论使用。删除个人记录的控制权优先于一般的历史可追溯要求；系统应随之撤销或降低依赖该证据的判断确定性。

### 2. 代表性贯通活动：代数变形的适用条件

以下是**假设学习轨迹**，用于检验架构，不代表用户实际基础或已经验证的教学方案。

**目标。**在实数范围内，判断从 \(ab=ac\) 推出 \(b=c\) 是否有充分条件，并在方程变形中保留解集。

**输入依据。**本例明确采用乘除运算规则及可代入核验的例子。正式教学时替换为可定位的教材片段与已核验题目；当前没有虚构教材章节或用户先验水平。

**高层教学意图。**学习者需要自主检查变形条件，并区分“结论不能保证成立”与“结论必定错误”。不能只背诵“不能除以零”。

| 环节 | 学习者完成什么 | 执行与记录要求 |
|---|---|---|
| 起点任务 | 判断上述推断并说明理由 | 若遗漏条件，暂时保留规则不熟、忽视条件、表达省略等解释 |
| 有区分力的检查 | 用具体取值检验自己的判断 | 可参考 S06／X01 检查前提与推断，D06 检查消去规则的适用边界；所给提示必须记录 |
| 必要支架与修订 | 在最小帮助下修订原命题，并解释修改理由 | 若 AI 已指出 \(a=0\)，随后答对只构成提示下表现 |
| 独立检查 | 在未练方程中自主选择合法变形，并说明解集 | 例如 \(y^2=3y\)；须先确认因式分解等前置，否则失败原因仍有歧义 |
| 边界反向检查 | 处理已限定变量非零的表达式 | 防止形成“永远不能除以变量”的新误解 |
| 后续检查 | 延迟后恢复条件，并在另一表达形式中使用 | 记录间隔、提示和改变的维度；这里只能支持相应保持或近迁移判断 |

**供设计审查的核验锚点：**

- 当 \(a\ne0\) 时可以消去；当 \(a=0\) 时，原等式不能保证 \(b=c\)，也不能据此断言 \(b\ne c\)。例如 \(a=0,b=1,c=2\) 是无条件消去规则的反例，而 \(a=0,b=c=1\) 表明结论并非必错。
- \(y^2=3y\) 等价于 \(y(y-3)=0\)，实数解为 \(0,3\)。直接除以 \(y\) 会遗漏零解。
- 对原式 \((x^2-x)/x=0\)，定义域为 \(x\ne0\)，约分后得到唯一解 \(x=1\)。这里允许除以变量。
- 以上答案属于设计和核验材料，正式验收前不能直接暴露给学习者。单次正确数字答案不足以确认学习者自主检查了条件。

中层可调整解释或采用已核验的近邻例。若局部练习成功而父目标仍失败，应重新检查诊断，并在需要时上报。局部修复参考 S10 的父目标返回要求。

如果参考答案遗漏零解，而学习者指出问题，流程进入**题目与评分纠错**：重核依据、修订评分和受影响判断；不能继续把该表现记作学习者错误。

若时间临时缩短，本轮可停在“提示下已修订、独立表现待检查”；保存当前条件和下一步需求。跨天恢复时先重定范围，再取得新的无提示证据，不因上次修订流畅而跳过检查。若旧错误复发，记录发生条件，重审边界理解或提示依赖，并调整后续新学范围。

### 3. 架构验收场景

| 场景 | 通过条件 |
|---|---|
| 基础不足 | 能定位必要前置，提供局部支架，并返回原目标的新任务 |
| 同错反复 | 能重审诊断、题目及反馈，不只增加同类练习 |
| 提示下会、独立不会 | 两类证据分开保存，后续目标仍包含独立调用 |
| 原题会、新情境不会 | 区分方法识别、关系映射、执行和新情境前置问题 |
| 材料或评分有误 | 能定位受影响结论，保留历史语境并安排必要重核 |
| 时间临时缩短或复习积压 | 能收缩承诺范围，明确延期部分，不把全部任务移到明天 |
| 中断或更换 Agent | 能恢复目标、关键证据、提示条件、未解决项及返回位置 |
| 用户改变目标或质疑判断 | 能更新当前安排并保留修改理由 |
| 无法获得可靠答案 | 能保留未知、暂停相关判断，继续不依赖争议的活动 |

跨学科沿同一流程走查，但使用各自的内容和评分标准：

| 学科 | 必须保留的正确性要求 | 不足时的处理 |
|---|---|---|
| 数学 | 对象域、前提、量词、合法推导与解集；类比不能代替证明 | 返回相关前提或推导步骤；保留证明未完成的边界 |
| 人工智能 | 概念解释、代码行为、实验结果与推断分别验收；记录实验条件 | 区分概念、实现和实验设计问题，不能用能聊天替代能实现 |
| 金融 | 模型假设、适用情境、数据时间和不确定性 | 检查条件与数据；本系统的课程评价不等同于真实投资决策成效 |
| 政治 | 区分事实、因果解释、价值判断及竞争理论；按证据与论证评价 | 核查来源、辨认分歧类型，允许多种有依据的答案和信息不足 |

对仅涉及约定或事实的目标，准确记忆可以是合适的结果；无需强加机制解释。跨学科迁移另外检查关系映射、成立条件及新领域前置，不能只凭术语相同判断成功。

### 4. 四类验证与首期范围

验证分别回答：

1. **内容是否正确：**材料、题目、变式、参考答案及评分能否依据可信内容、推导或工具结果核验。
2. **教学是否落实：**学习者是否完成目标要求的关键工作；提示是否泄露验收所需判断；局部修复是否返回父目标。
3. **学习是否获益：**即时独立表现、延迟保持、迁移、提示依赖、错误复发、用时和主观负担如何变化。
4. **协作是否值得：**相较简单流程，是否改善质量或节省成本，同时检查等待、交接损失和维护负担。

【设计】个人试用采用难度和前置尽量匹配的有限单元，控制学习时间与反馈机会，分别比较：

- 自适应活动选择与合理的固定教学流程，检查独立新题及延迟表现。
- 分层多 Agent 与较简单的单 Agent 流程，尽量保持任务、材料和判据一致，比较学习结果与总成本。

避免同时改变多项因素；不把同一已学内容的第二次学习当作全新基线。保留个人样本小、顺序效应、题目差异和学习不可逆的限制。具体分配、题量、评分和延迟安排进入阶段 E 的试用方案，本轮不宣称因果收益。

**首期选择一门课程的有限主题，覆盖完整闭环：课程资料 → 目标与材料 → 教学 → 独立检查 → 延迟回访 → 计划修订。**只使用有明确用途的少量策略；具体课程待真实资料进入 B1 后确定。

首期最小运行材料包括：目标与判据、核验过的学习任务、条件化证据记录、暂定诊断与未解决项、下一次计划。

| 观察结果 | 对策略或协作环节的处理 |
|---|---|
| 能支持目标表现且成本可承受 | 保留，并继续关注适用条件 |
| 有部分收益但提示依赖、错误或成本偏高 | 调整支架、任务范围或调用时机，重新比较 |
| 两个环节重复取证或提供同类反馈 | 合并责任或复用同一学习事件，避免重复计分 |
| 无可观察收益而持续增加成本，或超出首期必要范围 | 暂停或删除该环节；保留调整依据 |
| 内容依据失效、反复生成错误或造成误判 | 立即暂停相关使用，先纠错再考虑恢复 |

这些是设计层面的处置方向，不能凭一个失败样本断言某策略永久无效。教学失配、题目问题、资源不足和学习者表现需分别检查。

## 五、后续工作包、依赖与完成标准

### 1. 工作包安排

保留原有 A—E 五阶段组织。后续首先对齐共同语义，再展开教学和持续运行，避免 Encoding 与 Post-Encoding 分别建立诊断、评分和状态体系。

| 工作包 | 要解决的问题与产出 | 依赖与检查条件 | 主要未决事项 |
|---|---|---|---|
| **B1 课程目标与验收** | 课程到能力的分解规范、前置关系、学科判据 | 依赖 v0；重要目标都有可观察表现 | 真实课程、深度、验收覆盖 |
| **B2 学习证据与诊断** | 表现条件、暂定诊断、判断更新与撤销规则 | 与 B1、B3 并行；不同帮助条件不混为相同能力证据 | 冷启动、证据充分性、冲突与过期 |
| **B3 材料与来源** | 材料粒度、生成内容核验、冲突及纠错影响 | 与 B1、B2 并行；任务与评分可追溯依据 | 材料选择、可信参考、版本影响 |

### 2. 教学领域的子工作包

Encoding 保留 E1—E5，Post-Encoding 保留 P1—P5，本文完整写为 Encoding-E1—E5 和 Post-P1—P5，以区别原研究报告的证据等级 E1/E2/H。它们是需要分别解决的设计问题，不是每次学习的固定步骤或 Agent 名单。

| 子包 | 主要输入及问题 | 输出与检查条件 |
|---|---|---|
| **Encoding-E1 目标与内容结构** | B1/B3 的目标、材料与前置：本次要形成哪些关系和条件？ | 当前理解目标；深度与验收任务相符，不另建知识库 |
| **Encoding-E2 初始理解与支架** | Encoding-E1 与 B2 的先验证据：输入、示范或尝试如何起步？ | 进入与帮助配置；前提不足时有支架，撤除后需检查 |
| **Encoding-E3 表征建构活动** | 当前缺口、材料、C-S：由学习者完成什么？ | 具体活动设计原则；产物和认知劳动归属清楚 |
| **Encoding-E4 修订与局部修复** | 实际错误、替代诊断及父目标：修复哪一层？ | 修复分支和返回条件；子任务成功后回测父目标 |
| **Encoding-E5 当前收束与交接** | 当前独立表现、帮助历史和未决项：可以结束什么？ | 当前结论和后续检查需求；不宣告长期掌握 |
| **Post-P1 检索任务与提示** | 已学目标、证据和检查目的：恢复什么，如何区分提示依赖？ | 检索规格、提示原则及失败入口；不把未学猜测计作已学检索 |
| **Post-P2 关系加工与迁移** | 目标关系、案例与前置：整合、辨析或新情境应用缺什么？ | 分别给出关系加工与迁移判据；改变的情境维度明确 |
| **Post-P3 错误修复与更新** | 新旧主张、来源、条件及错误：替换还是按情境共存？ | 更新与反馈路径；检查旧错误复发和仍有效旧情境 |
| **Post-P4 活动组合与转接** | 目标、当前表现、反馈可用性和预算：下一步为何改变？ | 组合、回退和停止规则；结构缺口能返回局部 Encoding |
| **Post-P5 延迟维护与验证** | 当前证据、保持期限与后续使用：还需哪些跨时检查？ | 检验需求、优先理由和计划反馈；全局时间由 D1 统一安排 |

Encoding 与 Post-Encoding 共用 C0 的任务、反馈和评估语义。Post-P2 内分别制定关系整合与迁移应用的判据；两者不能因共享活动形式而共用一个成功标准。各子包的具体题目、判据和参数作为上述输出继续设计，不在 v0 提前冻结。
