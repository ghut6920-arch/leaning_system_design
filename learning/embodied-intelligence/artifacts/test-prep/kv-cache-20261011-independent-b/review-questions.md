# AG3 从原用途先定的反向审查问题

状态：作者成品接触前冻结的问题。日期：2026-10-11。

## 接触顺序与范围

本子 Agent 首先只取得父 Agent 转交的原用途和用户测试前提，再读取共享 `AG3-assessment.md`、`learning-assessment/SKILL.md`、`product-review.md`、`evidence-rules.md`、`disciplinary-to-teaching.md`，随后核查下列一手材料。此时未读取作者目标、方案、参考答案或同主题旧备课。后续实质审查记录在 `review.md`。

本次用途是为 Transformer Attention、KV Cache 与长上下文推理制作独立测试备课成品，先交成品供审查；不开展教学、不评真实学习者、不更新进度。四层前提来自用户：识别选择与条件后果已有较强支持；多选择交互部分具备；未知约束、竞争目标和不充分证据下构造、验证、调整方案尚未充分检验。这些是本次备课的给定前提，不是本 Agent 新形成的能力结论。

问题用于检查用途承接、学科关系、输入和学习者工作，不逐条转换为新增必修题。现有连贯解释或同一整体任务足以承担时应直接采用。只核当前有限用途，模型训练、内核实现、生产部署不是自动新增目标。

## 先定问题、所需连接及失败风险

| 编号 | 从原用途提出的关键判断或条件变化 | 成品应能支撑的关系与操作 | 容易造成假通过的失败风险 |
|---|---|---|---|
| R1 | 为什么历史 K/V 能复用？若相同 token 的前缀、位置、掩码、模型权重或适配器变了，哪些缓存还能沿用？ | 把因果可见范围、各层历史表示、位置及缓存身份接起来；区别合法追加、共享同一前缀与修改旧上下文。必要定义可由教师提供。 | 把 KV 当 token 级无条件字典；只会口述“避免重复计算”，不能解释条件改变后是否失效。 |
| R2 | 缓存预算为何随有效驻留 token、KV 头和层数增长？并发请求长度不同、存在共享、分页或量化时，简单乘法何时失效？ | 用张量对象推得未压缩理想存储，辨 `H_Q` 与 `H_KV`，再区分有效数据、物理分配、元数据和运行时余量。允许未知量保留为区间。 | 用查询头数计算 GQA 缓存；只算平均长度；把理想容量当峰值可运行保证；把分页当无损删除必要 K/V。 |
| R3 | 长输入短输出与短输入长输出切换后，改善 TTFT、逐 token 延迟及吞吐的优先方案是否相同？ | 区分 prefill 的已知序列工作与 decode 的新增 token 工作；将阶段、数据移动、队列/调度和指标口径连接到条件方案。 | 把所有 attention 都称一个复杂度；将 kernel 加速等同服务 p95 改善；以总 tokens/s 替代交互 SLO。 |
| R4 | 多个优化选择何时互补，何时改变语义或增加另一瓶颈？ | 分清精确 attention 的 IO 改写、KV 存储管理、可共享前缀、精度变换、历史淘汰/窗口和跨设备移动各改变哪个对象；按给定模型与后端约束判断合法组合。原生 GQA 的头数是架构条件，不能当任意现有模型的无成本运行开关。 | 把 FlashAttention、分页、前缀复用当同一种节省；把局部窗口无条件套到全注意力模型；忽略卸载传输或量化质量代价；只列独立优缺点而不检查组合。 |
| R5 | 有显存上限、延迟/吞吐/质量竞争目标，但负载、输出增长、共享率或硬件带宽还未知时，当前究竟能决定什么？ | 由学习者组织已知/未知、选会改变决策的信息、给有边界的可行方案与条件分支，允许有理由暂不定唯一方案或判不可行。为减少未知而搜集什么、为何有价值，应留下真实选择。 | 题干或标题已点名最优技术；全部约束已算好，仅换数字；要求没有证据也必须给唯一正确配置；把“缺数据”一句当完整构造。 |
| R6 | 如果观测到长上下文变慢、OOM 或 p95 恶化，什么检验能区分容量、分配浪费、KV 读带宽、prefill 干扰及到达负载等解释？新结果怎样改变原方案？ | 同一完整产物中提出候选原因、匹配基线/控制条件、可区分的观测、可接受/否定范围及下一调整。由学习者选择最有信息的检验与停止/回退条件；测试不必实际运行，但计划须可执行。 | 给完整实验矩阵再让学习者复述；只写“压测”；一次均值或单序列速度直接支持生产有效；观察与调整脱节；为了通过无限增加实验。 |
| R7 | “可接收某长度”和“在该长度完成用途”之间还缺什么证据？位置、干扰信息、跨段关系或缓存近似改变后，质量判断为何可能变化？ | 将模型/位置支持、资源可运行与实际任务质量分开；提出与用途匹配的质量观察及可比基线，说明有限检索测试能支持和不能支持的主张。 | 把最大 context 配置或 needle 检索正确当长文推理保证；引用旧论文的特定模型现象作为所有新模型必然规律；以省显存替代质量验证。 |
| R8 | 既有较强的辨认与条件后果前提怎样成为支架，尚未检验的构造/验证/调整工作由谁完成？ | 检查用户可见输入、标题、图、默认选择、范例和备用帮助；必要前提应交付，目标内核心选择与连接留给学习者。参考应容纳合法多解、条件不足与不同帮助程度。 | AI 将整套选择与调整路径先示范，再把复述评价为自主构造；数道局部选择题取代连续方案；备用答案默认可见；把备课审查通过写成真实能力/效果结论。 |

## 专业核查的边界与依据

以下材料只是支持先定审查问题，不是替作者规定技术菜单或要求学习者阅读全部论文。

- R1：因果历史表示及逐层缓存机制、注意力掩码与 cache position 需相容，见 [Transformers v4.57.0 Caching](https://huggingface.co/docs/transformers/v4.57.0/en/cache_explanation) 的 Attention matrices、Cache class 和 Cache position。网页示意的掩码公式不可机械当实现公式：因果屏蔽通常用加性负无穷或等价 masked softmax。
- R2：未共享、等 KV 维度、未压缩的理想缓存是 `2 × L × H_KV × d_head × bytes_per_element × Σ_i T_i`；等长时 `Σ_i T_i = B×T`。这是张量元素计数，不是全部显存预算。分页的浪费与共享对象见 [PagedAttention 原论文](https://arxiv.org/pdf/2309.06180) §2.3、§4、§7；GQA 架构范围见 [GQA 原论文](https://arxiv.org/abs/2305.13245)。
- R3/R4：FlashAttention 的精确算法以 tiling 改善 HBM/SRAM 数据移动，并不删去全注意力依赖，见 [FlashAttention 原论文](https://arxiv.org/abs/2205.14135)。前缀缓存主要复用 prefill，不能直接假定加速 decode，见 [vLLM Automatic Prefix Caching](https://docs.vllm.ai/en/stable/features/automatic_prefix_caching/) 的 Limits。原论文中的速度倍数不能直接迁到本次未知环境。
- R6：PagedAttention 原论文 §6 使用不同请求到达率/输入输出分布比较端到端性能，§7 的 kernel 结果与整体服务结果不等同；该证据支持检查匹配工作负载和口径，不支持一概断定任何实现都是 KV 带宽瓶颈。
- R7：上下文长度配置不足以直接证明任务有效范围。位置控制的研究例子见 [Lost in the Middle 原论文](https://arxiv.org/abs/2307.03172)；超出单一 needle 检索的任务范围例子见 [RULER 原论文](https://arxiv.org/abs/2404.06654)。这两项是有限研究结果，本次具体模型的表现仍未知。

## 后续审查的判定方式

收到新成品后，先读目标建议和学科依据，再读完整用户材料、主要任务、备用支持、教师参考，最后读作者通过总结。将 R1–R8 对应到实际位置和缺失连接，分别判断用途承接、专业内容、教学功能、剩余学习者工作及未观察适配。必要回提指出责任和可定位影响；充分内容保留，修复后仅重核受影响项。

没有真实学习者原答：只能形成有范围的准备判断，不形成能力、保持/迁移、教学效果或多 Agent 协作收益结论。本阶段不写 `state/`、`goals/`、`assessment/` 或 `sessions/`。
