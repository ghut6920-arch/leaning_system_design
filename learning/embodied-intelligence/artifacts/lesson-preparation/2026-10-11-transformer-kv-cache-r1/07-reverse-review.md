## 先于成品提出的专业问题

### R1：新增 token 后，为什么旧 K/V 仍代表同一个计算对象？

应能够把“因果遮罩禁止看未来”连到“固定前缀的旧位置在每层的表示不因后续 token 追加而改变”，再连到“每层旧 K/V 可复用”。只说 K/V 是历史记忆或计算很贵，不承担这一连接。模型参数、既有 token、位置／位置变换和注意力条件一致，推理计算确定；前缀被编辑、权重变更或位置解释变化时必须重审。双向 self-attention 不能未经限定套用同一增量复用理由。无需将全部条件另出题，但正文和参考应保留必要成立条件。

关系检查也包括：新位置仍须产生当前 Q/K/V；新 Q 与缓存 K 得到当步权重，再混合缓存 V。旧 Q 对“只求最新位置输出”的当步目标无必要，不能误说 Q 无法缓存。缓存按层存储，不是一个跨层通用 token 字典。[官方缓存说明](https://huggingface.co/docs/transformers/main/cache_explanation)与[原 Transformer 论文](https://arxiv.org/abs/1706.03762)提供对象依据；逐层不变性须在成品中用因果依赖关系解释。

### R2：一次 prefill 和一次 decode 的输入、输出、cache 长度如何连起来？

长度为 P 的 prompt 经过 prefill 后，最后位置输出预测第一个新 token y1；y1 尚未进入缓存。再以 y1 为新输入得到其表示／K/V，并预测 y2，此时 cache 长度为 P+1。材料中的 token 名称、当前位置、序列长度、输出预测对象应一致，防止把“预测出来”与“已送入模型”混为一件事。若示范是固定 Q/K/V 的 attention 内核，必须说明它没有演示词表 logits、采样或完整多层语言模型。

### R3：示范能否让一个新 Q 的计算与无缓存路径逐项对应？

需要实际输入、维度、scores、softmax 与 V 混合，以及追加后的 K/V。足够小的可核数值、清楚的矩阵／表或实际图可以承担，不统一要求交互媒体或程序实现。应把旧结果不变与新行注意力改变分开：新 token 可以改变当前行的权重和结果，却不回写旧行。若展示缓存／无缓存结果一致，参考应查相同权重、位置、掩码与精度条件；有限数值运行只核该实例，不能代替一般理由。遮罩在 softmax 前排除不可见位置，不能只把未遮罩分数乘零而使其仍获得概率。

### R4：“长上下文快了”究竟省掉什么，仍须做什么？

应区分 prefill 全序列的注意力工作、一次 cached decode 的当前行工作，以及生成 G 个 token 的累计工作。标准 dense causal attention 的 prefill 仍有二次长度项；cache 使最新位置不必重算全部历史层状态，但新 Q 仍读取／比较可见历史 K/V。注意力项可写为单步约 O(T d_h)，累计为 O(GP+G²) 的长度项，而不是“缓存后长上下文整体线性／常数时间”。未缓存的比较基线须明确是否每步重跑整个前缀；不能把某个 attention 项直接当整模型延迟或硬件测速结果。FlashAttention 改变访存和中间矩阵保存，标准精确 dense 算术的二次长度项仍在。[FlashAttention 原论文](https://arxiv.org/abs/2205.14135)支持访存与精确注意力的区别。

### R5：容量变化为何改变选择，算出的是什么容量？

在各层配置相同、完整 dense KV、key/value 头维相同的约定下，逻辑数据量为 2×B×L×T×H_kv×d_h×s 字节。长度、并发批量与每元素字节数的变化要能回到实际存储对象。MHA、GQA、MQA 比较用 KV 头数，不能误用 Q 头数；真实显存还包括参数、工作区、分配／分页开销等。逻辑容量／剩余显存足够不构成速度或整体服务可行性证明。公式、单位和假设有可靠参考，具体材料应容纳预算不足或信息不足的可靠结论。[GQA 原论文](https://arxiv.org/html/2305.13245v3)说明共享 KV 头以及 checkpoint 转换和后续训练；原 MHA 模型不能只在推理时删头就宣称无损切换 GQA。

### R6：上下文已进入 cache，为什么仍不能保证任务信息被可靠利用？

需要区分可存储、可计算、位置／模型支持范围和实际任务质量。缓存保存计算状态不能证明模型正确检索、整合或推理。长输入的任务证据可受信息位置、干扰内容、任务类型影响；判断应限定到所用模型／任务与比较条件。若采用 Lost in the Middle，只能说明其已测模型与任务上出现的位置敏感现象，不能推出所有当前模型永远同样失败或“中间位置必然没用”。[Lost in the Middle 原文](https://arxiv.org/html/2307.03172v3)提供这种证据边界，不提供当前单元的学习者表现。

### R7：优化方案改变的对象与代价是否匹配当前瓶颈和任务？

成品应能够在已介绍的少量方案中作有条件判断：访存／中间矩阵、逻辑 KV 数据量、物理分配／共享、跨设备搬运、可见上下文分别是不同对象。不能把页式管理、FlashAttention、GQA、低精度、offload 与滑窗全部说成同一种“压缩”。某方案可保持给定注意力语义，另一些改变数值精度、模型架构或可见 token；质量和延迟收益须有相应证据。审查不要求囊括所有工程技术，但实际主线采用的方案应有足够输入供比较，题面不能只给名称后让学习者猜关键前提。
