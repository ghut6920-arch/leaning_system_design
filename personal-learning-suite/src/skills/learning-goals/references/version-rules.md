# SK01 版本与纠错规则

资源版本：`pl-goals/0.1.0`；协议：`pl-contracts/0.1.0`。依据 D02 第四、八至十节，D03 第十节；当前权责与控制以[共享契约](../../../../contracts/shared-contracts.md)为准。

## 身份与兼容

`GoalSpec.id` 在同一目标修订中稳定；`revision` 表示目标内容修订，`criterion_revision` 表示各要求判据修订，协议版本独立。`requirement_id` 在要求身份未改变时保留，历史引用锁定 `{id, revision}`，不跳到最新版。拆并须明示新旧要求映射、未映射部分和新增综合工作，不伪造旧证据。

| 变化 | 对旧依据的处理 |
|---|---|
| 当前目的与条件完全兼容 | 复用原目标及修订，不追加诊断或目标 |
| 措辞／定位等价维护 | 给等价依据；关键操作、正确性条件与证据含义未变才保留支持关系 |
| 拆分 | 只向实际观察的子要求映射支持，其余待查 |
| 合并 | 保留局部依据；新增组织与协调要求待证 |
| 扩范围／加深度／减少帮助 | 旧依据保留原范围，新范围由 AG3 重审，不能自动升级 |
| 正式缩小个人目标 | 新版本明确范围取舍；旧范围延期／替换，不改历史达成 |
| 内容／判据实质纠错 | 请求即时限制受影响用途，重审原答和判据；不预判用户错误 |
| 会话缩时 | GoalSpec 和判据不变；交 SK05 缩承诺或暂停，并列未覆盖影响 |

相同文本不必然等价，内容变化也不必然使所有旧证据失效。自动比较只发现结构差异并给保守重核建议；专业等价或支持判断仍由责任方完成。判据的实质内容改变需增加 `criterion_revision`，不能用修改文本保持旧判据号来掩盖变化。

用户决定新的正式用途、最终范围或新增投入。已有明确授权的粒度维护、事实纠正等可由 AG1 执行；未授权结果保持候选。旧候选不覆盖新承诺，单纯增加目标版本不解除已有用途限制。

## 错误传播与恢复

先定位争议来源、具体修订、受影响要求及用途。发 `ChangeNotice`，请求当前受控入口落实 `UseRestriction`；未取得控制回执只能说“需限制”，不能说“已暂停”。受影响活动先停相关使用，无关可靠范围继续。

沿两条链回查：来源 → 解释／任务／参考 → 评分／判断 → 学习安排；以及来源 → 目标／判据／前置 → 相应任务／材料／评价。未知依赖保留限制与下一核查责任，不视为零影响。

AG2 提供更正内容与支持条件，AG1 仅修相关目标／判据，AG3 根据原题、原答、实际帮助及当时语境复核。原答足够时直接重评；不足时只请求会改变决定的必要补证。纠正旧错误标准与后来新增标准分开，不能以新增要求倒判旧答。纠正参考不凭空产生未观察能力。

材料用途、历史判断、实际误导与计划安排四项恢复分别记录。SK01 仅处理目标和判据及其影响；不称其他责任已完成。删除后从剩余合法依据判断，不从摘要、缓存或旧候选恢复被删内容；进入当前 Agent 上下文的已删材料按宿主实际控制范围处理。
