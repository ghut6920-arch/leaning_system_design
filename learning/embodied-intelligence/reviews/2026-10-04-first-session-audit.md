# 首次 WM 学习：Encoding 与交互执行审查

日期：2026-10-04。依据为 Codex 聊天“启动第一次学习”（thread 01a10610-c8df-7e10-b4de-1126abeb7be4）12 个已完成轮次，以及本工作区实际题面、原答、会话记录和共享教学规则。范围是执行与设计一致性，不据此断言学习者脑内状态或验证全部学习收益。本报告属于真实学习过程的审查，删除范围应覆盖相应个人内容。

## 结论

已读取 Skill，但教学原则落实不充分。执行将局部检查串当成主要教学路径；Encoding 及启动配置对首次陌生主题的正向教学组织要求偏弱。两者共同造成失序感。首轮并非完全没有输入：AI 已解释张量、轴及 RGB，再提形状/计数题；缺少的是课程用途与局部关系的连贯支架。最后一轮已补整体任务图，不应忽略这一修正。

## 实际路径及判断

| 聊天中的工作 | 依据与问题 |
|---|---|
| 询问时间、已有 Python/作品 | 可以改变本次范围及实践入口，合理；属于安排信息，不是 Encoding 能力测评 |
| 轴释义后写形状与乘积 | 有教学输入，题目本身可用；未先解释该知识在世界模型数据接口中的用途，整体定位不足 |
| 修改帧数并运行乘法循环 | 符合用户实践意图，但操作对象还是尺寸元组，尚无真实视频数据；不能据运行输出推断数据表征已建立 |
| 单独追问 len(shape) | 教师主动追加。用户已完成映射与计数，尚无混淆轴数/元素数的原答证据；可以在例子里直接说明，没有充分展示独立检查的决策价值 |
| 让用户先辨别 reshape 与轴交换 | 属目标关系，但尚未连贯示范坐标身份和真实用途，对陌生学习者的输入不足 |
| 用 10–22 数值运行比较 | 数据值、帧/颜色、简化轴及目标表的对应尚未讲清。用户正确提交输出，却明确表示不理解在做什么；这是当前材料/教学不足的证据，不能推断编程能力不足 |
| 补带表头的 RGB 表，问 [11,21] 含义 | 针对明确困难的有限观察有价值；关系说明本应在首次展示数例时就具备 |
| 接着单独问轴编号序列 | 回到父关系方向合理，但再次形成微题往返。可在完整转换示范/实践中自然完成，不必把单行序列设为新等待轮次 |
| 用户多次质询后才完整说明、画任务图 | 教师承认碎片化，并给出整体定位。改善已发生；此前需要用户反复要求才执行正向组织，显示默认流程有缺口 |

保留得较好的部分：原答与修订分离；AI 代码/提示贡献明确；代码输出没有被冒称概念理解；没有将几道题正确升级为 G0 通过。这些证据规则不能替代教学本身。

## 是否遵循了 Skill

首轮工具轨迹可见实际读取了 SK00、AG0、共享契约、SK03、C0、Encoding，以及 AG1/AG2 和目标/材料规则，不能判为完全没有加载。

[Encoding 运行规则](../../../personal-learning-suite/src/skills/learning-teaching/references/encoding.md)允许完整解释先提供、没有错误模型时直接教学、局部够用后返回。设计源[Encoding 方案](../../../docs/designs/AI个人学习系统_工作包5_Encoding_设计方案_v0.md)第 55 行强调只在改变安排时拆分、第 132–148 行允许从输入/示范开始；各回答仍导向同一必要解释时，应直接解释而不是增加诊断。

[SK03](../../../personal-learning-suite/src/skills/learning-teaching/SKILL.md)规定只追加会改变下一步的小检查。当前微题链体现了这些原则的落实不足，不能用已经读取、已经记录或没有正式测评来证明执行合格。

## 设计及启动配置的漏洞

1. “完整解释可先提供”是许可，尚未明确首次陌生主题如何优先提供够用的目的、对象、关系、例子和范围。避免统一强制讲课是合理边界，但不能只剩负面约束而缺正向设计。
2. START_PROMPT 的“一次一项能完成的工作”、避免倾倒整章等措辞没有明确工作单位应是连贯关系/产物。可被误读为一句解释配一道微题。此提示词由本项目整理时编写，需承担这一诱导风险。
3. 对检查题的决策价值提出了文字要求，但缺少可审查的触发：观察什么、不同答案会如何改变教学、能否直接说明或整合到实践。给一个任意分支描述并不能证明题目必要。
4. 对完整复杂证明有整体检查要求，初学者的简单单元却可以合法拆成许多小目标，各自父任务 not_applicable。需要保留当前单元的自然主任务/用途，而不把每个定义都变成阶段验收。
5. 文件和程序检查重在记录、引用、授权及条件，无法替代内容设计审查。历史自动化通过记录不等于首次课程教学质量已验证。

## 当前案例应采用的组织方式

这是针对当前新手、陌生主题及用户明确希望先整体说明的设计建议，不是所有课程的固定教学顺序：

任务用途与够用整体图 → 当前局部关系图 → 一个含义完整的示范 → 学习者完成有意义的操作 → 根据真实障碍局部补充 → 回到完整产物及应用。

对于 M0，本次可围绕“把一小段视频以正确帧/颜色身份送进指定模型接口”组织。先说明相机观测、表征、动作、反馈及可选世界预测支路，再定位视频接口；用带帧与通道标签的二维缩小表说明每个数值的身份；示范正确轴交换及错误 reshape 的含义；之后让学习者修改/解释完整转换并检查一个坐标是否保持。不默认先测试 len、每个轴名或每行输出。

教师图是外部支架。学习者是否形成可用表征，通过后续解释、操作、条件辨析等表现作有范围判断；看过图不能记为已理解，也不需要为了证明看懂立即再追加一串检查。

## 等待的证据边界

最近 10 个已完成轮次，总周转最短 71.495 秒、最长 198.220 秒、中位数 122.833 秒；首次启动轮 319.718 秒，且包含入口澄清回复，不能当纯模型耗时。单轮 shell 命令记录的运行合计通常约 1–4 秒，其他时间可能涉及推理、生成、调度和工具往返，缺少进一步遥测，不能全部归因于文件读写。

可以确认“微题往返 × 较长周转”是本次体验成本。减少重复文书有必要，但仅改等待动作或缩短回复不能修复缺乏整体关系的教学。

## 后续修订应覆盖的层次

- AG1/SK03/Encoding：补首次陌生主题的够用支架与连贯内容单位；保留已有熟练产物直接使用等分支。
- AG0/检查规则：每项额外检查能说明会改变何项安排，无区别就直接教学或整合到主任务；限制无依据微题连发。
- 启动提示词/工作区接入：强调默认先有可用输入及任务定位，用户“不理解”时先修材料与说明；一次一项指连贯工作，不是一行知识一道题。
- 真实试用：审查学习者是否知道在做什么、例子是否有充分含义、必要实践是否完成及等待成本，不能只数保存文件或局部答对项。

本次完成审查和具体修订方向；未修改公共 Skill/Agent 或原始个人表现，也未向 WM 聊天发送消息。当前唯一教学入口仍以该学习聊天的实际控制为准。
